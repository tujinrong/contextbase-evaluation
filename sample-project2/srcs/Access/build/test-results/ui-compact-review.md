# Accessの入力欄・配置・描画制御の修正

2026-11-04。sample-project2のAccessを更新しました。本文11ptを維持し、単行入力欄の過大な高さ、入力群の不揃い、初期化途中の描画、処理後のスクロール位置ずれを修正しています。

## 変更内容

| 箇所 | 修正 |
| --- | --- |
| 単行TextBox・ComboBox | 高さ480→360twip（約8.5→6.35mm）。上下余白15、左右30twip。同じ論理欄の補助入力面にも適用 |
| ログイン | ID・パスワードを4800twipの同幅・同高に統一。ラベル・入力・メッセージ・ボタンを一群で中央配置 |
| タイトル | 本文11ptと分けて18pt・高さ540twip。対象表示と重ならない位置へ調整 |
| 操作・ラベル | 検索ボタン、経歴追加/除去、保存/取消と作用範囲の説明、分類ラベルの幅と位置を整列 |
| 描画 | 短い同期更新を入れ子対応の描画scopeへまとめ、正常・早期終了・例外で解放。同値属性の再設定と空一覧の不要な再問合せを抑止 |
| スクロール復帰 | Detailの原点とスクロール量を区別。Header/Footerの固定位置からDetailの位置を推測して先頭へ戻す処理を廃止 |

複数行入力の高さ・全文到達、業務項目、入力上限、認証、保存・取消、既存データは保持しています。Accessの通常入力にWinFormsのAutoSizeがあるものとして実装していません。

## 残る確認と別件

最終候補の実画面は、現在Accessを前面にできず、Windowsの解除状態の確認待ちです。直前の中間候補では5Form/6表示、日本語・英字、Tab切替、Combo候補、エラー後の再検索とログイン整列を確認しましたが、そのPASSを最終候補へ転記していません。静止画や描画scopeの状態だけで点滅が完全になくなったとは判定しません。

旧画面状態試験には、CurrentSectionTopを一律0とする誤り、未連結の不正rawをBeforeUpdateで閉じ込める旧期待、既存キーへのTab到達を禁止する旧期待がありました。採用済み仕様へ同期し、Header/Detail/Footerの原点、選択後の意図したスクロール、初期位置を分けました。旧v1.1のスクロール負例fixtureは現行契約に対応せず、別範囲の未実施です。

Excel出力は44条件通過後に内容検査MSG-037で停止しました。変更前の元ACCDBでも同じ失敗を対照確認しました。[比較記録](export-baseline-comparison.json)を参照してください。今回Excel出力の実装は変更しておらず、原因は未確定で、出力の合格を出していません。

IME/clipboard、他の表示条件・Office環境、同値Pendingのマウス採用、実Excelプレビュー/紙印刷、全663条件の実画面適合、利用者受入と正式採点は別に残ります。正式outputsは未発行、formalScore=nullです。
