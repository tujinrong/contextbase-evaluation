# 共通UI・入力設計

版1.4／2026-10-29。WEB/BROWSERの基本UIを再設計する。業務入力・保存・認証・帳票条件は継承し、静的モックと製品検査を分ける。

## 画面と操作

screenFamily=WEB、renderer=BROWSER。方式固有の採用環境は[プロジェクト情報](../プロジェクト情報.md)、利用者確定の寸法は[UI生成条件](../規約/UI生成条件.md)を継承する。1366×768 CSS px・100%を設計確認基準とし、狭幅・文字拡大は折返しと縦スクロールで到達させる。全項目を一画面へ押し込まず、項目や文字を削って収めない。今回の採用差分はQA-026～029。

F01だけは公開ログイン領域。認証後のF02/F03/F04/F06は、共通ヘッダー（サービス名・現在利用者/役割・ログアウト）＋左サイトメニュー＋本文を使用する。左メニューは「業務の入口」「社員検索」「汎用コードマスタ（ADMINのみ）」とし、現在の業務にaria-current相当の表示を付ける。F04は社員検索配下の現在位置を示す。F02は既存の業務入口画面として残し、利用者情報と利用方法を案内する。ダッシュボードや通知を追加しない。画面を移るたびのF02経由は要求しない。

ページ名と主操作、対象の識別、入力/条件、結果/明細、補助操作を分ける。グループ名は内容の上方の独立見出しとし、枠線へ重ねない。移動はリンク、検索/保存/出力等の実行はボタン。F03新規はページ主操作、各社員の編集は行の直接リンクとする。出力対象の選択は1人に限定し、現在の対象番号・氏名を表示する。コード保守の一覧＋編集は選択中の対象を並行して確認する用途のため維持する。

### 一覧・復帰・キーの契約

検索一覧は採用済みの最大200件を全件取得し、一覧内の縦スクロールで表示する。小規模・上限固定のためページングなし・件数切替なしをWUI-07の理由付き例外として継承し、20/50/100を追加しない。社員番号は全社員で一意のため、番号昇順を安定した順序とする。件数Nなら「検索結果N件・一覧全N件」を示し、0件・未検索・取得失敗・201件超過を区別する。出力は選択中の保存済み社員1人の全経歴で、一覧全件や表示範囲へ変更しない。

入力中のraw4条件、最後に成功した適用済み条件、未検索/取得中/検索済み/失敗、結果/選択、スクロール位置を別に保持する。条件を一字でも編集した時点で結果と選択を失効させる既存契約を維持し、「条件未適用・検索してください」を示す。新規へ進むときは未検索でもraw4条件と状態を退避する。無編集取消・破棄して戻る場合はrawをそのまま戻し、未検索を0件や初期値へ変えず自動検索しない。検索済みからの復帰だけは元の適用済み条件で再取得し、対象が含まれる場合だけ選択を復元する。保存成功で元の適用済み条件がない場合もrawを勝手に適用せず、保存済みの案内と未検索で待つ。PH-05の合格条件をBUI-05に定める。

初期フォーカスはF01ログインID、F03社員番号、F04新規社員番号/編集氏名、F06分類。Tab順は共通ナビ/ヘッダーと本文を論理的に分け、本文は表示順で操作へ進む。Enterは単一行の意図した検索/保存契機だけにし、textareaの改行を妨げない。Escは確認/補助領域の閉鎖と編集継続に使い、全体破棄へ直結させない。本物のタブは矢印キー/選択状態/パネルの関連を設計し、エラー時は対象タブ・欄へ戻す。参照値のコピーと長文へのキーボード到達を保つ。

HTMLは仕様の静的配置図で、製品実行画面ではない。各機能の概要GRID内のHTML/CSSを唯一の画面正本とし、設計注記や状態見本は業務UIと分ける。同じ断片を.tmp/へ抽出して描画し、今回のMD/断片SHA・環境・状態を記録する。CSSファイルやデモJavaScriptがあるだけで実操作・保存・認可を合格にしない。

### 項目一覧の記載

11列を維持し、各行は固有の制限・書式・初期値・候補や保存条件だけを短く記す。

| 表記 | 意味 |
| --- | --- |
| 空欄 | 初期値が空、未選択、備考なし。前行の値は引き継がない |
| - | その属性は非該当 |
| 必須欄の〇／空欄 | 必須／任意 |
| 必須欄の条件付／一部 | 備考の条件時に必須／備考で示す一部のみ必須 |
| 真偽の〇／空欄 | true／false。CheckBoxの初期値・一覧の有効欄にも適用 |
| QA-ID付き記載 | 未確定。空欄や-へ置換しない |

初期値は新規・初回の値。編集時は保存済み値を読み込む。選択前の編集欄と操作可否は各イベントに従い、ボタンの初期値欄は「-」とする。処理中の入力・二重実行は不可。これらの共通条件を各行へ繰り返さない。

空のTextBox・未選択のComboBox・CheckBoxのfalseは部品の型で区別する。表の空欄をDBのNULLへ直接対応させず、保存時のNULL・正規化は入力契約と更新仕様に従う。真偽の記号は文書・一覧の表示であり、DBへ文字列の〇を保存する指定ではない。チェックボックスは標準のチェックで操作する。

WebはTextBox（input/textarea）・Select・Table・RadioButton・Button・Label・Tab等を使う。サーバーコントロールの採用を意味しない。 帳票のExcelセルは出力先で、画面の入力部品やセル保護を追加しない。文字数の数え方と受理範囲は以下の契約を維持する。

## 入力の契約

長さはUnicodeスカラー値の個数。入力上限と保存時の条件は各項目の入力制限・フォーマット・備考へ明記し、特記がなければ同値とする。Unicode正規化で保存値が上限を超えた場合もエラーにし、切り詰めない。氏名・説明の表示文字を勝手にNFKC変換しない。通常文字列は前後の空白だけを除去し、任意欄の空白のみは未設定とする。改行はLFに統一し、タブは空白へ変換する。パスワードは空白も含め加工しない。

社員番号は6桁半角数字のみ、文字列として先頭ゼロを保持する。氏名カナは全角カタカナ・長音・中点・空白を許容し、半角カナは全角へ正規化する。検索キーだけNFKC・空白除去・英字大小無視とし、氏名またはカナに部分一致する。%・_・*・?などは検索の演算子にせず通常文字として扱う。番号は完全一致、他の条件とANDで結合する。

1000文字の上限は標準的な約800文字の説明に25%の余裕、40文字の氏名は32文字に25%、80文字のカナは64文字に25%、100文字の会社/案件名は80文字に25%、500文字の技術環境は400文字に25%を加えたDEMOの採用値である。番号6桁、コード2桁、年月等は固定形式として別扱い。技術環境は「OS: …／言語・FW: …／DB: …」を任意の自由記入1欄とし、専用マスタ・自動経験年数計算は設けない。

長文は複数行欄と欄内スクロールで全文編集できるようにする。一覧では1行要約を表示してよいが元値を短縮保存しない。資格は1資格1行の自由記入（例：資格名／取得年月）で、資格専用テーブルは作らない。任意テキストの不正な制御文字は保存前に拒否し、HTMLや数式として実行しない。

## 状態と候補

新規は自動採番IDと監査属性を入力不可、社員番号を入力可とする。編集では社員番号を変更不可。処理中は二重実行を防ぎ、失敗後は入力と選択を保持して該当欄へ戻す。保存成功後はF03へ戻す。元の状態が検索済みなら適用済み条件で再取得し、保存社員が条件に合う時だけ選択する。元が未検索/条件未適用ならraw4条件と状態を復元して待機し、自動検索しない。取消・メニュー遷移・ログアウトは未保存がある場合のみ確認し、取消なら編集を継続する。

候補は有効なコードを並び順・コードの順に表示する。停止済みコードを既存行が持つ場合は「名称（停止）」として現在値だけ表示し、変更せず再保存できる。他の停止コードへの変更と新規割当は禁止する。コードが未登録なら表示/保存をエラーにし、未知の名称で補完しない。在籍区分3値は固定で停止できない。

認証が切れた場合は自動保存しない。再認証で編集状態を復元しないことを案内する。個人情報やパスワードをURL、一般ログ、エラー詳細へ出さない。Webでは認証切れ・不正要求にもサーバー側で同じ権限検査を行う。

URLは画面/業務対象の遷移先を特定するために用い、氏名・検索raw・パスワード・未保存本文を含めない。一覧復帰の状態は所有する認証セッション/ブラウザータブに対応する一時情報で保持し、URLの不透明な状態参照が失効した場合は未検索と失効案内を示す。直接URL・別タブは現在認証/権限/対象存在を再確認し、他タブの未保存入力を流用しない。具体的route/状態識別/APIは詳細工程で既存方式と対応させる。

アプリ内のメニュー・戻る・ログアウト・対象切替では、未保存があれば既存の破棄確認を「変更を破棄して移動」「編集を続ける」と結果が分かる選択肢で表す。既存MSG-015と各手順/CHKの「はい」は表示選択肢「変更を破棄して移動」（同一画面内取消/対象切替では「変更を破棄する」）、「いいえ」および確認を閉じる操作は「編集を続ける」に対応させる。MSG-ID・承認/拒否の分岐・破棄範囲を変えず、表示は具体的な結果を示す。保存は独立した明示操作とし、遷移による暗黙保存を増やさない。ブラウザーの戻る/進む・再読込・終了ではアプリ内確認と同じ独自表示や発火を保証せず、採用ブラウザーの警告可能範囲を詳細/実装で確認する。通信断/強制終了後の復旧やlocalStorage下書きは追加しない。保存失敗時は全入力と対象を保持し、そのまま移動しない。認証失効と結果不明は既存の専用契約を優先する。
