# 日付・データアクセス仕様

版1.4／2026-10-28。論理契約。採用方式の構成は[プロファイル](../プロジェクト情報.md)を参照する。

## 日付と年月

業務日はAsia/Tokyoの暦日。入社日は1900-01-01以上、業務日以下の西暦日付で、時刻・時差を持たせない。経歴の開始/終了は1900-01以上、業務年月以下。保存上はその月の1日を表す日付とし、日を利用者へ入力させない。終了未設定だけが継続中で、開始以前の終了は禁止する。入社前の前職と同月を含む並行案件は許容する。

画面の入社日はYYYY-MM-DD、経歴年月はYYYY-MM、帳票年月はyyyy年MM月。和暦入力・年齢・実務経験年数の集計は対象外。開始/終了月を両方含めた参考月数は、終了月（継続中は出力業務年月）と開始月の月差+1として案件ごとに示してよいが、重複案件を合算して経験年数にしない。更新日時と認証制御日時はUTCの時点として保存し、表示は日本時間とする。

## 参照と保存

すべての検索・更新はパラメーター化し、文字列のSQL連結で条件を作らない。検索条件は社員番号完全一致、氏名/カナ照合用文字列の部分一致、部署・在籍区分のコード一致をANDで結合する。未設定条件は省略する。並び順は社員番号昇順で固定。201件目の存在を確認できた時点で超過として一覧表示しない。

社員保存は親1行とその経歴全行を原子的に確定/取消する。経歴の追加・更新・除去は保存前の一時状態で、DBへ即時保存しない。開始時の社員版と現在版が一致する場合だけ更新し、成功時は版を1増やす。変更がない保存は版・更新日時を変えない。新規版は1。参照先コードは分類・値の組で再確認する。社員総数200人・経歴20件の上限も確定直前の同一排他範囲で検査する。失敗時は親・子とも取消し、入力を保持する。

汎用コードは1行単位で同じ版比較を行う。キー（分類・コード）変更や物理削除は許可しない。固定在籍値は保護する。部署/役割の停止は既存参照を消さず、保存前後の値が同じ既存選択は許容する。変更時は現在有効な値だけを選択できる。コード停止と社員保存の同時実行でも無効な新規割当を通さない。


### 保存の共通手順と判定時点

| 段階 | 処理仕様 | 不成立・失敗 |
| --- | --- | --- |
| P01 事前検査 | 操作開始時に業務日を1回固定。認証、raw/正規化後の形式・長さ、必須、項目間、入力側のコード・重複・上限を確認。処理中は操作を無効化 | MSG-002/003/004/005/007/016/018/026。DB変更0件 |
| P02 排他開始 | 確定対象とコード/件数の判定を保護する短い確定単位を開始。排他待ち上限10秒。待機中に入力を破棄しない | 未確定を確認できる待ち超過はMSG-027。入力保持、再操作を有効化 |
| P03 現在認可 | セッション期限、利用者の存在/有効・現在役割を再確認。F06はADMIN必須。確認から確定まで停止/役割変更との競合も同じ保護範囲で整合させる | MSG-002/003、確定単位取消 |
| P04 存在・版 | 編集は対象1件と読込版一致を確認。0件と版競合を区別。新規は未使用キーであることを確認 | 対象なしMSG-019（社員）/016（コード）、版MSG-008。無変更判定へ進めない |
| P05 所有・参照・上限 | 経歴IDの重複/所有/読込集合と削除集合、現在の分類/コード、新規割当の有効性、一意性、社員/経歴/コード件数を再検査 | MSG-006/016/018/020/022/024/025/026。全体取消 |
| P06 差分確定 | 正規化後の入力と同じ版の保存値を比較。任意空欄はNULL、年月は月初、順序のみの違いは業務差分にしない。経歴の追加/変更/除去は親の変更に含む | 差分なしはMSG-021、変更0件・版/日時/更新者据置。差分ありの版上限はMSG-039 |
| P07 書込み | F04は親1件→既存子の除去/変更→新規子、F06はコード1件。各操作の対象キー・所有・版条件と期待件数を照合。経歴ID/社員管理IDは新規だけ採番、欠番可 | 親の条件付き更新0件は再確認して対象消失MSG-019/版不一致MSG-008、子の所有/要求矛盾は025、想定外件数は020。途中成功を取消 |
| P08 全体確定 | すべて成功した確定単位をコミット。成功を確認した後だけMSG-014、入力と一覧を保存済み状態へ同期 | 取消確認済みのDB障害MSG-017。成否が確定できない場合MSG-034、再保存禁止 |

保存と帳票の一貫読取開始の排他待ち上限10秒はPilotの設計採用値（QA-022）。物理ロック/API・タイムアウト例外の識別は詳細工程で具体化する。自動保存再試行は行わず、利用者が明示再操作する。10秒待ちの間に期限切れした認証はP03で拒否する。

### 親子差分と停止値の判定表

| 対象状態 | 判定・動作 |
| --- | --- |
| 読込済み経歴IDが保存要求にあり、編集値が同じ | 行を保持、子更新0件 |
| 読込済み経歴IDが保存要求にあり、編集値に差分 | 親IDと経歴IDで同じ社員の1件だけ更新 |
| 読込済み経歴IDが明示除去集合にある | 親IDと経歴IDで1件除去。入力の欠落だけを削除指示にしない |
| 新規一時行 | 読込IDを付与させず、新規に経歴IDを採番。同じ社員へ1件追加 |
| 読込行が保持/更新集合と除去集合の両方、または両方にない | MSG-025、全体取消。送信途中の欠落を全削除へ変換しない |
| 同じ経歴IDが複数行、別社員ID、未知ID、更新/除去の重複 | MSG-025、全体取消 |
| 部署/役割が停止、当該既存行の読込時と分類・値が同じ | 参照が現在も存在する場合のみ保持可。保存後に停止表示 |
| 停止値を別の既存経歴へコピー、新規経歴へ割当、別分類で送信 | MSG-016。新規行に社員の既存選択例外を流用しない |
| 有効コードを選択後、別操作で停止 | P05で現在の停止を検知しMSG-016。社員保存が先に確定した場合は既存参照として後の停止を許可 |

経歴の重複判定は開始/終了年月、会社名、案件名、概要、担当業務、成果、使用技術、工程、役割、人数の11値を保存用正規化後に比較する。任意NULL同士は同値とし、内部ID・監査属性・固定分類は比較から除く。氏名検索用のNFKC/空白除去を業務本文の重複判定へ転用しない。同一会社・同期間・同案件でもいずれかの編集値が違えば許可する。

## 競合と帳票

版不一致は無変更で停止し、自動リトライで相手の変更を上書きしない。再読込みは入力破棄の確認を必要とし、利用者が差分を確認して入力し直す。削除予定の経歴は社員所有を確認し、別社員の経歴IDを受け入れない。

F05は社員・経歴・コード名称を同じ読取時点から取得する。全データを短い読取単位でメモリーへ取得後、DBのロック/トランザクションを解放してExcel生成へ進む。検索一覧の古い表示値やF04の未保存バッファを帳票へ流用しない。取得前に社員の存在と利用者有効性を再確認する。取得中の整合性を確保できなければ出力せず再実行を案内する。取得後の更新はすでに取得済みの帳票を変えず、取得時点を帳票の作成日時として明記する。

Accessでは同時操作の少ないDEMOとして、すべての業務更新・認証状態更新と帳票読取を同じアプリケーション更新ゲートで直列化する。ゲートは所有プロセスの異常終了時に解除できる方式を詳細工程で定め、手作業のDB直接更新を契約対象外とする。SQL Serverでは短いスナップショット読取または同等の直列化を採用し、更新時のコード有効性・件数判定も競合のない境界で確認する。どちらもExcel生成中までDBロックを保持しない。排他方式の具体的API/SQLは詳細工程の残件であり、今回の実装済み機能ではない。


### 競合・失敗・成否不明

保存時の版検査は差分判定より先に行う。別操作が更新した後、同じ内容に見える入力をMSG-021で成功扱いしない。子だけの変更でも親版と監査を1回だけ更新する。版上限2147483647は実変更のみMSG-039、無変更は据置可能。件数の事前取得を確定時の上限判定へ代用しない。

| 終了状態 | DBと入力 | 再開 |
| --- | --- | --- |
| 入力不備/認可拒否/競合 | 変更0件。通常不備は入力保持、認証切れは破棄を案内 | 訂正または再ログイン。競合は破棄確認後再読込 |
| 途中書込み失敗、全体取消確認済み | 親子/コードをすべて取消。採番の欠番は正常。MSG-017 | 入力保持で明示再実行 |
| 排他取得前・未確定の待ち超過 | 変更0件、MSG-027 | 入力保持で明示再実行 |
| 確定通知喪失、確定/取消不明 | 成功/失敗を断定せずMSG-034。再保存を無効化 | 入力は保持表示、破棄確認後にキー検索して現在値/版を照合 |
| 全体確定後の検索/一覧再表示だけ失敗 | 保存は確定済み。『保存しました。』と再表示失敗の案内を別表示。保存の再送はしない | 明示再検索/再読込。新規として二重登録しない |

保存結果確認用の新規テーブルや自動マージは追加しない。再読込した現在値と保持入力は利用者が確認し、必要な差分を入力し直す。パスワード等の機密を復旧メモへ保存しない。

### 帳票の整合性検査

F05の業務日、取得日時、社員・全経歴・参照名称を固定する。取得途中で別トランザクションの名称だけを補い直さない。読取時点で社員1件、経歴1～20件、各参照1件、所有と必須・年月・11編集値完全重複なしを確認する。保存時に有効だったコードが現在停止でも、存在する名称を出力する。参照欠落を空欄や『不明』で補完しない。

生成後は2シート名、全経歴の連番と件数、全項目の文字列/改行・先頭ゼロ、継続行の順序、期間計算、式/マクロ/外部リンクなしを読み返して検査する設計とする。表示ラベルと分割した本文を区別し、本文の復元値が取得値と一致しなければMSG-037。生成前の保存値不整合はMSG-020、一貫読取の成立失敗はMSG-028、資源/生成障害はMSG-013とする。

生成中はDBを解放する。受渡し直前は利用者の有効性・役割・認証期限だけを再確認し、業務データを再照会しない。停止/権限変更なら完成ファイルも渡さず破棄する。先行確定済みの帳票内容を後続更新に追随させない。日付をまたいでも基準日は変更しない。画面の二重要求防止とサーバー/Access処理側の防止を両方定め、後続要求で先行処理のフラグを解除しない。

## 非機能条件

小規模DEMOの目標は、社員200人・経歴4000件・同時操作2人・通常LAN相当で検索2秒以内、社員1人のExcel生成5秒以内（Office起動時間・手動保存は除く）。試験データ量と実測方法を詳細工程で具体化し、未測定の目標を達成済みとしない。

業務データは端末/サーバーの許可領域で管理する。ダウンロードや保存後のExcelには社員経歴が含まれるため、出力画面付近に取扱注意を示す。出力ファイルをサーバーへ恒久保存せず、一時資源は成功/失敗とも解放する。バックアップ復元・実機競合・障害時の回復は次工程で検証する。
