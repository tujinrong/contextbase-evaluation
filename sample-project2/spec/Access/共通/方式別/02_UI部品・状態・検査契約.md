## 採用と構造

[共通UI](../03_共通UI・入力設計.md)1.4、[画面・状態・受入条件](../09_UIパターン・状態・受入条件.md)1.0、[UI生成条件](../../規約/UI生成条件.md)1.2を具体化する。screenFamily=WINFORMS、renderer=ACCESS。5Form/2Pageと必要Dialogを維持し、取得callback・未連結・社員/全経歴の原子保存・DEMO認証・5表48列・seed1.1を変更しない。基本と同じHTML断片は配置の正本で、ネイティブの境界/スクロール帯・セクション座標への読み替えは本書に明示する。

全FormはRecordSource=""、DefaultView=Single Form、RecordSelectors=False、NavigationButtons=False、DividingLines=False、AutoResize=False、AutoCenter=False、PopUp=False、Modal=False、ScrollBars=Both、KeyPreview=Trueを採用する。Form.Width=18900twip（1260px相当）。FormHeader/Detail/FormFooterを持つ。InsideWidth/InsideHeightをモニター解像度や1366×768に等しいと仮定せず、Open後の実値とOffice枠・DPIを測る。足りないDetailは縦横スクロールし、ヘッダーとフッターを固定する。初期は上端/左端、一覧内部の復帰位置は別状態とする。

F04のTab見出しをDetailのスクロールで失わないため、標準tabEmployeeをFormHeaderへ置く。Style=0（Tabs）、MultiRow=False、TabFixedHeight=510twip、TabFixedWidth=1800twip、Height=900twip、Page0=pgBasic「基本情報・職務」、Page1=pgCareer「経歴（件数）」の2つの空Pageを持つ。入力部品は実際にはForm.Detailに置き、Page0/1に対応する部品集合のVisibleを切り替える。Page.Controls内に入力が存在するという虚偽の親子関係を作らない。実親Sectionと論理Pageの対応を分ける。新Form/サブフォーム・独自Webタブは追加しない。DQA-UI08で標準Tabの最小Page帯を含む高さと余白を再設計した。900は現実測最小780の転記ではなく60px相当の採用余裕を含む。Header2400は下端2265から135twipの余白を持つ。基礎の画面構成・業務/字体/固定入力幅は不変で、改訂後の実Access適合はbuildで再検証する。

字体を持つアプリ管理部品は全件FontName="Yu Gothic UI"、FontSize=11pt。タイトル/領域見出し/主操作はFontBold=True、他はFalse。付属Label・一覧見出し・Tabも対象とし、存在しない字体プロパティをSectionへ設定しない。背景RGB(239,239,239)、入力RGB(255,255,255)、文字RGB(0,0,0)、SpecialEffect=Flat、単純な灰色境界。選択/フォーカス/無効は標準機能を維持する。エラー暗赤は既存の意味付き例外。標準MsgBox/Excel保存先はOS/Office管理の字体/外枠として例外を別記録し、文言・対象・分岐・操作の検査から除外しない。

## 状態とイベント順

### 初期表示・通常復帰

1. Form_Openで表示予定とsession/起動引数を固定する。Form_LoadはIsInitializing=TrueでDTO/候補/キャプションを一度設定し、F04はAcceptedPage=0、tabEmployee.Value=0、Page0群だけVisibleにする。Form_Currentは業務再取得・保存・焦点再設定を行わない。
2. 初回Activate後の一回だけ、標準GoToPageを使うDetail原点復帰（第1ページ、Right=0/Down=0）と所定SetFocusを順に行う。GoToPage後にfocusで生じる移動を測り、ヘッダー/Tabが残ることを確認する。毎Timer/Activateで再実行して利用者の一覧位置を奪わない。意図した通常再表示要求だけ原点復帰する。
3. F03呼出前に`clsSearchReturnState`へRawEmployeeNo/RawName/RawDepartment/RawStatus（表示文字列）、SearchState=Unsearched/Changed/Searched、AppliedCriteriaの有無/値、ResultRows、SelectedEmployeeId、ListTopIndex、FocusControlを別保存する。取消は検索0で原状態復元。保存成功は同じraw4条件を再検査・正規化して再検索し、保存IDが結果内なら選択。元が未検索でも同じで、古いAppliedCriteriaへ代替しない。raw不正はMSG-014＋条件エラー、再表示障害は014＋040。保存を再送しない。
4. ListTopIndexの直接設定APIを仮定しない。記録した表示先頭ID/選択IDと、ListBoxを先頭からその行へ表示するキーボード相当の移動/標準操作で復元し、実行時の先頭可視行を観測する。完全な位置再現を実機前にPASSとせず、旧結果・条件・選択の復元と別条件にする。

RawDepartment/RawStatusはComboの表示text（未採用時はPendingRaw）を表し、検索へ渡すcodeではない。AcceptedDepartmentCode/AcceptedStatusCodeのVariantを別保存し、復元はcodeで選択キーを戻した後に同じ候補の表示text、Pendingがあれば未採用textをfocus時に戻す。再検索はraw番号/氏名の検査とaccepted codeの存在/分類検査を行い、Pendingが残ればMSG-016で拒否する。名称文字列をコードとして照合しない。txtName等TextBoxの.Textはfocus中だけ読み、ClickのActiveControlがボタンなら保存済みrawを使用する。

### F04のTab/行切替と2165回避

1. `tabEmployee_Change`は新ValueをRequestedPageへ一時保存する。IsSwitchingPage中なら戻り、通常は旗を立てた上でValueをAcceptedPageへ戻し、旧Detail群をまだ隠さない。Enter前に保存したLastEditFocus/AcceptedCareerKeyとraw入力を保持する。

3. 承認後は、現在focusの入力をHidden/Disabledにする前に、常時可視・EnabledのtabEmployeeへSetFocusする。次に旧Detail群/付属LabelをVisible=False、RequestedPageの群をVisible=True、Value/AcceptedPageを更新、明細データと状態属性を設定する。空Pageにfocusを閉じ込めず、Page0は新規番号/編集氏名、Page1は一覧（0件なら追加）へ明示的にSetFocusする。旗は終了節で解除する。エラー2165をResume Nextで握りつぶさない。
4. 行選択も新List.ValueをRequestedKeyへ退避し、IsRestoringSelectionを立てて旧キーへ戻す。未反映保護が完了してから新キー/ActiveDraft/表示を同時に設定する。確認拒否は旧キーと入力を維持。ListBox.Requeryはこの選択変更の代替にしない。

`Undo`は非連結編集の全体破棄APIとして採用しない。`Dirty=False`や`DoCmd.RunCommand(acCmdSaveRecord)`でDB確定しない。`Refresh`はDAO DTOの再取得を代替しない。`Requery`は明示したメモリーcallbackの再表示だけに限定し、事前に選択を退避して再入を抑える。Form.BeforeUpdateは業務保存入口にせず、未連結の想定外連結を検出して保存を拒否する。閉じる/ログアウトの全体取消はサービス/DTO責務である。

InputMaskはtxtPasswordのPasswordだけ。番号/コード/日付/年月/人数/順序はInputMask/Formatを空にし、未完成6桁や年月でもrawのまま移動/取消できる。マスクを外しても保存長/形式/必須/範囲は変更しない。マスク未完了のネイティブfocus拒否とサービスの業務拒否を混同しない。rawは画面専用Dictionary（Control名→String/Variant）へ置き、認証秘密は認証要求終了時に消去する。

busy開始は現在.Text回収→検査用コピー固定→IsBusy=True→focusをtabEmployee（F04）又は開始CommandButtonへ退避→他の変更/遷移Controlを無効化の順。focus所有ControlだけEnabled=Trueを保ち、Tabの変更は旧Valueへ戻し、ボタンはCaption「処理中」/IsBusyガードで後続サービス0件とする。成功/通常失敗は結果確定→操作属性/元Caption復元→IsBusy=False→指定focusの順。CommitUnknownはCanSave=Falseを保持して通常失敗と分ける。後続要求は先行RequestIdのbusyや資源を解除しない。

### ComboBoxのNotInListと取消

LimitToList=True/AutoExpand=True/非表示コードBoundColumn=1を維持する。自由文字を新コードとして採用せず、候補への自動追加・acDataErrAdded・DB投入を行わない。TextBoxの中央検査とは別に、cboDepartment/cboStatus/cboRole/cboCategoryすべてのNotInListへ同じ未採用raw保護を設定する。

1. `NewData`をPendingComboRaw(Control名)へ文字列そのまま保存し、直前に承認済みのValue/ListIndex/選択候補と分ける。Response=acDataErrContinueで標準エラーを抑え、IsRestoringSelection中だけ当該Combo.Undoを呼び、ネイティブのfocus離脱拒否を解く。これはControlの未採用表示を戻すためだけのUndoで、Dictionaryのraw/親子DTO/未保存差分を消さない。Change/AfterUpdateでこの保護rawを正常値へ上書きしない。
2. lblMessageへMSG-016と対象項目/「未採用の入力があります」を表示する。Pendingがある間は検索/反映/保存とF04/F06の明細/コード対象への確定切替を中央検査で拒否し、同Comboへfocusを戻して.Text=PendingRawを再表示する。F03の新規社員起動は検索条件のPendingで妨げず、raw/accepted key/Pendingをreturn stateへ無検証捕捉して進める。取消はその原状態へ復元し、保存後の再検索はPendingがあればMSG-016で拒否する。旧有効コードへ黙って代替保存しない。候補から有効値を明示選択した場合だけPendingを解消し、分類/停止/必須を通常検査する。
3. 不正文字から取消/閉じるを押した場合、NotInListのraw捕捉とControl.Undo後に離脱確認へ進む。MSG-015/033等で「いいえ」/確認取消なら旧対象/全raw/変更状態を保持し、同ComboへSetFocus→.TextへPendingRawを再表示する。Unloadの中で即時復帰できない場合はCancel=Trueとし、1回だけのTimerで同順を実行して元のTimer間隔へ戻す。認証期限の時刻を更新/延長しない。「はい」で全体/該当明細の破棄を確定したときだけその範囲のPendingを消し、Control表示を有効旧値へ戻して安全に閉じる。
4. F03のreturn stateはComboのPendingRawと承認済みキーも別保持する。取消復元でPendingがあれば検索0のまま同Comboへfocusしrawを再表示する。NotInList中に再帰的に.Textを戻したり、黙って新規候補へ置換したりしない。Esc時にNotInList未発火なら先に現在.TextをPendingへ捕捉し、Control.Undo後にPendingを含む未保存確認へ進む。拒否はrawを復元する。

この設計のAPI根拠は[NotInList](https://learn.microsoft.com/en-us/office/vba/api/access.combobox.notinlist)と[LimitToList](https://learn.microsoft.com/en-us/office/vba/api/access.combobox.limittolist)（2026-10-29確認）。NewData捕捉/Response/Control.Undoは公式の一般契約に従い、今回の後続Click/Unload/Timer/focus順は実機未検証としてbuildで確認する。MSFormsのTakeFocusOnClickをAccessの存在確認なしに前提としない。
