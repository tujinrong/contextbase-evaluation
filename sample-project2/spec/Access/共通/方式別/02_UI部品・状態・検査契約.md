# Access UI部品・状態・検査契約

版1.2／2026-10-30。stage=detail-design、change_scope=ui_behavior、runId=sp2-ui-regenerate-20261029。DQA-UI10で未採用Combo入力の標準補助面を詳細化する。設計した期待条件であり、実部品の観測結果ではない。

## 採用と構造

[共通UI](../03_共通UI・入力設計.md)1.4、[画面・状態・受入条件](../09_UIパターン・状態・受入条件.md)1.0、[UI生成条件](../../規約/UI生成条件.md)1.2を具体化する。screenFamily=WINFORMS、renderer=ACCESS。5Form/2Pageと必要Dialogを維持し、取得callback・未連結・社員/全経歴の原子保存・DEMO認証・5表48列・seed1.1を変更しない。基本と同じHTML断片は配置の正本で、ネイティブの境界/スクロール帯・セクション座標への読み替えは本書に明示する。

全FormはRecordSource=""、DefaultView=Single Form、RecordSelectors=False、NavigationButtons=False、DividingLines=False、AutoResize=False、AutoCenter=False、PopUp=False、Modal=False、ScrollBars=Both、KeyPreview=Trueを採用する。Form.Width=18900twip（1260px相当）。FormHeader/Detail/FormFooterを持つ。InsideWidth/InsideHeightをモニター解像度や1366×768に等しいと仮定せず、Open後の実値とOffice枠・DPIを測る。足りないDetailは縦横スクロールし、ヘッダーとフッターを固定する。初期は上端/左端、一覧内部の復帰位置は別状態とする。

F04のTab見出しをDetailのスクロールで失わないため、標準tabEmployeeをFormHeaderへ置く。Style=0（Tabs）、MultiRow=False、TabFixedHeight=510twip、TabFixedWidth=1800twip、Height=900twip、Page0=pgBasic「基本情報・職務」、Page1=pgCareer「経歴（件数）」の2つの空Pageを持つ。入力部品は実際にはForm.Detailに置き、Page0/1に対応する部品集合のVisibleを切り替える。Page.Controls内に入力が存在するという虚偽の親子関係を作らない。実親Sectionと論理Pageの対応を分ける。新Form/サブフォーム・独自Webタブは追加しない。DQA-UI08で標準Tabの最小Page帯を含む高さと余白を再設計した。900は現実測最小780の転記ではなく60px相当の採用余裕を含む。Header2400は下端2265から135twipの余白を持つ。基礎の画面構成・業務/字体/固定入力幅は不変で、改訂後の実Access適合はbuildで再検証する。

字体を持つアプリ管理部品は全件FontName="Yu Gothic UI"、FontSize=11pt。タイトル/領域見出し/主操作はFontBold=True、他はFalse。付属Label・一覧見出し・Tabも対象とし、存在しない字体プロパティをSectionへ設定しない。背景RGB(239,239,239)、入力RGB(255,255,255)、文字RGB(0,0,0)、SpecialEffect=Flat、単純な灰色境界。選択/フォーカス/無効は標準機能を維持する。エラー暗赤は既存の意味付き例外。標準MsgBox/Excel保存先はOS/Office管理の字体/外枠として例外を別記録し、文言・対象・分岐・操作の検査から除外しない。

### ComboBoxのNotInListと取消

LimitToList=True/AutoExpand=True/非表示コードBoundColumn=1を維持する。自由文字を新コードとして採用せず、候補への自動追加・acDataErrAdded・DB投入を行わない。TextBoxの中央検査とは別に、cboDepartment/cboStatus/cboRole/cboCategoryすべてのNotInListへ同じ未採用raw保護を設定する。

1. `NewData`をPendingComboRaw(Control名)へ文字列そのまま保存し、直前に承認済みのValue/ListIndex/選択候補と分ける。Response=acDataErrContinueで標準エラーを抑え、IsRestoringSelection中だけ当該Combo.Undoを呼び、ネイティブのfocus離脱拒否を解く。これはControlの未採用表示を戻すためだけのUndoで、Dictionaryのraw/親子DTO/未保存差分を消さない。Change/AfterUpdateでこの保護rawを正常値へ上書きしない。
2. F03はlblSelection、F04/F06はlblMessageへMSG-016と論理項目名/「未採用の入力があります」を表示する。Pendingがある間は検索/反映/保存とF04/F06の明細/コード対象への確定切替を中央検査で拒否する。旧有効コードを代替保存しない。拒否時の表示先/焦点は上記の補助TextBoxで、Combo.Text/SelTextへの候補外文字設定を使わない。
3. `UiBindPendingEditor(f,owner,focusRequested)`はそのowner専用補助面のrawを先に捕捉し、Pending(owner)をStringのまま補助TextBox.Valueへ設定して、上表の固定矩形/付属Label/可視属性を設定する。他ownerの面へ付け替えず、他ownerのLabel/TabStop/Pending表示を変更しない。全ownerの表示同期とfocus回復を別処理にし、通常のNotInList後に先頭Pendingへfocusを強制しない。利用者が別欄へ移った場合はTimerでもfocusを奪わない。取消No・検索復帰・中央MSG016等の明示回復時だけ指定owner（中央検査では論理順の先頭Pending）をfocusRequested=Trueとする。イベント/Unload中にfocusできない場合だけ所有Timerへその回復要求を一度キューイングし、同じ要求/ownerが有効で可視/有効になった後にSetFocusする。Timerは元間隔へ戻し、認証期限を延長しない。再試行を繰り返してエラーを隠さない。失敗時はrawを保持しレイアウト不適合を記録するが、shadowだけ残った空欄を表示成功としない。
4. 補助TextBox.Changeはfocus中.Textを元Combo名のPending/Rawへ無加工で写す。末尾空白・全半角・大小を保持し、非focus時.Valueで保護rawを上書きしない。プログラム復元時はIsRestoringSelectionで利用者変更と分離する。補助面の文字が偶然正規名称と一致してもPendingを解消せず、AcceptedCodes/AcceptedCategory、Combo.Value、親DTO/ActiveDraft/編集コード/候補集合を更新しない。F03の実編集だけは既存条件変更イベント同様に結果/選択/AppliedValidを失効させ、検索は0回とする。
5. 全ownerのPending/Rawは独立して保持し、可視Pageの各Pendingをそれぞれの補助面へ同時表示する。F03部署+在籍、F04基本部署+在籍が同時にPendingとなっても一方を空欄/旧採用値へ戻さない。各補助面をTab/逆Tab・マウスで修正でき、他ownerへの流用/破棄/同時採用をしない。MSG-016案内には未採用の論理項目名を列挙する。F04経歴の役割Pendingも独立保持し、既存のTab/明細切替ガードを通った論理Pageで同補助面を表示する。親/他Pageの未保存入力を再ロードしない。
6. 補助面でAlt+↓/F4、又は残した矢印を使うと、rawを捕捉してから元Comboへfocusし標準Dropdownで正常候補へ到達する。候補操作中は元Comboの入力面/元Labelを示してよいがPendingを消さず、閉じる/Esc/選択しないfocus移動は補助面を戻す。正常候補の実行為（クリック又はキーボードによる候補確定）とListIndex/実候補キーを確認した場合だけ通常の受入経路へ渡す。元の有効値を明示的に選び直した場合も受理できる一方、単に一覧を開閉しただけではPendingを消さない。プログラムValue設定/Undo/補助Changeは明示選択の根拠にしない。同値選択でAfterUpdateが発火しない場合もネイティブ候補操作の確定を扱う必要があり、イベント名の存在だけで実証済みにしない。
   候補操作中のGotFocusで直ちに補助面へfocusを奪い返してdropdownを閉じない。利用者が元Comboへ戻って文字編集した場合は、その実.TextをRaw/Pendingへ捕捉し、当該補助面だけを畳んで元入力を見せる。候補外確定は次のNotInListで新原文を捕捉して専用補助面へ戻す。元Combo自身が実入力を表示している一時状態を除き、可視PageのPendingを空欄や旧採用値で代用しない。
7. F03/F04の採用キーはAcceptedCodesとCombo.Value、F06分類はAcceptedCategoryとcboCategory.Valueを保つ。F06の別分類を要求した場合は旧分類/編集コード/原文を保持して既存の未保存確認を行い、「いいえ」なら旧Pending表示/焦点へ戻す。「はい」で承認された旧コードの破棄と分類切替が成立した後だけ要求分類を採用する。正常候補という理由だけで他の未保存rawを消さない。受入成立後に元Comboへfocusを退避し、対象ownerのPendingを除去して補助面/付属Labelを畳む。他ownerにPendingが残ればその補助面/案内へ移る。
8. 不正文字から取消/閉じるを押した場合、NotInListのNewData捕捉とControl.Undo後に離脱確認へ進む。MSG-015/033等で「いいえ」/確認取消なら旧対象/全raw/変更状態を保持して補助TextBoxを可視にし、原文を選択・修正できる状態と焦点を復元する。「はい」で全体/該当明細の破棄を確定したときだけその範囲のPendingを消す。経歴だけの破棄で親部署/在籍Pendingを消さず、F06は編集コード1件の範囲を守る。失効MSG-002は既存どおり優先し、期限切れの編集を自動復旧しない。
9. F03の新規社員起動は検索条件のPendingで妨げず、raw/accepted key/Pending/補助ownerに対応する論理focusをreturn stateへ無検証捕捉する。通常NotInListのcapture/Undo/表示同期はSetFocus/Dropdownを呼ばず、新規Clickを奪わない。cmdNew.Click先頭でもActive Combo/補助面のrawを無検証捕捉し、その1回のClickで新規を起動する。Clickの自動再送/入力注入で補わない。取消は検索0で原状態を復元し、Pendingがあれば補助面を表示・編集可能にする。保存後は既存Access契約のraw再検査を行い、Pendingなら014＋016で検索0、保存成功は維持する。Esc時にNotInList未発火なら現在Combo.TextをPendingへ捕捉してからControl.Undoし、Pendingを含む未保存確認へ進む。補助面のEscは最終.Text捕捉後に同じ確認へ渡し、標準欄Undoによる無警告消去を防ぐ。

API根拠は[NotInList](https://learn.microsoft.com/en-us/office/vba/api/access.combobox.notinlist)、[LimitToList](https://learn.microsoft.com/en-us/office/vba/api/access.combobox.limittolist)、[TextBox.Value](https://learn.microsoft.com/en-us/office/vba/api/access.textbox.value)、[SetFocus](https://learn.microsoft.com/en-us/office/vba/api/access.combobox.setfocus)（2026-10-30確認）。標準propertyによる表示復元を採用し、SendKeys/SendInput/clipboard貼付/未確認LB_*メッセージを製品の復元処理に使わない。ShowOnlyRowSourceValuesやLimitToList/BoundColumnの変更、rawを正規候補へ追加する方式にも依存しない。DQA-UI10はCombo.Text2101という候補限定の観測を改訂契機にするが、新TextBoxの実表示・操作・Tab/採用境界は未検証として下流へ渡す。MSFormsのTakeFocusOnClickをAccessの存在確認なしに前提としない。

複数行TextBoxのEnterは改行で、F04/F06保存を既定Enterにしない（cmdSave.Default=False）。cmdCancel.Cancel=Falseとし、EscはKeyPreview側でMSG-015/継続へ渡す。標準入力のEscによる欄Undoを全体取消として扱わず、意図しない原入力消去を避ける。Form_KeyDownでF04/F06のEscを処理した場合はKeyCode=0で消費する。F05 Export中Escは既存CancelRequestedのみを立て、ファイル確定途中へ割り込まない。

確認前にScreen.ActiveControl.Nameを保存し、所有者が可視/有効なら戻す。非表示になった場合は当該論理Pageの先頭可視入力へ移す。エラーは対象Pageを前記安全順で開き、先頭誤りのControlへSetFocus。Ctrl+Home/End・範囲選択・コピーをreadonlyでも禁止しない。OS Dialogのキー/既定/取消はその標準操作を実機確認する。

DQA-UI10の補助面は上表の元Comboと同じ論理位置へ代入し、独立の末尾項目として足さない。`UiLogicalOwner(f,physicalName)`は上表の固定対応で補助名を元Combo名へ正規化し、`UiEffectiveFocus(f,logicalName)`は当該Pending/可視Pageに対応する補助面を返す。既存Controlのnative TabIndexは維持し、追加TextBoxだけ各実Sectionの既存最大TabIndex+1から、F03=部署→在籍、F04=部署→在籍→役割、F06=分類の順に連番を採用する。これは新Controlの保存値の算式であり実測から採る値ではない。同一TabIndexを代入して既存順をずらさない。Form.KeyDownはTab/Shift+TabをKeyCode=0として上表の論理前後へ移し、必要なとき標準Page.SetFocusを経由する。物理的に後置された補助面も当該Comboの位置で一度だけ通る。初期hidden/TabStop=Falseの補助面は順路に入れず、Pending表示中は補助面TabStop=True/元Combo=Falseとする。F03の部署/在籍が同時Pendingなら両補助面を順方向/逆方向ともに通る。LabelはTab非対象である。

F03条件内Enterは元Comboへ正規化して検索ガードへ渡し、Pending中はMSG-016・検索0。F04/F06の補助面Enterは改行/自動保存にせず、既存の確定しない入力操作とする。Alt+↓/F4は該当正常候補を開き、Escで選ばず閉じた場合は同じPending原文と補助面focusへ戻す。F04/F06で候補操作外のEscは最終.Textを捕捉→KeyCode=0→既存の取消確認で、Noは全raw/各面/対象/焦点を保持する。F03 Escで補助面の保護rawを無警告にUndoしない。

UiCaptureText/UiChanged/確認前capture/return state/busy開始と終了/エラーfocusは同じ正規化を使う。補助TextBoxを新しい業務項目名でRawへ二重登録したり、補助.Valueの非focus読取りで末尾空白を失わせたりしない。保存等の先頭Pendingは元の論理Tab順で決定し、必要な論理Pageへの表示だけを安全順で開いて専用面へfocusする。このエラー表示のために親/他Pageを再ロード・反映・破棄しない。
