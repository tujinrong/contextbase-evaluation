## 採用と範囲

screenFamily=WINFORMS、renderer=ACCESS。今回の利用者指示とQA-026により、基本設計Agent1.11、専用規則1.2/工程1.3、[UIパターン規約](../../../../docs/UIパターン規約.md)1.0、[WinForms画面品質規約](../../../../docs/WinForms画面品質規約.md)1.0、[Access画面品質規約](../../../../docs/Access画面品質規約.md)1.0を採用する。入力文書ID・版・SHA-256は今回の固定inputs/manifestに記録する。方式内の具体値は[UI生成条件](../規約/UI生成条件.md)、[共通UI](03_共通UI・入力設計.md)、各基本設計を正本とする。

DEMO認証admin/ADMIN・staff/STAFF・共通123、パスワード3～128スカラー、単体ACCDB、社員200人/経歴20件/コード99件、5画面・6機能・5表48列、未連結の明示保存、社員削除なし、保存済み1人のExcel2シート出力を継承する。認証/業務上限・帳票の元データ・保存単位をUI変更で変えない。新表示項目は画面名・対象・モードのLabelだけで、DB列や入力業務項目ではない。

本文・見出しを含むアプリ管理文字はYu Gothic UI 11ptを維持する。タイトル16ptの新規設計向け提案は不採用とし、独立した画面ヘッダー・太字・余白で階層化する（QA-027）。R01の帳票字体は別契約で、画面の11ptを帳票へ移植しない。モック1366×768 CSS px/100%は配置検査条件で、Office枠を除いた実client領域やDPIの対応保証ではない。

ヘッダー/Tab見出しがスクロールで消えたまま通常表示へ戻らない構成を避ける。画面を開く操作そのもので再現し、撮影直前の手動補正を合格根拠にしない。標準フォームの表示方式/各セクション高/スクロール・フォーカスの具体的プロパティとイベント順は詳細工程で確定する。

F03のrawは空白・大小・全半角を含む表示文字列そのままで、最後に適用した検索条件の正規化済みセットと分ける。取消は原状態の復元、保存成功は既存の同条件再検索という別契約である。保存後のraw条件が不正なら条件エラー/結果なしを表示するが、社員保存の成功を取り消さず、保存を再実行しない。全体ヘッダーの可視性とListBox内部の保持位置を別々に検証する。
