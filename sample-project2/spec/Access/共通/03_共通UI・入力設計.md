# 共通UI・入力設計

版1.4／2026-10-29。今回の基本設計で配置・対象識別・表示トークンを再採用する。入力・保存・認証の業務条件は継承する。

## 画面と操作

screenFamily=WINFORMS、renderer=ACCESS。[採用プロファイル](../プロジェクト情報.md)のWindows 11・64bit Access/Excel・単体ACCDB・標準未連結単票フォームを継承する。メニューはF02、社員検索はF03の独立画面とし、Webのサイトバー・行内編集・ページングを追加しない。5画面・6機能・5表を維持する。今回の用途/状態/受入条件の正本は[UIパターン・状態・受入条件](09_UIパターン・状態・受入条件.md)とする。

HTMLは仕様の配置図で、製品の実行画面ではない。各機能の概要GRID内の静的HTML/CSSを唯一の画面正本とし、同じ断片だけをsourceRoot/.tmp/basic-design/へ抽出する。単独HTMLやPNGを仕様へ併置しない。標準部品で表現できる配置にし、HTMLのtableはListBoxの列と見出しの位置を示す。実部品のTab順・IME・スクロール・DB確定をモックから合格にしない。

### 対象と操作の配置

F03は「検索条件」「検索結果」「選択中：番号 氏名」「選択社員への操作」を区別する。新規登録は未選択でも使え、編集/経歴書Excelは現結果の1人選択時だけ有効。F04は共通ヘッダーに親社員を表示し、基本情報/経歴の両Tabとスクロールの途中でも維持する。経歴Tabは「経歴一覧」と「選択中の経歴」の見出しを持ち、一覧と詳細の対象を一致させる。案件名100字は一覧で短縮表示しても、選択詳細の案件名欄からキーボードで全文を確認・コピーできる。

F04-I26の表示は「経歴一覧へ反映」、補足は「未保存」。F04-I28は「社員・経歴を保存」とし、親1人と全経歴のDB確定を表す。反映・追加・除去はDBを変更しない。反映せず保存しても現在入力中の経歴を同じ検査で反映してから保存し、押し忘れを黙って捨てない。タブ/行/追加の切替は既存MSG-032→033の確認・取消を維持する。F04-I29は「取消・検索へ戻る」で全体破棄範囲を補足する。ラベル変更はID・保存単位・確認分岐を変更しない。

検索一覧は上限200件を全件取得して内部スクロールする。ページング・件数切替・高度検索は設けない。コード候補は名称表示、コード値を保持する。短い番号・コード・日付の幅は長文欄と区別する。Tab順は画面の左上から右下、初期フォーカスはログインID、検索の社員番号、登録の新規時社員番号/編集時氏名、コード画面の分類とする。

2026-10-29の確定UI条件と今回採用差分は[UI生成条件](../規約/UI生成条件.md)、QA-026/027、[共通09](09_UIパターン・状態・受入条件.md)へ記録する。各詳細の業務値・項目別寸法は次工程で本基本版に照合し、同じ属性の矛盾を残さない。旧版の仕様モック確認と今回の最終成果物の適合検査を分ける。

### 項目一覧の記載

11列を維持し、各行は固有の制限・書式・初期値・候補や保存条件だけを短く記す。

| 表記 | 意味 |
| --- | --- |
| 空欄 | 初期値が空、未選択、備考なし。前行の値は引き継がない |
| - | その属性は非該当 |
| 必須欄の〇／空欄 | 必須／任意 |
| 必須欄の条件付／一部 | 備考の条件時に必須／備考で示す一部のみ必須 |
| 真偽の〇／空欄 | true／false。CheckBoxの初期値・一覧の有効欄にも適用 |
| QA-ID付き記載 | 未確定。空欄や-へ置換しない |

初期値は新規・初回の値。編集時は保存済み値を読み込む。選択前の編集欄と操作可否は各イベントに従い、ボタンの初期値欄は「-」とする。処理中の入力・二重実行は不可。これらの共通条件を各行へ繰り返さない。

空のTextBox・未選択のComboBox・CheckBoxのfalseは部品の型で区別する。表の空欄をDBのNULLへ直接対応させず、保存時のNULL・正規化は入力契約と更新仕様に従う。真偽の記号は文書・一覧の表示であり、DBへ文字列の〇を保存する指定ではない。チェックボックスは標準のチェックで操作する。

AccessはTextBox・ComboBox・ListBox・CommandButton・Label・TabControl・CheckBoxを使う。 帳票のExcelセルは出力先で、画面の入力部品やセル保護を追加しない。文字数の数え方と受理範囲は以下の契約を維持する。

## 入力の契約

長さはUnicodeスカラー値の個数。入力上限と保存時の条件は各項目の入力制限・フォーマット・備考へ明記し、特記がなければ同値とする。Unicode正規化で保存値が上限を超えた場合もエラーにし、切り詰めない。氏名・説明の表示文字を勝手にNFKC変換しない。通常文字列は前後の空白だけを除去し、任意欄の空白のみは未設定とする。改行はLFに統一し、タブは空白へ変換する。パスワードは空白も含め加工しない。

社員番号は6桁半角数字のみ、文字列として先頭ゼロを保持する。氏名カナは全角カタカナ・長音・中点・空白を許容し、半角カナは全角へ正規化する。検索キーだけNFKC・空白除去・英字大小無視とし、氏名またはカナに部分一致する。%・_・*・?などは検索の演算子にせず通常文字として扱う。番号は完全一致、他の条件とANDで結合する。

1000文字の上限は標準的な約800文字の説明に25%の余裕、40文字の氏名は32文字に25%、80文字のカナは64文字に25%、100文字の会社/案件名は80文字に25%、500文字の技術環境は400文字に25%を加えたDEMOの採用値である。番号6桁、コード2桁、年月等は固定形式として別扱い。技術環境は「OS: …／言語・FW: …／DB: …」を任意の自由記入1欄とし、専用マスタ・自動経験年数計算は設けない。

長文は複数行欄と欄内スクロールで全文編集できるようにする。一覧では1行要約を表示してよいが元値を短縮保存しない。資格は1資格1行の自由記入（例：資格名／取得年月）で、資格専用テーブルは作らない。任意テキストの不正な制御文字は保存前に拒否し、HTMLや数式として実行しない。

## 状態と候補

新規は自動採番IDと監査属性を入力不可、社員番号を入力可とする。編集では社員番号を変更不可。処理中は二重実行を防ぎ、失敗後は入力と選択を保持して該当欄へ戻す。保存成功後は検索に戻って保存済み社員を再検索する。取消・メニュー遷移・ログアウトは未保存がある場合のみ確認し、取消なら編集を継続する。

候補は有効なコードを並び順・コードの順に表示する。停止済みコードを既存行が持つ場合は「名称（停止）」として現在値だけ表示し、変更せず再保存できる。他の停止コードへの変更と新規割当は禁止する。コードが未登録なら表示/保存をエラーにし、未知の名称で補完しない。在籍区分3値は固定で停止できない。

認証が切れた場合は自動保存しない。再認証で編集状態を復元しないことを案内する。個人情報やパスワードを一般ログ、エラー詳細へ出さない。Accessの検索・保存・出力側でも現在認可を検査し、ボタン表示だけで保証しない。
