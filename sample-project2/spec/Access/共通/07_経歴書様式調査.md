## 調査条件

利用者から「WEBを参照して、日本で使用できる立派な経歴書」「経歴書はExcel」と指定された。一般職務にも使える職務経歴書を設計対象とし、調査はIT分野の公開事例を中心に行う。技術環境と担当工程は任意とし、技術職に対象を限定しない。転職支援事業者と厚生労働省の公開一次資料を参照し、必要な情報の種類と読みやすい構成を確認した。原本テンプレートのレイアウト・文章・画像は複製せず、DEMOに必要な最小データで独自のExcel様式を定義する。

検索結果の抜粋だけで採用を決めず、下表のHTML本文を閲覧した。ハローワークのパンフレットには転載を禁止する案内があるため、当該資料や記載例を成果物へ取り込まない。公的な履歴書の様式例と、本システムの職務経歴書は別の文書である。

## 採用様式

### 情報構成

帳票の正本は[経歴書出力 基本設計書](../基本設計書/05_経歴書出力.md)とする。本記録は採用理由を示し、別レイアウトを定義しない。

| 区分 | 採用内容 | 根拠の位置付け |
| --- | --- | --- |
| タイトル・基準日・氏名 | 職務経歴書の表題、日本の業務日、氏名とカナを表示する | 公開事例の基本的な識別情報を参考にした |
| 取得日時 | データの一貫読取時点を「作成日時（JST）」としてyyyy年MM月dd日 HH:mmで2シート上部と印刷フッターへ表示し、出力基準日と区別する | 共通の日付・データアクセス契約を具体化した独自項目。公開元が規定した項目ではない |
| 社員の要約 | 職務要約、活かせる経験・知識・技術、資格、自己PR | WEB-R01・WEB-R02の記載観点を参考にした |
| 案件ごとの情報 | 期間、所属会社、案件名、概要、担当業務、工程、実績・工夫、技術、役割・人数 | WEB-R01・WEB-R02の案件説明の観点を参考にした |
| 2シート | 「職務経歴書」で全体を把握し、「案件経歴」で案件内容を確認する | 本DEMOの独自設計。公開元がExcel2シート構成を規定したものではない |
| 紙面 | A4縦、白地、濃紺の見出し線、本文10.5pt、横1ページ・縦増頁 | 日本語文書として読みやすい簡潔な独自配置。実Excel印刷は未確認 |
| 案件順序 | 開始年月降順、同年月は内部経歴ID降順。経歴を全件掲載する | 直近の経験を先に確認できる本DEMOの選択。すべての応募先の指定を意味しない |
| 社内識別 | 社員番号と部署を表示する | 社員経歴管理のDEMO向け独自項目。外部提出時の項目変更は別の要件とする |
| 自由記入 | 技術・資格は保存済みの文章と改行をそのまま表示する | 専用の資格・スキル明細機能を増やさない最小構成の選択 |
| 個人属性 | 住所、生年月日、性別、写真を収集・出力対象に含めない | 経験・能力説明に必要な範囲へ絞る本DEMOの選択。法的な必須・禁止の主張ではない |
| 出力対象 | 1名、保存済み経歴1～20件、Excel1ファイル | 利用者の最小機能要求を具体化した独自制限 |
| 長文保持 | 行を増やして全文を表示し、多数ページを許容する | Excelの表示制限に対応する本システムの設計。文字を縮小・切捨てて成功にしない |

### 今回採用しない機能

応募先別のテンプレート切替、会社資本金・売上・従業員数の管理、顔写真、住所、希望条件、志望動機、資格マスタ・技術スキル明細、経験年数の自動集計、AIによるPR作文、英語版、PDF、電子署名・承認・配信を対象外とする。公開事例に含まれる項目をすべて管理機能へ追加しない。

### 独自設計と出典の境界

公開資料は記載観点の確認に用いた。セル範囲、シート名、色、書体、項目長、最大20件、並び順、保存ファイル名、全量保持、停止コード・排他・失敗時の動作は本プロジェクトが定義した仕様である。公開元の推奨完成構成や検証済み製品として紹介しない。企業の募集要項や提出形式に特別な指定がある場合は、当該指定を別途確認する。

## 後工程の確認

基本設計として、管理する社員・経歴項目から帳票へ移せることと、出典の観点を最小機能へ反映したことを確認する。後工程では先頭ゼロ、日本語、長文、改行、最大20件、参照コード名称、継続期間、取得日時と基準日の区別、数式に見える入力、2シート、改ページ、10.5ptの可読性を実ファイルで確認する。

本記録の資料閲覧完了は、実Excel生成、ダウンロード・保存、印刷、採用先の受入れ、正式採点の合格を意味しない。実装・実機試験は未実施、正式率はnullとする。
