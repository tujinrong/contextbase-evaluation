## 概要

業務5表の全89列を省略せず1行1列で示す。業務的な長さ・必須は[論理テーブル仕様](../../基本設計書/03_テーブル仕様書.md)と一致させる。実装の直接入力は本書。生年月日は内部日付、画面は和暦。その他は西暦。日付下限・元号・動的範囲は[共通日付](../../共通/07_日付・和暦仕様.md)。

DB既定値が「指定なし」の列は保存入口で値を明示する。画面初期値とDB DEFAULTは別物。NOT NULLと空白禁止、NULL可と条件付き必須を分ける。業務5表と認証・競合・確認の技術補助表を区別する。サーバー業務日による検査は変動するため固定CHECKへ埋めない。

Unicode文字列はvarcharの文字数。UTF-8バイト数と別。PostgreSQL18を採用案として維持する。技術根拠：PostgreSQL18 Character Types https://www.postgresql.org/docs/18/datatype-character.html （2026-10-11参照）。

PostgreSQL 18、UTF-8。ID=bigint identity、L=bigint、I=integer、B=boolean、D=date、T=timestamptz、Vn=varchar(n)。?はNULL可。他はNOT NULL。Aはcreated_at T、created_by V64、updated_at T、updated_by V64、row_version L DEFAULT 1。Entity名はPascalCaseへ対応、API出力はcamelCase。DBのLはJSONで文字列。

PK＝student_id/class_id/category_id/(category_id,code_value)/log_id。UQ＝student_no全件と(school_year,class_code)。FK＝学生クラス、学生4分類組→m_code、クラス学年組→m_code、m_code分類→m_code_category。RESTRICTで参照先実体を残す。固定分類をCHECK、必須空白・版>0・在籍日付と所属・生年月日≦入学日・連絡手段・緊急一式・削除属性一式・クラス年度内期間と定員・コード期間を行内制約と保存検証で保護する。現在日、有効性、分類桁、定員集計はAPI側の保存時確認。

索引＝非削除birth_date、(class_id,enrollment_status_code)、admission_date、updated_at、本人・緊急電話。履歴は(target_table,target_key,executed_at)。name_key2000は無条件B-treeに入れず、重複候補は生年月日で絞る。CodeEntryのコード値は数値化せず、01を保持する。

### COBOL：PostgreSQL物理全89列

ID=bigint identity、L=bigint、I=integer、B=boolean、D=date、T=timestamptz、Vn=varchar(n)。?だけNULL可。A＝created_at T、created_by V64、updated_at T、updated_by V64、row_version L DEFAULT 1。COBOL確定データ項目は列名を大文字・ハイフンへ変換し`ST-`を付ける（student_name→ST-STUDENT-NAME）。画面rawのE-名とはSTNORMで対応する。

Aを4表に展開。PKは各ID・分類・分類値複合、UQは全学生student_noとクラス(school_year,class_code)。FKは学生クラス、4分類コード組、クラス学年コード組、コード種別。RESTRICT、NULL続柄可。固定分類CHECK、正の版、在籍状態と終了日／所属、連絡手段と緊急一式、日付順、削除属性整合、クラス年度内期間・定員1～9999またはNULL・表示順、コード期間を検査。現在日・分類桁・有効性・集計はSTRULESで保存時に再確認。

索引は非削除birth_date、(class_id,enrollment_status_code)、admission_date、updated_at、本人／緊急電話、履歴(target_table,target_key,executed_at)。巨大なname_keyの通常B-treeを仮定しない。
