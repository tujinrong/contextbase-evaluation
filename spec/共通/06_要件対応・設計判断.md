## 原資料と本版の差分

| 事項 | 1.0版からの扱い | 理由・影響 |
| --- | --- | --- |
| 書式 | 表紙・概要・項目一覧・イベント仕様・補足説明を継承 | 元資料は別業務の書式。年金業務やソースを流用しない |
| 画面数・5表・5分類70値 | 維持 | 新しい業務画面や成績管理は増やさない |
| 31チェック・55メッセージ | 維持し共通へ集約 | 重複定義の不一致を防ぐ |
| テーブルの物理名 | 元版の大文字論理表記から小文字へ統一 | PostgreSQLの引用なし識別子に合わせる。全89カラムの意味・長さを維持 |
| 郵便番号・追跡番号・変更列 | 論理長は維持、物理型を具体化 | 郵便番号はvarchar(7)、追跡番号はuuid、変更列はjsonb配列 |
| 技術構成 | 今回の追加設計案 | 空リポジトリのため既存実装に由来しない。.NET 10 MVC/Razor、PostgreSQL 18、Npgsql |
| 画面モック | 文字図から埋込みHTMLへ変更 | 基本・詳細の両方に画面を収録。動作アプリではない |
| 同一人物候補の同時保存 | 同生日の保存を直列化する保護を追加 | 元版では同一人物候補の警告漏れに対する具体的なDB保護が未確定。別クラスへの同時登録も再確認できるようにする |
| ロック順 | 同生日保護→コード分類→コード値→クラス→学生 | 既存順序の先頭へ保護を追加。詳細05で全経路を統一 |
| HTTP・画面状態・戻り値 | 今回具体化 | 変数名、長整数の扱い、警告トークン、保存不明時の手順を定義 |
| コード保守の参照影響 | 設計変更時の影響調査と通常保存を区別 | 意味変更・キー変更・物理削除を通常処理で一律禁止し、学生の連鎖更新をしない |
| 自動再送 | 正確に一度だけの処理は新設しない | 元版の一意制約・版制御・結果不明時の検索確認を維持。障害時の盲目的再送は禁止 |

## 変更時の連動確認

項目追加は基本画面・論理テーブル、詳細モデル・物理テーブル・SQL・画面、共通チェック・テストを同時変更する。状態コード変更は必須日付・クラス要否・定員・権限・保護対象を同時に見直す。画面モックと入力一覧で必須・桁・表示順を一致させる。クラス所属履歴を追加する場合は既存の現在値置換モデルをそのまま流用せず、移行・期間重複・検索対象年度を再設計する。

## 検証の位置付け

今回の納品物は仕様書であり、単体・結合テスト文書は実装後に実行する試験設計である。試験ケースを記載しただけで合格とはしない。文書確認ではファイル配置、相互参照、分類・項目の件数、画面と項目表の対応、SQLと物理列の一致、排他・失敗分岐を確認する。実行環境での性能・DB・ブラウザーの確認は別の実装工程として記録する。
