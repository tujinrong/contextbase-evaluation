## 画面共通設計

タイトル、パンくず、利用者、メッセージ、業務入力領域、主要操作の順とする。入力はPCで2列、長い氏名・住所・備考は全幅。幅1280px以上を標準とし、900px未満は1列。入力領域は最大1200px、余白24px、項目間16px、本文16px、ラベルとエラーは14pxを基準とする。入力高40px以上、操作領域の高さ40px以上。広い一覧は領域内の横スクロールを認め、ページ全体の横スクロールは避ける。

静的HTMLモックはMarkdown内に直接埋め込む。GitHub表示ではスクリプト、インラインスタイル、class/id等が除去されるため、モックの見た目だけにサイズや挙動の仕様を依存させない。以下の部品仕様と詳細画面の要素IDを実装の正本とする。根拠は[設計書一覧](00_設計書一覧.md)のGitHub公式資料。

## 入力部品の実装契約

画面要素IDは英小文字ハイフン、外部JSONはcamelCase、C#プロパティはPascalCaseとする。例：`student-name` → `studentName` → `StudentName`。属性値と入力値はRazorでエスケープする。JavaScriptは`textContent`、`value`、DOM APIで描画する。`innerHTML`や`Html.Raw`へ学生情報・エラーパラメーターを渡さない。

```html
<label for="student-name">氏名 <span>※必須</span></label>
<input id="student-name" name="studentName" type="text"
       aria-required="true" aria-describedby="student-name-help student-name-error">
<small id="student-name-help">100文字以内</small>
<p id="student-name-error"></p>
```

コード例は実装構造の例であり、上部の静的モックとは分ける。エラー時は`aria-invalid="true"`を付与する。エラー解除で削除し、対応する文言も更新する。Unicodeコードポイント数で長さを判定し、UTF-16コード単位の`maxlength=n`だけに依存しない。IME入力中は確定前の文字を勝手に削除・変換しない。サーバー再表示で変換後の値を見せるが、拒否された入力は切り捨てず保持する。

必須項目は記号と説明を併記。読取専用は値を表示し、不正な編集をサーバーでも拒否する。画面上で編集不可の値を送信しなくても必要な既存情報はサーバーが読込む。セレクトの`disabled`だけをデータ保護とみなさない。

## 選択部品・候補連動

| 操作 | UIの処理 | サーバー側との境界 |
| --- | --- | --- |
| 年度・学年を変更 | 候補取得中と表示しクラス選択を一時不可 | 最新要求番号と一致した応答だけ採用 |
| クラスが新条件に不適合 | 選択を解除しW-STU-107 | 保存時にもクラス実値との一致検査 |
| 未所属のみをON | 年度・学年・クラスを解除・無効化 | 不正な同時指定はE-SRC-001 |
| 在学・休学→卒業・退学 | 終了日を入力可能・必須、クラスを任意 | 最終所属期間の重なり検査 |
| 卒業・退学→在学・休学 | 終了日を空にし無効化、クラス必須 | 管理者・理由・新規所属可否を検査 |
| 候補取得失敗 | 古い候補を新条件で有効とみなさず操作不可 | 入力と元選択の表示情報は保持。E-COM-004 |

既存の停止値を表示するoptionを単純にdisabledにして送信不能にしない。値を変更しないことを許すかはサーバーが旧値と比較する。検索では停止・期間外の候補も選べる。空選択の表示は検索＝すべて、登録必須＝選択してください、任意＝未選択で統一する。

## 一覧・ページ部品

ソート可能列は見出し内の操作ボタンとし、`aria-sort`で方向を示す。ソートキーにSQL列名を使わず、`studentNo/name/admissionDate/updatedAt`を送る。学籍番号・氏名の長文は折返し、内容を省略する場合も全文確認手段を用意する。行操作は氏名を含む読み上げラベルを付け、位置番号で学生を指定しない。

検索中は新たな検索・ページ・ソートを無効化する。現在の入力と実行済み条件を別管理し、入力変更後にページ操作をしても現在の入力値を検索条件へ混入させない。エラー・上限超過時は古い一覧を消す。0件なら表示範囲0～0、ページ1／1、全ページ操作不可。20・50・100以外の値はサーバーが拒否する。

## ダイアログ・フォーカス

ダイアログには`role="dialog"`、`aria-modal="true"`、見出し参照を付ける。初期フォーカスは取消ボタン、Tab移動は内部に閉じ込める。Escは取消と同じ。閉じた後は呼出ボタンへ戻す。理由必須時に空の確認ボタンを押すとダイアログ内エラーを表示し、最初のエラーへフォーカスする。削除・重複続行の確定はEnterによるフォーム暗黙送信で実行しない。

入力エラーは画面上部のエラー一覧へフォーカスを移し、各項目へのリンクを提供する。情報通知は`role="status"`、緊急エラーは`role="alert"`を使用する。色だけでエラーを識別させない。キーボードだけで検索・編集・保存・取消できるようにする。

## 通信・未保存状態

全POSTはCSRFヘッダーと同一オリジンCookieを付ける。保存成功の応答を受けてからDirtyGuardを解除し、サーバーが返した相対復帰先へ遷移する。任意の外部URLへ遷移しない。401は共通ログインへ誘導し、入力値をURLや永続ストレージに退避しない。

通信断・タイムアウトで保存結果が不明の場合は、成功にも失敗にも決めつけない。Busy状態を解除し「検索で登録状況を確認」を表示する。自動リトライしない。保存成功を確認できなかった場合もDirtyGuardを勝手に解除しない。二重クリック防止は一意制約・版制御の代替ではない。

## 評価観点

入力200文字のカナ変換後100文字、サロゲートペア、IME、長いエラー、狭い画面、停止値、候補応答の逆転、キーボード操作、スクリーンリーダーの項目名、通信断、戻る際の変更破棄、複数タブを試験する。静的HTMLを見ただけでこれらの試験合格とは扱わない。
