任意のraw入力はstring?で受け、厳密検査後に型付けする。Checkboxが全OFFで省略される場合はStatusCodes=空配列とする。未所属trueで所属条件が残った不正要求は拒否。

### ルートと検索イベント

| メソッド・パス | 処理・応答 |
| --- | --- |
| GET /students | Read権限。候補と初期01・02・20件、未検索HTMLを表示 |
| POST /students/search | CSRF、入力、マスタ存在、条件整合→同一読取Txで件数・一覧→HTML200。入力不備422 |
| POST /students/page | ContextId・Revision・ページ指定だけ。サーバーの実行済条件で再取得 |
| POST /students/clear | Contextを初期化、未検索画面 |
| POST /students/options | 候補連動用の許可された条件だけ。HTML部分画面または候補JSON |
| GET /students/new | Create権限、新規画面 |
| GET /students/{id} | Read権限、最新の非削除対象、Update権限に応じ編集／参照 |

初回GETは学生検索なし。検索条件はSearchContextに保存し、pageとsortは最後に成功した条件だけで実行。ソート・件数変更はpage=1。0件はページ1/1、移動不可。上限超過は200で警告と一覧空、古い結果を残さない。検索失敗・不正入力は条件を保持し一覧消去。

年度・学年変更は候補を取得し、不適合クラス解除を通知。JavaScript補助がない場合でもPOSTによる再描画で操作可能にする。検索条件フォームとページ操作フォームを分け、未実行の入力をページ操作に混入させない。

### 全入力から物理列への対応

`StudentNo→student_no(20)`、`StudentName→student_name(100)`、`StudentNameKana→student_name_kana(100、raw200)`、`BirthDate→birth_date`、`GenderCode→gender_code(1)`、`PostalCode→postal_code(7、raw10)`、`PrefectureCode→prefecture_code(2)`、`AddressLine1/2→address_line1/2(各200)`、`PhoneNumber→phone_number(16、raw32)`、`EmailAddress→email_address(254)`、`AdmissionDate→admission_date`、`EnrollmentStatusCode→enrollment_status_code(2)`、`EnrollmentEndDate→enrollment_end_date`、`ClassId→class_id`、`EmergencyContactName→emergency_contact_name(100)`、`RelationshipCode→relationship_code(2)`、`EmergencyPhoneNumber→emergency_phone_number(16)`、`Remarks→remarks(1000)`の19入力を保存対象とする。

名前・カナからNameKey/KanaKeyをサーバー生成。SchoolYear/GradeCodeは整合検査のみ。OperationReasonは履歴、ExpectedVersionは更新条件、ReturnContextIdは復帰先、DuplicateTokenはサーバー確認情報。StudentIdはルートID、作成・更新日時・者・分類・削除情報は入力DTOに含めない。

### 登録・更新の要求契約

POST /students/create、POST /students/{id}/updateでStudentSaveInputを受ける。すべてraw string?、ExpectedVersionは新規null・更新正整数、日付はyyyy-MM-dd。専用DTOに限定しEntity直接バインドを禁止。

認証・CSRF→サイズ・型→正規化・入力→Tx・同時保存制御→対象版・マスタ・在籍・定員→変更なし判定→全重複候補・確認→INSERT/UPDATE＋履歴→Commit。確認待ちはRollbackしてHTTP409のEdit Viewと確認部分を返す。理由付き再POSTでも全検査。候補内容はサーバー再検索し、送信された候補一覧を信用しない。

ModelStateへ日本語項目別エラーを追加し、入力エラーではraw値を残す。候補一覧を再構成して同じViewを返す。無条件ModelState.Clearで誤入力を消したり、古い停止候補を先頭選択で置換しない。NoChangeは200で情報のみ、版・監査なし。成功時だけサーバーFlashを保存し303で安全なローカル復帰先へ移動する。失敗時はリダイレクトで入力を失わせない。

削除はPOST /students/{id}/delete、DeleteInput(ExpectedVersion,DeleteReason,Confirmed,ReturnContextId)のみ。管理者と明示確認、未削除・旧版を検証して論理削除＋監査。編集中の学生入力は受け取らない。

## 3. 戻る・権限・保守・試験

検索状態は認証者・セッション・タブ別30分、重複確認10分。改変・他人のIDは拒否。取消は最後の読込スナップショット、再読込は明示確認後GET、戻るは未保存破棄確認。保存確定後の応答喪失は結果不明で検索を案内。

管理者用`StudentMaintenance`コンソールはWebと同じサービスとゲートを利用。初期5分類70値、キー不変、保護コード、クラス参照・定員・期間の確認と監査を実行。マスタ専用Web画面は追加しない。

共通T-01～28に加え、CSRF欠落、余分なEntity管理列の送信、フォーム二重POST、ブラウザー戻る、認証失効、XSS文字列、条件がURLへ出ないこと、ModelState入力保持、候補0件、cookieに個人情報を保存しないことを試験する。
