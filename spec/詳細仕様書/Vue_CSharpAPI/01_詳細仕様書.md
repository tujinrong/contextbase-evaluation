### 検索I/O・API

| TypeScript項目 | C#型付き値 | SQL条件 |
| --- | --- | --- |
| studentNo: string | StudentNoPrefix | student_no前方一致 |
| name: string | NameKey | name_key部分一致 |
| kana: string | KanaKey | kana_key部分一致 |
| schoolYear: number または null | int? | m_class.school_year |
| gradeCode: string または null | string? | m_class.grade_code |
| classId: string または null | long? | m_student.class_id |
| unassignedOnly: boolean | bool | class_id IS NULL |
| statusCodes: string[] | IReadOnlyList<string> | enrollment_status_code。[]は全区分、nullは不正 |
| prefectureCode: string または null | string? | prefecture_code |
| phoneNumber: string | string? | 本人／緊急電話完全一致 |
| admissionFrom/To: string または null | DateOnly? | admission_date、両端含む |

ID・rowVersionはJSON文字列。schoolYear・page等の小さい整数だけnumber。入学日をJavaScript DateのUTC変換でずらさずyyyy-MM-ddで扱う。

| API | 入力 | 出力・処理 |
| --- | --- | --- |
| GET /api/students/bootstrap | なし | Read権限、初期候補・01/02・新Context、学生一覧なし |
| POST /api/students/search | contextId、criteria、pageSize、sortKey、sortDirection | 同一スナップショットの件数・items、1ページ目 |
| POST /api/students/page | contextId、contextRevision、page、pageSize、sort | API保持の最後の実行条件を使用 |
| POST /api/students/context/clear | contextId | 初期条件・未検索へ |
| POST /api/students/options | 用途・年度・学年・学生ID・在籍区分・日付 | コード・クラス候補。用途と権限を検証 |
| POST /api/students/resume | contextId | 所有者確認後、検索済みなら再検索 |

`search()`はdraftを複製して送信、処理中は重複操作不可。成功時だけappliedCriteria更新。入力不備422、システム障害503で古いitemsを消去しdraft保持。検索0件はoutcome=empty、上限超過はtooMany・totalCount=null・items=[]、その他found。ソート4キー以外は拒否、ページ変更は実行済み条件のみ。

候補watchは自動検索しない。`lookupSeq`とAbortControllerで最新応答だけ採用。Abortできなかった応答も番号確認で破棄。未所属ONは年度・学年・クラスを解除。新規・編集へは元ContextIdだけを渡し、ブラウザー永続領域に検索個人情報を保存しない。

### 全項目マッピング

formのcamelCase名をC#のPascalCaseへ対応付け、DBは以下のsnake_case列とする。

| form項目 | DB列・保存型上限 |
| --- | --- |
| studentNo | student_no 20、必須・登録後不変 |
| studentName | student_name 100、必須 |
| studentNameKana | student_name_kana 100、raw200、必須 |
| birthDate | birth_date、必須 |
| genderCode | gender_code 1、初期0 |
| postalCode | postal_code 7、raw10、必須 |
| prefectureCode | prefecture_code 2、必須 |
| addressLine1 / addressLine2 | address_line1 / address_line2 各200、1必須・2任意 |
| phoneNumber / emailAddress | phone_number 16（raw32）/ email_address 254、連絡手段条件 |
| admissionDate | admission_date、必須 |
| enrollmentStatusCode / enrollmentEndDate | enrollment_status_code 2 / enrollment_end_date、区分と日付整合 |
| classId | class_id、01/02必須、ID文字列 |
| emergencyContactName | emergency_contact_name 100、一式 |
| relationshipCode | relationship_code 2、一式 |
| emergencyPhoneNumber | emergency_phone_number 16（raw32）、一式 |
| remarks | remarks 1000、任意 |

APIがname_key/kana_keyを生成する。年度・学年は選択補助、理由は履歴、expectedVersionは競合検査。studentId・管理情報・削除状態・分類固定値を一般保存JSONで受けない。余分なキー・重複JSONプロパティは拒否する。

### 登録APIと結果

| API | 契約 |
| --- | --- |
| GET /api/students/new | Create権限、性別0・在籍01・当年度・入学日空、候補 |
| GET /api/students/{id} | Read権限、非削除、最新全項目・rowVersion・permissions |
| POST /api/students | 新規、form＋selectionHints＋operationReason＋duplicateToken＋returnContextId |
| PUT /api/students/{id} | 同入力＋expectedVersion必須。ルートIDを対象の正本とする |
| POST /api/students/{id}/soft-delete | expectedVersion、reason、confirmed、returnContextIdのみ |

保存順は認証・CSRF→raw検査・正規化→DBゲート→最新対象版・マスタ・状態・定員→変更なし→全候補確認→変更＋監査→確定。409 confirmationRequiredの場合はTx終了後にダイアログ、別人確認と理由付き再送でもAPIで全検査。変更された入力・候補集合・期限切れは再警告。

```json
{
  "outcome":"confirmationRequired",
  "messageId":"W-STU-101",
  "message":"同一人物の候補があります。確認してください。",
  "duplicateToken":"<server-issued-token>",
  "candidateCount":1,
  "candidates":[{"studentId":"1001","studentNo":"S2026-0001",
  "studentName":"見本 太郎","birthDate":"2008-05-15","classLabel":"Aクラス"}]
}
```

例のmessageは説明用で、実文言は共通メッセージ正本から生成する。候補に住所・電話・メールを返さない。成功新規は201、更新・削除は200、noChangeは200。savedの確定応答を受けたときだけdirty解除して検索へ復帰しresumeで再検索。

## 3. UI状態・保守・試験

`originalSnapshot`、`form`、`expectedVersion`、`dirty`、`isBusy`、`duplicateToken`、`lookupSeq`、`returnContextId`を分離。routerの離脱ガードで未保存破棄確認。v-modelが原スナップショットまで変更しないよう深い複製を用いる。リセットは原値、再読込は確認後GET。保存失敗・競合で版を自動更新しない。

管理者保守はC#コンソールから同じAPI側サービスを利用し、5分類70値・クラス規則・履歴原子性を実装。SPAにマスタ画面は増設しない。

共通T-01～28に加え、API直接呼出での権限、CSRF、IDが9007199254740991を超えても文字列保持、fetch応答逆転、ブラウザー戻る、watchループ、401・409・422・503ごとの表示、APIとフロントのスキーマ契約、永続ストレージに個人情報がないことを試験する。
