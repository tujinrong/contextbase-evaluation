任意日付のDateTimePickerはShowCheckBox=True、Checked=Falseを未設定とする。Checked=True時だけValueをDateOnlyへ変換。表示された当日日付を無条件に条件へ使わない。ComboBoxはDropDownList、ValueMemberをID／コード、DisplayMemberを名称とする。

### 検索イベント

| イベント | 実装と処理 |
| --- | --- |
| Shown | `_initializing=True`で候補設定。在学・休学、20件、未検索。初期設定によるSelectedIndexChangedで検索しない |
| btnSearch.Click | UI値を一度読み取る→正規化・CHK検査→SearchAsync→件数上限→一覧へ反映。成功時だけAppliedCriteriaを更新 |
| 所属候補変更 | 未所属ONで年度・学年・クラス解除。非同期候補の要求番号を比較し古い応答を破棄 |
| ページ・ソート | 保持済AppliedCriteriaだけを使用。ソート／件数変更はpage=1。件数減少なら最終有効ページ補正 |
| dgvStudents.CellContentClick | 操作列以外は無視。DataBoundItem.StudentIdから対象を開く。RowIndexを学生IDにしない |
| btnNew.Click | Create権限→新規登録フォーム。検索条件を初期学生値に流用しない |
| 登録フォーム終了 | DialogResultと確定結果を確認し、検索済みなら元条件で再取得。未検索なら未検索 |
| btnClear.Click | 初期値・一覧空・保持状態初期化。学生DB変更なし |

`ReadOnly=True, AutoGenerateColumns=False, AllowUserToAddRows=False`。学生IDは非表示列またはモデルだけに保持。検索失敗・上限超過では古い一覧を消し、入力を残す。

### 登録イベント・状態

`LoadAsync`で最新の非削除学生と版を取得。不在は終了し、新規へ切替えない。`_originalModel`を複製し、フォームが保存済Entityを直接変更しない。参照は全入力readonly、保存・削除・取消を非表示。

`btnSave.Click`：二重実行抑止→読取・正規化→入力検査→共通保存手順。結果はSaved/NoChange/ConfirmationRequired/ValidationFailed/Conflict/Unknownに分ける。ConfirmationRequiredならDB処理を終了してから確認ダイアログを開き、理由と確認情報を付けて再度保存処理へ入る。確認中は接続・Txを保持しない。

`btnDelete.Click`：保存済ID・ExpectedVersion・理由・明示確認だけを渡す。入力途中の業務値を削除サービスへ送らない。管理者以外は拒否。`btnReset`は原スナップショット、`btnReload`は確認後最新値、`FormClosing`は未保存破棄確認。保存の確定後だけ`_dirty=False`、成功結果を返して閉じる。

## 3. マスタ保守・例外・試験

`StudentMaintenance.exe`の管理者用VBコンソールから`MasterMaintenanceService`を呼ぶ。入力は承認済みJSONファイルを読み、型付き値に変換する。5分類70値を初期投入、同値再実行は変更なし、差分は黙って上書きしない。クラス年度＋コード一意、同年度・同学年同名は警告、参照学生がいる学年変更・人数未満の定員縮小・在学休学のいる利用停止は拒否。学生保存と同じ同時保存制御・監査を使う。

`ErrorProvider`と全体メッセージに同じエラーを対応付ける。UIイベント以外のAsync Subは禁止し、非同期例外をAwait元で処理。破棄済Formへ結果を反映しない。保存結果不明では再保存前に検索確認を案内。

共通T-01～28に加え、フォーム2枚で条件が混ざらない、DateTimePicker未チェック、IME入力確定前の変換抑止、DPI150/200%、長文、読み取り専用行、フォーム終了中の非同期完了、2プロセス最終席競合を試験する。
