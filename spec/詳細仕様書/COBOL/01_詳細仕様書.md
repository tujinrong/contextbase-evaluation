# COBOL 詳細仕様書

版3.0／2026-10-10。**GnuCOBOL 3.2＋Linux CGI＋PostgreSQL 18**を選定案とする。IBM CICS／3270版ではない。業務ロジックはCOBOL、SQL接続・Unicode・暗号の補助だけをCブリッジに分離する。

[検索基本](../../基本設計書/01_学生検索画面.md)、[登録基本](../../基本設計書/02_学生登録画面.md)、[共通チェック](../../共通/05_チェック・メッセージ設計.md)、[言語依存仕様](02_言語依存仕様書.md)を参照。

## 1. 処理単位

クラスを前提にしない。`STMAIN`がCGI要求を受けて`STSRCH`（検索）、`STEDIT`（登録表示）、`STSAVE`（保存）、`STDELT`（削除）、`STMAINT`（管理者CLI）へ振り分ける。データ構造はCOPY句で共通化する。画面HTMLは`STRENDER`がUTF-8で出力する。

### 検索入力COPY・条件

| CGI項目名 | COBOL領域 | 条件 |
| --- | --- | --- |
| studentNo | Q-STUDENT-NO | 正規化student_no前方一致 |
| name / kana | Q-NAME / Q-KANA | name_key / kana_key部分一致 |
| schoolYear / gradeCode | Q-YEAR / Q-GRADE | m_class.school_year / grade_code |
| classId | Q-CLASS-ID | class_id完全一致、未設定別標識 |
| unassignedOnly | Q-UNASSIGNED | 0/1、未所属なら他所属条件なし |
| statusCode（複数） | Q-STATUS OCCURS 4 | 全未選択は全区分 |
| prefectureCode | Q-PREFECTURE | prefecture_code |
| phoneNumber | Q-PHONE | 本人／緊急電話完全一致 |
| admissionFrom / admissionTo | Q-ADMISSION-FROM / TO | 入学日両端、片側可 |

文字項目はUTF-8バッファと実バイト長の組。空の日付を00000000やSQL NULL以外の特殊日で保存しない。IDをPIC Xの辞書順で大小比較しない。

### 要求・イベント

`/cgi-bin/student.cgi`へのGETは認証後の初期表示・既存参照だけ。POSTのactionはSEARCH/PAGE/CLEAR/OPTIONS/CREATE/UPDATE/DELETE/CONFIRMに限定し、許可外は400。複数値を許すのはstatusCodeだけ。同名の単一項目重複は拒否する。

初回STSRCHは候補、在籍01/02、20件、未検索。SEARCHは共通CHK入力・存在・組合せ→同一読取Txの最大10001件判定と一覧→HTML200。0件と上限超過は一覧空。PAGEはサーバー状態の最後の実行条件を使用し、本文に含まれる新条件を使用しない。年度・学年変更はOPTIONSで候補更新し不適合クラス解除、まだ検索しない。JavaScriptなしでもPOST再描画で使える。

ページ件数20/50/100、ソートstudentNo/name/admissionDate/updatedAt。ソート／件数変更は1ページ、結果減少時最終ページ補正。結果領域は最大100行、候補確認の表示は最大20行であり、全候補集合の判定上限ではない。

CGIは要求ごとにプロセスが終了するので、WORKING-STORAGEに保存した検索条件を次の要求で再利用できると仮定しない。所有者付きの`T-RUNTIME-STATE`に検索状態と期限を保存する。

### 全保存入力の対応

E-STUDENT-NO→student_no、E-STUDENT-NAME→student_name、E-STUDENT-KANA→student_name_kana、E-BIRTH-DATE→birth_date、E-GENDER→gender_code、E-POSTAL→postal_code、E-PREFECTURE→prefecture_code、E-ADDRESS-1/2→address_line1/2、E-PHONE→phone_number、E-EMAIL→email_address、E-ADMISSION-DATE→admission_date、E-STATUS→enrollment_status_code、E-END-DATE→enrollment_end_date、E-CLASS-ID→class_id、E-EMERGENCY-NAME→emergency_contact_name、E-RELATIONSHIP→relationship_code、E-EMERGENCY-PHONE→emergency_phone_number、E-REMARKS→remarks。以上19入力にサーバー生成NAME-KEY/KANA-KEYを加える。

E-YEAR/E-GRADEは補助検査、E-REASONは監査、E-EXPECTED-VERSIONと確認状態は非表示制御。必須と保存文字長は基本02を保持し、PICの長さに合わせて短縮しない。生年月日・入学日はISO日付10文字から厳密解析する。

### 保存・削除フロー

STSAVEはSTAUTH→STNORM→STVALID→STDBOPでTx開始・ゲート取得→最新学生版／コード／クラスを取得→STRULESで有効性・在籍・定員→変更なし→STDUPで全候補を照合→学生書込み→STAUDIT→COMMIT。重複未確認ならROLLBACK後に確認HTMLを返す。CONFIRM再POSTは状態所有者・期限・入力・全候補を再照合して全検査を再実行する。

STDELTは対象ID・旧版・理由・明示確認だけを受け、一般学生入力を無視するのではなく削除要求の許可項目以外を拒否する。元学生の業務値は保持し、削除属性・版・更新情報と履歴だけを書く。

STRENDERは入力不備422、版・確認409、不存在404、障害503で入力値を再描画する。成功確定後だけ303で元検索状態へ戻す。生成HTMLの値はすべてエスケープ。保存が不明なときは検索確認を案内し、STSAVEを自動再実行しない。

## 4. 保守・試験

`student-maint`はCGI公開外の管理者CLI。STMAINT→同じ検証・保存・監査プログラム。初期5分類70値、差分時上書き禁止、クラス年度内一意、参照時学年不変、定員・期間・保護コード規則を維持する。

共通T-01～28、UTF-8の1～4バイト文字、PIC領域境界、URLデコード不正・重複項目・CONTENT_LENGTH超過、CGI再起動後の状態復帰、C ABIの長さ・NULL・ポインター、DB失敗時のSQLSTATE、全候補を20件だけで判定していないことを試験する。
