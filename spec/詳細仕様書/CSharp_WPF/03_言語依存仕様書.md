## 2. 全89列の物理定義

PostgreSQL 18、UTF-8。表の`Vn`はvarchar(n)、`D`はdate、`T`はtimestamptz、`L`はbigint、`I`はinteger、`B`はboolean、`ID`はbigint identity。`?`だけNULL可。Aはcreated_at T、created_by V64、updated_at T、updated_by V64、row_version L（全NOT NULL、版初期1）。全4マスタの末尾にAを展開し、履歴にAを追加しない。

| 表・列数 | 物理列（論理テーブル仕様書の項目順） |
| --- | --- |

Entityはsnake_case→PascalCase対応。m_classの型名はSchoolClass。日時はUTC、DateOnlyを日時へ変換して保存しない。省略不可の既定値は学生is_deleted=false、マスタis_active=true、display_order=0、row_version=1、duplicate_confirmed=false。固定分類GENDER/PREFECTURE/ENROLLMENT_STATUS/RELATIONSHIP/GRADEはDB側でもCHECKを置く。

PKは各ID、コード種別はcategory_id、コードは(category_id,code_value)。UQは学生student_no全件とクラス(school_year,class_code)。FKは学生class_id→m_class、学生4組の(分類,値)→m_code、クラス学年組→m_code、コードcategory_id→m_code_category。すべて削除RESTRICT、NULL続柄は許容。学籍番号・クラスキーは更新入口で不変を検査。

CHECKは版>0、必須空白禁止、状態01/02なら終了日NULL・クラス必須、03/04なら終了日非NULL・入学日以上、生年月日≦入学日、連絡手段1つ以上、緊急一式、削除属性のNULL整合、年度1900～9998・年度内期間・定員NULLまたは1～9999・表示順非負、コード期間順を持つ。業務日、有効性、集計定員、分類の桁は保存入口で確認する。

索引は学生の非削除birth_date、(class_id,enrollment_status_code)、admission_date、updated_at、本人／緊急電話、操作履歴(target_table,target_key,executed_at)。氏名キー2000文字の無条件B-tree索引は作らず生年月日で絞って候補照合。部分一致の性能は実測し、機能要件を変えない範囲で専用索引を追加検討する。

## 3. Repository・SQL

NpgsqlDataSourceはアプリ単位、接続とTxは処理単位でdispose。QueryServiceはReadOnly RepeatableRead。件数は最大10001件のキーを取得した数、10000以下なら同じTxで一覧ページ。名称は停止値も残すLEFT JOINで分類＋値を結合。WHEREは常にNOT s.is_deleted。AND条件、在籍OR、電話OR、日付両端、未所属NULLを共通の条件ビルダーで件数・一覧両方に使う。

学籍前方、氏名カナ部分は`LIKE $n ESCAPE '!'`。入力の!、%、_を順にエスケープしてからパターンを付加。ソートはstudent_no COLLATE "C"、name_key COLLATE "C"、admission_date、updated_atの許可マッピング、同順位はstudent_id。ユーザーからSQL列名を受けない。

```sql
BEGIN;
SELECT pg_advisory_xact_lock(75310,1);
-- 取得後の別命令で最新対象・マスタを再読込する
SELECT * FROM m_student WHERE student_id=$1 AND NOT is_deleted FOR UPDATE;
SELECT count(*) FROM m_student WHERE class_id=$1 AND NOT is_deleted
 AND enrollment_status_code IN ('01','02')
 AND ($2::bigint IS NULL OR student_id<>$2);
SELECT student_id,row_version FROM m_student WHERE NOT is_deleted
 AND birth_date=$1 AND (name_key=$2 OR kana_key=$3)
 AND ($4::bigint IS NULL OR student_id<>$4) ORDER BY student_id;
-- 全検査後：学生変更と監査追記。確認待ちなら書かずROLLBACK
COMMIT;
```

全学生保存・削除・クラス／コード保守が同じDBゲートを取得する基準案。Read Committedなのでゲート後のステートメントで先行確定を読める。細粒度化はT-15/16/28を維持した別改訂。ユーザー確認待ちでゲートを持たない。

INSERTは19業務入力＋2照合値＋分類固定値＋作成・更新＋版1を設定しRETURNING student_id,row_version。通常UPDATEは19入力から学籍番号を除く18入力＋照合値2＋更新者日時＋版加算。WHERE student_id=$id AND row_version=$old AND NOT is_deleted、RETURNING row_version、0件はE-STU-103/105。DELETEは物理削除せず削除4列と更新情報・版のみ。t_operation_logは同じ接続・Txで1件追加、CREATE/UPDATE/DELETE/DISABLE/ENABLE、変更列だけの配列、理由を記録。失敗は全Rollback。

## 5. 確認情報・権限・配置

メモリーSearchContextはWindowインスタンス別30分。警告は10分、正規化全業務値・対象・旧版・全候補ID/版を対応付け、確認ダイアログを開く前にTx終了。DBに対する不正なクライアント直結を防ぐ本番境界は、DBで認証された個別主体＋実行専用関数`student_api.prepare_save / persist_student / delete_student`を基準とする。直接DMLは許可せず、DB入口でも主体の役割と権限を検査する。

`t_confirmation`補助表はtoken uuid PK、principal varchar(64)、session_id uuid、target_id bigint NULL、expected_version bigint NULL、payload_hash bytea、candidate_hash bytea、expires_at timestamptz、consumed boolean。学生業務5表ではない。DB入口は発行済み確認情報を照合して業務値を更新する。関数内部でCOMMITせず、UnitOfWorkが確定する。理由だけで警告を迂回させない。秘密をWPFバイナリーやappsettingsへ埋め込まない。

SQLSTATE23505は制約名で番号重複／マスタ重複、23503は参照不整合、版0件はE-STU-105、ロック待ち・デッドロックは自動業務再送せず再確認、その他は受付番号付きE-COM-004。Commit後通信断は結果不明。

.csprojはTargetFramework=net10.0-windows、UseWPF=true、Nullable=enable。Npgsql版を固定しWindows環境でXAMLをビルド。ViewModel単体試験、独立した2本の実DB接続の競合試験、UI自動化・DPI・日付入力・アクセシビリティを行う。実装とコンパイル結果は未提供であり、例は構造と契約を示す。

共通16の入力は元号識別値・年・月・日という原文字列4値と業務日。出力は正規化日付と和暦表示文字列、または項目エラー。共通17は項目種別と日付／年度にDATE-R01～06を適用する。変換で不正日を補正しない。OS全体の暦設定を変更しない。元号表の版を画面・保存側で一致させる。

| 役割 | 実装仕様 |
| --- | --- |
| 共通16物理名 | JapaneseBirthDateField / JapaneseDateService |
| 内部日付型 | DateOnly / DateOnly? |
| 入力と保存 | 和暦原入力4値から日付を生成。StudentDraft等のbirth_date相当は正規化日付。元号をDBへ重複保存しない |
| 呼出境界 | 本方式はネイティブ画面。和暦原入力4値を業務処理へ渡し厳密変換する。取得時は内部日付を和暦表示に変換。Web JSON契約は本方式に適用しない |

| 例外 | CHK-032～034、E-DATE-001～003。構文検査後、実在日、元号境界、逆変換、業務範囲、前後関係を順に検査 |
