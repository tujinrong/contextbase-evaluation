# 仕様書チェックリスト・採点規則

版6.0／2026-10-11。仕様→プログラム→逆仕様の評価用。現在は仕様策定段階であり、リバース実行と採点は未実施。

## 概要

画面項目を１項目１点で評価する。例として学籍番号は「必須・20文字・登録後変更不可・全行一意・対応DB列」等を１つの行で確認し、全部一致した場合に１点とする。「３桁」は利用者提示の書式例であり、実際の学生項目を３桁へ変更しない。生年月日も和暦入力・内部日付・年範囲が一式で一致して１点。属性単位の漏れは指摘欄に列挙できるが、この基本採点方式では同じ画面項目を属性数だけ加点しない。

イベントは、概要説明３点、処理手順３点、処理フロー３点、ER図３点、DB操作３点、結果・例外３点を標準とする。各観点は０点または３点で、見出しだけ・汎用説明だけでは加点しない。ER図は多表照会がある場合に適用。単一表・DBなしは理由付き非適用で母数から除く。

DB項目、コード値、メッセージ、共通チェック、共通DB操作はそれぞれ１定義１点。詳細の親項目と重なる内部値は診断行（０点）で追跡し、二重加点を避ける。画面レイアウトは１機能３点。各方式の合計は下表の最大点を使用する。方式を跨ぐ比較には点数だけでなく適用範囲・分母を併記する。

## 判定と集計

判定は「一致・欠落・矛盾・未確認・非適用・未評価」。一致だけ加点する。評価済みの欠落・矛盾・未確認は０点。未評価は獲得点を未採点のままとし、完了得点を出さない。非適用は原仕様と対象方式から事前決定し、資料不足を理由に母数を減らさない。全適用行完了後、獲得点＝各行獲得点の和、満点＝適用行最大点の和、一致率＝獲得点÷満点×100。満点０の評価は「評価対象なし」で率を算出しない。

本版は合格最低点を勝手に設定しない。重要度必須の欠落・矛盾・未確認は得点によらず要対応。原仕様同士の矛盾が見つかった場合は正解基準が不成立のため採点を保留し、仕様を改訂・版固定してから再評価する。

## 逆生成の独立性・原因の切分け

原仕様・期待値を含む採点表は評価者が保有し、逆生成Agentの入力に含めない。逆生成Agentにはプログラム、DDL、画面資源、設定、記述フォーマットを渡す。コード内のコメントや仕様IDは探索の手掛かりであり実行動作の証拠そのものではない。

原仕様と逆仕様が違う場合、(a)実装が原仕様と違う、(b)実装は正しいが逆抽出で欠落した、(c)外部依存で未確認、を分けて指摘する。逆仕様がコードの不具合を忠実に記述した場合は「実装差を正しく抽出」と記録し、逆生成Agentの抽出ミスと混同しない。実装適合得点と逆抽出の忠実度は別の軸で報告し、この表の満点を両方の達成とみなさない。

原仕様位置、逆仕様の見出し／項目ID、ソースのコミット・ファイル・シンボル・行範囲、観測値、判定理由を残す。テスト実行でしか確認できない条件は静的読解と実行結果を区別する。採点者、評価日、原仕様版、生成ソース版、逆仕様版を記録し、再評価は履歴を残す。
