# WEB系画面の設計・実装品質

版1.1／2026-10-30。[UIパターン規約](UIパターン規約.md)のWEB系を具体化する。参照元は[web-ui-standard](../references/web-ui-standard/README.md) v1.0。以下はBROWSERを対象とし、WPFは専用節の範囲で構成・利用者品質を採用する。

## 適用と構成

**WUI-01［必須］** 共通のサイト構造と現在位置を定め、通常の業務ページ間移動で独立した「メニュー画面」への往復を前提にしない。基本は共通ヘッダー＋左サイトメニュー＋本文。少機能なら理由付き上部メニューを使える。同じ全機能を上下/左右へ二重掲載しない。サイトメニューは業務機能、ページ内タブは同一対象の情報分類に使う。利用者表示/ログアウトは採用認証がある場合だけ具体化し、認証なしの既存前提を変えない。

ホームは必要な未処理・最近利用・業務状況を表示する。不要なら主一覧を入口とし、指標や巨大な遷移ボタンを作るためだけにホームを追加しない。公開認証画面やエラー等の共通枠の例外を記録する。

**WUI-02［必須］** ページの主見出し・対象/モード・主操作を識別可能にする。グループ見出しは内容の上方へ独立して置き、Access風の枠線上の見出しをWebの既定にしない。移動はリンク、実行はボタン、単一行の詳細/編集は名称リンクや行操作を基本とする。離れた選択＋編集は対象選択の業務目的がある場合に限定する。

共通AppShell/ナビ、PageHeader、FilterPanel、DataTable/Pagination、FormField/Section、ActionBar/離脱保護、状態表示、Dialog等の責務を同方式内で共有する。特定フレームワークや外部UIライブラリーの導入を必須にせず、他方式の実装を横断参照しない。

## 文字と寸法のトークン

**WUI-03［標準］** 次を参照CSSの初期提案として、方式内共通トークンへ採用/調整する。既存デザインシステム/確定値を優先し、採用値・理由・密度・例外を記録する。root=16pxの場合の換算を固定保証にしない。

| 役割 | 初期トークン/値 | 補足 |
| --- | --- | --- |
| 書体 | Noto Sans JP、Yu Gothic UI、Hiragino Sans、Meiryo、system-ui、sans-serifの順 | インストール状態とフォールバック字幅を確認。外部配信を無断追加しない |
| 本文/入力 | 1rem、行高1.6/入力1.5 | htmlは100%。文字設定・ズームを妨げない |
| ページタイトル/セクション | 1.5rem/1.125rem、太字 | 見出し階層を作る |
| ラベル/ボタン/メニュー/表/補足/エラー | .875rem、行高1.5 | 本文と役割を区分。重要情報をさらに小さくして収めない |
| 余白系列 | .25/.5/.75/1/1.5/2/3rem | ラベル間.25rem、関連操作.5rem、項目1rem、グループ1.5remを初期値 |
| normalの入力/操作最小高、行最小高 | 2.5rem、3rem | compact:2.25/2.5rem、touch:2.75/3.5rem。固定高で文字を切らない |
| ヘッダー最小高/ナビ幅 | 4rem/15rem | 内容と環境で調整する |
| 一覧/編集/認証の最大幅 | 90rem/60rem/28rem | 全画面を同幅にしない |
| 長文入力の初期最小高 | 7rem | 縦伸縮と全文確認を確保する |
| 入力/パネルの角丸 | .375rem/.5rem | 役割で揃え、枠/カードの過剰な入れ子を避ける |

通常ボタンはラベルと左右余白から幅を決め、短い通常操作の最小幅は5remを初期候補とする。行内/アイコン操作は用途別バリアントとし、ラベルも含めた操作対象を確認する。同じ領域で密度を意図なく混在させない。

**WUI-04［必須］** 本文/入力/ボタン等に共通のフォント系列を明示し、同じ役割の値を散在させない。参照CSSを使う場合は必要な採用値を方式内へ取り込み、参照ディレクトリーや他方式への実行時依存を作らない。root全体へ作用するセレクターをMDビューアーへ漏らさず、設計断片のroot内へスコープする。配色は意味別に定義し、選択/必須/エラーを色だけで伝えない。

**WUI-04a［必須］** [UIパターン規約](UIパターン規約.md)のUIP-03aを適用し、認証のID/パスワードと既存の同型ペアを共通の幅・高さ・整列トークンへ対応付ける。BROWSERでは同じ入力群/コンテナー内で枠の幅・高さと、縦配置の左右端又は横配置の上下端を揃え、size/maxlengthや入力値の文字数から個別幅を決めない。パスワード補助アイコンやエラー表示で片方だけ幅を変えず、採用した各幅/ズームと初期/エラー/再表示で実DOM矩形を比較する。WPFも同じ目的をDIPと実Controlで具体化し、CSSやAccessのTwipsを転用しない。

## 配置と表示領域

**WUI-05［必須］** 本文をページ識別/主操作→条件又は要約→主要情報→補助情報に構成する。フォームは内容幅に応じて1〜2列を標準とし、短い関連項目以外の多列化は理由を残す。CSS Grid/Flex等を用い、空白文字・空セル・固定座標で揃えない。短いコード/日付/数量に上限幅を与え、名称/説明へ残余幅を配分する。用途を無視して全欄へ全幅や同幅を強制しない。

**WUI-06［必須］** ビューポートとナビ等を除いた内容幅を別に計測する。参照標準の64rem/48remのサイト枠境界、内容45rem以上で2列という値は採用時に具体化する。狭幅ではナビの折畳み、1列化、操作の折返しを設計する。長文は折返し/欄内移動等で全文へ到達させ、必要なmin-width:0等を設定する。overflow-x:hiddenや文字縮小で欠陥を隠さない。比較に必要な多列表だけ局所横スクロール等を採用し、識別列を黙って隠さない。

固定ヘッダー/保存バーは入力・フォーカスを覆わず、低い高さや拡大時に非固定へ切替える等の到達方法を定める。PC優先・狭幅等の採用条件を記録し、項目削除や業務の変更で収めない。1440/1280/1024/768/390/320 CSS px、文字拡大200%、OS倍率は確認候補と実施済みを分ける。リフローやアクセシビリティの正式適合を要求する場合は対象基準/例外を明記し、PCだけの確認を全幅対応としない。

## 検索と対象操作

**WUI-07［必須］** 入力中と適用済みの条件、検索状態/件数/表示範囲、並び順、ページサイズ、対象選択、出力範囲を一つの契約として定義する。新規は一覧の主操作、参照/編集は行からの直接操作を標準とし、一括選択は必要時だけ追加する。

新規の増加する一覧では番号方式20件・20/50/100選択を提案初期値とする。固定少件数、カーソル、採用済み方式には理由/根拠を残す。並び順に安定した一意キーを含め、検索/並び/件数変更時の先頭復帰、端ページ・0件・削除後の有効ページを定める。ページ移動は適用済み条件を保持し、詳細から戻ると条件/ページ/並びを復元する。

総数/範囲は取得結果と一致し、不明を0件や架空の総ページで代替しない。クリアは初期値への復帰と再検索の有無を明示し、参照標準の再検索既定で現行契約を上書きしない。増加する本番一覧ではサーバー側の条件/並び/取得範囲と検証を具体化し、全件取得のデモ配列を本番ページングとしない。要求競合で古い応答が新結果を上書きしないよう扱う。

複数選択は現在ページ/ページ跨ぎ/検索全件を区別し、安定IDで対象を保持する。出力の現在ページ/選択/検索全件を勝手に変更せず、実行時の認可と対象を確認する。URL等で復元する状態と、機密のため別の認可された保存先を使う状態を分け、直接表示/期限切れ/別タブも定義する。

## 入力と状態と移動

**WUI-08［必須］** 保存方式/単位/確定時期/破棄範囲、未反映明細、保存中/失敗/競合、二重送信と再試行を定義する。画面の無効化だけを重複防止や権限の保証にせず、必要なサーバー側検証・認可・原子性を仕様へ結ぶ。明示保存は現在編集中の値を含め、失敗時は入力を保持する。業務にない下書き保存やlocalStorageへの機密保存を追加しない。

アプリ内移動・対象/タブ切替、ブラウザーの戻る/進む・直接URL・別タブ・再読込/終了を区分して設計する。アプリ内の保存/破棄/継続と、ブラウザー終了警告の制約を区別し、beforeunloadで独自の三択や全環境での発火を保証しない。成功トーストだけを保存確認手段にせず、保存/破棄後に再表示して確認できる状態を残す。

**WUI-09［必須］** 未取得/取得中/正常/0件/通信失敗/権限なし/対象なしを区別する。ラベル関連付け、見出し、表見出し、ボタンtype、名前のあるアイコン、キーボード/フォーカス、色以外の状態表現を定義する。意味を持つHTMLを使い、通常リンクへARIA menu等を一律付与しない。モーダルと本物のタブは適用するキー/選択/フォーカス管理を具体化し、ページリンクをタブの役割だけで表現しない。エラーは要約と項目近傍に示し、値を保持して復帰可能にする。製品UIへ設計注記・検査用状態切替を混ぜない。

コントラスト、操作対象、読み上げ、動きの削減、文字拡大を対象基準に照らして確認する。参照原文I-031〜034の規格値と本標準独自の40/44px相当の提案を区別し、一部の検査や見本の過去PASSをWCAG全体の適合表明に使わない。

## WPFへの適用

**WUI-10［必須］** CSharp_WPFはWEBという配置分類を保ち、XAML/ネイティブ部品で画面階層、現在位置、関連項目の近接、対象識別、状態/保存契約を実現する。ナビゲーション枠や必要な一覧操作は採用済みのWPF方式へ具体化する。ブラウザーのURL/HTTP/履歴/DOM/ARIA/CSSやWebライブラリー、参照CSSの値を実行条件にしない。

Grid/StackPanel等の配置、DIPと字体の役割別値、サイズ制約/ScrollViewer、ItemsControl等の列/選択、バインド/検証/コマンド、Tab/Enter/Esc/フォーカス、モーダル/画面終了、UIスレッドと非同期結果を詳細へ記す。px/remを無根拠にDIPへ換算しない。ページング・行操作・ボタン形状は現行方式の採用契約に従い、ブラウザー参照例から追加しない。実XAML部品の属性・配置・キー・バインド/保存結果を測り、HTMLモックやcomputed styleでWPF適合を証明しない。

## 完了条件

**WUI-11［必須］** [UI適合検査](UI適合検査.md)へ、共通枠/現在位置、タイトル/対象、役割別字体・寸法、内容幅/長文/主要操作、一覧の条件/ページ/選択/出力、保存/離脱/エラー、キーボード/状態の個別期待値を渡す。BROWSERは最終publishのDOM/computed style/矩形と実操作、WPFは最終製品の実部品/ネイティブ操作から独立観測する。

採用ページサイズNに対して0/1/N-1/N/N+1/多件数、端ページ、条件変更/削除/詳細復帰、直接表示、未反映入力/保存失敗/競合、長い値と対象幅を該当範囲で検査する。画面/項目/操作/条件ID・根拠版/SHA・状態/環境・証拠・未実施を対応させ、合理性/統一性/見やすさ/操作性を独立レビューする。設計HTML、ビルド、実画面、API/保存再読込、アクセシビリティ、正式受入を別に報告する。
