# Text型画面の設計・実装品質

版1.0／2026-10-29。[UIパターン規約](UIパターン規約.md)のTEXT/TERMINALを具体化する。Web参照標準の対象識別・操作結果・状態保持という目的を固定行桁の文字画面へ適用し、GUIの寸法や部品を要求しない。

## 適用と端末プロファイル

**TUI-01［必須］** 採用処理系、端末/エミュレーター、端末行数/桁数、行列の原点、固定セル寸法/フォント、文字コード/CCSID、DBCS/日本語の扱い、使用可能なキーを仕様入力として固定する。COBOLの端末画面とAS400_RPGの5250を区別し、24×80等の値を未指定の全方式へ強制しない。端末未決なら仮定/QAを残し、実機対応済みにしない。

メニュー/画面名・対象番号/名称・モード、入力/一覧、メッセージ、操作キーの領域を行桁で確保する。用途パターンは業務目的で選び、Webのサイトバー/カード/リンク/ドロワー/ドラッグ/マウス操作を画面部品として持ち込まない。階層/予定/状態等は番号選択・表・別詳細・確認画面等の実現可能な表現へ具体化する。

## 行桁と文字と入力

**TUI-02［必須］** 全項目・ラベル・一覧列・メッセージ・キー案内に開始行/列、表示セル数/高さ、入力/保護属性を定める。採用した半角1/全角2セル等の規則で日本語を計測し、入力文字数・ホストのバイト数/レコード長・表示セルを別に管理する。Unicode文字数だけでDBCSや全角の占有を判定せず、使用不可/結合/補助文字等の扱いも定める。符号化失敗を黙って置換・切捨てしない。

**TUI-03［必須］** 共通の見出し/対象/入力/一覧/メッセージ/操作行、列境界と行間を定義する。端末の右端/下端超過、保護域/入力域の重なり、操作案内とエラーの上書きを防ぐ。名称/説明の全文は続き画面・拡大表示・分割/継続入力等で到達させ、見た目の欄幅を保存上限にしない。入力済み部分と未入力部分の保持/結合・保存/取消を定義する。Webのフォント縮小・折返し・可変高さで収めない。

必須/空欄/ゼロ/未設定、番号の先頭ゼロ、数値/日付の書式は業務仕様から定める。入力域/表示保護域、選択欄、候補の呼出しと戻り、参照コピーの可否を明示し、権限と画面保護を同一視しない。色だけに頼らず状態文字・エラー番号等を併用する。

## 検索とページと状態

**TUI-04［必須］** 条件入力と適用済み条件、未検索/正常/0件/取得失敗、選択対象と表示詳細、出力対象を対応付ける。一覧の物理表示行数から1画面の行数を算定し、Webの20/50/100件を転記しない。画面の前後ページと検索の分割取得/ホストカーソルを区別する。総数不明を架空の総件数/末尾ページで表示しない。

並び・検索条件・ページ/選択の保持、検索変更時の先頭復帰、先頭/末尾/0件/削除後の動作と操作不可の通知を定める。複数選択はページ内/ページ跨ぎ/全件の対象範囲を明示し、選択番号だけを別の結果集合へ誤用しない。詳細/入力画面から戻る際の一覧状態を契約化する。

処理中/ホスト待機、入力エラー、対象なし、権限不足、失敗/競合を可能な表示領域で識別できるようにする。エラーは項目・理由・直し方を示し、入力保持と該当欄へのカーソル復帰を定義する。処理受付と完了を区別し、時間経過から進捗/成功を捏造しない。

## キーと確定と復帰

**TUI-05［必須］** Tab又は端末の項目移動、Enter、実在する機能キー、前/次画面、戻る/取消、候補、確認/実行の割当をキー表へ残す。押下キーと画面モードによる処理/送信、入力カーソルの初期位置・復帰・移動順、保護欄の扱いを定める。EscやFキーの意味を処理系間で同じと推測しない。GUIのクリック試験だけで主要操作を確認したことにしない。

**TUI-06［必須］** 画面送信・入力チェック・明細反映・レコード更新・全体確定の段階を分ける。親子/複数画面の追加/変更/削除、長文の継続部分、未反映入力の保存単位と取消範囲、ホストの確定/ロールバックを定義する。単に画面を閉じる操作を破棄と約束せず、採用ホストとの往復で検証する。エラー/通信失敗/再送/タイムアウトや別対象切替で入力と対象を取り違えず、保存失敗後に成功として戻らない。

確認画面は対象と影響、実行/戻る/編集継続を利用可能なキー/選択値で示す。入力のない移動に不要な確認を繰り返さない。採用済みの認証・権限・保存/取得方式を、Webの離脱保護やページングへ置き換えない。

## 設計表現と詳細契約

**TUI-07［必須］** 画面正本はMD概要GRID内の固定行桁を保つ静的HTMLとする。等幅のpre等又は固定文字セルを使い、行/列原点、端末行桁、半角/全角規則、画面/項目/操作IDを対応付ける。可変幅のフォームやブラウザーの自動折返しを採用端末の表現としない。枠・色等のモック表現をホストの入出力定義と混同しない。

詳細は画面項目/列/キーと入出力レコード・変数・物理長/型・入力/保護属性、カーソル/メッセージ、イベント/送信処理を対応付ける。5250のフィールド属性やCOBOLの画面定義等は採用処理系で具体化し、実際には未対応のキー/長文入力/全角配置をモックに描かない。Excel変換でも行桁・空白・項目IDを保持する。

## 完了条件

**TUI-08［必須］** [UI適合検査](UI適合検査.md)の個別期待値に、行桁/セル占有・原点・端末の字体/設定、保護/入力属性、キー/カーソル、メッセージ/確認、検索/ページ/選択、保存/取消・継続入力を渡す。実端末で制御できない字体等は適用範囲/端末設定と測定方法を明記し、架空のDOM/CSS観測で補わない。

環境観測はviewport.unit=cells、width=列数、height=行数で表せる。ピクセルDPI/倍率が意味を持たない実端末は、今回のUIパターン規約を凍結したTERMINALに限りdpi/scaleをnullとし、各々のdpiReason/scaleReasonへ非適用の理由を記録する。未測定や取得失敗を非適用にせず、端末モデル・行桁・プロファイルを根拠にする。エミュレーターの実測DPI/倍率は正数で残す。取得できない値を96dpi等の仮値で埋めない。

実端末/エミュレーターとホストの対象版・SHA、文字コード、画面サイズ/行桁・キー入力・送受信/再読込・証拠を記録する。全角/混在/最大長、右端/下端、未選択/0件/表示行境界、エラー復帰、長文前後移動、未反映入力、保存失敗/破棄/再表示を該当範囲で検査する。ブラウザー文字モックの構造/描画と、DBCS/CCSID変換・実キー・保存結果を区別し、処理系未導入や未実施を明記する。利用者4観点の独立レビューと正式受入は別の状態とする。
