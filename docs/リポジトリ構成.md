# リポジトリ全体構成

版7.2／2026-10-22。Git管理とローカル実行記録の配置規則を追加。今回の変更でアプリ実装・実機試験・逆生成採点は行わない。

## 概要

仕様作成Agent、順生成Agent、逆生成Agentを複数の独立したテストプロジェクトへ適用する。現在は仕様策定段階であり、Agentの実装・実行済みを意味しない。docsは全体の規則、agentsは役割・入出力契約、test-project1は最初の評価題材。test-project2は将来の追加予定で、今回の業務要件をコピーして未承認の第二プロジェクトを作らない。

## 配置一覧

| 領域 | 目的 | 書込み範囲 |
| --- | --- | --- |
| docs/ | 全プロジェクト共通の仕様作成、MD/Excel、開発、評価方針 | 共通ルールの変更のみ。特定業務の桁数やDB採用は置かない |
| agents/ | Agentの役割・入力許可・出力契約 | Agent定義。特定プロジェクトの正解仕様を内蔵しない |
| test-project1/ | 題材の要求・仕様・開発プロファイル・履歴 | 選択されたプロジェクト内 |
| test-project1/spec-eval/ | 基本/詳細/共通/DB定義の期待値・採点と証拠 | 評価者だけ。逆生成Agentから隔離 |
| test-project2/（将来） | 独立した次の題材 | 明示的作成指示後。他プロジェクトの入力を混ぜない |

## 識別と変更

projectId/仕様セット版/方式ID/文書ID/機能ID/項目IDを識別子として保持する。プロジェクトを跨いだ同じ項目IDは別物。移動では相対リンク・メタ情報path・評価根拠・画像参照も更新する。同一IDの意味を変更した場合は仕様版を更新する。評価旧版はGit履歴で保持する。共通ルールを変えても、既存プロジェクトの承認済み範囲へ無断適用しない。

## テーブル文書の配置

各プロジェクトのspec/基本設計書/テーブル/およびspec/DB定義/＜プロファイル＞/テーブル/へ１テーブル１文書を置く。全体の[記述規約](テーブル仕様書記述規約.md)を使用する。具体的な業務項目・長さ・DB採用は全体docsへ転記しない。

## Git管理とローカル実行記録

ソース、正式な試験コード・fixture、設定例、Agent定義、仕様・評価基準、QA、ContextBaseの解析正本（identities.jsonを含む）、正式なoutputとspec-analysisはGit管理を継続する。拡張子だけでJSON・画像・HTML・Excel等を一括除外しない。

agents直下の各Agentのreport/・test-report/、test-project1のreport/・test-report/・test-evidence/とsrcs内各方式のtest-report/はローカル実行記録とする。test-project1/test-report/README.mdは既存スクリプトが参照する入口として例外的に保持する。既存文書から実行記録へのリンクはローカルで参照できるが、新しいcloneには記録本体を含めない。

.tmp/・.runtime/・.specgen-state/・.contextbase-work/、Pythonキャッシュ、依存パッケージ、ビルド出力はローカル保持とする。既存のcore-r19-root-r01/、all-ai-r14-live-20261013-1303/およびreverse-agent配下のfocus-*・method-integration-*・20261013-r15-cluster-title-full-01/では、Markdown・citation・fixture.htmlを保持し、描画結果とmanifest・計測結果だけを除外する。新規の試行は各Agentの.tmp/またはtest-report/へ置く。

対象の正確なパターンはルートの.gitignoreで管理する。実行記録の保存義務は継続し、Git除外を理由にローカル記録を削除しない。新しいcloneでは必要な入力を用意して新規実行IDで再生成する。既に追跡中のファイルは.gitignoreだけでは外れないため、git rm --cachedで索引からのみ外す。過去コミットは変更せず、履歴にある旧記録も今回の改訂の検証結果へ流用しない。
