# 仕様書作成ルール（全体）

版7.5／2026-10-25。画面設計をWEB系（WPFを含む）・WinForms系・Text系の三分類とし、新規画面にも適用する。業務アプリ・実DBの実行試験は未実施。

## 適用と読者

仕様書をMarkdownで作成する。基本設計は顧客団体のIT部門向けに論理名・言語非依存で記述し、画面とDBの関連を重視する。詳細は経験5年程度の実装者向けに、物理名・変数/型・クラス/プログラム・引数/戻り値・分岐・例外・確定境界を記述する。基本/詳細/DB定義の重複は許容し、矛盾は認めない。仕様作成Agentの共通規則として、特定の業務項目数・文字長・採用DBはここに固定しない。

## 章立て

機能仕様は1機能1ファイル。本文主章は概要・項目一覧・イベント仕様・補足説明。詳細は基本と同じ機能ID/項目ID/イベントIDで対応し、同じ見出しの下へ実装をぶら下げる。表紙属性はタイトル直下、独立主章にしない。項目移送・項目更新・候補一覧などは必要なら独立LIST主章にしてよい。

概要内に画面設計とファイル/DB入出力を置く。画面・外部ファイル・永続DB・一時情報を区別し、外部ファイルがなければなしと明示する。対象・開始契機・呼出し・権限・処理単位・対象外を記載する。

項目一覧は一章一矩形表だけ。論理項目名、入力/表示/保存、raw上限、正規化/保存上限、長さ単位、必須区分/条件、初期値、未設定、関連DB項目、候補元を明記。詳細には物理コントロール・バインド/変数・言語型・DB列/型/NULLを加える。文字列長は基準値・余裕率・算定式の根拠をプロジェクト共通仕様に記録する。

選択候補は分類・元テーブル・キー・名称・抽出条件・並び順・初期値・上位変更・停止既存保持を説明する。項目移送/更新は移送元と設定先・条件・加工・変更不可/更新なし・論理削除時の範囲を特定する。

## イベント・DB

イベントごとに処理概要、処理手順、処理フロー、SQL・テーブル関連（ER図）、DB操作の詳細、結果・例外時の扱いの6下位見出しを設ける。複数表の検索/参照は当該処理のER図が必要、単一表なら対象と省略理由を記す。外部キーと検索JOINを混同しない。DB操作は対象表、操作、実行条件、取得/更新項目、抽出条件、件数、順序、確定/取消を含む。重複・存在・有効性・条件付き必須・同時更新・例外を具体的に記す。共通処理を呼ぶだけでなく当該機能の引数と結果分岐を書く。

## 画面とExcel

基本と詳細の画面は概要にHTML/CSSをコードフェンス外へ埋め込み、同じ画面・状態の配置を一致させる。画面表現の正本はこの埋込みHTMLだけとし、同じ画面の単独HTMLやPNGを仕様書へ併置しない。ブラウザー確認用HTMLとスクリーンショットは方式内.tmp/へ抽出して検査し、今回の入力版・断片ハッシュ・サイズ・計測・目視結果をsourceRoot/build/の固定記録へ残す。MDビューアーがCSSやフォーム要素を制限する場合はその制限を記録し、別レイアウトのPNGで補完しない。仕様モックと製品実機画面を区別する。既存の原入力・QA・正式試験fixtureの画像は、この画面表現整理を理由に削除しない。

### 画面設計の三分類

画面設計は次の三種類から選ぶ。新規画面も、作図前に対象方式の分類、採用部品、基準サイズと操作方法を方式別共通UI仕様へ定義し、基本・詳細で共有する。未分類の方式は三種類のいずれかへの所属と方式固有制約を実装前に決定する。HTMLは配置を示す媒体であり、分類によって実装技術を置き換えない。

| 画面分類 | test-project1の対象方式 | 設計基準 |
| --- | --- | --- |
| WEB系（WPFを含む） | CSharp_ASPNET、CSharp_WPF、Vue_CSharpAPI | 見出し、入力、操作、一覧の順序と整列を揃え、指定サイズで主要操作を近接配置する。WPFもこの配置分類へ含めるが、XAML・バインド・フォーカス等のWPF固有仕様は維持する |
| WinForms系 | VB.NET_WinForms、Access | 従来の固定フォームと標準部品を使う。Accessは単票フォームとラベル・テキストボックス・コンボ・チェック・枠・リストボックス・コマンドボタン、WinFormsはForm・Label・TextBox・ComboBox・CheckBox・GroupBox・DataGridView・Buttonの制約を守る |
| Text系 | COBOL、AS400_RPG | 固定行・固定桁の文字画面とし、入力域、保護表示域、選択欄、メッセージ行、操作キーを行桁で配置する。COBOLの端末画面とAS400_RPGの5250画面は、各処理系・端末の制約を別途記す |

WinForms系へ色帯、カード、角丸、影、入力の一律全幅化、レスポンシブなカード積替えを既定設計として持ち込まない。Text系へGUIのボタン、ドロップダウン、可変高さカード、マウス操作を必須とする構成を描かない。各分類とも必要な検索条件だけを採用し、同じ意味の項目・操作の位置と幅を揃える。

Text系は端末の行数・桁数、行列原点、フォント、半角1セル・全角2セルの表示規則、使用文字と文字コードを明記する。日本語の表示セル数、入力文字数、ホストのバイト長を別々に管理し、全角文字や項目が端末の右端・下端を越えないようにする。保護/入力属性、初期カーソルと移動順、選択値と候補の呼出し、Enter・機能キー・取消・前後ページの意味、エラー行と該当欄への復帰、確認画面、長文の分割/継続入力を定義する。詳細には画面項目IDとレコード/入出力領域の対応を残す。ブラウザーの文字モックでCCSID変換、DBCS、実端末のキーや入力動作を検証済みとせず、採用処理系・エミュレーターによる実機確認の状態を区別する。

入力幅は表示する文字数・文字種・フォントの字幅に、内側余白・枠・選択矢印を加えて決める。番号・コード・郵便番号・電話・和暦の小欄と、氏名・住所・備考を同じ幅へ引き伸ばさない。同じ領域のラベル開始位置と幅、入力左端、同種部品の高さ、行間、操作の位置を揃える。長文は複数行・欄内移動・拡大入力・別ページ等で全文へ到達できるようにし、見た目の幅をraw/保存上限へ読み替えない。詳細仕様には基準サイズ、座標原点、位置・幅・高さ、単位、フォントと拡大時の挙動を記す。AccessのTwips/pt、WinFormsの基準DPIのpx、WPFのDIP、WebのCSS px、Text系の行・表示セルを区別する。

ページングは分類名だけで決めず、利用者指定と方式別契約に従う。test-project1のAccess/WinFormsはページングを設けず、取得上限を持つ全件取得と一覧内スクロールを維持する。Text系で一覧や長文を複数ページに分ける場合は、表示ページと検索の分割取得、入力保持、移動キー、確定/取消の関係を明示する。今後の画面も通常、空結果、入力エラー、長い値、選択、確認、ページ境界等の必要な状態を対象分類で確認し、未実施を残す。

LIST章へ図/文章/コード/複数表を混ぜない。その他GRIDは細かい列のExcel方眼に変換する。spec-metaの章種別とシートキー、先頭ゼロ/長いID/日付/数式文字列の保持は[MD規約](MD構造・Excel変換規約.md)に従う。

## 分担と検証

docsは全体ルール、agentsはAgent契約、各test-projectは題材の仕様・仮定・規約・証跡・spec-eval。独立方式の仕様正本はproject/spec/方式ID/（specRoot）へ置き、ソース正本project/srcs/方式ID/（sourceRoot）と分ける。業務仕様と仕様間参照は選択方式のspecRoot内で閉じ、共通の配置索引から他方式の業務仕様を共有しない。開発入力は同じspecRootの機能別詳細・共通・DB定義・開発規約に閉じ、要件/基本は理解に使う。単独の言語依存仕様書は作らず適切な責務へ統合する。共通仕様にはシステム概要・CRUD・共通モジュール/UI・チェック/メッセージ・日付・データアクセスを含む。方式固有のAPI/型は方式別共通、DBはDB定義、命名/配置は開発規約。各仕様に評価基準を作り、構造検査と内容評価と実行試験を分ける。未確定・提案・承認・実装・試験済みを混同しない。

## テーブル別文書

[テーブル規約](テーブル仕様書記述規約.md)に従い１テーブル１ファイル・１シートへ分冊化する。論理テーブル仕様でも物理名は対応確認用に併記可とする最新指定の例外。言語非依存の業務意味を維持し、９列表にNOT NULLを設け、実DB型をタイプ欄に直接記載する。非該当・初期値なしの埋草を省き、条件付き必須・制約を保持する。
