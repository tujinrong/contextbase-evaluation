# テーブル仕様書・DB定義書 記述規約

版7.1／2026-10-12。仕様書の書式改訂。業務アプリ・実DBの実行試験は未実施。

## 適用範囲

テーブル仕様書・DB定義書は１テーブル１MDファイルとする。Excel化ではその１ファイルを１シートへ変換し、同じ系列・同じDBプロファイルの複数テーブルを１ブックへまとめられる。テーブルヘッダーと項目詳細を別シートへ分けない。索引・DB共通規則は別文書に置き、業務表と技術補助表を区別する。画面仕様の標準４章は変更しない。基本テーブル仕様の物理名は照合用の参照名として許容し、論理説明・タイプ・長さは言語非依存を維持する。

## 書式

各テーブル文書はタイトル、メタ情報、見出し「テーブルヘッダー」「項目詳細」だけで構成する。ヘッダーは項目・内容の２列表１つ、項目詳細は下記８列表１つとする。本文中の他の表、箇条書き、SQL、図は索引・共通規則へ移す。項目詳細の章内はその表だけを置く。

| No | 論理名 | 物理名 | PK | タイプ | 長さ | 初期値 | 説明 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 表示例の数値項目 | example_value | － | 数字 | 3.1 | 指定なし | 書式例。整数３桁・小数１桁。実際の業務項目を追加する例ではない。 |

ヘッダーには文書ID・版・論理/物理テーブル名・DBプロファイル/スキーマ・用途・項目数・順序付き主キー・共通制約の参照・初期値と長さの意味を記す。複合主キーは構成する各行に「〇」、ヘッダーに構成順を記す。PKでない行は「－」。Noはテーブルごとに1から連番、欠番・重複不可。

## 列の意味

| 列 | 記載方法 |
| --- | --- |
| No | テーブル内の項目順。1から連番。 |
| 論理名 | 既存仕様の論理項目名。補助表の名称を補足する場合は由来をヘッダーへ記す。 |
| 物理名 | 既存DB列名。基本設計でも対応確認用に併記する。 |
| PK | 構成列は〇、その他は－。一意キー・FKと混同しない。 |
| タイプ | 文字、数字、日付、日時、真偽、識別子、バイナリ、配列。DB定義の実DB型・容量は説明欄にDB:型として保持する。 |
| 長さ | 文字＝業務文字数、数字＝整数部桁数.小数部桁数、バイナリ＝バイト数。適用なし・論理層で未指定は－とし根拠を説明。 |
| 初期値 | 基本は業務初期値、物理DB定義はDB既定値。指定なし、NULL、空文字、未定義、自動採番を区別。処理設定だけが分かる値は処理:値と書く。 |
| 説明 | 必須/条件付き、自動設定、DB型、NULL可否、参照先、範囲、変更不可等を簡潔に記す。長い規則は明示リンクした共通定義へ集約し、省略しない。 |

## 数字と長さ

長さ「3.1」は本規約では整数部３桁、小数部１桁、合計４桁を意味する。SQLのprecision.scaleそのものではない。decimal(p,s)へ対応する場合はp=整数桁+小数桁、s=小数桁であり、この例はdecimal(4,1)相当。符号・小数点は桁数に含めない。整数は4.0などと書き、文字列として保存する。3.10を数値3.1に変換すると意味が変わるため、Excelでも長さ列は文字列に固定する。

数字の長さは桁の表現であり、その桁数の全数値を許可する保証ではない。業務範囲と実DB型の範囲を併せて検査する。基本層で具体的上限を決めていないID等は勝手に実DBの桁数を採用せず「－」、範囲は採用DB仕様を参照する。文字列のコード・郵便番号は数字だけでも先頭ゼロを保持する「文字」とし、数値型へ変更しない。日付・日時の長さを画面書式の文字数で代用しない。Unicodeの業務長と物理コード単位容量は別であり、説明欄の実DB型と共通規約で追跡する。

## 同一シートへの配置

通常のLIST/GRID章からの自動分類は使用せず、テーブル文書はlayout=TABLE、schema=spec-md/1.1を明示する。sheetsは１要素だけ、kind=TABLE、そのsectionsはHEADER（テーブルヘッダー）とLIST（項目詳細）の２要素とする。１章１シートという一般則より、この例外を優先する。項目詳細は８列の単一矩形表を維持し、ヘッダーはその上へ配置する。

Excelの例：A1:H1はタイトル、A3:B3にヘッダー項目、C3:H3に内容の見出し。A4以降はA:Bに項目名、C:Hに内容を記載（各領域内で結合可）。作成元MDのURLはヘッダー領域へ出典行として追記できる。ヘッダー終端から１行空けてA:Hへ項目詳細の８列を置く。明細のセル結合は禁止。フィルターは明細表だけ、明細見出しまで固定する。長さ・コード・初期値・論理/物理名は文字列、Noだけ数値としてよい。各表のシート名は物理テーブル名を既定とし、31文字・禁止文字・重複を検査する。テーブルごとに独立した表紙シートを作らない。

メタ情報table.fieldIdsには物理名と既存項目IDの対応だけを保持し、業務上の制約を隠さない。文字列の記法・式に見える値の保護はMD構造・Excel変換規約に従う。今回の正規化は文書構造の統一であり、業務データモデルの正規化・テーブル再設計ではない。

## 保持と評価

分冊化前後で論理/物理名・順序・PK・既定値・NULL・型容量・業務長・条件付き必須・FK・索引・制約を照合する。既存項目IDと評価IDは移送先に維持する。項目は属性一式１点、テーブルヘッダーは意味・キー・参照の一致で３点とする。索引の参照行は診断０点とし同じ項目を再加点しない。新旧の項目採点行を二重保持しない。反証・原仕様内の不一致は未確認事項として記録し、書式変更に合わせて無断で設計判断を追加しない。
