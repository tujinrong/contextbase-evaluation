# 業務Web画面実装ルール ― フォント・サイズ・部品・動作

版：1.0 / 日付：2026-10-29 / 工程：実装 / 規則ID：`I-*`

## 1. 実装の前提

**I-001 必須**：合意済みHTML設計書とプロジェクト設定を入力とする。デモHTMLのJavaScriptを、本番の認証・権限・DB保存処理として扱わない。

**I-002 必須**：画面ごとにデザインを作り直さず、共通レイアウト、部品、デザイントークンを使う。React、Vue、Blazor、Razor Pages等の違いは実装層で吸収する。特定のフレームワークやUIライブラリを標準の必須条件にしない。

**I-003 必須**：設計と異なる機能、項目、保存時期、権限、ページング方式を追加する場合、差分・理由・影響を記録する。既存修正の範囲がレイアウト限定なら、業務動作は変更しない。

## 2. フォント・文字サイズ【標準値】

以下は本標準の提案値。`rem`のpx換算はブラウザーの基本文字サイズが16pxの場合であり、固定保証値ではない。`rem`はルート要素の文字サイズを基準にする。[S1]

**I-010 必須**：`html { font-size: 100%; }`とし、利用者の文字サイズ設定を尊重する。基本文字サイズを10pxにするための62.5%指定や、ズームの禁止を標準にしない。

**I-011 標準**：日本語UIのフォントを次に統一する。

```css
font-family: "Noto Sans JP", "Yu Gothic UI", "Hiragino Sans", Meiryo, system-ui, sans-serif;
```

インストール状況により表示フォントは異なる。厳密な書体統一が必要な場合は、配信許諾・配信方式・読み込み失敗時の代替・文字幅を別途定義する。外部フォント配信を無断追加しない。本配布物にフォントファイルは含めない。

| 用途 | トークン／値 | 16px基準 | 太さ | 行高 |
|---|---|---:|---:|---:|
| 本文・入力値 | `--font-body: 1rem` | 16px | 400 | 1.6／入力は1.5 |
| 画面タイトル | `--font-title: 1.5rem` | 24px | 700 | 1.4 |
| セクション見出し | `--font-section: 1.125rem` | 18px | 600 | 1.5 |
| ラベル・ボタン・メニュー | `--font-ui: .875rem` | 14px | 500〜600 | 1.5 |
| 表の本文・ヘッダー | `--font-table: .875rem` | 14px | 400／600 | 1.5 |
| 補足・エラー・状態 | `--font-help: .875rem` | 14px | 400〜600 | 1.5 |
| 強調指標 | `--font-metric: 2rem` | 32px | 700 | 1.25 |

**I-012 必須**：重要な本文やエラーを14px相当未満にしない。長い文字の問題は折り返し、列幅、レイアウトで解決する。画面単位で勝手に本文を12pxに変更しない。

**I-013 必須**：ボタン・入力・選択欄にも明示的に同じフォント系列を適用する。ブラウザー初期値の違いを放置しない。コード／ID等の等幅が必要な部分のみモノスペースを使う。

## 3. 寸法・余白【標準値】

寸法は原則`rem`、境界線は`px`、文章やコードの幅は必要に応じて`ch`を使う。高さは固定ではなく**最小高さ**とし、拡大・折り返しで伸びるようにする。

| 対象 | normal | compact | touch |
|---|---:|---:|---:|
| 一行入力・select・通常ボタンの最小高さ | 40px相当 | 36px相当 | 44px相当 |
| 一覧行の目安となる最小高さ | 48px相当 | 40px相当 | 56px相当 |
| 表セル上下padding | 12px相当 | 8px相当 | 16px相当 |
| 表セル左右padding | 16px相当 | 12px相当 | 16px相当 |
| ページャーの操作対象 | 40×40px相当以上 | 36×36px相当以上 | 44×44px相当以上 |

| 対象 | 初期値 |
|---|---:|
| 基本余白系列 | 4、8、12、16、24、32、48px相当 |
| 入力ラベルと入力欄 | 4px相当 |
| 横に並ぶ関連操作 | 8px相当 |
| 項目間 | 16px相当 |
| セクション間 | 24px相当 |
| 通常ページ余白 | 24px相当。狭幅では16px相当 |
| パネル内側余白 | 24px相当。狭幅では16px相当 |
| ヘッダー最小高さ | 64px相当 |
| サイドメニュー幅 | 240px相当 |
| 一覧・集計の最大幅 | 1440px相当 |
| 標準編集フォームの最大幅 | 960px相当 |
| ログイン領域の最大幅 | 448px相当 |
| 入力・ボタン角丸 | 6px相当 |
| パネル角丸 | 8px相当 |
| 境界線 | 1px |
| textarea初期最小高さ | 112px相当。縦リサイズ可 |

**I-020 必須**：密度はページ／領域の明示設定で切り替える。同じツールバー内で36pxと44pxのボタンを意図なく混在させない。

**I-021 標準**：ボタン幅はラベル＋左右16px相当の余白。短い通常ボタンの最小幅は80px相当、アイコン専用は高さと同等の幅を確保。表内操作は別バリアントとする。全ボタンを固定幅にしない。

**I-022 必須**：数値入力・日付・短いコードは適正な上限幅を持ち、名称・説明は残余幅を使う。ただし狭幅では最大幅100%に制限する。入力上限と見た目の幅を混同しない。

## 4. 配色とアクセシビリティ

**I-030 標準**：白い本文領域、淡い中立色の背景、1系統の主要色を基本とする。枠・影・色の強調を一度に使いすぎない。選択状態はラベル、線、チェック等を併用する。

| 意味 | 初期値 |
|---|---|
| 本文 | `#182230` |
| 補助文字 | `#526171` |
| ページ背景 | `#F4F6F9` |
| 表・パネル | `#FFFFFF` |
| 主操作・リンク | `#1D4ED8` |
| 主操作hover | `#1E40AF` |
| 選択背景 | `#EFF6FF` |
| 入力欄の境界 | `#758295` |
| 装飾的な区切り | `#D6DDE7` |
| エラー | `#B42318` |
| 成功 | `#166534` |
| 警告 | `#854D0E` |

**I-031 必須**：通常文字4.5:1以上、大きな文字は規格上の条件を満たす場合3:1以上を確認する。[S2] 認識に必要なUI境界・状態表示等は、適用条件に従い隣接色との3:1以上を確認する。[S3] 薄い装飾線を唯一の入力欄識別手段にしない。

**I-032 必須**：キーボードフォーカスを視認可能にする。`outline: none`だけを指定しない。固定領域でフォーカス対象を隠さない。最低基準は「完全には隠れない」だが、本標準は可能な限り全体を見せる。[S4]

**I-033 必須**：WCAG 2.2の対象サイズ最低基準は24×24 CSS px、または定められた例外条件である。[S5] 本標準の40px／44pxは独自の操作性向上値であり、WCAGが一律40pxを要求するとは記載しない。小さなチェックボックスはラベル込みのクリック領域も評価する。

**I-034 必須**：キーボード操作、ラベル関連付け、適切な見出し、色以外の状態表現、エラーの読み上げ、動きの削減を実装する。これら一部の確認だけでWCAG全体へ適合済みと表明しない。

## 5. 共通レイアウトと部品

**I-040 必須**：サイト共通の構造を1つのレイアウト部品に集約する。

| 共通部品 | 責務 |
|---|---|
| AppShell / SiteNavigation | 共通ヘッダー、現在位置、サイトメニュー、利用者領域 |
| PageHeader / Breadcrumbs | ページ名、対象、主操作、階層 |
| FilterPanel | 入力中条件、検索、条件初期化、詳細検索 |
| DataTable / Pagination | 列、並び順、行操作、選択、件数、ページ移動 |
| FormField / FormSection | ラベル、説明、必須、入力、エラー |
| ActionBar / UnsavedGuard | 保存、戻る、未保存、送信中、離脱保護 |
| StatusBadge / EmptyState / ErrorState | 正常以外も含む一貫した状態表現 |
| Dialog / Drawer | 確認、簡易編集、フォーカス、閉じる |

**I-041 必須**：サイトメニューはリンクを使い、現在の機能を`aria-current`等で示す。ホバーだけのサブメニューを作らない。認証後ページに毎回「メニューへ戻る」ボタンを生成しない。

**I-042 必須**：HTMLの意味を使う。`header`、`nav`、`main`、`form`、`label`、`button`、`table`、`th`等を優先する。一般のサイトリンクに複雑なARIA menuロールを無条件に付けない。

**I-043 必須**：文字列のHTML挿入を安全に扱う。ラベル未設定のアイコン操作を作らない。ボタンの`type`を明示し、補助操作で意図せずフォームを送信させない。

## 6. 画面幅への対応

| ビューポート基準の初期境界 | サイト枠の標準動作 |
|---|---|
| 64rem以上（通常1024px以上） | 左サイトメニューを表示 |
| 48〜64rem未満 | サイトメニューを折りたたみ、本文を優先 |
| 48rem未満 | 1列中心、主操作の折り返し、16px相当の外周余白 |

**I-050 必須**：フォームの列数は「サイドメニューを除いた実際のコンテンツ幅」で判断する。初期値は内容幅45rem以上で2列、それ未満は1列。ビューポート幅だけを見て狭い詳細領域を2列にしない。

**I-051 必須**：Flex/Gridの子に必要な`min-width: 0`を設定し、長い文字に折り返しを定義する。`overflow-x: hidden`でレイアウト不良を隠して完了にしない。

**I-052 必須**：通常コンテンツは320 CSS px相当の幅でも情報・機能を失わずリフローさせる。2次元配置が本質的な表等は例外になり得るが、表の外まで横スクロールさせない。[S6]

**I-053 条件付き**：固定バーは高さを考慮した余白・スクロール位置を確保する。小さい高さ・拡大時は非固定へ切り替える選択肢を用意する。すべてを`position: fixed`にしない。

## 7. 検索・ページングの実装契約

**I-060 必須**：標準は`page=1`始まり、`pageSize=20`、選択肢20／50／100。並び順は安定する一意キーを第2キー等として加える。固定件数が小さい一覧の省略やカーソル方式は、設計で例外を定義する。

**I-061 必須**：データ量が増加する一覧はサーバー側で検索・並べ替え・ページングする。全件取得後に画面だけ20件へ切り分けることを標準にしない。静的な設計デモと本番を区別する。

```text
検索要求（例）: query, filters, sortKey, sortDirection, page, pageSize
番号方式応答: items, page, pageSize, totalCount
カーソル応答: items, nextCursor, previousCursor（提供可能時）, hasMore
```

**I-062 必須**：ページ番号・ページサイズ・並べ替えキーをサーバー側で検証する。許可上限を超えるページサイズや未許可列のソートを受理しない。

**I-063 必須**：入力中条件と適用済み条件を分離する。ページ移動は適用済み条件を使う。検索・並べ替え・件数変更では1ページ目へ戻す。検索要求が競合したとき、古い応答が新しい結果を上書きしないようにする。

**I-064 必須**：URL等へ復元可能な一覧状態を保持する。機密条件はURLへ入れず、認可されたセッション等で管理する。詳細から戻った際に条件・ページ・並び順を復元する。画面状態用の不透明IDだけに依存する場合は、期限切れ・直接表示・別タブの扱いを定義する。

**I-065 必須**：件数表示は取得結果と一致させる。0件では「0件」、不明では「総件数未取得」等とし、存在しない0〜20件表示を作らない。範囲は1始まりとする。

**I-066 必須**：ページャーを意味のあるナビゲーションにし、現在ページを示す。前後・番号リンクは復元可能なURLを持たせる。必要に応じて省略表示を使う。[S7] 端の無効操作を見た目だけ無効にしない。

**I-067 条件付き**：一括選択は安定したレコードIDで保持する。標準は現在ページ内。全検索結果を選ぶ場合は別の明示操作とし、実行時にも認可と対象を再確認する。

**I-068 条件付き**：出力・一括更新は、表示ページと対象範囲を分離する。大きな出力はジョブ化する。進捗・件数を仮の乱数や時間経過から生成しない。

## 8. フォーム・保存・遷移

**I-070 必須**：入力状態、元データ、保存中、保存済み、失敗、競合を分ける。ブラウザー側とサーバー側の両方で必要な入力検証を行う。未定義の必須条件は追加しない。

**I-071 必須**：保存前の追加・更新・削除を保存単位に応じて保持する。親子全体保存なら、現在編集中の子行を含めて検証・送信する。原子的な保存が要件ならサーバー側でも対応させる。

**I-072 必須**：二重送信対策、タイムアウト、再試行、並行編集を設計する。ボタン無効化だけで重複登録が防げると判断しない。サーバーで必要な冪等性・競合検出を確保する。

**I-073 必須**：未保存のアプリ内遷移を保護する。ブラウザーの閉じる・再読込に使う`beforeunload`は、独自文言を指定できない等の制約があり、特にモバイルでは発火が保証されない。変更があるときだけ登録し、それだけをデータ保全策にしない。[S8]

**I-074 条件付き**：下書き保存が必要なら保存先・期限・復旧・機密性を別途定義する。個人情報を無断でlocalStorage等へ保存しない。

**I-075 必須**：エラーはフォーム上部の要約と項目近傍で示し、値を保持する。エラー項目へ移動できるようにする。長文欄のEnterによる改行を壊さない。

## 9. 状態と操作の実装

**I-080 必須**：初期／取得中／正常／0件／通信失敗／権限なし／対象なしを区別する。読込中に空結果を一瞬表示しない。再試行で条件や入力を失わない。

**I-081 必須**：モーダルは開始時に内部へフォーカスを移し、内部でTab順を管理し、閉じたら起点へ戻す。Escや背景操作で意図せず入力を消さない。適切なタイトル・ロールを与える。[S9]

**I-082 条件付き**：本物のタブUIには選択状態、関連パネル、左右キー等の操作を実装する。[S10] ページ移動リンクをタブに見せる場合は、リンクとして扱い、タブ用ロールだけを追加しない。

**I-083 必須**：非同期処理の結果は適切に通知し、成功トーストだけを唯一の保存確認にしない。自動消去する通知へ重要なエラーを隠さない。

**I-084 必須**：ボタン非表示は権限制御の代わりにしない。対象IDを直接指定したAPIもサーバー側で認可する。エラーに内部秘密、トークン、個人情報を露出しない。

## 10. 実装完了の判定

| ID | 必須の確認 |
|---|---|
| I-Q01 | HTML設計と実装の画面ID・主操作・対象・配置が対応する |
| I-Q02 | computed styleでフォント、文字サイズ、部品寸法がトークンと一致する |
| I-Q03 | 1440、1280、1024、768、390、320 CSS px等の対象幅で重なり・切れ・不要な全体横スクロールがない |
| I-Q04 | 文字拡大200%、320 CSS px相当のリフロー、対象OS表示倍率を別々に検証する |
| I-Q05 | 0件、1件、19、20、21、57、1000件等で範囲・ページ数・端ページが正しい |
| I-Q06 | 条件変更、並べ替え、ページサイズ変更、削除後、詳細から戻る、直接URL、再読込が整合する |
| I-Q07 | 保存成功・失敗・競合、破棄、明細編集中の最終保存、二重送信を確認する |
| I-Q08 | キーボード、フォーカス、ラベル、ダイアログ、読み上げ、色のコントラストを確認する |
| I-Q09 | 権限、出力範囲、機密情報、並行要求、サーバー側検証を確認する |

ビルド成功、静的検査、ブラウザー操作、本番API試験を分ける。未実施は「未検証」と記録する。
