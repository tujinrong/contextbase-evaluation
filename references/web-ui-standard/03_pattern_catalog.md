# 業務Web画面パターンカタログ

版：1.0 / 日付：2026-10-29

## 適用方法

主パターンを1つ選び、必要な補助パターンを組み合わせる。P00は認証後サイトの共通枠、P23は部分領域にも使う。24パターンをすべて作る指示ではない。
各パターンには`01_design_rules.md`の設計仕様と`02_implementation_rules.md`の共通実装規約を適用する。

| ID | パターン | 主な用途 |
|---|---|---|
| `P00_APP_SHELL` | サイト共通構成 | 認証後の全ページ |
| `P01_HOME` | ホーム・業務入口 | 未処理業務や最近の活動を把握する |
| `P02_SEARCH_LIST` | 検索・一覧 | 条件に合う対象を探す |
| `P03_DETAIL` | 詳細参照 | 対象情報を読む |
| `P04_EDIT_FORM` | 新規・編集 | 対象を入力・更新する |
| `P05_MASTER_DETAIL` | 一覧＋詳細・親子明細 | 対象を切り替えながら詳細を編集する |
| `P06_EDITABLE_GRID` | 一覧内編集・一括修正 | 多数の同形式データをまとめて更新する |
| `P07_WIZARD` | 段階入力・申請作成 | 長い作業を順序立てて進める |
| `P08_APPROVAL` | 承認・レビュー | 申請等を判断する |
| `P09_DASHBOARD` | ダッシュボード | 業務状況の変化や異常を把握する |
| `P10_REPORT` | 集計・帳票照会 | 条件に基づく集計・帳票を確認する |
| `P11_IMPORT` | ファイル取込 | 外部データを検証して取り込む |
| `P12_EXPORT` | 出力・ダウンロード | 条件や選択対象をファイル化する |
| `P13_SETTINGS` | 設定・マスター管理 | 個人・組織等の設定を変更する |
| `P14_PERMISSIONS` | 利用者・権限管理 | 実行権限や所属を管理する |
| `P15_HISTORY` | 履歴・監査ログ | 誰がいつ何を変更したか確認する |
| `P16_CALENDAR` | 予定・予約・稼働 | 日時に紐づく業務を管理する |
| `P17_BOARD` | ステータス別ボード | 作業の状態を一覧し更新する |
| `P18_TREE_EXPLORER` | 階層・分類・エクスプローラー | 分類構造から対象を探す |
| `P19_FILES` | 添付・文書管理 | 文書を添付・確認・管理する |
| `P20_JOBS` | ジョブ・バッチ実行状況 | 長時間処理を追跡する |
| `P21_AUTH` | 認証・本人確認 | 利用開始・再認証を行う |
| `P22_SYSTEM_STATE` | システム状態・エラー | 通常業務を継続できない状態を説明する |
| `P23_DIALOG_DRAWER` | 確認・簡易入力・補助パネル | 主画面の文脈を保って小さな処理をする |

## P00_APP_SHELL：サイト共通構成

**用途**：認証後の全ページ。

**領域構成**：ヘッダー／サイトメニュー／現在位置／本文。

**主な操作**：機能へ移動、利用者メニュー。

**固有ルール**：独立メニュー画面への往復を前提にしない。現在位置を表示し、権限別の入口を整理する。

**設計する状態**：通常、狭幅、メニュー展開、権限差。

**受入条件**：どのページからも主要機能へ移動でき、狭幅でも本文を圧迫しない。

## P01_HOME：ホーム・業務入口

**用途**：未処理業務や最近の活動を把握する。

**領域構成**：要対応／最近利用／業務へのリンク。

**主な操作**：未処理対象を開く。

**固有ルール**：指標や入口には実務上の意味を持たせる。大きなメニューボタンだけを並べない。不要なら主一覧をホームにする。

**設計する状態**：通常、未処理なし、取得失敗。

**受入条件**：要対応項目から対象へ直接移動でき、情報の基準時点が分かる。

## P02_SEARCH_LIST：検索・一覧

**用途**：条件に合う対象を探す。

**領域構成**：タイトル・新規／検索／件数・表／ページャー。

**主な操作**：検索、新規、行の参照・編集。

**固有ルール**：単一行操作は直接リンクを基本とし、複数選択は必要時のみ。ページング、並び順、条件復元、出力範囲を定義する。

**設計する状態**：初期、取得中、通常、0件、失敗、端ページ。

**受入条件**：20件の境界を超えても範囲と総数が一致し、詳細から戻ると一覧状態が復元される。

## P03_DETAIL：詳細参照

**用途**：対象情報を読む。

**領域構成**：対象識別／要約／情報区分／関連情報。

**主な操作**：編集、関連情報へ移動。

**固有ルール**：読み取り情報は定義リストや表で表示し、無効な入力欄の羅列を避ける。更新日時・状態・識別子を示す。

**設計する状態**：通常、対象なし、権限なし。

**受入条件**：入力不可の情報でも確認・コピーができ、編集先の対象を取り違えない。

## P04_EDIT_FORM：新規・編集

**用途**：対象を入力・更新する。

**領域構成**：対象・モード／入力グループ／保存・戻る。

**主な操作**：保存、変更破棄。

**固有ルール**：1〜2列を基本とし、必須・形式・単位を明示する。保存単位と未保存離脱、検証エラー、競合を定義する。

**設計する状態**：未変更、変更あり、保存中、入力エラー、失敗、競合。

**受入条件**：保存失敗で値が消えず、保存・破棄後の再表示が契約と一致する。

## P05_MASTER_DETAIL：一覧＋詳細・親子明細

**用途**：対象を切り替えながら詳細を編集する。

**領域構成**：対象識別／一覧＋詳細／全体操作。

**主な操作**：対象切替、明細追加、変更、削除、保存。

**固有ルール**：幅比を固定せず双方の最小幅を確保する。明細選択と編集対象を一致させ、最終保存に編集中の値を含める。

**設計する状態**：未選択、選択、明細変更あり、保存失敗。

**受入条件**：別行選択で入力を失わず、削除対象と保存対象が明確。狭幅は上下配置または画面分離。

## P06_EDITABLE_GRID：一覧内編集・一括修正

**用途**：多数の同形式データをまとめて更新する。

**領域構成**：対象条件／編集表／検証・一括確定。

**主な操作**：セル編集、行追加、一括保存。

**固有ルール**：スプレッドシート同等操作を無断で増やさない。セルエラー、未保存行、部分成功、貼付範囲を定義する。

**設計する状態**：編集、検証エラー、部分成功、競合。

**受入条件**：行と列を特定してエラーを直せ、ページをまたぐ未保存が失われない。

## P07_WIZARD：段階入力・申請作成

**用途**：長い作業を順序立てて進める。

**領域構成**：手順表示／現在手順／戻る・次へ／最終確認。

**主な操作**：次へ、前へ、確定。

**固有ルール**：手順移動と保存を区別する。戻っても値を保持し、完了前の不可逆処理を避ける。

**設計する状態**：入力中、手順エラー、中断、最終確認。

**受入条件**：前の手順へ戻っても値が維持され、最終確定前に対象・内容を確認できる。

## P08_APPROVAL：承認・レビュー

**用途**：申請等を判断する。

**領域構成**：対象要約／内容・差分／履歴／判断領域。

**主な操作**：承認、差戻し、却下。

**固有ルール**：状態・実行権限・理由必須条件を業務定義する。承認を削除と同じ危険色に統一しない。最新状態を実行時に再確認する。

**設計する状態**：待ち、実行中、決定済み、競合。

**受入条件**：二重承認や権限外実行を防ぎ、誰がいつ何を判断したか追跡できる。

## P09_DASHBOARD：ダッシュボード

**用途**：業務状況の変化や異常を把握する。

**領域構成**：期間／要点指標／傾向／要対応。

**主な操作**：期間変更、詳細へ掘り下げ。

**固有ルール**：指標の定義・単位・基準時点を示す。全データが同じ時点でない場合は明記する。図には表や文章の代替を用意する。

**設計する状態**：通常、0、データなし、部分取得失敗。

**受入条件**：数値の意味を説明でき、0と未取得を区別できる。

## P10_REPORT：集計・帳票照会

**用途**：条件に基づく集計・帳票を確認する。

**領域構成**：条件／集計要約／表／出力。

**主な操作**：集計、出力、印刷。

**固有ルール**：表示条件と出力条件を一致させる。日付基準、通貨、丸め、集計単位を定義する。印刷レイアウトは操作画面と分ける。

**設計する状態**：集計中、0件、成功、失敗。

**受入条件**：総計と明細が整合し、出力範囲・条件が画面から確認できる。

## P11_IMPORT：ファイル取込

**用途**：外部データを検証して取り込む。

**領域構成**：形式説明／ファイル選択／検証結果／実行。

**主な操作**：選択、検証、取込。

**固有ルール**：選択・検証・実確定を区別する。文字コード、サイズ、重複、エラー行、部分成功、再実行を定義する。

**設計する状態**：未選択、検証中、エラー、実行中、完了。

**受入条件**：検証だけでは本番データが変わらず、失敗行と修正方法を特定できる。

## P12_EXPORT：出力・ダウンロード

**用途**：条件や選択対象をファイル化する。

**領域構成**：対象範囲／形式／実行／結果。

**主な操作**：出力予約、取得。

**固有ルール**：現在ページと検索全件を区別する。大きな処理はジョブ化し、取得期限・機密性・権限・再実行を定義する。

**設計する状態**：準備、実行中、生成済、期限切れ、失敗。

**受入条件**：画面に表示した対象範囲と実際の出力対象が一致する。

## P13_SETTINGS：設定・マスター管理

**用途**：個人・組織等の設定を変更する。

**領域構成**：適用範囲／分類別設定／保存。

**主な操作**：保存、初期値へ戻す。

**固有ルール**：個人設定と全体設定を区別する。即時反映、保存後、再起動後の違いを示し、変更破棄と初期値復元を分ける。

**設計する状態**：通常、変更あり、反映待ち、失敗。

**受入条件**：対象範囲と反映時点が明確で、無関係な設定を上書きしない。

## P14_PERMISSIONS：利用者・権限管理

**用途**：実行権限や所属を管理する。

**領域構成**：対象／ロール・権限／影響／確定。

**主な操作**：権限変更、利用停止。

**固有ルール**：変更の影響を表示し、最後の管理者の喪失等の制約を業務定義する。権限の非表示だけで認可を済ませない。

**設計する状態**：権限不足、変更、影響確認、競合。

**受入条件**：対象外の操作がAPIでも拒否され、変更の監査履歴が残る。

## P15_HISTORY：履歴・監査ログ

**用途**：誰がいつ何を変更したか確認する。

**領域構成**：期間・対象条件／時系列／差分。

**主な操作**：検索、変更差分の参照。

**固有ルール**：タイムゾーン、操作主体、対象、結果を示す。履歴の編集・削除を通常操作として出さず、機密情報を制御する。

**設計する状態**：通常、0件、取得不可。

**受入条件**：履歴と現在状態を混同せず、日時と対象が明確。

## P16_CALENDAR：予定・予約・稼働

**用途**：日時に紐づく業務を管理する。

**領域構成**：期間・表示切替／予定／詳細。

**主な操作**：期間移動、作成、変更。

**固有ルール**：月・週・一覧等の必要表示を選ぶ。重複、終日、タイムゾーン、変更確認を定義し、ドラッグだけに依存しない。

**設計する状態**：空、重複、変更中、権限差。

**受入条件**：ドラッグなしでも予定を確認・変更でき、狭幅では一覧へ切り替えられる。

## P17_BOARD：ステータス別ボード

**用途**：作業の状態を一覧し更新する。

**領域構成**：絞込／状態列／カード／詳細。

**主な操作**：開く、状態変更。

**固有ルール**：大量カードの取得範囲を決め、状態遷移の権限を検証する。移動先を選べるボタンを併設する。

**設計する状態**：空列、移動中、遷移不可、競合。

**受入条件**：ドラッグ操作なしで同等の状態変更ができ、失敗時に元へ戻る。

## P18_TREE_EXPLORER：階層・分類・エクスプローラー

**用途**：分類構造から対象を探す。

**領域構成**：階層／一覧または詳細／階層操作。

**主な操作**：展開、選択、移動。

**固有ルール**：パンくずと選択を一致させる。子要素取得中、循環参照、移動権限を考慮する。狭幅は階層を段階表示する。

**設計する状態**：未展開、取得中、空、選択、失敗。

**受入条件**：深い階層でも現在位置と親に戻る方法が分かる。

## P19_FILES：添付・文書管理

**用途**：文書を添付・確認・管理する。

**領域構成**：対象／ファイル一覧／アップロード／詳細。

**主な操作**：追加、プレビュー、取得、削除。

**固有ルール**：種類、容量、版、公開範囲、検査待ち、削除を定義する。アップロード完了と業務データ保存完了を混同しない。

**設計する状態**：送信中、検査待ち、利用可、拒否、失敗。

**受入条件**：危険なファイルをそのまま実行せず、対象と共有範囲が分かる。

## P20_JOBS：ジョブ・バッチ実行状況

**用途**：長時間処理を追跡する。

**領域構成**：処理一覧／状態／詳細／結果。

**主な操作**：開始、結果参照、再試行、取消可能時の取消。

**固有ルール**：不明な進捗率は表示しない。受付・待機・実行・完了・失敗・取消を区別し、再実行の重複を防ぐ。

**設計する状態**：待機、実行、完了、失敗、取消。

**受入条件**：画面を離れて戻っても状態を復元でき、部分成功を全件成功として扱わない。

## P21_AUTH：認証・本人確認

**用途**：利用開始・再認証を行う。

**領域構成**：サービス名／認証／補助導線。

**主な操作**：ログイン、再認証。

**固有ルール**：共通業務メニューの例外とする。パスワード貼付・管理ツールを不要に妨げず、失敗・期限切れ・復帰先を定義する。

**設計する状態**：初期、送信、失敗、期限切れ。

**受入条件**：秘密を漏らさず、再認証後の復帰先と入力保護が定義されている。

## P22_SYSTEM_STATE：システム状態・エラー

**用途**：通常業務を継続できない状態を説明する。

**領域構成**：状態見出し／理由／次の操作／参照ID。

**主な操作**：再試行、戻る、再認証。

**固有ルール**：403、404、通信失敗、保守等を区別する。スタックトレースや秘密を表示しない。再試行で入力を消さない。

**設計する状態**：権限なし、対象なし、障害、保守。

**受入条件**：原因の範囲と次の操作が分かり、サポートへの照会情報がある。

## P23_DIALOG_DRAWER：確認・簡易入力・補助パネル

**用途**：主画面の文脈を保って小さな処理をする。

**領域構成**：タイトル・対象／内容／確定・閉じる。

**主な操作**：確認、簡易保存、閉じる。

**固有ルール**：モーダルは一つの目的に限定する。多段モーダルを避け、複雑な編集はページ化する。ドロワーのモーダル性を定義する。

**設計する状態**：表示、入力エラー、実行中。

**受入条件**：フォーカス、Esc、閉じた後の復帰と未保存保護が設計どおり。

## 組み合わせ例

| 業務の型 | パターンの組み合わせ |
|---|---|
| 一般的な台帳 | P00＋P02＋P03＋P04＋P15 |
| 親子伝票 | P00＋P02＋P05。大量の行編集が必要ならP06 |
| 申請・承認 | P00＋P07＋P08＋P15＋P19 |
| 定期取込・出力 | P00＋P11＋P12＋P20 |
| 運用・設定 | P00＋P09＋P13＋P14＋P15 |
| 予約・作業管理 | P00＋P16またはP17＋P03＋P04 |

## 新しいパターンの追加書式

既存パターンの組み合わせで足りない場合だけ、`PX-001`等を追加する。

```yaml
pattern_id: PX-001
name: 新しいパターン名
purpose: 利用者が何を達成するか
use_when: 適用条件
avoid_when: 適用しない条件
inherits: [P00_APP_SHELL]
regions: []
primary_actions: []
state_model: []
selection_contract: null
save_contract: null
pagination_contract: null
responsive_behavior: {}
accessibility_requirements: []
acceptance_tests: []
exceptions_to_common_rules: []
```

共通部品の変更で解決できる問題を、新しい画面パターンで隠さない。新パターンの追加で既存プロジェクトの動作を黙って変えない。
