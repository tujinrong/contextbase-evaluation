# 提示画面のレビューと汎用ルールへの変換

対象：提示されたWebの登録・検索・メニューの3画像。レビュー日：2026-10-29。
画像から確認した配置と、実機確認が必要な動作を分ける。コード、API、保存結果は未確認。
特定の業務項目は本標準の必須項目にしない。

| 観察できること | 問題・改善方向 | 汎用化した規則 |
|---|---|---|
| 独立メニュー画面に大きな遷移ボタンが並ぶ | 操作のたびにメニュー画面を経由しない共通サイトメニューへ変更 | D-010〜013、P00 |
| 一覧では行選択と上部の編集操作が分かれる | 単一対象の参照・編集は行リンクを基本とする。一括操作が必要ならチェック選択を追加 | D-014、D-030 |
| 5件の画像にはページャーが見えない | 大量データ時の動作は未確認。総件数、表示範囲、20／50／100件、条件保持を仕様化 | D-031〜037、I-060〜068 |
| 経歴編集に「明細へ反映」と全体保存がある | 二段階確定の意味を仕様で明確化。押し忘れを黙って無視しない | D-041〜044 |
| 登録画面で編集対象の番号・氏名が見当たらない | 新規／編集のモードと対象識別情報を共通ヘッダーへ | D-040、P03・P04 |
| 入力欄が複数列に分かれ、関連情報が離れる | 項目グループとコンテンツ幅で1〜2列を選ぶ | D-021〜024、I-050 |
| 文字・行・操作が比較的大きく、一覧の表示効率に調整余地がある | 単純に小さくせず、normal／compact／touchの共通密度を選ぶ | I-010〜022 |
| 見出し・タブ・表等の枠とボタンが多い | 見出しと余白で階層を作り、主操作を一つに絞る | D-020〜022、I-030 |
| 「01 在職」「02 リーダー」等のコード付き表示がある | コードが業務上必要か確認し、不要なら表示名称を優先 | 項目仕様D-050。コード除去を一律強制しない |
| 保存、取消、再読込が並んでいる | 未保存時の離脱・再読込、入力保持を実機確認する | D-043〜044、I-073 |

## 画像だけでは判定しない事項

ページングの実装有無、保存・破棄の正しさ、レスポンシブ、フォントの実際のCSS値、ブラウザーの戻る、認可、読み上げ、キーボード操作。
画面にない状態を「未実装」と断定しない。スクリーンショットのピクセル値からCSS pxやブラウザー倍率を確定しない。

## 今回の優先順位

1. サイト共通構成と画面パターンを決定する。
2. HTMLで一覧・編集・明細の配置と状態を可視化する。
3. 保存と明細確定、ページングと出力対象を明文化する。
4. 共通フォント・サイズ・部品を適用し、実装と実機検証を行う。

本レビューは見た目をWeb風に装飾することではなく、サイト全体の移動、対象操作、状態復元をWebの構成として再設計するための入力である。
