# relationship — 関係構築

版1.4／2026-10-26。v2の3抽出層の実装契約。step --stage relationshipで抽出し、verifyが別task・文脈で独立検証する。

共通条件の正本は [AGENT.md](../../AGENT.md)、論理手順は [PROMPT.md](../../PROMPT.md)。入力権限、原文保持、版、配置、独立検証、採用、取消・再開は共通契約を使い、本書へ機構を複製しない。

物理requestはcontextbase-analysis/2。今回の義務id／question／stage／scope／requiresをホストが割り当て、検証済みの同scope前提だけを利用する。出力recordには唯一のownerRequirementと依存keyを記録し、ホストが依存の内容版を固定する。未知の関連先・阻害先・範囲理由を分け、非阻害も独立検証へ渡す。

## 入力と担当範囲

元目標・質問、当該領域の検証済み目録と基準版、封印原文、利用可能な構造索引・能力、検証条件、作業領域を受け取る。前提不足は目録化へ根拠付き質問を返す。

業務機能・入口・実装・データ・共通・外部対象の関係を構築する。関係を判断するための条件、引数、値の引渡しも読んでよい。動作記述を禁止する分離ではなく、接続の確かさと適用範囲を主な成果とする。

## 手順と引渡し条件

1. 目標に必要な対象と前提目録の有効性を確認する。全リポジトリの目録完了を待たず、該当領域の不足だけを返す。
2. 共有アダプターとSourceAccessを随時使い、定義・参照、呼出点、登録、データ利用、外部接続を原文から追う。
3. 始点・終点または候補集合、方向、条件、引数の対応、適用範囲、導出方法、根拠を記録する。構文上の呼出、束縛済み、規則推定、未解決を区別し、同名だけで接続しない。
4. 逆参照や登録点から漏れを点検する。各必要関係について確認候補か、未解決理由と具体的な次の質問を提示できれば独立検証へ引き渡す。閉じたグラフを作るために曖昧さを埋めない。

## 出力・上下層補査・権限

根拠付き関係候補、適用条件、依存、未解決、被覆、追加調査要求を作業領域へ提出する。新対象・分類不足はdiscoveryへ返し、動作に関する課題はbehaviorへ引き渡す。behaviorからの不明関係は該当箇所を再調査する。

独立検証とホスト採用を経た該当関係をbehaviorの前提にする。関係だけで目標を満たせばそこで止める。変更した目録・関係の依存先を示し、旧検証の有効性をホストが確認できるようにする。正本更新・自己受入れは行わない。

修訂時はホストがreviseで採用済み義務と依存下流を撤回し、必要に応じstep --feedbackで原文を再調査する。runが未定義の補査やscope拡大を自動実行するとは扱わない。旧v1や旧役割値は自動変換しない。
