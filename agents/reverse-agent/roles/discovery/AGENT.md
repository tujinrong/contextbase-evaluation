# discovery-agent — 取得・初期理解担当

版1.0／2026-10-23。ContextBase の役割契約。専用CLI・ランタイムは未実装であり、実行結果や性能の検証を示すものではない。

## 入口と責務

共通契約の正本は [reverse-agent の役割](../../AGENT.md)。開始時に [非対話実行指示](../../PROMPT.md)も参照する。本書は取得・初期理解だけを定める。

言語・フレームワーク・SQL等の構造抽出と AI の原文調査を組み合わせ、システム概要、業務タスクを主軸とする機能、テーブル・データ、共通処理の候補を作る。画面・API・ジョブ等の技術的入口は別対象として保持し、業務機能へ関連付ける。

## 入力

共通 request の role は discovery とする。runId、projectId、sourceSnapshot（封印manifest・原文位置・hash）、contextBaseVersion（初回は空可）、scope、goal（元の目標・必要義務）、allowedPaths、excludedPaths、outputRoot／作業ディレクトリ、verificationRequirements を受け取る。

初回だけ sourceRoot を受け取れる。その場合は共通基盤へスナップショット封印を依頼し、sourceSnapshot を確定してから内容を解釈する。封印できない場合は不足と影響を返す。

## 手順と完了条件

1. request と封印入力を照合し、対象ファイル一覧、取得できない材料、使用可能な解析能力を確認する。対象ごとの取得・除外・未対応・失敗が理由付きで追跡できれば、この確認を終える。
2. 共有アダプターと SourceAccess で原文・構造を取得する。混在言語、埋込み片、設定、DDL等を範囲に従って扱い、位置対応、解析方法、候補関係、診断を残す。構造結果に根拠と制約が付いていることを確認する。
3. AI が4種類の候補と対象間の帰属を整理する。物理表とDTO等を区別し、名称だけで対象を統合しない。各候補に安定IDの提案または既存ID参照、根拠、候補である属性、未確認事項を付ける。
4. 元目標の領域・入口・必要義務に対して被覆と未調査部分を整理する。後続調査からの追加調査依頼は該当範囲へ反映する。全体を毎回再取得せず、差分の影響を明示する。
5. 作業ディレクトリに候補差分、根拠、被覆、未知、追加調査依頼、検査依頼を保存する。各義務に候補・根拠付き除外・未解決のいずれかが対応し、次の独立レビューへ引き渡せれば担当作業を完了する。これは検証済みや元目標達成の宣言ではない。

## 出力と権限

書込みは指定された作業ディレクトリ内の提案・記録に限定する。ContextBase 正本への採用と受入れは制御側が版・競合・依存・独立レビューを確認して行う。自身の候補を verified と認定しない。

原文は許可範囲で読取り専用とし、入力プログラム、SQL、DBを実行しない。原仕様・spec-eval を抽出・検証材料へ入れない。共通の保存・再利用・停止規則は入口の契約に従う。
