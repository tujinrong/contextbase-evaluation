# behavior — 動作深化

版1.4／2026-10-26。v2の3抽出層の実装契約。step --stage behaviorで抽出し、verifyが別task・文脈で独立検証する。

共通条件の正本は [AGENT.md](../../AGENT.md)、論理手順は [PROMPT.md](../../PROMPT.md)。入力権限、原文保持、版、配置、独立検証、採用、取消・再開は共通契約を使い、本書へ機構を複製しない。

物理requestはcontextbase-analysis/2。今回の義務id／question／stage／scope／requiresをホストが割り当て、検証済みの同scope前提だけを利用する。出力recordには唯一のownerRequirementと依存keyを記録し、ホストが依存の内容版を固定する。未知の関連先・阻害先・範囲理由を分け、非阻害も独立検証へ渡す。

## 入力と担当範囲

元目標の具体的質問・必要義務、当該領域の検証済み目録・必要関係、基準版、封印原文、能力・制約、検証条件、作業領域を受け取る。未確認の関係を動作の既知前提へ変換しない。

どの条件で、どの値・状態を使い、どの順序で何が起きるかを深化する。正常・異常、取消、権限、既定値、変換、状態変化、副作用、トランザクション、呼出元の差異を、元目標に必要な範囲で扱う。

## 手順と引渡し条件

1. 必要関係と根拠・検証の有効性を確認する。不足箇所はrelationshipへ戻し、確認可能な部分と未確認前提を分ける。
2. 共有アダプターとSourceAccessで原文を追加取得し、条件、値の由来・変換、分岐、順序、例外、結果を追う。後続層での構造・関係補査を禁止しない。
3. 共通動作と呼出元の引数・既定・権限・副作用の違いを区別する。結論ごとに前提、適用範囲、依存関係と原文根拠を付ける。
4. 各必要義務について動作候補、根拠付き非該当、未解決と次の質問を整理し、独立検証へ渡す。読み直しや要約の反復だけを深化・完了としない。

## 出力・上流補査・権限

事実・動作関係の候補差分、根拠状態、呼出差、被覆、未知、追加調査要求、変更影響を作業領域へ提出する。新対象はdiscoveryへ、不明・誤った関係はrelationshipへ返す。上流変更で前提が失効した結論は有効と表示しない。

共通の独立検証は別task・文脈で原文の反例と漏れを探す。修訂後は該当版を再検証し、ホストが元目標の受入れを判断する。未達義務は部分成果として残し、対象外への変更や未知の削除で完了にしない。正本・受入状態を直接変更しない。

修訂時はホストがreviseで採用済み義務と依存下流を撤回し、必要に応じstep --feedbackで原文を再調査する。runが未定義の補査やscope拡大を自動実行するとは扱わない。旧v1や旧役割値は自動変換しない。
