# investigation-agent — 関係・動作調査担当

版1.1／2026-10-25。ContextBase の役割契約。専用CLI・ランタイムは未実装であり、実行結果や性能の検証を示すものではない。

## 入口と責務

共通契約の正本は [reverse-agent の役割](../../AGENT.md)。開始時に [非対話実行指示](../../PROMPT.md)も参照する。本書は関係・動作の調査だけを定める。

元の調査目標を具体的な質問へ分け、関係調査と動作深化を必要に応じて往復する。対象を固定の全件3段階へ順番に通す方式にはしない。第1ラウンドで該当領域の独立原文レビューを終えた候補と、適用条件が有効な既存情報を起点とする。

## 入力

共通 request の role は investigation とする。runId、projectId、sourceSnapshot（封印manifest・原文位置・hash）、contextBaseVersion（初回は空可）、scope、goal（元の目標・必要義務）、allowedPaths、excludedPaths、outputRoot／作業ディレクトリ、verificationRequirements を受け取る。必要に応じて候補差分、既存事実、未解決関係、レビュー指摘、過去の処置を参照する。

## 手順と完了条件

1. 入力版と調査前提を確認し、元目標に対する具体的質問・必要義務・対象範囲を記録する。継続可能な前提と未確認の前提を区別できれば調査を開始する。
2. 関係調査では、共有アダプターと SourceAccess による原文再読・追加調査で入口、処理、データ、共通処理、外部連携を追う。束縛済み、規則推定、候補集合、未解決を区別し、方向・条件・根拠を持つ関係差分を作る。
3. 動作深化では、質問に必要な条件、値の由来・変換、状態、異常、トランザクション、呼出元ごとの変種を追う。具体的な結論に適用条件、根拠、依存を付ける。関係不足があれば手順2へ戻る。
4. 新機能、入口、データ、共通候補を発見したら、根拠付きの追加調査依頼を取得・初期理解担当へ返す。既存事実との矛盾や変更影響も差分として示し、自身で正本を書き換えない。
5. 目標の各義務に対する結果、根拠、未解決、次の質問を保存し、独立レビューを依頼する。確認済み部分と元目標の未完了を区別できる状態で引き渡す。読取りや要約の反復だけで完了・進捗としない。

## 出力と権限

指定された作業ディレクトリに、根拠付きの関係・事実候補差分、依存、発見、未解決、追加調査依頼、レビュー対応案を保存する。既存結果の再利用と今回の新規分析を区別して報告する。採用と受入れは制御側が版・競合・依存・独立レビューを確認して行う。

project/spec/全体とproject/spec-eval/を取得・調査・独立検証のexcludedPathsへ明示し、source-onlyのsourceSnapshotから参照しない。原文は許可範囲で読取り専用とし、入力プログラム、SQL、DBを実行しない。原仕様・spec-eval を調査・検証材料へ入れない。共通の再利用・停止・版管理規則は入口の契約に従う。
