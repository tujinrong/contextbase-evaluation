# reverse-agent の役割

版7.2／2026-10-13。AI工程の契約。業務アプリと実DBの実行試験を意味しない。

## 役割と入力

選択したprojectIdのソース、DDL、ビュー、CSS、設定から、根拠付きの仕様書をAIが解析・執筆する。[全体規則](../../../../docs/仕様書作成ルール.md)、[実行範囲と運用規則](OPERATING-RULES-20261023-before-split.md)、[非対話実行指示](PROMPT-20261023-before-split.md)を併せて使用する。全体Agent一覧が参照する本ファイルを役割定義の入口とする。

実行ID、projectId、方式、入力版とハッシュ、許可・除外パス、工程、出力先、期限を固定する。通常はsource-onlyとする。ユーザーが明示許可した訓練の参考設計はtraining-assistedとして別区分で保存し、設計意図と観測した実装を区別する。評価期待値は生成者へ渡さない。原本のプログラム、SQL、スクリプトを実行しない。

## 工程と分担

新しい解析は `python -m contextbase.ai` を使用する。原文snapshotの収集後、AIが機能境界と文書計画を決め、依存先を追跡してfactsと根拠位置を記録し、AIが仕様書本文を執筆する。別のAIプロセスが原文と原稿を比較する。機械処理は収集、範囲・ハッシュ・形式検査、記録、保存、描画を担当し、業務判断や仕様本文を組み立てない。特定の画面、項目、条件、値を共通プログラムの正解へ固定しない。

原稿、解析、計画、未加工応答、使用プロンプト、schema、実行ログ、失敗を保存する。関連文書はAIが作成した固定済み計画のID・path・責務と対応させる。未生成の参照先を生成済みと扱わない。

本文と原文を読むレビュー、Markdown構造検査、描画検査、原画面材料と描画画像の視覚比較、評価者による意味採点を区別する。テキストレビューの承認やPNG生成成功を視覚的一致や正式合格へ読み替えない。視覚レビューは実際に閲覧した画像と対象原稿のハッシュを記録する。

## 改訂と完了

修正時は新しい反復IDで原ソースを再解析し、AIが再執筆する。前稿と原文根拠付きの批評を改訂材料とし、採点期待値を移送しない。中断した執筆を再開する場合だけ、同一入力・計画・未加工解析応答の検証済みcheckpointを明示的に使用できる。解析再利用を新規解析の実績へ数えない。

生成者へ渡す批評もAIがJSON本体として直接執筆・保存する。Pythonのbuilderへ業務文言・条件を埋めず、機械処理はschema、文書ID、許可材料、根拠範囲、ハッシュの検査と保存を行う。新しい批評のclassificationは汎用実行契約の `GENERATION_SAFE_SOURCE_BACKED_FEEDBACK`、対象IDは `reviewDocumentId` とする。期待セル・採点値・評価行IDを含めず、参考設計の根拠もユーザーが許可した材料に限定する。

入力の名称だけを変更するために、受理するclassificationを無制限に拡張しない。メタデータの整合が必要なら、旧bytesと新しい版・変更理由を別に保存し、業務文言と他のフィールドが変わっていないことを検査する。独立した原文照合を終えるまで生成者入力として受理しない。参考設計の具体的な表示・入出力・確認責務を、実装との差の否定文や未実施の注意だけで代替しない。

今回使用した入力・出力の版、ファイル、検査範囲、結果、保留、未実施を報告する。原本不変を検査し、過去の合格や旧稿の点数を新稿へ流用しない。期限切れや未解決を完了・合格へ丸めず、途中成果物と失敗の証跡を残す。従来の機械解析経路の説明と実績は[README](README-20261023-before-split.md)で区別する。
