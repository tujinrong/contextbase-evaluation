# 外部仕様・画面配置の復元とPilot

## 方針

基本設計書は、利用者の入力・表示、操作順、確認、結果、失敗・取消、ファイルの入出力、データの業務上の関係を定義する。コード、関数呼出し、SQL、転送用オブジェクト、ソース行の列挙は検証資料へ分離する。

汎用の文書・画面描画は `src/contextbase/external_spec.py`、状態ごとのブラウザー幾何検査は `src/contextbase/external_browser.py`。行・列比率、グループ、項目、一覧幅、表示状態からなる言語非依存の木を入力とする。対象のクラス名や業務辞書を汎用側に置かない。

今回の適用対象は社員マスタ。対象依存のVue解釈、論理名と項目仕様、15操作の外部契約、原本ハッシュは `src-dynamic/mcterp/mcterpgen/employee_*` に置く。他88機能へ社員の規則を流用しない。別言語には同じ中立契約を出す解析アダプターを追加し、対象原本と独立照合してから適用する。あらゆる言語・画面方式の自動完全復元を意味しない。

## 画面

単純な全項目2列への再配置をやめ、原本の行・列・入れ子・見出し・タブ・固定列幅・条件表示を保持する。画面幅を文書の幅に合わせて勝手に縮小せず、文書内の画面枠をスクロールする。候補値と動的列は設定が未取得なら未確定として示す。実データやソース内の固定個人値は表示例に使わない。

HTMLはMDに埋め込み、docsiteで文書全体を変換する。状態別HTMLをブラウザーで描画し、画面幅、列比率、同行の位置、可視項目、ページ外へのはみ出しを検査する。これは生成HTMLの構造・配置検査で、稼働アプリの画面とのピクセル同一性や実APIの動作比較ではない。

## 項目とイベント

入力部品のmaxlengthと、業務上の有効値の長さ・桁数を区別する。表示項目に必須入力を要求せず、ボタンへDB列の対応を付けない。外部仕様の固定項目数と、動的設定による項目数、解析器が列挙する全コンポーネント件数を分ける。

イベントは契機・前提、入力、出力・反映先、利用者から見える順序、取消・異常、データ例を必須とする。内部の定義順を実行順として説明しない。観測された不整合を仕様として隠さず、外部への影響と確認事項を明示する。

## 再実行

```bash
python -m contextbase rebuild --replace-output --browser
python -m contextbase.external_browser
```

必要な原本がない、レビュー対象の原本が変わった、未知の条件式がある場合は停止し、古い業務説明の流用や未知条件の省略を防止する。固定ハッシュは顧客承認や署名ではなく、レビュー時点との対応確認である。
