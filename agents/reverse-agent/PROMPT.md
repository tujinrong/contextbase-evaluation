# reverse-agent 実行指示

版1.0／2026-10-23。ContextBase の取得・調査・独立検証を依頼するための文書契約。新しい自動 dispatch・採用・復元の専用 CLI は未実装であり、以下はコマンド例ではない。

## 依頼の指定

[共通契約](AGENT.md)の request を使い、runId、projectId、scope、goal、allowedPaths／excludedPaths、outputRoot、verificationRequirements を指定する。取得済みなら sourceSnapshot と contextBaseVersion を渡す。初回 discovery は sourceRoot と ContextBase 未作成を明示できる。role は単独指定、または統一入口による選択とする。

例：対象機能の一覧だけを確認する、特定テーブルの利用機能を調べる、登録処理の保存値と失敗状態を追う。要求ごとに必要事項を決め、固定の情報量3段階を指定したものと解釈しない。

## 進め方

1. 対象・入力版・権限・出力先を確認する。目標が明確な部分を具体化し、実質的な不明点は未解決へ残す。対象や権限を決められない部分は調査を開始しない。
2. role を選び、その契約だけを追加で読む。

   | 条件 | 使用する契約 |
   | --- | --- |
   | 初回の取得、業務候補、新対象の追加 | [discovery-agent](roles/discovery/AGENT.md) |
   | 既知対象の関係・条件・値・状態・異常を調べる | [investigation-agent](roles/investigation/AGENT.md) |
   | 候補や目標範囲を原文から独立に確認する | [review-agent](roles/review/AGENT.md) |

3. 役割は固定した入力と目標を使い、作業領域へ根拠付き候補差分または指摘を保存する。全件の再読取りや3役割の常時直列実行を前提にしない。初期目録は領域別の独立検証を経てから深化する。
4. 共通制御が版・競合・依存・根拠・必須検査を確認し、作者とは別文脈の独立検証と指摘処置を結ぶ。指摘に応じて取得または調査へ戻り、変更後の内容版を確認する。
5. 共通制御が候補採用と範囲受入れを別々に判断する。必要事項が残れば、既知の成果を返しつつ元目標を未完了とする。単独 review 依頼の完了は検証結果の提出までであり、正本の書換えや目標全体の合格を含めない。
6. 入出力・契約・根拠の版、調査範囲、使用能力、採用・検証・未実施、停止理由と再開条件を報告する。新規分析、再利用、checkpoint 復元を区別する。

各手順の完了は、対応する契約の完了条件と記録によって確認する。手動進行では主担当者が共通制御の確認を担当し、未実装の機械検査を実施済みとしない。

## 旧経路の選択

現存する文書単位の AI 執筆や機械変換を明示的に依頼された場合だけ、[旧仕様書生成経路](docs/legacy/README.md)を参照する。過去の訓練案件・期限・参考設計の許可を新しい依頼へ持ち越さない。旧 CLI を新しい3役割の自動実行入口として起動しない。
