# reverse-agent 作業規則

版8.5／2026-10-26。新設計の3子Agentは取得・目録化、関係構築、動作深化。独立検証は共通実行能力とする。v2の層分離・独立検証・ready queue・明示修訂を実装した。任意の自動補査修復、長期運用、cross-session P6再利用は未完了である。

## 入口と書込み範囲

- 共通の役割・入力・採用条件は [AGENT.md](AGENT.md)、実行要求は [PROMPT.md](PROMPT.md) を読む。指定した抽出層だけを `roles/` の契約で補う。独立検証は共通契約に従い、層ごとの自己検査へ置換しない。
- Agent 改善の書込みは `agents/reverse-agent/` 配下に限定する。入力・正式な ContextBase・QA・既存成果物の変更は、その実行要求で対象と範囲を確定する。
- 実装や実解析の指示がない段階では文書更新までとする。実装の有無と実行・受入れの実績を分ける。操作手順は [初期実装ガイド](docs/ContextBase初期実装.md)を使い、旧文書CLIへ流さない。

## 原文と既存資産

- 選択 projectId の許可されたソース、DDL、画面資源、設定を読み取り、snapshot と内容 hash に固定する。入力のコード、SQL、ビルド task、plugin を実行しない。
- 新しい ContextBase 経路は source-only とする。原仕様と spec-eval は生成・独立検証の入力から除外する。実行権限・入力選択ではproject/spec/全体とproject/spec-eval/を禁止し、選択する --source の外へ物理的に隔離する。--source はsourceRoot=project/srcs/方式ID/または隔離したsource-only入力に限定し、projectルートへ広げない。CLIのallowedPaths／excludedPathsは --source 内の相対パスだけを指定する別の層であり、兄弟のproject/specを列挙したり ../ で根の外を参照したりしない。過去の参考設計・訓練許可を現在の許可へ継承しない。
- `input/` の変更・削除を行わず、既存 `src-dynamic/` を無関係な変更で壊さない。`tujinrong/source-to-doc-v2` は参照専用とし、変更や外部投稿をしない。
- ContextBase の正本、identities.json、人が記入した QA・回答・状態、正式な最終outputと今回の最終検査記録を固定先へ更新し、過去生成世代はGitで管理する。新規候補は承認済み作業領域へ分離し、役割から正本を直接上書きしない。

## 調査と検証

- 根拠・候補・推定・未知・未調査を区別する。情報不足を不存在に変換せず、根拠のない値、DB 物理名、成功、顧客承認を補わない。
- QA は既存台帳と回答を保持し、矛盾や不足を新しい確認事項として関連付ける。自由記述や過去の採用を自動でソース観測事実へ変換しない。
- 共通の独立検証は作者とは別task・文脈で原文を直接確認し、作成側の一覧だけに検査範囲を閉じない。候補採用と範囲受入れは共通制御の記録で判断する。manual／injected の結果を採用可能な実モデル結果へ読み替えない。v2 requestはstage／scope／requiresを明示し、同scopeの目録→関係→動作前提を検証する。旧v1や --role を自動変換しない。
- 新規分析・再利用・checkpoint 復元を分け、現版の依存と検証を確認する。新しい自動再利用は実装計画 P6 の検査前に有効化済みとして扱わない。
- 固定総時間・総 token 予算は既定にしない。実質的進展に基づいて継続し、取消・故障・入力失効・無進展では状態、停止理由、再開条件を保存する。個別操作 timeout と外部明示期限は共通契約に従う。取消は旧返却を失効させるが即時の子プロセスkillを保証しない。

- store はホスト管理領域とし、hash を認証や署名と説明しない。人手正解表の受入れと実モデル候補の採用を別に記録する。

- 各領域の検証済み目録・関係を前提に進める。前層で要求を満たせば止め、妥当な既存成果を確認して使う。全倉障壁や全対象3層直列を設けず、上流の変更は依存成果の失効を確認する。
- relationshipによる条件・引数の読取りや、behaviorによる関係補査を禁止しない。共通snapshot／SourceAccess／ID／store／adapter／検証機構は複製しない。

- runは定義済み目標グラフのready義務を進め、阻害やグラフ外補査は保存停止する。同basisの反復を新進捗へ数えず、scopeや義務を自動拡大しない。
- 採用済み上流の再調査はreviseで依存下流も撤回し、step --feedback後の原文調査・独立検証・採用を行う。recordの所有義務とkey/version依存、未知の関連先と阻害先を区別する。

## 記録と旧経路

- 現CLIは --source と --work の同一・親子配置を拒否する。対象方式sourceRoot/.tmp/内の準備済みsource-only展開先と、その兄弟の作業先で分離できる。配置条件は [共通契約](AGENT.md)に従い、同期作業だけを理由に入力の複製・再実行を始めない。
- 作業中間物・試行は対象方式の `.tmp/` へ置き、最終検査記録は同方式 `build/` の固定先へ更新する。方式を持たない共通作業だけ担当Agentまたはproject内の `.tmp/`・`build/` を使う。旧生成結果は別名保存せずGit履歴を使う。正式な契約、解析正本、QA、回帰 fixture を一括除外しない。
- 旧仕様書生成 CLI を明示選択した実行だけ、[旧経路の契約と運用規則](docs/legacy/README.md)を追加で読む。旧資料は新経路の手順や今回の実行許可を与えるものではない。
- 入出力・契約の版、ファイル、確認範囲、検査結果、未実施を報告する。過去の合格を新改訂へ流用しない。コミット／push は実行要求に従い、force push はしない。
