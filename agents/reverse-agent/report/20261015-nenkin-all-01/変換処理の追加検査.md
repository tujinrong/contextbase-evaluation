# 変換処理の追加検査

対象実行：20261015-nenkin-all-01。対象文書版：2.0。作成日：2026年10月15日。

本記録は、生成したMDをHTML・PDF・Excelへ変換する工程の修正記録である。原アプリケーション、SQL、DB、ビルドは実行していない。全機能一式の公開完了を示す記録ではなく、最終公開状態は `publication.json` で確認する。

## 修正した問題

| 問題 | 原因と修正 | 確認方法 |
| --- | --- | --- |
| フォームのないエラー画面を画面画像として取得できない | 静的画面の検出対象を `main`、画面用コンテナー、明示された画面領域へ拡張した。入力のJavaScriptは実行しない。 | フォームのない画面を含む描画テストと、実生成したエラー画面の画像を検査した。 |
| PDF本文の一部の文字が異なるUnicode文字として抽出される | 画面用CSSが文書本文へ漏れ、文書用フォントを上書きしていた。画面は固定した画像へ投影し、画面用CSSを本文へ適用しない。 | PDF本文を空白だけ除いて原稿の文字列と比較する。Unicode文字の置換や正規化で差を隠さない。 |
| 図がネイティブExcelの印刷で途中分断される | 用紙と改ページ位置を図の高さ・幅に合わせる。大きな図はA2縦、通常はA3横、表紙はA4縦とする。単一図の寸法が許容範囲を超える場合はAIが意味のまとまりで分割し、別プロセスのソース照合をやり直す。 | Microsoft Excelを読み取り専用・マクロ無効・外部リンク更新なしで開き、保存せず印刷PDFへ出して検査する。 |
| PDFで図の見出しだけが前ページに残る | 既存の見出し・説明・図を、内容順を変えずに同じページのまとまりへ配置する。 | ソースの図見出し文字列と、図画像が現れるPDFページを照合する。 |
| 太字の親手順とフロー見出しをExcelで認識できない | Markdownのインライン解析には、太字トークンの前後に空のテキストトークンが入る場合があった。空トークンを除いて強調範囲を認識する。 | 日次・月次処理の変換モデルで、親手順15件と図キャプション6件を認識した。番号と本文は原稿の文字列を保持する。 |

## 追加した独立検査

`verify_artifact_pagination.py` は、生成器の「合格」フラグを採用せず、元の図画像と実際のPDF内画像を、寸法とデコード後のRGBバイト列で照合する。通常PDFとネイティブExcel印刷PDFの両方について、画像の出現回数と、ソースにある図見出しの同一ページ掲載を確認する。

既知の不良版を使い、次の欠陥を検出した。

1. システム分析書の旧変換：図見出し2件が画像とは別のPDFページにある。
2. 日次・月次処理の旧変換：高さ2052pxの同一図が、ネイティブExcel印刷の2ページに出現する。
3. 日次・月次処理の旧変換：複数のフロー見出しが画像とは別のページにある。

修正後の実ファイルに対して同じ検査を実行する。表示レビューが承認していても、この検査や追加目視で欠陥が見つかった版は公開対象から外す。撤回と再変換の対応は `host-visual-corrections-01.json`、`host-visual-corrections-02.json` と作業領域の `withdrawn-conversions.json` に残す。

この照合は、画像の同一性・出現回数・見出しの配置の検査である。文字の読みやすさ、線の重なり、表の改ページなどは、全PDFページ、Excelの全プレビュー、ネイティブExcelの全印刷ページを使う別の表示レビューで検査する。原アプリの画面との画素一致や、原仕様・spec-evalによる正式採点は実施していない。正式点数と95%判定は `null` とする。

## 保全と公開条件

最終公開では、計画の34文書を一意なIDで照合し、納品33文書を各4形式で揃える。解析報告1文書はreportへ分離する。全成果物のハッシュ、MDとHTMLのリンク先、HTMLの節へのリンク、ネイティブExcel検査、画像検査を確認してからoutputを入れ替える。旧QAの回答・状態・レコードを保持し、今回の原文確認結果と追加の問題だけを追記する。
