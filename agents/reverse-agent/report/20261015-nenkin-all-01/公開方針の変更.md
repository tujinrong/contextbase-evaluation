# 公開方針の変更

2026年10月15日、利用者から「一定の品質になればoutputへ出力」「長時間同じ処理の繰り返しを避けたい」「既存古いファイルを削除」と指定されたため、全形式の表示指摘ゼロを待つ方式から、内容確認済み文書を順次公開する方式へ変更した。

- 旧outputの906ファイルは削除済み。検証済み保護コピーは本reportの `backup-before/output` に保持する。入力、QA、ソースは削除していない。
- 仕様の本文はAIが執筆する。既に完了したソース解析と原稿を再利用し、新規原稿は初回と必要な内容修正1回を基本とする。図の表示問題を理由に業務解析からやり直さない。
- 構造違反、重要な内容の誤り・欠落、未解消の重要事項は公開しない。独立レビューに軽微な内容指摘だけが残る場合は、その指摘をreportとmanifestへ保持し、承認済み・正式合格とは書かない。
- MDは内容確認を通過した時点で公開する。Excel・HTML・PDFは形式ごとに確認できたものを追加する。内容の欠落、文字・項目の重なり、判読不能がある形式は保留する。
- 内容がすべて存在し読める場合、見出しだけの印刷ページなど改ページ・余白上の課題は、独立レビューがmajorと記録していても元の重要度を変更せず、既知の印刷制約として明記して公開する。これは表示承認や正式合格への変更ではなく、利用者の反復抑制指定に基づく公開方針である。`acceptedPrintLayoutFindings` に当該指摘をそのまま残す。
- 表示レビューの回答を書き換えたり、変更した画像へ過去の承認を流用したりしない。同一SHA256の画像に限り、元のレビューの該当画像と指摘を特定した再利用記録を保持する。
- Microsoft Excelで開いている `~$` 一時ファイルは削除せず、納品ファイルの件数にも含めない。outputディレクトリを開いている状態でも、変更したファイルだけを原子的に更新する。
- 原仕様・spec-evalを使う正式な95%採点は未実施であり、点数と判定は `null` とする。

公開済みの文書と形式、未出力の対象は `output/index.html` と `output/manifest.json` に記録する。各更新の記録は `incremental-publication-*.json` に保存する。
