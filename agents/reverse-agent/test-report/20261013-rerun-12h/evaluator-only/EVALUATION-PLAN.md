## 実行方法

Pythonはbundled 3.12を使用する。今回の局所依存 `.tmp/20261013-rerun-12h/engine-runtime-deps` を先頭にしてjsonschema4.25.1を固定し、`.tmp/session-python-deps` は補助にする。旧 `.tmp/pydeps` のrpdsはcp311のため使用しない。prepare時にPython実体・版・jsonschema版・モジュールhashを固定し、実行時に再照合する。モデル指定を加えず利用者設定を継承する。

1. `grader.py prepare --batch <本フォルダ内の新規batch> --draft <今回原本同名稿のroot> --snapshot <固定source-only snapshot> --document-id <対象ID> --maximum-rows 80`
2. rootとの調整後、`grader.py run --batch <batch> --deadline 2026-10-13T20:15:58Z --workers 1 --max-jobs 1` で最初の測定を実施。
3. 測定後、同batchの成功jobは原応答を再利用して残りを実行。失敗jobは証跡を保護し、新batchで再試行する。
4. `normalize_defects.py --batch <batch> --deadline ... --output <batch内normalization.json>`。
5. `grader.py aggregate --batch <batch> --normalization <normalization.json> --output <batch内summary.json>`。JSONと文書別評価MDを出力。

期限切れ・入力不一致・未生成・未採点・視覚未検証を合格へ丸めない。原本不変はrootが保存した218ファイルの保護ハッシュで最後に照合する。生成者へ改善を渡す際は別のsource-backedレビューを使用し、評価行・正解セル・採点根拠の期待値は移送しない。
