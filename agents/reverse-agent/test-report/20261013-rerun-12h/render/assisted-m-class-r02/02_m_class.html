論理名・物理名・データ単位 クラスマスタ／dbo.m_class。学校年度内のクラス1件を管理する17列の表。学生はclass_idで現在所属または最終所属を参照し、年度・学年・クラス名を学生へ重複保存しない。現在人数の保存列はない。学年00のクラスへの所属と、学生の所属NULLは別の状態である。実装根拠：sources/database/001_schema.sql:24-28,62-88、sources/Core/Contracts.cs:25-25,63-67、sources/Core/SqlServerStudentService.cs:201-214、sources/database/002_seed.sql:78-84。
用途と処理への接続 学生画面から候補取得・所属条件検索・所属ID保存へ接続される。クラス自身の書込みはMasterMaintenanceService.SaveClassAsyncに宣言されているが、確認したWeb登録・学生ルートからの呼出しはない。本書の保守規則は同サービスの契約であり、公開保守画面・HTTP API・稼働CLIの仕様とは確定しない。実装根拠：sources/Program.cs:3-7、sources/Infrastructure/WebHostSetup.cs:13-19、sources/Web/Controllers/StudentsController.cs:5-42、sources/Infrastructure/WebStudentCoordinator.cs:7-19、sources/Core/MasterMaintenanceService.cs:9-15,30-77。

保守の例外経路と確定境界 トランザクション内は単一catchであり、検証例外、一意違反、保存時競合、取消、監査失敗、commit失敗をrollback試行へ進める。Rollbackは取消トークンNoneを使い、SqlException・InvalidOperationExceptionならfalseを返す。保守はこの戻り値で結果分類せず、補助が戻れば元例外を再送出する。補助の未捕捉例外が生じればその例外が伝播する。DB一意違反をValidationFailed、OUTPUT不取得をConflict、commit失敗をUnknownという保守戻り値へ置換しない。前処理・接続認証・トランザクション開始はこのcatchの外。commit・rollback失敗後の確定状態と利用者向け最終応答は、未確認の保守入口で確定する必要がある。実装根拠：sources/Core/MasterMaintenanceService.cs:32-41,77-77,130-130、sources/Core/SqlServerStudentService.cs:329-329。
