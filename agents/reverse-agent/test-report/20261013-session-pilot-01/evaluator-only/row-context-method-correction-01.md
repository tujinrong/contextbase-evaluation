# 評価行の意味・根拠割当の再確認

評価専用。生成プロンプト・製品コードへの変更はない。

Round2の原行15と16では、stable評価IDと配点は正しかったが、理由と生成本文の根拠を別操作に割り当てた。行範囲とSHAが有効でも意味の対応を証明できない。初回報告は保存し、同じ候補SHAに対する訂正報告を追加した。両行の正しい本文・ソースを再読し、得点286/316は変わらなかった。

今後は最終理由と根拠を確定した後、選択原行のstable ID、文書ID、index、章、仕様項目、判定観点、論理項目名またはイベント文脈を改めて読む。その文脈で本文の対象、効果、条件、失敗経路を確認し、最終理由と根拠が同じ対象を説明していることを評価者が再確認する。近接行の順番、同じ表の行、共通イベントの見出しだけを対応の証明にしない。

row_context_guard.pyは原行の文脈をselected-rows.jsonから汎用的に導出し、評価者の明示レビューを最終理由・全根拠のハッシュに結び付ける。操作名を固定した分岐、キーワード一致による加点、意味判定の自動生成は行わない。評価者は各行に原文脈と、実際に読んだ生成文脈・根拠を記録する。機械検査はその記録のID/文脈/ハッシュ整合だけを検査する。

Round3は281原行/316点を保持し、検索120行と登録161行について、候補SHAが完了生成記録と一致した後に全文を新規再読する。公開前にこの文脈レビューを各行へ適用する。原行の配点、重大指定、未裁定の扱いは変更しない。

この方法は、隣接行の割当ミスを防ぐための追加レビュー記録である。ハッシュ一致やレビュー宣言だけで意味の正しさ、実装試験、95%達成を推論しない。源泉・期待セルを生成へ渡すための資料でもない。
