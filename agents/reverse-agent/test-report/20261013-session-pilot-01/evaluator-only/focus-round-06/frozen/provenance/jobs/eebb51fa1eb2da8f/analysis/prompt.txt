共通の応答境界\n\n以下の「共通応答」は、応答未開始の場合だけ適用される。WebFaultは発生箇所のStatusを保持し、それ以外の例外は503となる。学生ルートでは文言をHTMLエスケープしたエラーHTMLと検索リンクを返す。応答開始後の例外はこのcatch条件に入らない。Authorize・Cookie認証・CSRFの先行拒否は、本体内のWebFaultやサービス結果とは別の境界である。根拠: `sources/Infrastructure/WebHostSetup.cs:14-25`。\n\nSnapshot.GetはNULLキーを事前検査しない。NULLがストアへ届いた場合はConcurrentDictionary.TryGetValueのArgumentNullExceptionが独自の409検査より前に生じる。保存ではGetが個別WebFault catchより前、削除・Resetにはこの個別catchがないため、いずれも復元・原入力再表示・削除非成功後Loadへ進まず、応答未開始なら共通503となる。非NULLキーの不在・期限切れ409、所有等相違403とは区別する。HTTP項目欠落・空値から具体的なバインド後値を保証する記述ではない。根拠: `sources/Infrastructure/EditorSnapshotStore.cs:10-10`、`sources/Web/Controllers/StudentsController.cs:29-37`、`sources/Web/Controllers/StudentsController.cs:41-41`、`sources/Infrastructure/WebHostSetup.cs:16-23`。\n\n### ModelState不正なら422としてサービスを呼ばない。有効ならcatch内でCoordinator.Saveを呼び、権限と復帰Contextを再検査する。\n4. ToRequestで19業務値をDraftへ移す。ClassIdを任意正のInt64へ変換した後、更新期待版を必須正のInt64へ変換する。新規の非空期待版はWebFault400となる。\n5. Open、ReadCommitted開始、共通書込ゲート取得へ進む。Openと開始はDB結果分類tryの外である。\n9. 更新では非削除対象を再取得し、存在、投稿期待版一致、学籍番号不変の順で確認する。旧03・04から異なる区分への訂正にはAdministratorと理由を要求する。\n10. 最新DBのコード、クラス存在、補助値整合、所属期間、新席取得時の定員を確認する。\n11. 正規化22値を最新DBと比較する。差分なしは明示Rollback正常終了後NoChange。実変更があり現版がlong.MaxValueならConflictとなる。\n12. 削除済みを含む全学生から本人を除き、学籍番号の一意性を確認する。\n13. 全同一人物候補を取得し、EV-05の確認を再照合する。有効確認で理由NULLなら検証失敗。候補ありまたは供給キー非NULLで確認不成立ならRollback後に新確認を発行する。\n14.
