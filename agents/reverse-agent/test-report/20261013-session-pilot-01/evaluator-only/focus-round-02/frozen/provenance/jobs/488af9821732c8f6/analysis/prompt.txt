ModelStateが不正ならHTTP422にし、Coordinatorを呼ばず画面再構築へ進む。\n4. 有効ならCoordinatorが認証確認後にToCriteriaを呼び、ClassIdを解析し、Page=1と送信表示指定を設定する。この変換はGate取得前である。\n5. UseがGateを取得し、状態再確認と期待版照合を行う。\n6. SearchAsyncが表示指定・所属同時指定・在籍配列・各入力を検査する。Q-EXISTSとQ-SEARCHを実行する。\n7. EnsureSearchがSavedまたはNoChangeを認めた後、条件を深く複製してAppliedへ保存し、LastResultを置換してRevisionを1進める。検索サービスの正常・0件・超過はNoChangeである。\n8. Useが正常終了したら期限を延長し、Gateを解放する。\n9. Controllerが今回inputとQ-LOOKUPの候補で画面モデルを作り、PageSize・SortKey・SortDirectionを今回送信値で上書きする。\n10.
