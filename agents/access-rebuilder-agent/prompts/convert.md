# 抽出からC#／Webへの実装

実施指示とrequestのproject・対象ファイル・許可を確認し、prepareとbegin-iterationを実行する。台帳が上限なら新しい候補を作らない。

入力は同一hashのACCDB/MDBから取得した目録・DAO構造・オブジェクト原文に限定する。各イベントの入口、入力、正規化、状態、SQL、結果、例外、保存/取消、主体、版、監査を根拠付きで対応付ける。未取得と不存在を区別し、他方式の業務ソースや評価期待値で補わない。

汎用の機械翻訳を装わず、Codexが原文を理解して対象方式のCore/Web/SQLを作成する。C#はsrc/、構造とSQLはdatabase/、正式試験はtests/に置き、実在プロジェクトを.slnxへ登録する。重要な未対応を明記し、独立比較へ渡す。

検査の失敗は取得・設計・コード・環境に分類し、同じ回の内部で必要な局所修正を行う。候補全体の検証とルールへの反映を記録してcomplete-iterationする。次の候補へ進む前に台帳上限を確認する。
