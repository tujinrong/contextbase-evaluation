# Access再構築Agent 作成計画

版0.2／2026-10-27。状態：利用者が実施を指示。訓練は最大2回。根拠は[調査結果](調査結果.md)と[入力manifest](../build/research.json)、実施結果は[訓練結果](訓練結果.md)。

## 目的と今回の範囲

利用者が指定するAccessファイルから、ASP.NET Core／C#／SQL Serverのシステムを生成するAgentを作る。まずtest-project1の学生管理を題材に、抽出・変換・比較を反復し、再利用できるAgentルールへ整理する。

初回依頼では骨格と調査・計画を作成した。その後、利用者の実施指示を受けて対象アプリのフォルダー、.slnx、.csproj、DDLを生成した。変換候補・検証・ルール反映を1回とする反復は最大2回とし、その内部の取得再試行・局所修正は同じ回の記録へ残す。

| D03 | 配置具体化 | 出力sourceRootはtest-project1/srcs/Access-CSharp_ASPNET/。C#はsrc/、関連SQLとDB構成は別のdatabase/ |

| D06 | 技術提案 | SQL資源はSQL Server 2022互換を初期基準として設計。実DBの版・接続先・共有契約はDB実行前に確定 |

## 予定する成果物構成

```text
test-project1/
├─ spec/Access-CSharp_ASPNET/              # 移行設計・確定判断・QA
└─ srcs/Access-CSharp_ASPNET/
   ├─ README.md                          # 起動・操作・未対応
   ├─ StudentManagement.slnx             # 実在csprojを相対パスで登録
   ├─ Directory.Build.props              # bin/obj/cacheを.tmpへ集約
   ├─ src/
   │  ├─ StudentManagement.Web/           # MVC、Razor、静的資源
   │  └─ StudentManagement.Core/          # 業務、DTO、SQL Serverアクセス
   ├─ database/
   │  ├─ schema/                         # 構造メタデータ、型・関係対応
   │  ├─ sql/                            # DDL、制約、索引、変換SQL
   │  ├─ migration/                      # 移行手順・検証・データ対応
   │  └─ seed/                           # 架空の初期確認用データ
   ├─ tests/                             # Core、Web、SQL、比較fixture
   ├─ build/
   │  ├─ generation/                     # inputs/outputs、対応表、未対応
   │  ├─ test-results/                   # 今回の検査、操作確認
   │  ├─ publish/                        # 許可後に生成する最終配布物
   │  └─ source.zip                      # 原仕様・期待値を除くソース
   └─ .tmp/                              # Accessコピー、抽出途中、試行
```

Web→Core参照は対象方式内に閉じる。保守CLI等の追加はACCDB側で必要性を確認して決め、既存ソリューションの全プロジェクトを無条件には作らない。正式試験・fixtureはtests/に保持し、使い捨て実行コピーを.tmp/へ置く。

Agent自体はAGENT.md／PROMPT.md／docs／profiles／schemas／src／scripts／prompts／testsを持つ。今回のsrc等は責務を記した骨格だけで、実装ファイルはない。

## 実装工程

| 工程 | 作業 | 成果と通過条件 |
| --- | --- | --- |
| P0 今回 | 骨格、入力・参考構成の読取り調査、計画、初期ルール案 | 計画を利用者へ提示。実抽出・生成は未実施と明記 |
| P1 取得基盤 | request検査、環境/bit確認、原本hash固定、同一hashの.tmpコピー、起動抑止と外部接続回避の検証 | 原本保全、許可境界、抽出失敗時の記録を試験。抑止未検証なら実ファイル取得へ進まない |
| P2 本体抽出 | DAO構造・保存SQL、SaveAsText等によるフォーム/VBA/マクロ/レポート、起動・参照・依存の取得 | オブジェクト目録、根拠付きfacts、未取得一覧。sidecarと本体の差分を別記 |
| P3 移行設計 | オブジェクト→C#/HTTP/UI/T-SQLの対応、型・NULL・日付・主体・競合・保存/取消の設計 | specRootに根拠・判断・QA。SQL/DB構成を別フォルダーにする契約と.slnx構成を確定 |
| P4 最小経路 | 検索→選択→参照と、新規入力→保存→再検索の小さい一連の処理を生成 | src/Web、src/Core、database、testsを.slnxに束ねる。許可されたビルド・比較が通る |
| P5 全対象 | 目録にある編集・削除・確認/取消・権限・例外・共通・保守等へ展開 | 各原オブジェクトに変換先、対象外理由、未対応、要確認を付け、重要な未対応を解消 |
| P6 独立比較 | 生成担当と別の文脈で原抽出内容を再確認し、単体、Web操作、DB統合を検証 | 項目・分岐・保存値・並び順・権限差・競合・取消の比較結果。未実行/skipを合格へ含めない |
| P7 ルール改善 | 失敗原因をfixture化し、汎用ルールを改訂、同じ入力hashから再実行 | 個別業務値をAgentへ埋め込まず再現性を確認。固定build/へmanifest・今回結果・手順を更新 |

## 訓練の進め方

最初にACCDB本体からの目録を確定し、既存Accessソースとの照合はその後に行う。現時点の「フォーム5個」「schemaに6表」等は生成器・sidecarの観測であり、本体抽出の完了件数にはしない。

各反復は入力hash、ルール版、対象オブジェクト、期待する操作、生成先、検査条件を固定する。抽出不足・設計判断不足・変換バグ・環境不足を分け、原因に対応する工程へ戻る。過去の実行フォルダーは累積させず、今回の結果を固定パスへ更新し、履歴はGitで確認する。

訓練中の比較用Access操作は、原本の起動ではなく隔離した作業コピーと正式fixtureを使い、実施が許可された範囲で行う。コード・抽出物の比較と、実画面・DBの動作比較を別状態で報告する。

P4で取得から比較までの経路を成立させ、P5で範囲を拡張する。変更後は影響する回帰試験だけを再実行し、P7で同一入力からの再構築を確認する。test-project1だけの成功では別Accessへの一般適用性は未検証のままとする。別題材を自動作成・取得しない。

## 受入条件

入力目録の全オブジェクトが分類され、重要な処理・制約の未取得や未対応が残っていないこと。原本hashと対象外ファイルが変わらず、他方式へのProjectReferenceやSQLファイル参照を持たないこと。

StudentManagement.slnxが実在する対象方式内のプロジェクトを束ね、C#はsrc/、構造メタデータとSQLはdatabase/にあり、方式内.tmp/を使用して復元・ビルドできること。起動設定例には秘密を埋め込まない。

許可された環境で、正常な検索・新規保存・再検索・編集・取消、NULL/空文字・先頭ゼロ・文字正規化・日付・境界・権限差・同時更新・定員等の観測された規則を検証すること。必要マスタと架空の初期確認用データ、冪等な投入資源、操作手順を用意し、既存利用者データを初期化しないこと。

抽出・対応分類・生成・ビルド・単体・DB統合・ブラウザー操作・利用者受入をそれぞれ記録する。正式採点は今回の目的に含めずformalScore=null。未評価を含む状態から受入済み・完全互換・汎用検証済みと報告しない。

## 未確定事項と実行境界

本体の実オブジェクト数、保存クエリ、レポート、マクロ、参照、外部リンクはP2で確定する。暗号化、破損、取得できないコードや外部依存があれば未取得として記録し、推測で補わない。

Webの利用者主体・認証はP3でAccess側の観測から決める。参考方式のログイン方式や認証なし設定を自動採用しない。重要な権限判断が未確定のまま、全権限の主体で代替しない。

DB実行前にはSQL Serverの実バージョン、専用の検証先、接続方法、共有DB契約への適用有無、実行範囲を確定する。既存方式の共有DB・実データへ暗黙に接続しない。コード生成の実施指示だけならDDL・投入/検証資源までを作成し、DB統合は未実施と報告する。

入力内の業務データそのものを移行する範囲は別途確定する。最初の訓練では構造・動作の移行と架空の確認データを基準案とし、無断で原データを配布用SQLへ埋め込まない。

## 今回の到達点

P0の後、利用者の実施指示に従ってP1～P7を2回の変換反復で進めた。実抽出、生成、ビルド、単体、専用SQL Server、ブラウザー操作の実施範囲と結果は[訓練結果](訓練結果.md)へ記録する。原Access実画面の実行時差分比較、手動受入、正式採点、他Accessへの一般適用性は別の未確認事項である。
