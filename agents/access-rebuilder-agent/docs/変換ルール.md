# Access変換ルール案

版0.4／2026-10-27。完了済み2回の訓練から得た規則と、その後の利用者の確定ルールを保持する。AR028～030は省スペース・表形式・日付カレンダーの設計条件として追加し、適用後の画面実装・操作検証は未実施。

## 適用状態

初期規則と第1回の反省を下記へ保持する。検証済み範囲は[訓練結果](訓練結果.md)と対象方式build/の今回の記録で確認し、表の存在だけを合格としない。題材固有のオブジェクト名・列長・コード値・件数・権限・例外は汎用規則へ固定しない。

## 初期ルール

| ID | 規則 | 今後の検証 |
| --- | --- | --- |
| AR001 | ACCDB/MDB本体の目録とhashを基準とし、sidecarの存在を本体抽出成功としない | 本体/sidecar差分、未抽出と不存在の区別 |
| AR002 | 表・列だけでなくキー、索引、関係、既定値、ValidationRule、Required、AllowZeroLengthを抽出する | 複合キー、NULL、空文字、検証メッセージ |
| AR003 | AutoNumber、数値、Currency、Decimal、Yes/No、Date/Time、短/長テキスト等を属性と用途から型対応する | 精度、範囲、先頭ゼロ、Unicode、日付境界 |
| AR004 | 列名row_version等からSQL Server rowversion型を推定しない。整数版の加算・上限・競合判定を保持する | 版上限、競合、取消、再読込み |
| AR005 | 保存QueryDefだけでなく、VBA内SQL、連結SQL、フォームのRecordSource/RowSource、取得後フィルターを対象とする | パラメーター、SQL後の文字比較、SQL呼出経路 |
| AR006 | Nz、IIf、DLookup、日付リテラル、ワイルドカード、LIKE、照合、文字比較を構文と実行意味から変換する | NULL/空文字、評価条件、大小/全半角/かな、ANSIモード |
| AR007 | フォームのイベント、非連結入力、確認ダイアログ、取消、フォーカス、入力マスクと保存値をWebの操作へ対応付ける | キーボード、貼付、表示/正規化/保存、再表示 |
| AR008 | DAOトランザクション、guard行、ロック、エラー処理をSQL Serverの原子性・分離・楽観制御へ設計する | 同時登録/更新、上限制約、ロールバック |
| AR009 | Accessの利用者取得をWebサーバープロセスの利用者へ機械置換しない。主体・権限をリクエスト境界で定義する | Reader等の権限差、直接HTTP呼出、監査主体 |
| AR010 | マクロ、レポート、起動設定、外部リンク、参照、Win32/OLE/ActiveX依存を目録化し、変換/対象外/未対応を明示する | 抽出被覆、代替案、重要な未対応の停止 |
| AR011 | C#はsrc/、DB構成とSQLはdatabase/、正式試験はtests/、最終結果はbuild/、中間物は.tmp/へ分ける | .slnxの相対参照、方式外依存なし、配布物内容 |
| AR012 | 初期確認データは制約を満たす架空データとし、冪等投入と既存値保護を実装する | 通常画面での保存/再検索、再投入、キー衝突 |
| AR013 | 抽出・生成・構造・ビルド・動作・受入を別状態で報告する。未実行/skipをPASSに含めない | 最新hash、未実施、formalScore=null |
| AR014 | VBAはANSIの既定推測で読まず、可能ならAccess.Module.LinesのUnicode BSTRから取得する。SaveAsTextの設計定義と区別する | 日本語リテラル、先頭ゼロ、文字化け検出fixture |
| AR015 | 原本をAccessで開かず、DAO読取り専用と空ホストへの定義importを使う。AutoExecと起動フォームの非実行をfixtureで確認する | sentinelが増えないこと、定義取得、原本hash不変、外部リンク非接続 |
| AR016 | 検証式のCStr内の算術、文字列連結、ANSI89ワイルドカードを検証された構文だけ変換する。未対応はDDL公開前に停止する | CStr(年+1)、不明関数、引用符、否定文字クラス |
| AR017 | changed_columnsは実際に変更された列だけを原本の列順・追加規則で記録する。固定カテゴリ・正規化キーの有無も比較する | CREATE、電話のみ更新、マスタの1項目更新、NoChange |
| AR018 | guard取得後でもNoChange・確認待ちでは確定しない。変更検出前に版番号を加算しない | guard不変、版上限でのNoChange、取消と監査なし |
| AR019 | 和暦表示、元の編集値へのリセット、最新再読込み、再描画後の未保存状態、検索スクロールを別々に対応付ける | 実ブラウザーの保存・取消・候補更新・復帰 |
| AR020 | 直接・推移依存の脆弱性警告は監査を無効化せず、公式修正版へ固定して再検査する | lockファイル、audit有効の復元、ビルド警告 |
| AR021 | 訓練回数は永続台帳で制限し、上限到達後の再生成を開始しない。準備時の取得再試行と変換反復を区別する | 3回目拒否、二重開始拒否、入力hashと結果番号の照合 |
| AR022 | SQL Serverで文字FKの物理容量一致が必要な場合、元の許容容量をCHECKで保持して整合させる。業務長の無断拡大にしない | 親子の型・容量、元DATALENGTH上限、7関係の実DB作成 |
| AR023 | MVCアクションを他アクションから委譲する場合は返すビュー名を明示し、実HTTP経路で確認する | Reload→Editの実ブラウザー操作、誤ったReloadビュー解決の回帰 |
| AR024 | リセット・再読込み・保存成功で旧編集snapshotと対応する確認を失効させ、確認POSTでもsnapshotと主体を再検証する | 古い重複確認/削除確認の拒否、別の編集状態の維持 |
| AR025 | Accessは業務の根拠、利用者指定のWebソースは設計・実装の参考とする。デスクトップの操作形の再現を目的にしない | 参照ファイルhash、保持した業務制約、Webへ再設計した操作 |
| AR026 | 候補連動は全画面再送信を避け、ローカル処理または認証付きJSONで更新する。古い応答・通信失敗を扱い保存時にも検証する | 入力保持、フォーカス、CSRF、応答順序、候補改ざん |
| AR027 | 検索・件数・並び替え・ページング、項目別エラー、処理中表示をWebの利用経路として整える | ブラウザーの検索/編集/戻る/再送信、狭い幅、キーボード |
| AR028 | Webの有効スペースを節約する。余白・見出し・補助説明・項目幅を必要量に抑え、条件・一覧・主要操作を近接させる。文字の過度な縮小や業務項目削除で収めない | 対象viewport・拡大率、主要操作の到達、狭幅の折返し、切れ・重なりなし |
| AR029 | PCの検索・編集・参照は、左に見出し、右に項目の表形式とし、列開始位置を揃える。横幅に応じて見出し／項目の組を配置する | 見出し・項目の列揃え、label関連付け、Tab順、狭幅時の組の維持 |
| AR030 | 日付・和暦はコンパクトなカレンダー入力を原則とし、和暦表示と保存日付を同期する。元号・年・月・日の4欄常設を既定にしない | 選択・直接入力・クリア、必須／任意、過去日、閏日・元号境界、日付ずれなし |

## 改訂と採用

各改訂に失敗例、入力hash、根拠オブジェクト、変更理由、適用範囲、回帰試験、未検証範囲を付ける。訓練で検証された規則と初期仮説を区別する。test-project1固有の決定を一般規則へ昇格させない。過去版はGitで管理し、固定文書と今回の最終記録を更新する。
