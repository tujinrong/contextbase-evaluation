## 抽出と移行の技術方針

DAOでTableDefs／Fields／Indexes／Relations／Propertiesを調べ、QueryDefs.SQLから保存SQLを取得する案とする。DAOはテーブル定義とリンク情報を扱え、OpenDatabaseにはReadOnly指定がある。ただし外部リンクへの接続や起動処理の抑止は別途検証し、原本を直接開く運用にはしない。[TableDef](https://learn.microsoft.com/en-us/office/client-developer/access/desktop-database-reference/tabledef-object-dao)、[OpenDatabase](https://learn.microsoft.com/en-us/office/client-developer/access/desktop-database-reference/dbengine-opendatabase-method-dao)、[QueryDef.SQL](https://learn.microsoft.com/en-us/office/client-developer/access/desktop-database-reference/querydef-sql-property-dao)。

フォーム・レポート・マクロ・モジュール等の定義取得にはAccessのSaveAsTextを候補とする。単にテーブルをSQLへ変換する工程と、フォーム・VBAの動作をWebへ作り直す工程を分ける。[MicrosoftのSaveAsText資料](https://learn.microsoft.com/en-us/office/client-developer/access/desktop-database-reference/application-save-as-text)。

SSMAはDB構造・クエリ変換の補助候補であり、フォーム、レポート、マクロ、モジュールのC#変換を担当しない。パラメーターSELECT、クロス集計、更新系等も一律変換されるわけではない。このAgentには別途、動作抽出・Web/C#生成・独立比較が必要と判断する。SSMAの導入・実行は今回は行わない。[Microsoftの変換対象表](https://learn.microsoft.com/en-us/sql/ssma/access/converting-access-database-objects-accesstosql)。

.slnxはXML形式でプロジェクトを束ねる。Microsoft資料では.NET SDK 9.0.200から対応し、.NET 10のdotnet new slnの既定も.slnxである。ローカルの.NET 10 SDKに合わせ、ソリューション名と登録先を明示して生成する案とする。[Microsoftの.slnx資料](https://learn.microsoft.com/en-us/dotnet/core/compatibility/sdk/10.0/dotnet-new-sln-slnx-default)。

外部資料の確認日は2026-10-27。ツールの仕様が実ファイルで動作することは、実施指示後の抽出・ビルドで確認する。
