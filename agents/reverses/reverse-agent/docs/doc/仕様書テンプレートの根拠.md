# 仕様書テンプレートの根拠と採用ルール

調査日：2026-10-09。以下は文書構成の参考であり、解析対象の業務仕様の根拠ではない。
原本の動作を外部資料で置き換えない。テンプレートは本リポジトリ向けに作成した。

| 参考資料 | 採用内容 | 原本との境界 |
|---|---|---|
| Cucumber Gherkin Reference https://cucumber.io/docs/gherkin/reference/ | 前提・操作・観測できる結果を分け、利用者と同じ業務用語で説明する | Gherkinの採用やテスト実行を主張しない。DB内部の説明は本件要件として追加する |
| Mermaid Flowcharts https://mermaid.js.org/syntax/flowchart.html | 処理ノード・判断・接続を分けたフロー表現 | 実装は既存Graphvizによるオフライン描画。Mermaidを導入した意味ではない |
| Mermaid Entity Relationship Diagrams https://mermaid.js.org/syntax/entityRelationshipDiagram.html | 表・属性・関係をER図として説明。単独エンティティも許す | SQL結合から多重度やFKを捏造しない。図だけでSQLの条件・更新内容を省略しない |

## 本件の追加ルール

DB連携項目は、実際に表示・保存されるDB列を表す。Model型名や候補一覧の取得元をその代用にしない。
JSPのバインド式、要求パラメーター、Model setter/getter、ResultSet別名、PreparedStatementの設定順を根拠に結び付ける。
コード変換、複数表、削除履歴への転記、算出値は項目別DB連携備考へ展開し、原本位置を残す。

テーブル定義書は全テーブルの詳細を1個のMDと1冊のExcelへ統合する。異なる環境・スキーマは別の表定義として残す。
従来のDB使用・各表の項目欠落・日本語名・DML説明の独立検査を弱めない。

## ファイル

- `src/contextbase/templates/standard_rules.json`：プログラムが使用する見出し・公開パス・意味ルール。
- `src/contextbase/templates/event.md`：イベントの執筆・レビュー用テンプレート。
- `src/contextbase/templates/table_definitions.md`：統合テーブル定義書の構成。

テンプレートの変更も解析エンジンのハッシュに含め、再生成時に過去の文書モデルを無条件で再利用しない。
