# 独立品質評価

## 検査と実行

`python -m contextbase.validation --root .` は従来の工程契約・P3ソース非依存検査に加え、`validation/quality.py`の原本由来の義務を公開MDへ照合する。`rebuild`はこの検証が成功しない限り新しい成果物を公開しない。

| 規則 | ERRORの条件 |
|---|---|
| UI-001 / 002 | 原本画面の機能・基本設計書がない |
| UI-003 / 004 | レイアウト情報または本文掲載がない |
| UI-005 | 掲載画像が欠落・破損・領域外・微小・単色 |
| DB-001 | DB使用根拠があるがDB仕様書がない |
| DB-002 | 原本で識別した個別テーブルの定義書がない |
| DB-003 | DDLの列が定義表から欠落。文章中の言及だけでは不可 |
| NAME-001～004 | 機能・項目・表・列の論理名が日本語でない |
| NAME-005 | 公開MDの論理名が日本語でない。物理名・IDは除外 |
| DML-001 | 各原本の挿入・更新・削除・MERGEに対応する対象付き説明がない |
| DML-002 | 設定項目・対象条件・確定取消・処理説明の中身が不足 |
| DML-003 | 共通DB仕様書には説明があるが機能別仕様への掲載がない |

## 独立性

画面義務はP1の画面一覧ではなくinputの画面定義から取得する。DB義務はDDL・文字列SQL・JDBCの記述を別の字句走査で取得する。生成用SQL解析器・画面抽出器は呼び出さない。原本の表名・列名を保持し、定数結合、全角文字、同名更新メソッドの別定義を区別する。

正例と負例は手書きで、生成結果から期待値を複製しない。中間情報と公開文書から同時に表を削除しても原本義務で検出する。

## 新入力への生成側の補強

Javaの文字列結合・StringBuilder/StringBuffer・単純なSQL組立補助・直接実行引数を静的解析する。JSPの画面表示を解析し、画面・関連Action・Repositoryへ接続する。物理表定義はDDLとプログラム参照を区別し、DB2・SQL Server・ローカルH2の環境差はそのまま保持する。

DB操作仕様書に対象・列・設定式・WHERE条件・トランザクション根拠を保存し、基本設計書の関連処理へ展開する。SQLファイルの初期データ値、パスワード、サンプル個人データは説明へ転載しない。

`src-dynamic/nenkin/terminology.json`は識別名・処理役割から整理した日本語名称辞書。物理名の変更や、他案件の業務値の流用ではない。原本に明示されたタイトル／日本語Javadocを優先して用い、辞書の適用対象をsource_rootsで限定する。

## 限界と報告

この検査は全動的SQL・全実行経路・全表示条件の意味同等性証明ではない。検出可能なSQL組立に限定し、追跡不能な部分はreportへ残す。静的画像の存在・破損・単色を検査しても、実画面と寸分違わず再現した保証ではない。論理名の日本語判定は内容の言語条件であって、日本語訳の業務承認ではない。

`report/quality/validation.json`と`独立評価.md`が今回結果。未確定のDB型・制約、動的条件、名称採用の質問はQAへ、解析限界はreport/incompleteへ保存する。
