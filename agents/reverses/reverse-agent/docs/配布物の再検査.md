# 配布物の再検査とソース再解析の分離

## 修正した不具合

ソース整理後の配布物には業務原本 `input` を含めていません。従来の統合CLIは、MD／HTMLだけを読む `build`／`check` にも解析用の入力フォルダ存在検査を適用していたため、配布物の検査が `Input directory does not exist` で停止しました。

今回、設定読込の `require_input` を既定で真とし、`probe` と `rebuild` では引き続き入力を必須に、`build` と `check` では入力の存在を前提としないよう修正しました。リポジトリ外・コードとの重複・symlink等の設定検査は維持します。表示変換で対象プロファイルを選定・importすることはありません。

## 仕様書だけの検査

```bash
python -m pip install -e .
python -m contextbase check
```

`output/md` と `output/html` を照合し、本文・表・図・項目・内部リンク・アンカーを検査します。リポジトリ外のGitHubリンクは存在確認せず、業務原本や顧客データを配布する必要はありません。

`build` はMDからHTMLを作成します。既存HTMLが手修正済み、または所有台帳にない変更対象である場合の上書き保護は維持しています。配布ZIPには再開台帳が含まれない場合があるため、MD変更後に既存HTMLと競合した場合は、リポジトリの台帳と合わせて作業するか、別の空の出力先を持つ作業コピーで生成してください。検査のために入力コードを追加する必要はありません。

## ソースからの全工程再作成

```bash
python -m contextbase rebuild --replace-output --native --browser
```

このコマンドには原本が必要です。空の作業領域から解析、定義の回帰比較、Pilot、MD／HTML生成・描画検査を実行し、成功後のみ公開物を置換します。今回の修正後も同じ手順で最初から再実行し、結果は `report/rebuild` に記録します。

## 回帰試験

`src/contextbase/tests/test_publication_cli.py` に、原本・対象別プログラム不在の変換と検査、設定省略、解析時の原本必須、公開物の保護、危険な入力設定の拒否、本文欠落の検出、同一MDの再変換を確認する8件の試験を追加しました。業務解析のルール・対象別Python・Pilotの比較範囲は変更していません。
