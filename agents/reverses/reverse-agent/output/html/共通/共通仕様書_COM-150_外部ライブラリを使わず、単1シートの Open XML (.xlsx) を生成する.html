概要

OpenXmlWorkbookWriterは、呼出元が用意した列見出しと行配列から、単一シートのOpen XML形式Excelファイルを生成する。Java標準の文字列処理、ByteArrayOutputStream、ZipOutputStreamを使用し、完成したファイルをbyte[]で返す。生成器自身はDB、HTTP応答、ファイルシステムを扱わない。

店舗別出力では予約の一覧を18列へ移し、日次・月次出力では選択区分ごとの明細と帳票上部の情報を組み立ててから本生成器を呼ぶ。抽出条件の判定、日付・電話番号・担当者の表示用変換、ファイル名、複数ファイルの取りまとめ、ダウンロード送信は呼出側の責務である。本書に画面固有の入力コントロールはない。

呼出入口

public static byte[] buildWorkbook(
    String sheetName, List<String> headers, List<Object[]> rows)

public static byte[] buildWorkbook(
    String sheetName, List<String> headers, List<Object[]> rows,
    List<Object[]> leadingRows, List<String> mergedRanges, int printScale)

基本入口は拡張入口へleadingRows=null、mergedRanges=null、printScale=100を渡す。拡張入口はヘッダーより前の行、結合範囲、印刷倍率を追加指定する。ヘッダー列数がシートの列構成を決め、先行行・明細の配列長によって列を増やすことはない。

利用元 通常の呼出経路 生成器へ渡す構成

日次・月次の新規分 BatchDailyAction／BatchMonthlyAction → BatchRunAction → PensionBatchExportService.build シート名「新規分データ」、17列、先行7行、結合5件、倍率70％

通常画面の送信先はAction.doで、FUNCTION_ID=nenkinを用いる。店舗別はVIEW_ID=Excel・COMMAND_ID=Export、日次・月次はVIEW_ID=Batch・COMMAND_ID=DailyまたはMonthlyに対応する。本生成器はこれらのHTTP入口として直接公開されるクラスではなく、サービス内部から利用される。

イベント仕様

単一シートWorkbook生成

処理概要

呼出元が入力リストを渡した時点で生成を開始し、入力検査、共通XML、シートXML、ZIPの完成の順に処理する。headers.size()をC、leadingRowsがNULLなら0、それ以外はその件数をL、rows.size()をNとする。ヘッダーはL+1行目、最初の明細はL+2行目、最終行はL+1+N行目となる。

列名は1始まりの番号をA～Z、AA以降へ変換する。使用範囲dimensionはA1:最終列最終行であり、空の先行行も行番号へ含める。N=0でもヘッダーを含むシートを生成できる。実際の二サービスは検索0件時に生成器を呼ばないため、画面からの0件結果とは区別する。

処理手順

1. 入力を検査し、生成用のメモリを確保する。

1.1. headersがNULLまたは空なら、IllegalArgumentException「ヘッダーは1列以上必要です。」を送出する。

1.2. 1.1を通過後、rowsがNULLなら、IllegalArgumentException「明細リストはnullにできません。」を送出する。明細0行は拒否しない。

1.3. ByteArrayOutputStreamと、それを出力先とするZipOutputStreamを作る。両者の生成は後続のtryより前にある。ここまでの失敗は、生成器のIOException変換およびfinallyによるcloseの対象に入らない。

2. Workbookの共通部品を順に格納する。

2.1. [Content_Types].xml、_rels/.relsを作成し、ZIPへ書く。

2.2. シート名はNULLまたはtrim後空欄ならSheet1、それ以外はtrim結果を使用する。バックスラッシュ、スラッシュ、疑問符、アスタリスク、左右角括弧、コロンをアンダースコアへ置換する。その後、String.length()が31を超える場合にsubstring(0,31)で切り詰める。

2.3. 2.2の名前をXMLエスケープしてxl/workbook.xmlへ埋め込み、続いてxl/_rels/workbook.xml.rels、xl/styles.xmlを格納する。シートはsheetId=1の1件である。

3. シートの行・セルを組み立てる。

3.1. L・C・Nから使用範囲と固定位置を決める。ySplitはL+1、topLeftCellはA列のL+2行目、activePane=bottomLeft、state=frozenとする。

3.2. 各列について、ヘッダーの表示長+2と先頭最大100明細の同列値の表示長+2の最大値を求め、5～40へ補正する。customWidth=1を付けて列幅を出力する。表示長の数え方は補足説明に定める。

3.3. 先行行をリスト順に作る。NULL配列や全要素NULLでも行要素を作るが、セルはヘッダー列数以内の非NULL要素に限る。値はNumberを含めString.valueOfで文字列化する。1行目は高さ28・スタイル3、それ以降の先行行のセルはスタイル4とする。2行目以降の先行行には明示的な行高を設定しない。

3.4. ヘッダーをL+1行目へ、高さ45で作る。全列を文字列セル・スタイル1として出力する。

3.5. 明細をリスト順に作り、各行でC列分のセルを出力する。NULL行、配列の不足位置、NULL要素は空文字の文字列セル・スタイル0とする。非NULLのNumberは数値セル・スタイル2、それ以外はString.valueOfによる文字列セル・スタイル0とする。C列を超える要素は無視する。

4. 表の操作・印刷情報を付け、シートを格納する。

4.1. autoFilterをヘッダー行のA列から最終列・最終行まで設定する。N=0でもフィルター要素を作る。先行行はフィルター範囲へ含めない。

4.2. mergedRangesが非NULLかつ非空の場合だけ、件数をmergeCellsのcountへ設定する。各文字列をXMLエスケープしてmergeCellのrefへリスト順に出力する。値の移送・削除は行わない。

4.3. 水平中央、A4縦、倍率、余白を設定する。倍率は入力値を10～400へ補正する。用紙幅に合わせる自動収容、列数による用紙方向変更、印刷タイトル行の定義は行わない。

4.4. 組み立てたシートXML全体を文字列化し、xl/worksheets/sheet1.xmlとしてZIPへ書く。

5. 完成した内容を返し、ZIPを閉じる。

5.1. 全6エントリーの格納後にzip.finish()を呼び、output.toByteArray()を戻り値とする。

5.2. try内のIOExceptionは原因を保持したIllegalStateException「Excelファイルの生成に失敗しました。」へ変換する。他の実行時例外やErrorを同じ例外へ変換するcatchはない。

5.3. tryへ入った処理は、正常・異常ともfinallyでzip.close()を試みる。このcloseのIOExceptionだけは抑止する。失敗時に空の成功ファイルや途中の配列を返す処理はない。

SQL・テーブル関連（ER図）

本イベントはSQLを実行せず、テーブルを参照・更新しない。入力行はサービスが取得・変換済みのメモリ上の値であり、本生成器を対象とするER図はない。

店舗別出力の抽出元は予約本表、日次・月次の新規・変更分は現在の予約本表、削除分は削除明細である。性別等の名称はRepositoryの結合結果からモデルへ移され、本生成器へはStringとして渡る。コードの逆引き、候補取得、DB列のNULL可否判定を本生成器で行うことはない。

DB操作の詳細

生成器内のDB操作、commit、rollback、生成物保存は非該当である。保持領域は呼出元の行リスト、シートXMLのStringBuilderと完成文字列、UTF-8変換配列、ZIP用メモリバッファ、返却用byte[]である。逐次送信用APIや一時ファイルは用いず、全体をメモリへ保持する。

日次・月次の呼出側には生成前の削除明細整理がある。この更新とWorkbook生成は同一トランザクションではない。整理がcommit済みの場合、その後の抽出・変換・生成失敗では取り消されない。生成器の非DB処理と、呼出側の更新確定を分けて扱う。

数値セルには丸め、桁制限、有限値検査、Excelの数値精度への補正がない。数値を表すStringをNumberへ変換することもない。日付シリアル値、日付専用書式、boolean専用型、数式要素は生成しない。先頭が「=」のStringもinlineStrであり、本生成器は数式へ変換しない。

文字列セルは、まずコードポイント単位でXMLに使用する文字を選別する。保持する文字はU+0009・U+000A・U+000D、U+0020～U+D7FF、U+E000～U+FFFD、U+10000～U+10FFFFであり、それ以外は除去する。補助文字はコードポイント単位で保持し、孤立サロゲートは除去する。NULLは空文字として扱う。

選別後に、&、<、>、二重引用符、単一引用符をそれぞれ&amp;、&lt;、&gt;、&quot;、&apos;へ置換する。選別後の文字列が非空で、先頭または末尾のcharがCharacter.isWhitespaceに該当する場合だけ、t要素へxml:space="preserve"を付ける。trim・文字数切詰めは行わず、ヘッダー中の改行も残す。

シート名と結合範囲にはXMLエスケープを適用するが、セル本文の文字選別は適用しない。シート名の31という制限はUTF-16コード単位数であり、31コードポイントや31バイトではない。補助文字の途中で切る可能性や、制御文字が残る経路を排除する実装はない。結合範囲も構文・重複・重なり・シート内外を解析せず、結合先の値を整理しない。

列幅・表示固定・印刷スタイル

表示長はコードポイントごとにU+007F以下を1、それ以外を2として加算する近似値である。実フォントの幅やバイト数ではない。改行も行分割せず1として数え、XML不適合文字の除去前の値で算定する。先行行と101件目以降の明細は算定対象にしない。幅5～40の指定はExcelの自動調整要求ではなく、固定のcustomWidthである。

先行行なしでは1行目、先行7行では1～8行目を固定する。固定表示と印刷時の繰返しヘッダーは別機能であり、印刷タイトル行を登録する定義はない。フィルターは先行行を除いたヘッダー・明細範囲へ設定する。

電話番号はDBの取得値から数字を抽出してASCII数字へ寄せ、先頭0を整理した後、9桁または10桁で0始まりでない場合に0を一つ前置する。両出力とも結果はStringであり、数値セルへの変換で先頭0を失う経路ではない。

店舗別の日付はRepositoryのgetString結果を追加の書式変換なしで渡す。日次・月次の日付はNULLまたはtrim後空欄なら空文字、それ以外はDateUtil.toAccessWarekiでR8.06.11のような形式へ変換する。形式不正や和暦変換の対象外の日付は、行変換・上部レイアウト作成時にIllegalArgumentExceptionとなり、生成器へ到達しない場合がある。

日次・月次の担当者コードはNULLなら空文字、それ以外はString.format(Locale.ROOT, "%02d", value)による最低2桁のStringとなる。3桁以上は切り捨てない。店舗別はIntegerを渡すため、同じ担当者コードでもセル型と表示用ゼロ埋めが異なる。

店舗別出力との接続

Actionは職員確認後、BRANCH_NOをNULL→空文字・trimしたStringとしてBeanへ保持し、正のIntegerへ変換する。空欄または変換結果NULLを先に拒否し、続いて3文字超またはASCII数字以外を拒否する。ブラウザーのexcelBranchのmaxlength=3とは別のサーバー検査である。店名照会で名称が得られなくても、対象予約の検索へ進む。

buildByBranch(int)は画面用の店番検査を繰り返さず、受け取ったintで検索する。結果は請求予定日降順、担当者コード、顧客番号の順で行配列へ移す。0件なら生成器を呼ばず、ファイル名空文字・空配列・件数0を返す。Actionは店番・取得済み店名を保持し、「入力された店番には対象データがありません。」としてExcel画面へ戻す。

非0件では本生成器の基本入口を呼ぶ。N件の場合、ヘッダーは1行目、明細は2行目から、使用範囲とフィルターはA1:R(N+1)となる。ファイル名は年金データ_店番_yyyyMMdd.xlsxで、店番は最低3文字まで0を前置する。サービス自体に3文字超を切り捨てる処理はない。日付部分はDateUtil.todayIso()からハイフンを除いて作る。

日次・月次出力との接続

Actionは職員確認後、職員番号・日付・削除基準日をtrimしたString、出力区分をbooleanとしてBeanへ保持する。POST・CSRF照合、いずれかの区分選択、職員番号が空欄または8文字以内のASCII数字であることを順に確認し、通過後に要求DTOを作る。日次と月次のモードはActionが指定する。これらは抽出制御値であり、生成器の明細列へそのまま移す入力ではない。

サービスは要求NULL、全区分未選択、モードNULLを拒否する。日次は対象日を開始日・終了日に使用し、月次は両端を解析して開始日が終了日より後なら拒否する。職員番号空欄は全職員、それ以外は整数の更新者指定となる。サービス単体では大文字小文字を問わないALLも全職員にするが、通常Actionの数字検査からこの文字列は渡らない。

必須日付の検査はtrim後の空欄に対して行い、その後のNFKC正規化で空になった値を再検査しない。全角空白だけの値等がこの経路を通ると、日次は日付条件なし、月次は両端が空なら日付条件なし、開始だけ空なら終了側の上限条件だけとなり得る。開始が非空で終了が空なら前後比較で拒否する。これらの値を生成器が再検査することはない。

期間・職員番号の解析後、削除基準日のtrim結果が非空なら整理処理を呼ぶ。整理側で正規化後に空なら0件を返して更新しない。それ以外は基準日以前の削除明細を削除し、独立してcommitする。後続出力と一体でrollbackされる処理ではない。

選択区分は新規、変更、削除の順に処理する。新規・変更は現在の予約本表の変更区分で抽出し、削除は削除明細を抽出する。職員番号による条件は明細の担当者コードではなく更新者である。取得後は店番、顧客番号、検索時の連番auditIdの昇順へ並べ替え、店番・顧客番号のNULLは先に置く。ExcelのNoはこの並べ替え後に区分ごとに1から付け直す。auditIdは永続監査IDではなく、新規・変更分も完全な変更履歴を復元する取得ではない。

検索0件の区分はWorkbookを作らずメッセージだけを追加する。非0件の区分は下表の上部レイアウトを組み立て、本生成器の拡張入口を呼ぶ。どの区分も先行7行、ヘッダー8行目、明細9行目以降となる。

シート名は「新規分データ」「変更分データ」「削除分データ」、タイトルは「年金予約【区分名】データ明細リスト」とする。ファイル名は年金予約【区分名】データ明細リスト（対象範囲＋処理周期）.xlsxで、対象範囲は「担当者別」または「全担当者」、処理周期は「日次」または「月次」となる。

区分結果のqueryNameはサービス内で作る識別情報である。Q番号は日次指定職員10、日次全職員40、月次指定職員70、月次全職員100を基数とし、新規+0、変更+10、削除+20を加える。100未満は数字の前に0を付ける。これはRepositoryへ保存クエリー名を渡す処理ではない。

結果の取りまとめとHTTP応答

店舗別結果はファイル名、内容、明細件数を保持する。日次・月次結果は選択区分すべての処理後に作り、次の分岐で名前・Content-Type・内容を決める。どの分岐でも生成ファイル情報のリストfilesと0件メッセージmessagesを引き継ぐ。filesにはQ番号を含む識別情報、ファイル名、区分表示名、明細件数を保持する。

生成Workbook数 結果ファイル名 Content-Type 内容と後続
0 空文字 Excel用 空byte配列。Actionがmessagesを空白で連結してBatch画面へ戻す。
1 生成した.xlsxの名前 Excel用 そのWorkbook。別区分の0件メッセージを.xlsxへ埋め込む処理はなく、Actionもメッセージ再表示へ進まない。
2以上 年金予約データ明細リスト（日次）.zip、または（月次）.zip application/zip 生成済み.xlsxを新規・変更・削除の処理順に格納した外側ZIP。

Excel用Content-Typeはapplication/vnd.openxmlformats-officedocument.spreadsheetml.sheetである。複数ファイルの外側ZIPは、個々の.xlsx内部にある6エントリーのZIPとは別階層である。messagesがある場合だけ「出力結果.txt」を追加し、各メッセージへCRLFを付けたUTF-8内容にする。外側ZIPもメモリ生成で、エントリー時刻を0Lにし、IOExceptionは原因付きIllegalStateException「ZIPファイルの生成に失敗しました。」へ変換する。

日次・月次は区分ごとの例外を捕捉して処理を続けない。後続区分の抽出・変換・生成で失敗した場合、先に生成したメモリ内のWorkbookだけを正常結果として返すことはない。

結果DTOはbyte配列を格納時・取得時にcloneする。日次・月次のfilesとmessagesは別リストへコピーして変更不可にする。hasContentは配列長が正であることだけを判定し、内容の妥当性や利用者の受領を判定する機能ではない。

Actionは完成した内容をwriteDownloadへ渡す。この処理はファイル名をUTF-8でURLエンコードして空白を%20へ変え、response.reset、Content-Type、attachmentのContent-Disposition、配列長のContent-Lengthを設定した後、出力ストリームへwrite・flushする。正常終了時のAction戻り値CSVは共通Servletのforward抑止値であり、CSV形式を生成したという意味ではない。

呼出経路 例外の扱い 応答・状態の境界
店舗別Action 個別catchなし。検索・生成・送信のExceptionは共通Servletへ伝播する。 Servletが共通エラー情報と戻り先を設定する。生成成功だけでは送信成功にならない。
日次・月次Actionのtry内 IllegalArgumentExceptionを先に捕捉し、メッセージと入力Beanを保持してBatch画面へ戻す。 サービスの入力・日付変換拒否等が対象。整理が既にcommit済みならその状態は残る。
日次・月次Actionのその他のException DBアクセス例外、生成失敗のIllegalStateException、送信IOException等は共通Servletへ伝播する。 先行するIllegalArgumentException用catchの処理をこの経路へ含めない。
共通ServletのAction実行catch Action.perform全体から伝播したExceptionを共通エラー化する。Errorは対象外。 後続のアクセス記録とJSPへのforwardはこのcatchの外にある。
再表示・ダウンロード途中以降 JSP描画や送信済み応答を生成器から巻き戻す処理はない。 共通エラー先の設定だけでは、送信済み内容の取消や最終HTTP応答を確定できない。

Batch画面への再表示では保持した入力値を用い、日付表示用変換で解析できない値は元文字列を返してからHTMLエスケープする。このforward・JSP処理はAction実行catchの外であり、再表示先の決定を描画完了と同一視しない。
