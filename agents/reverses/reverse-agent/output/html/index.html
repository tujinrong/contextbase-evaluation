概要

本索引は、年金自動受取予約管理システムの業務操作と仕様書の対応を示す。通常仕様は、本索引、8画面機能の基本設計・詳細仕様16文書、機能・共通・API・データ・DB・出力を扱う16文書の計33文書である。別冊解析報告1文書を含め、全体では34文書を対応付ける。

アプリケーションの初期入口は JSP/MENU/Login.jsp である。welcome JSPと index.jsp の転送先は同じログイン画面を指す。通常のフォーム要求は /Action.do に登録された common.ControlServlet を通り、要求識別値に対応するActionへ進む。

ログイン後のメニューは職員番号と氏名を表示し、「新規・変更・削除」「処理データ」「印刷」「EXCEL出力」の四つの入口を持つ。店番・担当者・顧客の参照は、予約入力や店舗別Excel出力から利用する共通画面として整理する。

以下のMarkdownリンクは、本索引の配置先 index.md を基点とする。文書版2.0は今回の仕様書の版であり、原プログラムの版とは区別する。

読み順と文書のつながり

業務全体、ログイン、メニュー

初めにSYS-FUNCTIONSで業務操作を確認し、SYS-ARCHITECTUREで画面から共通基盤・接続先までの構成を把握する。各操作は基本設計で利用条件と結果を読み、対応する詳細仕様で要求値、内部値、呼出しとデータ操作を確認する。

ログインはSCR-013・DET-SCR-013を入口に、共通認証をCOM-015、年金職員情報の成立条件をCOM-111で確認する。共通認証が成立しても年金側の職員確認が不成立なら、メニュー表示には進まない。メニューとログアウトの対応先はSCR-017・DET-SCR-017である。ログアウトで削除する共通属性と、残る年金セッション属性はCOM-015とDATA-CONTRACTSを併読する。

メニューの四つの入口は、順に Pension/View、Batch/View、Report/View、Excel/View に接続する。四ボタンの描画には役職による分岐がない。既存予約の変更・削除に適用する職員制限は、SCR-018・DET-SCR-018とCOM-111で確認する。

予約入力、参照、更新

予約入力の中心はSCR-018・DET-SCR-018である。店番・担当者・顧客の検索条件と選択値はSCR-016・DET-SCR-016、親画面への移送と通信はCOM-151で確認する。店舗別Excel画面からの店舗選択も同じ参照機能を使う。

予約画面の「候補」は顧客参照を開き、顧客選択後に予約読込みへ進む。予約読込みは予約データを先に検索し、予約がなければ店番・顧客番号による顧客基本情報の照会へ進む。表示する名称、受信するキー、読込み後の入力値の対応は、DET-SCR-016とDET-SCR-018を合わせて読む。

登録・変更・削除では、画面の検査、Actionによる対象の再照会、Repository内の存在再確認、DB更新、commitを区別する。各操作の条件と結果はDET-SCR-018、SQL・JDBC・件数確認・rollback・同期範囲はDB-OPSに対応する。業務更新と共通アクセス記録は別のトランザクションであり、後者はCOM-012で確認する。

列の意味はDB-LOGICAL、実DB型・NULL・制約はDB-PHYSICAL、フォームやモデルの型と保持領域はDATA-CONTRACTS、候補と保存コードの変換はCODE-NENKINで確認する。DB-INDEXの表IDを共通の手掛かりとして各定義を照合する。

出力と応答

日次・月次処理はSCR-014・DET-SCR-014、店舗別ExcelはSCR-015・DET-SCR-015、登録内容印刷はSCR-019・DET-SCR-019から読む。出力の列順、値、並び、ファイル名、0件・単独・複数ファイルの結果はOUTPUT-NENKINへ集約する。Excel生成の共通契約はCOM-150、ブラウザーの印刷表示はCOM-151に対応する。

日次・月次処理では、削除基準日が空でなければ削除明細整理を実行し、独立してcommitする。その後に抽出・Excel生成・送信が続く。後続処理が失敗しても整理が一体で巻き戻る構造ではないため、DET-SCR-014とDB-OPSで確定境界を確認する。新規・変更は予約本表、削除は削除明細を出力元とするため、これらの抽出結果を完全な変更履歴として扱わない。

登録内容印刷は明細プレビューをブラウザーから印刷する機能であり、共通ServletのGET側にある旧PDF処理とは接続経路が異なる。画面のプレビュー成立と、利用者の印刷完了は別の状態として読む。

Actionの戻り値 CSV はforwardを抑止する制御値であり、Excel・ZIP・JSONの直接応答にも使われる。実際の応答形式はAPI-NENKINと各詳細仕様で確認する。Action例外、業務画面への再表示、JSP描画時の例外、出力開始後の失敗は捕捉範囲と応答の確定範囲が異なるため、COM-012の共通境界と当該イベントの説明を照合する。共通エラー画面の表示はSCR-011・DET-SCR-011で確認する。

通常導線に接続しない資源

PensionLookupAction のJSON入口はAPI-NENKINで扱うが、収録UIからの呼出しは確認されておらず、通常画面の参照操作とは分ける。searchCandidates と findLatestAuditType も、宣言・SQLの存在と呼出元の確認状態をDB-OPSおよびREPORT-ANALYSISで扱う。

Staff系Actionは現在の実装ではメニュー表示へ委譲する。旧画面、互換Bean、未接続helper、他業務向け基盤資源の採否・統合先はREPORT-ANALYSISに対応付ける。通常導線での使用が確認できないことと、直接要求やカプセル外を含むすべての経路から到達不能であることは区別する。

文書の読み方

基本設計と詳細仕様

基本設計は論理名と業務上の意味、操作条件、画面状態、結果を説明する。詳細仕様は実コントロール、要求名、Javaの型、変換、呼出入口、保持情報、検索・保存列、JDBCとの対応を説明する。両者は「概要」「項目一覧」「イベント仕様」「補足説明」の順で読む。

項目一覧は「No、グループ、項目名、種類、入出力、DB連携項目、候補取得元、必須、形式・桁、説明」の10列で統一する。入出力はI、O、I／O、‐で示す。候補取得元、表示元、検索列、保存先を区別し、必須条件と空欄時の動作は操作別に記載する。ブラウザーの入力制限、正規化後の業務上限、DB容量は別の制約として読む。

イベント仕様は、各イベントの「処理概要」「処理手順」「処理フロー」「SQL・テーブル関連（ER図）」「DB操作の詳細」「結果・例外時の扱い」の六節で構成する。DBを使用しないイベントは、実際のセッション・メモリ保持とDB操作が非該当となる理由を説明する。長い手順の親番号・子番号は各形式で共通とし、共通仕様への参照には当該操作の引数、結果分岐、確定境界を対応付ける。

処理図と画面設計

大きい処理フローは意味単位のサブフローに分け、入口・出口・続き先と引き継ぐ値・状態を示す。本文の手順番号と図を対応させ、拒否経路、catchの順序、再表示、既に確定したDB状態を経路ごとに確認できる構成とする。

画面設計の静的HTMLは、個別JSPと共有レイアウト・CSSに基づく表示投影であり、実画面の撮影ではない。初期・既存・入力拒否などの状態ごとに、表示、候補、活性、readonly等の条件を示す。実アプリへ接続する送信先やJavaScriptイベントは設定せず、ボタンは type=button とする。元のrouteとHTTP methodは本文または非実行のdata属性で対応付け、HTMLのboolean属性は成立する状態だけに付ける。

データ定義と実装の確定範囲

論理データ仕様と物理テーブル定義は、それぞれ対象15表を一つのMarkdownと一冊のExcelに統合する。業務7表の TBL-NEN-001 ～ TBL-NEN-007、外部共通8表の TBL-N2-001 ～ TBL-N2-008 を、DB-INDEX、DB-LOGICAL、DB-PHYSICALの共通の表IDとして用いる。

SQLのJOINとFK制約、検索キーと一意性、ローカル互換DDLと本番物理定義を区別する。予約本表・削除明細の検索キー索引は非一意であり、検索キーが一致することをDBの一意制約と読み替えない。画面・モデルの型やNULL変換から、DB列の属性を推定しない。

本文では観測した実装、コメントに記載された意図、未確定事項を区別する。判断の原文位置と、文書ID・版・節・本文ハッシュの対応は別冊解析報告で管理する。

成果物と別冊解析報告

形式の対応

Markdownを仕様の正本とし、文書ID・版でHTML・PDF・Excelを対応付ける。各形式のファイルはMarkdownと同じ相対階層・ベース名を用い、形式別フォルダーに配置する。全形式への案内は output/index.html が担当する。

形式 位置付け ファイル名・内容の対応
Markdown 仕様の正本 本索引に記載した相対パスの .md 文書。
HTML 閲覧用 対応するMarkdownと同じベース名の .html。章・項目・処理番号を対応させる。
PDF 配布・印刷用 対応するMarkdownと同じベース名の .pdf。章・項目・処理番号を対応させる。
Excel シート形式 対応するMarkdownと同じベース名の .xlsx。章とシートを対応させ、論理・物理DB定義はそれぞれ一冊にまとめる。

ここで案内するExcel・PDF等は仕様書の派生形式である。年金アプリケーションが生成するExcel・ZIPや登録内容の印刷は、OUTPUT-NENKINと各機能仕様で扱う。

別冊解析報告

別冊の文書IDは REPORT-ANALYSIS、文書名は「解析差分・未解決・実行制限報告」である。文書計画上の論理パス report/解析報告.md に対応し、保管先は agents/reverse-agent/report/20261015-nenkin-all-01/analysis/解析報告.md とする。

別冊は納品Markdown群とは別に管理する。原文位置と本文の対応、読取り材料と確認範囲、旧文書・互換資源の採否、解釈の訂正、未解決事項、原プログラム等の非実行とソース由来の制限を集約する。業務・画面・データ・処理の確認には本索引の各仕様を、解析上の判断と確認範囲の確認には別冊を使用する。
