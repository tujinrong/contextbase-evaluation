# 認証入力欄と同型ペアの整列ルール改訂

版1.0／2026-10-30。利用者の「ログインのユーザーIDとパスワードは同じ長さに揃える」という指示を、表示枠の幅を揃える条件として反映した。Agent・規約の改善を対象とする。

## 対象と結果

[UIパターン規約](../../../../../docs/UIパターン規約.md)のUIP-03aを共通正本とし、WEB・WinForms・Textの3系統、Accessの専用規約、要件・基本・詳細・実装の4担当へ接続した。関連する19文書を改訂し、機械検査と各改訂文書の版・SHA-256は[検査記録](auth-input-alignment-validation.json)へ記録した。

ログインのID/パスワードは同じ表示幅・高さを共有する。縦配置は左右端、横配置は上下端と欄間を揃える。入力可能な文字数・認証条件・保存長・マスク方式は個別の条件として保持する。同型の開始/終了・下限/上限・既存の新パスワード/確認へも適用し、用途の異なるコード/名称/長文には必要な別幅を認める。

## 工程への反映

| 担当 | 今回明確にした出力と確認 |
| --- | --- |
| 要件定義 | 対象画面/項目、利用者指示を根拠にした受入条件、適用外理由。表示幅と入力上限を分ける |
| 基本設計 | 整列群と共通幅トークン、静的モック、状態別合格条件。既存11列の項目表を保持する |
| 詳細設計 | 部品ID/親/原点/単位/具体値、実装前の個別期待条件、初期化・補助部品・再表示による上書きの検査方法 |
| 実装 | 方式内の共通部品/定義を使用し、実製品の属性・矩形・描画を照合。同じ定義を使う類似画面も確認する |

「全項目を同幅にしない」という旧記載は、用途を無視した画面全体の均等化を避ける意味へ明確化した。初期/入力中/エラー/無効/再表示で片側だけ幅が変わる状態も対象とする。端末では表示セルと受理長を区別し、可視枠のない標準パスワード入力は理由付き適用外とする。GUIの寸法単位を端末へ強制しない。

## 確認と残件

規則の意味レビューでは、入力上限が異なるID/パスワード、同型の範囲入力、用途が異なる欄、補助部品/エラー表示、非表示の端末パスワード、縦/横配置を確認した。これは規則のレビューであり、アプリの実行試験・独立レビュー・利用者受入は今回実施していない。

既存Accessのフォーム生成定義では、frmLoginのtxtLoginIdが3600twip、txtPasswordが4800twipで、表示幅が異なることを確認した。Leftは共に7725twip、定義上の高さは共に480twipである。これはソース定義の読取り結果であり、今回のネイティブ実測ではない。次回の設計/実装時に、共通幅の採用値を決めて両欄へ適用し、実画面の初期/エラー/再表示と採用表示条件で確認する。

今回、既存projectの仕様・ソース・ACCDB・配布ZIPは更新していない。AccessのACCDBとZIPは直前の記録と同じSHA-256である。共通規約とAgentは新版になったため、次回の生成では今回版を入力凍結し、対象仕様と期待条件を改訂してから新しい製品を検査する。以前の製品検査のPASSを、新規則への適合として扱わない。正式評価は未実施である。
