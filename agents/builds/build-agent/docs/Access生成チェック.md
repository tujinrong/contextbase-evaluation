# Access生成時の品質チェック

版1.0／2026-10-25。build-agentがAccess方式を生成・更新する場合に適用する。方式の独立したspecRootで確定した業務桁数、入力可否、フォント、認証、単体/分割DB構成を根拠に具体化する。このチェック文書に特定題材の正解値を固定しない。

## 適用と入力

方式別共通UI/実装、基本・詳細、項目制約、正規化、DB列、開発規約を対応付ける。利用者の品質改善指示と既存仕様が異なる場合は、旧定義と新指示、適用範囲を今回の記録へ残す。仕様正本を変更しない工程では、仕様不備の根拠と次回修正案を報告する。UIのコード不備を仕様のバグとして扱わず、不足・矛盾・新要望・実装不備を区分する。

Accessの単票/連続フォーム、Label、TextBox、ComboBox、CheckBox、Rectangle、ListBox、CommandButton等の標準部品を使う。既存の非連結フォームと明示保存の契約がある場合は維持し、見た目の改善を理由に連結フォームの自動保存へ変更しない。別方式のUIやHTMLモックでAccess実装を代替しない。

## フォームと可読性

座標はTwips、文字はptとし、フォーム幅・Detail高・入力高・ラベル高・余白の換算を揃える。本文、ラベル、一覧、ボタン、ダイアログのFontName/FontSizeを明示し、既定フォント任せによる不揃いを防ぐ。利用者が読める文字サイズを先に定め、その実測字幅と部品の内側余白から欄幅/高さを決める。小さい文字へ縮めるだけで全項目を収めない。

意味を持たない装飾枠はRectangle等を使い、OptionGroupを枠線だけのために生成しない。OptionGroupは実際に相互排他的な選択を表す場合に使う。グループ見出しを枠上へ配置する場合は、文字幅に応じたラベル幅、左右余白、背景、前後関係を設定し、枠線が文字を横切らず過剰な白帯が生じないようにする。装飾部品が入力領域を覆うこと、Tab順へ入り入力を妨げることを防ぐ。

日本語・英数字・長い値を表示し、見出し、下端、入力の上下、コンボ矢印、一覧ヘッダー、エラー行、確認ボタンを確認する。主画面だけでなく確認・エラー・拡大入力のダイアログも確認する。対象Officeの32/64bit、DPI、Windows表示倍率、フォーム本文サイズを記録し、小幅/拡大ではスクロール等で必要な欄と操作へ到達可能にする。仕様HTMLのpx計測を実Accessの文字表示確認とみなさない。

ListBoxのRowSourceTypeにユーザー定義関数を使う場合は、[Microsoft公式のコールバック契約](https://learn.microsoft.com/en-us/office/vba/api/access.rowsourcetype)に合わせ、acLBOpenで呼出ごとに一意な0以外のIDを返す。丸めたTimer値をIDに使わず、プロセス内で重複しない連番等を採用し、上限到達時にも0や既存IDへ戻さない。RowSourceは明示的に空とし、列数・0始まりの行/列・戻り値とフォームの定義を揃える。描画やacLBGetValueからDAO検索・権限取得・画面の再問合せを実行しない。行値と役割別の表示文字列は描画外で取得してメモリへ保持し、フォーム終了時にそのフォームの状態を解放する。

Accessの子ウィンドウHWNDは、フォーカス移動やフォーム/ウィンドウの再作成をまたいで保持しない。ネイティブな一覧スクロールは操作の都度一覧へフォーカスを移し、その時点のHWNDが存在し対象フォームの子であることと対象一覧のフォーカスを確認する。GetScrollInfo/SendMessage等の呼出が終わるまで一覧のフォーカスを保ち、完了・失敗後に前のフォーカスへ戻す。古いHWNDが現在も存在するという検査だけで同じ一覧と判断しない。検索処理でDoEvents等によりイベントが入る間はbusy状態を維持し、検索フォームのForm_Unloadを取り消す。処理中に一覧の状態を解放したりフォームを閉じたりさせない。

## 入力状態とマスク

新規・編集・参照・処理中・検査エラー・リセット・保存後について、Locked、Enabled、TabStop、初期フォーカスを明示的に設定する。共通初期化の既定値や直前モードを引き継がない。自動採番IDは新規でも入力させず、新規だけ利用者が指定する業務キーは新規で実際に入力できるようにする。既存キー不変はUIと保存入口の両方で検査する。エラー後も編集中値と適切な入力属性を保つ。

編集フォームの終了可否判定では編集状態を破棄せず、Detach失敗等でForm_Unloadが取り消された場合も入力値と状態を保持し、状態解放は終了が確定したForm_Closeで行うことを回帰試験する。

VBAで引数のない手続を行頭の`EnsureMaps:`のように書かない。コロンで区切った呼出のつもりでもラベルと解釈され、初期化が実行されない。`Call EnsureMaps`または独立した呼出文を使う。検索フォーム経由だけでなく、未初期化の状態から編集フォームを直接開く経路も検査する。初期化失敗は段階を診断できるようにし、半初期化のまま保存を許可しない。試験コード内の取消・fixture清掃等でも、呼出が実際に行われた結果を確認する。

VBEへのソース投入がWindowsのANSIコードページを経由する場合は、非表現の中点・補助文字等を黙って`?`へ変換しない。必要なら`ChrW`とサロゲートの組合せで実値を構築し、フォームの実表示とDB値を確認する。同じ投入経路を通るVBAの文字リテラルだけを期待値にすると、実装と期待値が同時に文字化けして偽合格になり得る。外部から独立したUnicodeコードポイントで照合する。

Windows PowerShell 5等を試験に使う場合は、スクリプト読込みの文字コードも固定する。UTF-8の非ASCIIリテラルを既定ANSIとして解釈させず、対応するBOM/明示読込みを使うか、試験値と期待値を独立したコードポイントから構築する。文字化けした試験値で製品不具合を判定せず、試験ハーネス・VBE投入・製品値のどの段階で変化したかを区別する。

定型項目はInputMask、Format、IME設定、コンボのLimitToList等のAccess標準機能を適切に採用する。全項目へ固定長マスクを一律適用しない。InputMaskの必須/任意桁、リテラル、リテラル保存指定、プレースホルダー、コピー/貼付、全選択、Backspace/Delete、未完成入力を具体化する。Formatは表示書式、InputMaskは入力補助、保存検査は業務制約として区別する。コードや郵便番号等の先頭ゼロを数値化で失わせない。

マスク表示の桁、TextBox.Value、フォーカス中のText、raw原入力、正規化後の保存値を対応表で定義する。郵便番号等では区切り表示と数字のみ保存を区別し、DB物理容量やraw許容長をマスクの桁数として使わない。必須は完成後の桁検査でも保証し、空・Null・不完全マスク・過長・不正文字を受理しない。マスクを付けてもプログラムによるValue代入やDAO書込みは別経路なので保存入口で再検査する。

製品機能の根拠はMicrosoft公式の[InputMask](https://learn.microsoft.com/en-us/office/vba/api/access.textbox.inputmask)、[Format](https://learn.microsoft.com/en-us/office/vba/api/access.textbox.format)、[AcControlType](https://learn.microsoft.com/en-us/office/vba/api/access.accontroltype)（2026-10-25確認）。マスク3区分の意味、表示と保存の違い、プログラム経由入力の検査範囲を確認し、採用Officeで実測する。

NFKC、全角数字、空白、許可区切り文字等を受理する既存仕様とマスクの受理範囲を照合する。マスクが既存の受理値を拒否する場合は、正規化する補助入力/貼付経路を明示するか、利用者の指定に基づく契約変更を記録する。自動切捨て、無関係な記号の黙削除、raw上限を迂回する正規化をしない。日付は実在日・暦境界・空/不正原入力を保存側でも検査し、Accessの自動補正だけで日付の正当性を決めない。

## 初期確認用データ

[共通データ規約](../../../../docs/テストデータ整備規約.md)に従う。新しい確認用ACCDBへ必要マスタと架空の業務行を用意し、候補・検索・新規保存・編集を起動後に確認可能にする。既存利用者ファイルを再ビルドや起動時に初期化しない。単体ACCDBが確定済みの場合は、確認用業務データのために外部ファイルやリンクDBを新たな実行必須条件にしない。

通常配布データと異常系/大量/競合fixtureを分ける。役割表等は方式固有の認証契約に従い、確認のために無条件の管理権限付与や認証回避を加えない。参照マスタだけで候補が作れず登録できない状態、学生が0件で一覧操作を確認できない状態を防ぐ。初期件数、業務キー、日付基準、再投入方針、操作手順、未実施を固定manifestへ記録する。

投入全体の原子性をDAOトランザクションで保証しないビルドでは、新規の隔離staging/fixtureでだけ初期行追加を許可し、全作成・検査成功後に最終ACCDBを置換する。完成配布物では初期行追加の許可を無効にし、再確認で不足キーが見つかっても挿入前に停止する。既存サンプル行の利用者編集/論理削除を保持し、構築途中の失敗を公開ACCDBや既存利用者ファイルへ反映しない。行ごとのトランザクションをデータセット全体のRollbackと呼ばず、採用した公開境界と失敗時の最終ファイル無変更を検査する。

## 実機試験と証跡

VBAコンパイル、DAO制約/業務試験、属性/座標検査、実キーボード/貼付操作、画面の目視確認を別に実施・記録する。TextBox.Valueへの代入だけで新規入力やInputMaskが動いたと判定しない。少なくとも新規フォームの業務キーへフォーカスして文字を入力し、登録→検索→再読込でキー・保存値・書式を確認する。既存編集/参照の保護、モード移動、入力エラー後の再入力、取消後の無保存を検査する。

COM自動試験はVBE・CodeModule・CommandBars・DAO等の子RCWを明示的に解放し、GC/終了待機をCloseCurrentDatabase/Quitより先に行う。試験開始前の既存プロセスと今回の所有Accessを区別し、所有プロセスの終了コード0と、検証区間全体のWindows Application Errorに今回起動したAccessの異常終了がないことを確認する。関数のPASSだけで実行全体を合格にしない。

マスク対象は空、桁不足、正しい桁、過長、先頭ゼロ、区切りあり/なし、貼付、全角/許可区切り、Delete/Backspace、途中位置の修正、既存読込、再保存を対象仕様に合わせて確認する。入力補助経路と通常入力の保存結果を揃え、拒否時のエラー・入力保持も確認する。画面検査は見出し・グループ・一覧・ダイアログを含み、重なり・文字切れ・フォーカス・Tab順を確認する。

貼付はCtrl+V/Shift+Insertのイベント橋だけでなく、リボン/メニューのPaste、ネイティブWM_PASTE等の到達可能な経路も確認する。InputMaskが過長のクリップボード値を一部だけ取り込む場合、取り込み後の7桁検査だけではraw全体の拒否を証明できない。全量検査へ通す範囲を決め、経路ごとの通常値・過長値・raw上限超過を同じ受理/拒否契約で試験する。

一覧の実機試験はフォームを開く→検索→大量行の描画/スクロール→閉じる操作を反復し、再起動からの再実行も含める。対応上限が1万行の場合は1万行で試験し、RowSourceTypeの再問合せ、フォーカス移動、busy中の終了取消、終了後の再表示を確認する。試験が作成したAccessプロセスは正常終了まで確認し、クラッシュ・RPC切断・異常終了があれば、直前までのアサーションが通っていてもその実行を実機PASSにしない。段階、反復回数、対象プロセスと終了結果を記録し、他の利用者プロセスを終了させない。

ネイティブクラッシュの調査では、確認した不適切な寿命管理と、実測で確定した原因を分ける。今回追加したコールバックID、描画外キャッシュ、都度HWND取得、busy中終了禁止はそれぞれの危険を減らす保護であり、単一のクラッシュ原因が証明されたとは扱わない。保護追加後も該当版で反復試験を行い、未解決・未実施を残す。実装側の保護追加を理由に原仕様の業務条件を変更しない。

クリップボードを使う自動試験はSTAで全明示形式を変更前に実体化し、復元できない形式があれば変更前に停止する。元データは復元確認まで失わないよう、必要なら方式内.tmpへ利用者単位で暗号化した一時snapshotを保持する。変更/復元には上限付きretryを設け、finallyでCOM終了処理より先に元形式・内容を復元/照合し、成功後だけsnapshotを削除する。復元失敗は試験FAILとして以後のClipboard変更を停止し、別STAプロセスから回復できる手段を残す。元Clipboard本文を通常ログ・buildの最終成果・Gitへ含めない。

試験は.tmp内の隔離ACCDBへ実行し、最終配布ACCDBに試験で増減した行やテスト用権限を混ぜない。今回のソース/生成器/データ/ACCDBのハッシュ、Access版/bit、表示条件、試験コード、コマンド、実測件数と結果、目視範囲、未実施をbuild/test-results/の固定先へ残す。前回のPASSやモックの見た目を現在の実機合格として使わない。未検証の32bit/別DPI/利用者環境や正式受入は別状態で報告する。
