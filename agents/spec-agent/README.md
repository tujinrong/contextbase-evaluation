# spec-agent

定義版8.0／2026-10-23。指定projectの仕様書をCodexが作成・改善するための運用入口。

## 使い方

[AGENT.md](AGENT.md)が役割・工程・境界の契約、[PROMPT.md](PROMPT.md)が起動指示と実行要求の指定項目である。PROMPT.mdと対象project・方式・specRoot・今回の改善要求をCodexへ渡す。専用の業務アプリや自動採点プログラムを起動する構成ではない。

対象は実行要求で選ぶ。新規作成だけでなく、既存文書を入力にした局所的な改善を扱う。ユーザー指定の正本パスを優先し、指定外projectや方式へ変更を展開しない。全体docs・agentsの役割定義を読み、許可された入力の版とハッシュを固定してからAIが仕様本文を執筆する。

検索画面の改善では、業務で使う条件だけを残す理由、空条件・初期表示・クリア・一致方式・並び順・件数・ページングを仕様へ記述し、主要操作を近接させて余白を整理する。検索UIを簡素化しても、登録項目・保存制約・権限制約の削除とは扱わない。画面サイズと状態を固定して1画面の達成範囲を確認する。

2026-10-23のPilotは `test-project1/srcs/CSharp_ASPNET/spec`。小規模の学生管理に合わせた検索条件とレイアウトの改善を行う指定例をPROMPT.mdへ置く。これを将来のprojectや他方式への実行許可として流用しない。

## 成果物と確認

仕様の正本はMD。画面を変更したら、そのMD埋込みHTMLと同じ内容で単独HTML・PNGを更新し、実際にPNGを閲覧する。文書版、入力/出力SHA-256、ブラウザー版、画面サイズ・倍率、確認状態、計測と目視の結果を残す。新しいcloneで記録が必要なら未使用のrunIdで再作成する。

実行記録の既定先は選択projectの `report/<runId>/`。記録本体のGit管理可否は[配置規則](../../docs/リポジトリ構成.md)とルート.gitignoreに従い、Git除外でもローカル記録を保存する。仕様出力と参照用画面資源は指定specRootに保存する。既存レポートを上書きしない。

本文レビュー、構造検査、描画・目視、実装、ビルド、DB/実機試験、正式採点を分けて報告する。構造や描画のPASSは正式合格を意味せず、未採点ならformalScoreはnull。入力・既存QAを維持し、重大な矛盾は根拠と再開条件を残して該当部分を保留する。
