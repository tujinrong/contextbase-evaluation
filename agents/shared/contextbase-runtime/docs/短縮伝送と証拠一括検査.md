# 短縮伝送と証拠一括検査の契約

版0.1／2026-10-26。証拠検査の同一operation内の重複除去と、contextbase-wire/1による可逆な短縮伝送を定める。[ソース事実索引契約](ソース事実索引.md)と[機能分類境界](機能分類境界.md)の根拠・分類条件は維持する。新規回帰・実Dの最終結果は[実装ガイド](../../../reverse-agent/docs/ContextBase初期実装.md)へ記録する。

## 1. 実施する範囲

本改訂は、A：証拠の一括検査、B：task専用の短縮参照を実装対象とする。C：実際に必要な原文だけを複数回取り寄せる調査ループは未実装である。作者と独立検証者へ全索引・全inventory・全原文を渡し、用途を説明する。queryがあることを、モデルが真に按需検索している証拠へ読み替えない。

原文や未知を削ることで短縮せず、検査の重複と通信表現を減らす。目録の説明・rationale・alternative・unknown理由は一つずつ簡潔に述べ、内部条件・分岐・例外・状態遷移・詳細な呼出差は後続層の対象とする。ただし必要record、反証、未解決を省略して件数や文字数を減らさない。

## 2. operation単位の証拠検査

verify_evidence_manyは一回のoperationの開始・終了時に完全な封印snapshotを検査し、そのバッチ内では各引用ファイルを一度read／hashする。各evidenceは正確なフィールド集合、許可path、原文hash、整数型の行範囲を個別に検査する。boolを行番号へ受け入れず、範囲外や余分なフィールドを通過させない。

contractsとcatalogは証拠を集めて一括検査し、followupの許可pathも同operation内で一度取得する。operation間の永続キャッシュでsource検査を省かず、後続操作で原文の変更を再検知する。開始時の合格だけで、処理終了時まで材料が同一だったと断定しない。

## 3. 明示compactモード

```text
contextbase-discovery run --work WORK --inline-sources --compact
contextbase-discovery retry --work WORK --feedback CANDIDATE_SHA256 --inline-sources --compact
```

設定利用時は--work WORKを--config CONFIGに置き換え、必要なら--profile NAMEを指定する。--compactは明示した場合だけ有効で、source-fact対応discoveryに限定する。省略時はcanonical形式の従来互換経路を使う。relationship／behaviorのcompact実行を提供済みとしない。

保存taskのwireBindingはschema、task、context、snapshot、source-fact index、candidate、viewに束縛し、wireSha256で同一性を確認する。fileはp<tasknonce>_<番号>、factはkind:<tasknonce>_<番号>のtask固有参照へ置き換える。別taskのaliasを使い回さない。

モデル入力の事実表も短縮参照を使う。出力evidenceは{file,startLine,endLine}とし、factUsage.factIdsは対応する短縮fact参照を返す。モデルはtaskのwireSha256を正確に返す。完全な原文は保持し、短縮参照は意味判断の代用品にしない。

## 4. ホストによる正規化と再検査

1. raw出力をcompact専用の厳密schemaで検査する。fileの本task enumとfact alias patternでも事前制限し、展開時のホストlookupを維持する。
2. 同taskのwireBindingだけからfileを正確なpath／sha256へ、fact参照を正確なcanonical fact IDへ展開する。
3. canonical応答に通常の責務、fact利用、原文、分類、unknown／followupの全gateを適用する。
4. raw／canonicalの内容hash、materializationとprovenanceを保存する。adopt時に展開を再実行し、一致を確認する。

不正・過時alias、異なるsnapshot／index／candidate／view、bindingや保存内容の改変は明示拒否とする。ホストは省略された業務情報や未知を推測で補わない。展開は同じ情報の可逆な表現変換であり、原回答を意味的に修正して合格させる操作ではない。

portable record／handoffの契約は変更しない。aliasはtask内の伝送表現に限定し、正式な根拠とfact IDはcanonicalのまま受け渡す。独立検証のfactUsageCheckやcatalogの受入条件も維持する。

## 5. 測定と実績の区別

前回の保存回答を展開・再符号化した受動的replayでは、作者応答86055→58915文字（31.5%減）、検証応答34386→22253文字（35.3%減）を確認した。compact contextは作者625065・検証706795文字だった。前回prompt779305／885954文字とは政策等も異なるため、厳密な同条件比率として扱わない。

canonical証拠検査のreplayは作者0.394秒／完全snapshot検査3回、検証0.230秒／2回。別の20参照の単件検査は2.107秒／20回だった。これは局所的な受動replay・制御基準であり、モデル推論時間やD全体の速度改善を証明しない。

scope schema修正前の回帰は確認済みだが、compact初回実Dは封印範囲gateで拒否された。scope schema修正後の構造回帰は確認済みだが、実Dは意味参照で拒否された。repair追加後の回帰は確認済みで、実repairは全体機械・独立検証を完了したがcatalog未解決で未採用である。前改訂220件回帰・69候補未採用を本compact機構の合格へ流用しない。新work .tmp/contextbase/csharp_aspnet-compact-repairでDだけを実行し、source／request／固定outputは保持する。R／B、原アプリ・SQL・DBは実行しない。性能、fact利用の意味検査、catalog採用、人手受入れを分けて報告する。

## 6. 封印範囲のtask schema

ホストはauthorizedSourcePathsを封印inventoryだけから固定し、followups.pathsをそのenumへ制限する。manifest.omittedは不足材料の説明であり、許可された原文pathへ昇格しない。未取得の必要材料はpaths:[]とquestion／unknownで記録し、存在しない根拠anchorを作らない。

followupのrequirementは対象stageに応じた本scopeの元goal義務ID又はnullに制限する。unknownのrelatedRequirements／blocksRequirementsと検証decisionのblocksRequirementsは元goal全IDのenumを使う。これらのschema制約は、従来のsubset／stage／membershipを検査するホストgateに追加し、権限や対象範囲は拡大しない。

compact初回のraw展開は成立したが、omitted pathをfollowupへ指定して封印範囲gateが拒否したためcandidate・独立検証・採用は生成していない。元応答を手作業修正せず、新workで再調査する。詳細と修正後検証状態は実装ガイドを参照する。

## 7. 拒否草稿の明示repair

```text
contextbase-discovery init --source SOURCE --request REQUEST.json --work FRESH_WORK
contextbase-discovery repair --work FRESH_WORK --from-work OLD_WORK --task OLD_TASK --record common.date --inline-sources --compact
```

repairは新規抽出とは別の、ホストが明示指定した差分回復である。未使用のfresh discovery workに、host実行後に失敗した原応答をcontextbase-rejected-draft/1の未信頼seedとして取り込む。snapshot／request／source-fact indexを厳密照合し、旧エンジンの合格や採用権限は継承しない。旧taskと失敗・transportの原記録を監査へ保持する。

モデルは指定recordをexpectedRecordHashに束縛して全置換する。key／kind／ownerRequirement、coverage、unknown、followup、未指定recordは保持する。factUsage=nullは当該recordの元usageを保持する指定であり、正本にnullの利用証跡を追加する意味ではない。同じrecordKeyのfactUsageだけ明示置換できる。

追加・削除、scope／identity／unknownの変更が必要ならstatus=unresolvedを返す。ホストは存在しない意味参照を推測で埋めず、許可された置換だけ合成する。raw patch、seed、combinedのhashと由来を保存し、合成後の全体に通常machine gateと別文脈の独立verifyを適用する。adopt時にもseed・patchから再生して一致を確認する。

旧草稿をそのまま受入れたり、限定patchだけを独立検証して全体合格へ広げたりしない。回復結果の受入れと未解決を通常の基準で判定する。fresh抽出時間と差分回復時間は別に測定する。本機構の回帰は確認済みで、実repairは全体機械・独立検証を完了し、fact利用とcommon.date修復は支持されたがcatalog未解決で未採用である。候補化の回復と業務範囲の受入れを区別する。
