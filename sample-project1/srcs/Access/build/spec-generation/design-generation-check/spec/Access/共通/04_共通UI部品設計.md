# 共通UI部品設計（言語非依存）

版：8.5／2026-10-28。文書ID：COM-STU-004。

## 基本方針

本方式はWinForms系の画面設計とする。Accessの単票フォーム・標準コントロールの特性に合わせ、項目の表示桁数から幅を決める。今後の追加画面もラベル位置・入力左端・同種部品の高さを揃え、Twips/ptの寸法と拡大時の動作を明記する。学生検索は既存の全件取得・ListBox内スクロールを使用する。

本書の「部品」は利用者から見た共通の機能を表す。特定のHTMLタグ、Windowsコントロール、XAML、Vueコンポーネント、端末画面ファイルを指定するものではない。物理部品とイベントは方式別仕様で決定する。

### 基本設計の項目表と処理記述

基本設計の項目一覧は「項目ID・項目グループ・項目名・コントロール・必須・入力制限・フォーマット・初期値・DBテーブル名・DB項目名・備考」の11列とする。詳細仕様と共通09の制約正本はそのまま使い、業務値を変更しない。

必須は〇、任意は空欄、非該当は半角-、条件付き必須は条件付とし、成立条件を備考に記す。値が実際に空なら空欄、属性が非該当なら-とする。真偽の表示は〇/空欄、DBは既存の真偽型のままとし、未設定・NULL・falseを混同しない。検索在籍の初期選択は01/02、全解除は全区分で、コード値の0や00を空欄扱いしない。

初期値は新規/初回の実値。編集は保存値、表示は取得値、操作ボタン/機能キーは初期値-で、操作可否はイベントの役割・モードに従う。検索一覧の初回は未検索で行なし、表示欠損は既存の表示規則、参照マスタ欠落は不整合とする。旧表の「システム設定」「権限・モードに従う」は行ごとの埋草にしない。

入力制限で原入力と正規化/保存後の長さを区別する。文字数の数え方・受理文字は共通05・11、日付は共通07の既定を維持し、端末の表示桁/バイト領域やGUIのMaxLengthへ読み替えない。候補・N/CHK/EV・条件・未保存/保存先の固有関係は備考へ残す。DB2列は参照・検索・保存の論理対応であり、更新しない候補元も区別する。

4項目以上の処理手順は意味単位の大項目と小項目へ階層化し、同階層は最大4項目・深さ最大3階層とする。実行順・例外・既存IDを維持し、番号で参照する場合は階層番号も同期する。イベントの判定表は共通CHKと実メッセージを結び、操作なし/取消/未確定/成否不明を成功へまとめない。

## 画面の標準構成

見出し→メッセージ→項目グループ→主要操作の順とする。検索は条件と結果、登録は基本情報・住所連絡先・在籍所属・緊急連絡先・備考・理由に分ける。文字の必須印と説明を併記。参照専用値を編集可能に見せない。削除操作は保存と明確に区別する。

## 共通状態

| 状態 | 動作 |
| --- | --- |
| 初回・クリア | 初期条件。学生一覧は未検索 |
| 処理中 | 次の保存・削除・検索を抑止。単なる連打防止でDB排他を代替しない |
| 入力不備 | 入力値保持、エラー一覧と該当項目を関連付ける |
| 0件 | 該当なし、一覧空、選択行なし |
| 10,000件超 | 条件追加の案内、一部だけの結果は出さない |
| 条件変更未実行 | 新条件未反映を明示。並び替え・再表示は最後の実行条件 |
| 版競合 | 自動上書き・自動再読込をせず、入力保持と再読込案内 |
| 通信結果不明 | 再保存の前に検索確認。成功とも取消成功とも決めつけない |

## コード・クラス連動

検索は学籍番号・氏名・クラス・在籍の4条件だけ。クラス候補は全年度・停止・期間外を含み、一体識別する。変更時は未反映表示だけ。登録の年度・学年変更は不適合クラスを解除・通知し、古い候補応答を採用しない。

在学・休学は終了日を空、クラス必須。卒業・退学は終了日必須、クラス任意。コードやクラスの既存値が停止・期間外でも表示を消さない。保存時の有効性は保存済み値と比較して判定し、画面の「未変更」申告を信用しない。

## 操作・アクセシビリティ

キーボードで入力・検索・保存・取消を行えるようにする。確認は取消を既定とし、改行やEnter入力が削除・別人続行を不用意に確定しない。エラー項目への移動方法を用意する。色だけに意味を依存させず、使用不可・警告・必須を文字で表す。

一覧の長文は折返し・横スクロール・詳細参照等で全文を確認可能にする。全一致一覧は上限以内で一括取得し、物理的な表示行数はListBoxの高さで決める。文字変換不能のとき元値を代替文字で上書きしない。方式ごとの入力制約・補助編集方法・実機確認事項を詳細仕様へ記載する。

個人情報を画面アドレス、ブラウザーや端末の無制限永続領域、通常の障害ログに記録しない。画面を閉じる際は未保存変更確認を行い、正常保存を確認した後だけ未保存状態を解除する。

### 画面面積の設計確認


#### Access標準フォームの配置・寸法

frmStudentSearchは非連結Single Form（単票）を使う。Label／TextBox／ComboBox／CheckBox／ListBox／CommandButtonを配置し、標準の灰色フォーム背景、白い入力面、細いFrameで構成する。強い色帯・カード・角丸・Webの画面幅による縦積み切替は使わない。HTML/CSSはネイティブ部品の配置図を文書に埋め込む媒体であり、HTML実装へ変更する指示ではない。

フォーム外形1216×約575 CSS px相当を96 DPIで設計する。AccessはLeft／Top／Width／HeightをTwipsで指定し、1 CSS px=15 twips、1 pt=20 twips、96 CSS px=1440 twipsとして換算する。本文文字は9pt、入力高24px=360twips=18pt、行ピッチ28px=420twips、操作高26px=390twips。DPI・Office版・フォントで実画面の字幅は変わるため、Access実機で最終確認する。

条件行の開始位置は本文左端、入力左端をラベル列の後へ揃える。学籍番号は15文字を見込んで136px（2040twips）、氏名は全角8文字＋内側余白で120px（1800twips）、クラスは年度・学年・コード・名称を識別できる440px（6600twips）とする。在籍チェックを次行へ揃え、検索・クリアを左、登録・メニューを右へ配置する。選択候補が欄幅を超える場合はComboBoxのListWidthを広げて候補全体を確認できるようにする。

lstStudentsはRowSourceType=StudentListCallback、ColumnCount=8、BoundColumn=1、先頭StudentId列の幅0を維持する。表示7列の幅は学籍番号136／氏名とカナ340／生年月日152／年度学年164／クラス244／在籍72／操作案内80px相当（合計1188px）。ColumnWidthsへは各値×15のTwips換算を適用する。氏名とカナは同一セルの単一行文字列であり、複数行セルやセル内ボタンを仮定しない。

ListBoxの表示高268px、行高24px相当は静的図示の寸法である。検索一致0～10000件を一括取得し、一覧内はListBoxの縦スクロールだけで移動する。操作案内列は文字でありcmdOpenSelected／ダブルクリックから非表示StudentIdを使う。参照権限は新規非表示・参照案内とする。長い氏名／カナ・クラスは選択行全文欄とShift+F2の拡大表示で確認でき、表示省略を保存値へ反映しない。1366×650／1280×650のフォーム領域では通常の主要操作を表示し、狭幅・拡大時はフォームのスクロールで到達させる。リボン・ナビゲーションを含むAccess全ウィンドウ寸法ではない。

#### Access標準の単票編集フォーム・寸法

frmStudentEditは非連結Single Formのまま、左列を基本情報／住所・本人連絡先、右列を在籍・所属／緊急連絡先／備考・理由とする。灰色背景・標準Label／TextBox／ComboBox／Frame／CommandButtonを用い、同じ行の高さ・ラベル左端・入力左端・グループ左右端・下端操作を揃える。色帯のカード、全入力を同じ幅へ引き延ばす配置、画面幅によるWeb型の縦積みは採用しない。HTMLはAccessのフォーム設計を図示する媒体である。

外形幅1216px=18240twips、左右余白12px=180twips、列幅585px=8775twips、列間18px=270twips。各Frame内のラベル列120px=1800twips、ラベルと入力の間隔8px=120twipsで揃える。文字9pt、入力高24px=360twips=18pt、行ピッチ28px=420twips、操作高26px=390twips。1 CSS px=15twips、1pt=20twipsは96 DPIの設計換算であり、実AccessのDPI・フォント差の実測は別途行う。短い欄の右端まで同幅にせず、同種の欄を同幅とする。

字幅は9ptで全角を約12px、数字・記号を最大約8pxとする設計目安であり、Unicode文字数の検査式ではない。raw／正規化／保存上限と表示幅を分け、MaxLength等の物理ガードは補助文字のUTF-16容量も確保する。TextBoxの表示範囲で切り捨てたり、DB型を狭めたりしない。ComboBoxの候補はListWidth／選択全文欄、長文はTextBoxのカーソル移動・複数行・Shift+F2で全文を確認する。

通常編集は1366×650／1280×650、100%のフォーム本文領域で全入力と更新情報・操作へ到達できる配置を設計確認する。REG-001～034、新規19入力／通常更新18入力＋生成照合2、必須・権限・保存契約を維持する。狭幅・拡大・複数エラー時はフォームをスクロールし、項目エラーとSetFocusで該当位置へ到達する。レイアウトを縮小して文字を潰さない。

重複／論理削除／未保存破棄は標準の別ポップアップフォーム（Modal=True、PopUp=True）へ配置し、取消を既定とする。未保存破棄はfrmDiscardConfirm、削除はfrmDeleteConfirm、重複はfrmDuplicateConfirmへ分ける。frmDuplicateConfirm.lstCandidatesはListBox、REG-032～034は一覧・続行・取消へ対応する。frmDeleteConfirm.txtReasonはREG-026の削除理由で、削除時だけ使い、一般の編集中値は保存しない。確認フォーム表示中は背景フォームを操作不可とし、確認情報の10分期限・再認可・版検査・監査確定を変更しない。

## 和暦生年月日部品

UI-15は元号・年・月・日と項目エラーを持つ。候補は[共通暦定義](07_日付・和暦仕様.md)。元号名と識別値を分け、元年は表示に使用する。元号変更時は年範囲と境界日を再検査し、日付を自動補正しない。原入力と正規化日付を分離する。入力4値が空の新規状態と、未知元号・不正日を区別する。

一覧・参照・重複確認も共通16で和暦を表示。UI-04を全体的に和暦へ切り替える実装は不可。各方式はUI-15の物理コントロール名と保存側変換入口を方式別共通仕様に定義する。
