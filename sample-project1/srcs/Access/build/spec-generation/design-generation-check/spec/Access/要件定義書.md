## 概要

既存仕様の目的・必要な振る舞い・業務制約を要件として再構成した。確定区分の「既存仕様から再構成」は現在の設計契約を示し、新たな利用者の合意を意味しない。「利用者確定前提の継承」は根拠資料に明記された指定だけに適用し、「既存設計案」は承認未確定の案として残す。要件IDは本project・本方式内で識別する。

入力は根拠資料表の文書ID・版・SHA-256で固定する。既存の基本・詳細・共通・DB定義本文を変更せず、今回の出力と索引を追加する。ソース・実DB・他方式・評価資料は要件の根拠として読んでいない。受入条件は将来の確認条件であり、今回の試験結果ではない。

## 目的と業務範囲

単一校の学生基本情報を安全に検索・登録・編集・参照し、在籍区分と現在／最終所属を把握する。仕様作成、順生成、仕様復元を比較する評価題材として、要件と既存機能・項目・チェックIDの対応を残す。

対象は学生検索と学生登録の業務2画面、管理者向けクラス・コード保守処理、保存に伴う操作履歴である。登録画面は新規・編集・参照を共用する。補助画面・確認パネルはこの2画面の内訳とし、マスタ保守画面を新設する要求へ広げない。

成績・試験・科目・出欠・学費、帳票・CSV、一括更新、年度別所属履歴・兼籍・将来異動予約・自動進級、郵便番号と住所の外部照合は対象外。利用者マスタと独立ログイン画面の新規開発も含めない。
