## 概要

仕様セット7.1の差分はテーブル別分冊と対応する評価・記述規約。画面・業務仕様を変更していない文書は7.0のまま有効。

[プロジェクト情報](../プロジェクト情報.md)／評価／[全体規約](../規約/全体/仕様書作成ルール.md)。項目長は[設計基準](11_項目長設計基準.md)。基本/詳細/共通/DB定義の再掲値を照合する。採点表は仕様入力フォルダーから独立。

2026-10-25改訂: 本方式はText系。検索・学生登録/編集の基本/詳細を27行×132桁の固定行桁パネルへ統一し、F4候補/F8全文/項目エラー/各確認を別パネルで設計する。画面の正本はMD埋込みの等幅pre/spanだけで、単独HTML/PNGを置かない。検索4条件・8論理一覧項目・取得20/50/100・許可ソート・10,000件上限、編集REG全34項目・raw/保存長・DB/認可/監査は維持。Windows標準Console／Win32 W APIを技術選定し、QA-TEXT-COBOLには実glyph/IME/キー適合の未検証を残す。アプリ認証は利用者指定により本サンプルの対象外、旧CGIプログラムを含む実装は今回未変更。今回の版/ハッシュ/検査/未実施は方式内build/spec-generation/へ記録する。

## 補足説明

実装の直接入力は選択方式の機能別詳細・共通・DB定義・プロジェクト開発規約。基本は仕様理解用であると同時に評価対象。SQL Serverは元PostgreSQL採用5方式、ACE/Db2は各固有方式。test-project2は将来、別プロジェクトとして作る。

### 2026-10-23 改訂対象

検索・学生編集の基本／詳細、共通03～09、方式別共通、DB検索説明と入口を改訂し、基本・詳細の画面を同一のText系埋め込みHTMLへ統一する。恒久PNG・単独HTML・旧描画JSONは保持しない。検索4条件・8論理一覧項目、通常編集全REGと別確認状態を本方式内で閉じる。[画面最適化記録](../画面最適化記録.md)を参照。DB物理テーブル・索引・学生保存契約は変更しない。アプリ実装・実DB試験・正式採点は未実施。

## Windows認証なしサンプル

| 項目 | 本方式での適用 |
| --- | --- |
| 利用者指定 | 「Windowsで実行できる環境を想定する」「サンプルのため、認証はしない」 |
| 実行前提 | Windows x64／GnuCOBOL 3.2／同bit C／Windows標準ConsoleとWin32 W API／Windows ODBC Driver18。Linux・unixODBC・pkg-configの必須前提を置換する |
| 認証の例外 | このサンプルではログイン・Windows token・利用者/role mappingを行わず、実行側が固定actor `sample-user`、固定操作role `Administrator` を設定する。全サンプル機能確認用であり、本番認証・認可への適合を主張しない。一般の認証/権限表と用語は、本サンプルではこの例外を適用して読む |
| 信頼境界 | actor/role/sessionを端末rawまたはREMOTE_USER/ST_TRUSTED_ROLEから受付けない。DB接続の権限・TLS・保存時の業務検査・期待版・理由・同時保存・監査は維持する |
| 状態 | 接続ごとのCSPRNG32byte・64桁hex session、画面instance・要求ID・期待Revision・期限を照合。検索30分・確認10分。実キー活動だけがidle期限を更新し、timerでは延長しない。idle30分で失効し、終了/切断/再起動/別プロセスへ引き継がない |
| 正本と未実施 | [Windows実行環境](方式別/02_Windows実行環境.md)を適用。QA-AUTHは本サンプルで対象外、QA-TEXT-COBOLはOS/技術選定済み・実glyph/IME/キー適合未検証。実DB・本番受入・正式採点は未実施 |
