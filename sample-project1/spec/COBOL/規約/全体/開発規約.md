# 全体開発規約

版8.2／2026-10-25。設計・評価基準。アプリ実装・実機試験・逆生成採点は未実施。

## 概要

実装の直接入力は、選択プロジェクトのspec/方式ID/（specRoot）にある詳細仕様・共通仕様・DB定義・プロジェクト開発規約である。生成先は同じプロジェクトのsrcs/方式ID/（sourceRoot）とし、入力と生成先を別々に固定する。他方式のspecRootや評価期待値を実装入力にせず、旧sourceRoot/specを代替入力にしない。基本設計・要件は理解資料だが、同一属性の矛盾を優先順位で隠さない。対象は経験5年程度の実装者と生成Agent。初学者向けAPI解説を各機能へ重複させず、責務・入力型・状態・例外・DB確定境界を明示する。

## 共通原則

長さは業務文字数と物理バイト/コード単位、rawと正規化後、必須とNULLを分離。固定形式と通常上限＋余裕の算定を区別し、基準は各プロジェクトで確定する。入力・SQLパラメーターの暗黙縮小、時差による日付ずれ、未設定値の0化を禁止する。認証/権限は信頼境界で確認、画面ボタンの表示は権限保証ではない。共有処理は共通仕様、独立DB定義、開発規約へ分担する。独立した言語依存仕様書を必須入力に戻さない。

## 変更・証跡

実装前に入力セット版・依存関係を固定し、各プロジェクトのQAを解消する。ソースの仕様IDは追跡補助であり動作の証拠ではない。生成/ビルド/単体/結合/負荷/受入を別の状態で記録する。機能・言語・DBの追加は互換性と評価適用範囲を記録し、同時に関連詳細・共通・DB・採点表を更新する。

全方式とも仕様修正はspecRoot、生成ソース修正はsourceRootの正本を更新し、配布物・今回の最終検査記録・入出力manifestはsourceRoot/build/の固定パスへ更新する。中間結果・試行ログ・コンパイル作業・隔離展開はsourceRoot/.tmp/へ置く。過去生成結果を実行ID別・backup別に保存せず、Git履歴を使う。前回成功後に今回の生成・検査が失敗した場合は失敗を最終記録に明記し、以前のPASSを最新として提示しない。原入力、QA、正式試験コード・fixtureを一時生成物として消さない。

## Windows認証なしサンプル

| 項目 | 本方式での適用 |
| --- | --- |
| 利用者指定 | 「Windowsで実行できる環境を想定する」「サンプルのため、認証はしない」 |
| 実行前提 | Windows x64／GnuCOBOL 3.2／同bit C／Windows標準ConsoleとWin32 W API／Windows ODBC Driver18。Linux・unixODBC・pkg-configの必須前提を置換する |
| 認証の例外 | このサンプルではログイン・Windows token・利用者/role mappingを行わず、実行側が固定actor `sample-user`、固定操作role `Administrator` を設定する。全サンプル機能確認用であり、本番認証・認可への適合を主張しない。一般の認証/権限表と用語は、本サンプルではこの例外を適用して読む |
| 信頼境界 | actor/role/sessionを端末rawまたはREMOTE_USER/ST_TRUSTED_ROLEから受付けない。DB接続の権限・TLS・保存時の業務検査・期待版・理由・同時保存・監査は維持する |
| 状態 | 接続ごとのCSPRNG32byte・64桁hex session、画面instance・要求ID・期待Revision・期限を照合。検索30分・確認10分。実キー活動だけがidle期限を更新し、timerでは延長しない。idle30分で失効し、終了/切断/再起動/別プロセスへ引き継がない |
| 正本と未実施 | [Windows実行環境](../../共通/方式別/02_Windows実行環境.md)を適用。QA-AUTHは本サンプルで対象外、QA-TEXT-COBOLはOS/技術選定済み・実glyph/IME/キー適合未検証。実DB・本番受入・正式採点は未実施 |
