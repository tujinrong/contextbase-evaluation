## 隔離

仕様正本（specRoot）は `sample-project1/spec/COBOL/`、生成ソースと実行資源の正本（sourceRoot）は `sample-project1/srcs/COBOL/` とする。仕様の依存はspecRoot内で閉じる。本文中の方式内build/・.tmp/、生成コマンドの作業ディレクトリ、ソース相対パスはsourceRootを基準とし、仕様フォルダーの直下へ生成しない。順生成はこのspecRootを明示して入力版を固定する。

すべての仕様参照はこのフォルダー内で閉じる。業務項目・規則IDは維持し、文書IDは本方式専用とした。他プロジェクトと共通の仕様ファイル、symlink、外部への相互引用は使用しない。

## Windows認証なしサンプル

| 項目 | 本方式での適用 |
| --- | --- |
| 利用者指定 | 「Windowsで実行できる環境を想定する」「サンプルのため、認証はしない」 |
| 実行前提 | Windows x64／GnuCOBOL 3.2／同bit C／Windows標準ConsoleとWin32 W API／Windows ODBC Driver18。Linux・unixODBC・pkg-configの必須前提を置換する |
| 認証の例外 | このサンプルではログイン・Windows token・利用者/role mappingを行わず、実行側が固定actor `sample-user`、固定操作role `Administrator` を設定する。全サンプル機能確認用であり、本番認証・認可への適合を主張しない。一般の認証/権限表と用語は、本サンプルではこの例外を適用して読む |
| 信頼境界 | actor/role/sessionを端末rawまたはREMOTE_USER/ST_TRUSTED_ROLEから受付けない。DB接続の権限・TLS・保存時の業務検査・期待版・理由・同時保存・監査は維持する |
| 状態 | 接続ごとのCSPRNG32byte・64桁hex session、画面instance・要求ID・期待Revision・期限を照合。検索30分・確認10分。実キー活動だけがidle期限を更新し、timerでは延長しない。idle30分で失効し、終了/切断/再起動/別プロセスへ引き継がない |
| 正本と検証状態 | [Windows実行環境](共通/方式別/02_Windows実行環境.md)の確定前提を次回仕様生成へ継承する。適用はsample-project1/COBOLだけとし、他方式の認証前提を変更しない。QA-AUTHは本サンプルで対象外、QA-TEXT-COBOLはOS/技術選定済み。実glyph/手動IME/キー・実DB・本番受入・正式採点は対象版・ハッシュ付きの各実行記録で実施状態を確認し、未実施を合格へ読み替えない |

### 2026-10-28 基本設計の記述規則適用

検索・学生登録の基本設計を11列項目表へ整理し、候補/正規化/チェック/イベントと論理DB項目の対応を保持した。入力制限に原入力/保存上限を残し、4以上の手順を階層化し、既存CHK・実メッセージ・期待DB件数と原子的確定をイベントへ対応付けた。検索ERには既存の関係線を保持してキー/分類属性を補記した。

今回の更新は基本設計と説明/索引だけ。方式固有の確定前提、学生業務/制約、詳細仕様、物理DB定義、TABLE9列、画面HTML/CSSは維持する。実装・DB実行・ネイティブ画面/端末・正式採点の新たな実施を意味せず、検査記録は今回の入力版/ハッシュで更新する。
