# AS400_RPG プロジェクト仕様

版8.5／2026-10-28。独立した仕様入力。

## 対象

2026-10-25のText系改訂：本方式はText系（5250）に分類する。WEB系（WPFを含む）・WinForms系（Accessを含む）とは別に固定27行×132桁・行桁入力属性・Fキー/Enter/Tab・候補/確認/全文補助で設計する。学生編集はEDSTUDENTの通常1画面へ集約し、全19入力・全34項目・raw/保存上限・認可・保存境界を維持する。新画面の設計も[方式規約](規約/AS400_RPG.md)に従う。

学生の検索・登録・編集・参照・論理削除、クラス・コード保守。方式は AS400_RPG、DB は Db2_for_i。成績・出欠・年度所属履歴は対象外。

## 入力と境界

仕様正本（specRoot）は `sample-project1/spec/AS400_RPG/`、生成ソースと実行資源の正本（sourceRoot）は `sample-project1/srcs/AS400_RPG/` とする。仕様の依存はspecRoot内で閉じる。本文中の方式内build/・.tmp/、生成コマンドの作業ディレクトリ、ソース相対パスはsourceRootを基準とし、仕様フォルダーの直下へ生成しない。順生成はこのspecRootを明示して入力版を固定する。

この spec 配下の基本設計・方式内業務規則・詳細・DB定義・規約だけを使用する。他プロジェクトの仕様やコードを参照しない。重複した仕様は本プロジェクト専用の正本として維持する。仕様解析の検証では、この spec と評価資料を解析Agentのコード入力から除外する。

### 今回の画面改訂

2026-10-23、sample-project1の本方式を独立改訂。4検索条件・7列相当の一覧、全編集項目を維持した面積整理を適用。[画面最適化記録](画面最適化記録.md)にサイズ・状態・未実施を記録する。

2026-10-25の画面表現整理では、検索・学生編集の基本と詳細を同じ埋め込みHTMLに揃える。画面PNG・単独HTML・assetsの旧描画JSONを廃止し、抽出・描画は方式内.tmp/、最終検査と入出力manifestは方式内build/spec-generation/で管理する。検索4条件・7列、20/50/100件・既定20、並び順・ページ移動、登録項目・保存・権限の契約は維持する。

### 2026-10-28 基本設計の記述規則適用

検索・学生登録の基本設計を11列項目表へ整理し、候補/正規化/チェック/イベントと論理DB項目の対応を保持した。入力制限に原入力/保存上限を残し、4以上の手順を階層化し、既存CHK・実メッセージ・期待DB件数と原子的確定をイベントへ対応付けた。検索ERには既存の関係線を保持してキー/分類属性を補記した。

今回の更新は基本設計と説明/索引だけ。方式固有の確定前提、学生業務/制約、詳細仕様、物理DB定義、TABLE9列、画面HTML/CSSは維持する。実装・DB実行・ネイティブ画面/端末・正式採点の新たな実施を意味せず、検査記録は今回の入力版/ハッシュで更新する。
