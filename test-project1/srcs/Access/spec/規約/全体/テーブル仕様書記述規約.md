# テーブル仕様書・DB定義書 記述規約

版8.0／2026-10-12。

## 適用範囲

１テーブル１MDファイル、１Excelシート。テーブルヘッダーと項目詳細を同じシートへ置く。索引・共通制約は別文書へまとめる。基本テーブル仕様は言語・DB製品非依存とし、物理名は対応確認用に併記する。

## 書式

タイトルとメタ情報に続き、「テーブルヘッダー」「項目詳細」を置く。ヘッダーは２列、項目詳細は次の９列の表とする。各章には表１つだけを配置する。

| No | 論理名 | 物理名 | PK | NOT NULL | タイプ | 長さ | 初期値 | 説明 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 書式例の識別番号 | example_id | 〇 | 〇 | bigint | 19.0 | 自動採番 | IDENTITY(1,1)。 |
| 2 | 書式例の文字項目 | example_text |  |  | varchar(15) | 15 |  | 書式例。業務項目の追加ではない。 |

ヘッダーに論理・物理テーブル名、対象DB、用途、項目数、主キーの構成順、共通制約の参照先を記載する。Noは表内で1から連番。項目IDはメタ情報fieldIdsで既存の識別子を維持する。

## 列の意味

| 列 | 記載方法 |
| --- | --- |
| No | 表内の項目順。 |
| 論理名 | 業務上の名称。 |
| 物理名 | DB列名。 |
| PK | 主キー構成列に〇。その他は空欄。構成順はヘッダーに記載。 |
| NOT NULL | 常にNULL不可なら〇、NULL可なら空欄。条件付き必須は説明へ記載し、この列を〇にしない。 |
| タイプ | DB確定時はvarchar(15)、nvarchar(16)、bigint、date等の実DB型を直接記載。容量・精度・文字コードの既存指定も保持。DB非依存の基本仕様は文字・数字・日付等。 |
| 長さ | 従来どおり業務上限。文字数、整数桁.小数桁、バイナリのバイト数。該当する値がなければ空欄。 |
| 初期値 | 既存の初期値だけ記載。初期値なしは空欄。0、01、NULL、空文字の明示値は保持。基本は業務設定、DB定義はDB既定値。処理設定は処理:値と区別する。 |
| 説明 | 意味、条件付き必須、変換、参照先、範囲、変更不可など。タイプ・NULL可否の繰返しや埋草を記載しない。 |

## 数字と長さ

3.1は整数３桁＋小数１桁、3.10は整数３桁＋小数10桁。SQLのdecimal(p,s)ではp=整数桁+小数桁とする。整数は19.0などの文字列で保持し、符号・小数点を桁数へ含めない。型が許す範囲と業務範囲は別に検査する。

タイプの括弧はDB容量・精度、長さ列は業務上限。たとえばnvarchar(16)・長さ8は物理16単位、業務８文字の既存仕様を表す。業務上限をDB容量へ読み替えない。日付・日時の長さに表示文字数を記入しない。識別子や日付等で長さが対象外なら空欄、論理層の数値上限を物理仕様で定める場合も空欄とし参照先を残す。

PK・NOT NULLの空欄は非該当、初期値の空欄は初期値を設定しないことを示す。「－」「指定なし」等は記載しない。SQL DEFAULT NULLや空文字の明示指定と、DEFAULT未指定は区別する。未決事項を空欄へ隠さず、ヘッダーの共通規則または確認事項に記載する。自動採番は列属性でありSQL DEFAULTとは別。IDENTITYの開始値・増分等は説明へ保持する。

## 同一シートへの配置

layout=TABLE、schema=spec-md/1.1、sheetsは１件。sectionsにHEADERとLISTを定義し、columnsは上記９列を宣言する。変換器は列名とcolumns宣言を照合し、旧８列を９列として位置だけで読み取らない。通常のLIST/GRIDの１章１シート規則より本形式を優先する。

A1:I1をタイトル、A3:B3をヘッダー項目、C3:I3を内容とする。以降のヘッダーも同じ範囲に配置し、１行空けてA:Iへ９列の明細を置く。明細にセル結合を使わず、フィルターと固定表示は明細見出しへ設定する。No以外は文字列。空欄セルへダッシュ・文字列NULL・数値0を自動補充しない。シート名は物理テーブル名を基本とする。

## 保持と評価

変更前後の項目順・名称・PK・NULL可否・DB型容量・業務上限・既定値・条件付き必須・FK・索引を照合する。NOT NULL列の追加だけを理由に実DB制約を変更しない。採点表は既存評価IDと１項目１点を維持し、NOT NULLを属性一式へ追加する。ヘッダー３点、索引０点も維持し、変更した原仕様のハッシュ・期待値を更新する。
