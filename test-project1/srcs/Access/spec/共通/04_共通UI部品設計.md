# 共通UI部品設計（言語非依存）

版：8.1／2026-10-23。文書ID：COM-STU-004。

## 基本方針

本書の「部品」は利用者から見た共通の機能を表す。特定のHTMLタグ、Windowsコントロール、XAML、Vueコンポーネント、端末画面ファイルを指定するものではない。物理部品とイベントは方式別仕様で決定する。

| 部品番号 | 論理部品 | 共通動作 |
| --- | --- | --- |
| UI-01 | 画面枠・見出し | システム名、画面名、モード、利用者を表示 |
| UI-02 | メッセージ領域 | 情報・警告・エラーを文字で区別。受付番号を表示 |
| UI-03 | 文字入力 | 必須・最大文字数・入力保持・項目エラー。無断切捨てなし |
| UI-04 | 西暦日付入力 | 生年月日以外。西暦4桁、実在日・範囲、任意空欄、初期値を勝手に当日にしない |
| UI-05 | コード選択 | 値と名称を分離。検索は停止値も、登録は選択可否を表示 |
| UI-06 | クラス選択 | 検索は全年度候補の一体識別・上位条件なし。登録だけ年度学年連動、人数・定員参考 |
| UI-07 | 複数選択 | 在籍区分の複数選択。全解除はすべて |
| UI-08 | 検索一覧 | 論理一覧項目を参照表示。行単位編集／参照 |
| UI-09 | ページ・並び順 | 20・50・100、許可4項目の並び順、0件と未検索を区別 |
| UI-10 | 一般確認 | 未保存破棄・削除・再読込。既定は取消 |
| UI-11 | 重複候補確認 | 全件数・最大20件、確認理由、別人確認／取消 |
| UI-12 | 未保存管理 | 最後の読込値と編集中値を比較。保存失敗で解除しない |
| UI-13 | 処理中管理 | 二重操作を抑止。完了・取消・障害時に状態を戻す |
| UI-14 | 長文編集・参照 | 表示幅を超える全文を確認・変更する手段 |

## 画面の標準構成

見出し→メッセージ→項目グループ→主要操作の順とする。検索は条件と結果、登録は基本情報・住所連絡先・在籍所属・緊急連絡先・備考・理由に分ける。文字の必須印と説明を併記。参照専用値を編集可能に見せない。削除操作は保存と明確に区別する。

このHTMLは文書内の画面表現であり、すべての方式をWebで実装する指示ではない。端末型では同じ論理項目を複数のパネル・補助入力へ分割してよい。ただし項目を省略したり表示幅に合わせて保存上限を縮めない。

## 共通状態

| 状態 | 動作 |
| --- | --- |
| 初回・クリア | 初期条件。学生一覧は未検索 |
| 処理中 | 次の保存・削除・検索を抑止。単なる連打防止でDB排他を代替しない |
| 入力不備 | 入力値保持、エラー一覧と該当項目を関連付ける |
| 0件 | 該当なし、一覧空、ページ移動不可 |
| 10,000件超 | 条件追加の案内、一部だけの結果は出さない |
| 条件変更未実行 | 新条件未反映を明示。ページ操作は最後の実行条件 |
| 版競合 | 自動上書き・自動再読込をせず、入力保持と再読込案内 |
| 通信結果不明 | 再保存の前に検索確認。成功とも取消成功とも決めつけない |

## コード・クラス連動

検索は学籍番号・氏名・クラス・在籍の4条件だけ。クラス候補は全年度・停止・期間外を含み、一体識別する。変更時は未反映表示だけ。登録の年度・学年変更は不適合クラスを解除・通知し、古い候補応答を採用しない。

在学・休学は終了日を空、クラス必須。卒業・退学は終了日必須、クラス任意。コードやクラスの既存値が停止・期間外でも表示を消さない。保存時の有効性は保存済み値と比較して判定し、画面の「未変更」申告を信用しない。

## 操作・アクセシビリティ

キーボードで入力・検索・保存・取消を行えるようにする。確認は取消を既定とし、改行やEnter入力が削除・別人続行を不用意に確定しない。エラー項目への移動方法を用意する。色だけに意味を依存させず、使用不可・警告・必須を文字で表す。

一覧の長文は折返し・横スクロール・詳細参照等で全文を確認可能にする。端末の1パネル表示行数と検索の20・50・100件の単位を分離する。文字変換不能のとき元値を代替文字で上書きしない。方式ごとの入力制約・補助編集方法・実機確認事項を詳細仕様へ記載する。

個人情報を画面アドレス、ブラウザーや端末の無制限永続領域、通常の障害ログに記録しない。画面を閉じる際は未保存変更確認を行い、正常保存を確認した後だけ未保存状態を解除する。

### 画面面積の設計確認


#### Accessフォームとしての配置

frmStudentSearchは非連結単票フォームを維持する。見出し・状態を1行、条件を学籍番号／氏名／クラスの1行と在籍4チェックの1行へ集約し、検索・クリア・新規・メニューを近接配置する。1366×650および1280×650の100%設計確認領域で主要操作が見える配置とする。入力34px相当、文字12px以上。Accessウィンドウのリボン等を除いたフォーム領域を指す。

既存lstStudentsはListBox／StudentListCallbackを維持する。氏名とカナは「氏名 ／ カナ」の1行表示へ合成し、複数行セルやセル内ボタンを仮定しない。表示7列は学籍番号、氏名／カナ、生年月日（和暦）、年度／学年、クラス、在籍、操作案内。操作列は文字「編集／参照」で、既存cmdOpenSelectedかダブルクリックを使う。ListIndexを学生IDにせず、非表示ID列の値を使用する。

列幅を超える氏名／カナ・クラスは選択行全文欄へ表示し、必要なら横方向の参照補助を使える。値を切り捨てて保存しない。ListBoxは物理的に見える行数だけを持ち、取得済み20／50／100件内は縦スクロール、取得ページ間は既存ページボタンで移動する。参照権限は新規非表示、操作案内・外部ボタンを参照へ変更する。

#### 省スペースの編集フォーム

frmStudentEditは非連結単票フォームのまま、上段に学生ID・学籍番号・氏名・カナ・和暦4入力・性別、下段を住所連絡先／在籍所属／緊急連絡先・備考・確認理由の3列へ整理する。見出しとモード・メッセージを圧縮し、保存・編集取消・再読込・戻る・管理者の論理削除を最下段へ並べる。REG-001～034、全19入力、新規19／更新18＋照合値2、必須・raw／保存上限を維持する。全項目をタブ切替なしで辿れる。

1366×650・1280×650、100%のフォーム本文領域で通常編集の入力と操作を1画面へ収める。フォント12px以上・入力34px相当を確保する。各コントロールのMaxLength等は物理ガードであり業務上限を狭めない。住所・メールなど表示幅より長い入力はネイティブTextBoxの水平移動、備考と理由は複数行入力で全文を編集する。長文補助はShift+F2相当の拡大入力を案内する。狭幅・拡大・複数エラーは縦スクロールを許容し、最初のエラーへSetFocus・必要なScrollTop調整を行う。

重複／論理削除／未保存破棄は別のモーダルポップアップフォームにし、通常フォームの下へ常時並べない。取消を既定とし、背景は操作不可。重複確認の全件数・最大20件、理由・取消・続行へキーボード到達できる。論理削除のREG-026理由はその確認だけに配置し、編集中の一般項目を保存しない。新規／参照／権限差による表示制御、未保存管理・確認10分・再認可・版検査・履歴の確定単位は既存契約のまま。

## 和暦生年月日部品

UI-15は元号・年・月・日と項目エラーを持つ。候補は[共通暦定義](07_日付・和暦仕様.md)。元号名と識別値を分け、元年は表示に使用する。元号変更時は年範囲と境界日を再検査し、日付を自動補正しない。原入力と正規化日付を分離する。入力4値が空の新規状態と、未知元号・不正日を区別する。

一覧・参照・重複確認も共通16で和暦を表示。UI-04を全体的に和暦へ切り替える実装は不可。各方式はUI-15の物理コントロール名と保存側変換入口を方式別共通仕様に定義する。
