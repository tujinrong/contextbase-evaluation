# SQLServer DB定義書（索引・共通規則）

版8.1／2026-10-23。report指摘による設計改訂。本改訂の実DB・アプリ再検証は未実施。

## 概要

本書はテーブル別仕様への索引と共通の保存・制約規則。各テーブルは「テーブルヘッダー＋項目詳細」の１ファイルで定義し、Excelでは同一シートに配置する。索引・共通規則はテーブルシートへ繰返し展開しない。

業務5表・89列を維持し、従来のPostgreSQL採用5方式をSQL Server 2022（互換性レベル160）の設計へ変更する。版・CU・ドライバーの固定は実装工程で記録する。最新版という意味ではない。Access/ACEとRPG/Db2 for iは別プロファイルとして維持する。実DBへの移行は行わない。

主スキーマはdbo。表・列の識別子は既存を維持する。内部日付date、時点datetimeoffset(7)をUTC(+00:00)で保存、真偽bit、採番bigint IDENTITY(1,1)、受付番号uniqueidentifier、JSON配列はnvarchar(max)とする。`row_version`は正のbigintで明示的に1加算する業務版であり、SQL Serverのrowversion/binary(8)に変更しない。

日本語文字列は業務Nスカラー値に対しnvarchar(2N)を割り当てる。nvarchar(n)のnはUTF-16の2バイト単位数であり文字数とは限らないため、補助文字8文字を保持する氏名はnvarchar(16)とする。ASCII限定列はvarchar(N)。UTF-16容量を業務最大長と取り違えない。[SS-01]

固定長・可変長のバイト/単位ガード、スカラー長、必須空白、NUL・不正サロゲートを保存入口で検査する。Unicode表示列の照合はLatin1_General_100_CS_AS_SC、識別キー・照合キーの比較/順序はLatin1_General_100_BIN2を明示する。SC照合での`LEN(CONVERT(nvarchar(max),列)+N'#')-1`を使えば末尾空白を含むスカラー長を数えられる。比較用列でも式内だけSC照合を指定する。通常のLENだけは末尾空白を数えない。[SS-02]

検索はALLOW_SNAPSHOT_ISOLATION ONのDBで明示SNAPSHOTトランザクションを開始し、件数・一覧を同じスナップショットで取得する。READ_COMMITTED_SNAPSHOTだけを同一トランザクションのスナップショット保証としない。設定不能なら起動診断エラーとし、弱い分離へ黙って変更しない。[SS-03]

各分冊の明細は９列。NOT NULLは〇/空欄、DB確定時のタイプは実DB型、長さは業務上限。初期値なしは空欄とする。型容量・業務上限を維持。続柄分類のNULL条件は本改訂の保存契約に従う。

## 補足説明

### 書込みの確定単位・ロック

全学生更新・クラス/コード保守・確認情報消費は、READ COMMITTEDの短いトランザクションで次のロックを同じDB・@DbPrincipal（public）・資源名で取得する。接続する個別ユーザーが同一である必要はない。戻り値0/1だけ成功、負数は後続DML禁止。待機-1、取消-2、デッドロック-3、引数異常-999を区別し、必要なら明示Rollbackする。ゲート取得後に最新行/マスタ/候補/定員を別SQLで読む。確認ダイアログを待つ間にロックを保持しない。[SS-04]

```sql
SET XACT_ABORT ON;
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
BEGIN TRANSACTION;
DECLARE @lockResult int;
EXEC @lockResult=sys.sp_getapplock
 @Resource=N'test-project1:student-write', @LockMode='Exclusive',
 @LockOwner='Transaction', @LockTimeout=5000, @DbPrincipal='public';
IF @lockResult < 0
BEGIN
 ROLLBACK TRANSACTION;
 THROW 51001, N'保存用ロックを取得できませんでした。', 1;
END;
-- この後に最新値の読込・権限・必須・日付・存在・定員・全候補確認。
-- 学生変更と履歴、確認トークン消費を同一接続・同一Txで実施する。
-- 確認待ち/変更なしは変更せずROLLBACK。正常書込みだけCOMMIT。
```

上記はトランザクション開始の抜粋であり、単独で実行して未完了トランザクションを残さない。実装ではTRY/CATCHとXACT_STATE()で終了させる。新規19業務入力＋生成照合値2、通常更新は学籍番号以外18入力＋2生成値。削除は削除4属性・更新2属性・版だけを更新する。WHEREはstudent_id=@studentId AND row_version=@expectedVersion AND is_deleted=0、期待件数1。0件は存在と版を再確認し対象不在/版競合へ分ける。新規/変更/削除と操作履歴は同時確定、確認消費も同時確定。履歴失敗で全部取消。元の必須・存在・終了状態訂正・定員規則を緩和しない。

採番/版はOUTPUT INSERTED... INTO @changedでサーバー側に受け、COMMIT成功後にのみ結果を返す。OUTPUTの返却自体はコミット成功の証拠ではない。通信断は結果不明として再照会し、盲目的に再送しない。[SS-05]

### 検索の具体化

全条件を型付きパラメーターで渡す。学籍番号15の前方一致、氏名照合値160の部分一致、クラスID bigint完全一致の指定条件だけをAND結合する。カナ・年度・学年・未所属専用・都道府県・電話・入学日範囲の検索パラメーターは受け付けない。在籍値は0～4個のvarchar(2)パラメーターをIN(@status0,...)へ展開する。文字列配列のSQL連結やPostgreSQL配列構文は使用しない。0個は区分条件なし。ワイルドカードは`!`、`%`、`_`に加えてSQL Server固有の`[`を`!!`、`!%`、`!_`、`![`へこの順でエスケープし、LIKE @pattern ESCAPE '!'を使う。利用者入力は識別子へ埋め込まない。

件数は同一述語のSELECT TOP (10001) s.student_idを派生表にしてCOUNT_BIG(*)で上限判定する。10000超は一部結果を表示しない。0件/未検索は別。上限内は同じTxで名称LEFT JOIN、有効期間・利用可否は名称JOIN条件から除外。学生が不整合で消えるINNER JOINへ変更しない。ソートは学籍番号/氏名照合値/入学日/更新日時、ASC/DESCを許可表で選択、最後にstudent_idを追加。OFFSET @offset ROWS FETCH NEXT @pageSize ROWS ONLY、@pageSizeは20/50/100。件数と一覧のSELECT間にCOMMITしない。

### 固定制約と更新入口の分担

PKと全行の学籍番号UQ、年度＋クラスコードUQ、コード分類＋値のFKを維持する。SQL ServerのFK動作はON DELETE NO ACTION/ON UPDATE NO ACTION。自己版>0、固定分類、日付前後・固定下限1900-01-01、在籍01/02のクラス必須と終了日NULL、03/04の終了日必須、連絡先一式、削除3属性のNULL整合をCHECKとする。未来日・有効性・他行集計定員・既存値保持・変更禁止・参照マスタ意味変更は更新入口が再検証。CHECKでNULLがUNKNOWNとなり条件付き必須が抜けないよう、IS NULL/IS NOT NULLを明記する。

JSONはISJSON(changed_columns)=1だけでなく、配列・各要素が許可列名の文字列・重複なし・値の非保存を確認する。初期ID値や権限をクライアントから受けない。動的業務日をDB CHECKの恒久条件へ埋めない。論理削除の復旧と物理消去は対象外のまま。

### パラメーター・例外・稼働条件

.NETはMicrosoft.Data.SqlClient、SqlParameterのSqlDbType/Size/Precision/ScaleとDBNull.Valueを明示する。NVarCharのSizeは物理UTF-16単位数。入力値を検査する前に短いSqlParameterへ渡すと切捨ての危険があるため、Raw値と業務長を先に検査し、暗黙縮小を禁止。日付はSqlDbType.Date、時点はDateTimeOffset、ID/版はBigInt、真偽Bit。型の自動推測だけに依存しない。[SS-06]

2601/2627は違反キーをDB入口の固定エラーコードで番号重複等へ分類、547はFK/CHECK違反を区別して整合性エラー、1205はデッドロック、1222はロック待機、3960はスナップショット更新競合、コマンドタイムアウト/切断は確定状態を確認する。例外メッセージ文字列の言語依存解析でキーを判定しない。DBの生エラー・SQL・資格情報は利用者へ返さない。

書込みを担う全入口は同じゲートを使う。GUI直結は原則実行権限だけを付与したstudent_apiの保存手続＋個別認証、Webは信頼するアプリサービス主体＋最小権限。単にREVOKEしただけで別ロールの権限が消えたと仮定せず、有効な権限を試験する。接続暗号化とサーバー証明書検証を有効にし、共有パスワードを埋め込まない。

### 続柄の任意参照と行内制約（7.4）

`m_student.relationship_category`と`relationship_code`は共にNULL可。前者はコード選択時だけ`RELATIONSHIP`を保存入口が設定する。緊急連絡先４保存列の許可状態を、C-010の既存「連絡手段が１つ以上」の条件とAND結合する。次の述語は各列のNULL状態を明示し、CHECKのUNKNOWNを利用して部分入力が通る実装を防ぐ。

```sql
(
  (emergency_contact_name IS NULL
   AND relationship_category IS NULL AND relationship_code IS NULL
   AND emergency_phone_number IS NULL)
  OR
  (emergency_contact_name IS NOT NULL
   AND relationship_category IS NOT NULL AND relationship_code IS NOT NULL
   AND emergency_phone_number IS NOT NULL
   AND relationship_category = 'RELATIONSHIP')
)
```

C-008の旧「学生４分類は常に固定」を、必須３分類の固定と、上記の条件付き続柄分類へ置換する。既存の複合FK `(relationship_category, relationship_code) → m_code(category_id, code_value)` は有効のまま維持し、親コードの参照中削除・キー更新を拒否する。新規および通常UPDATEのSET対象へ派生分類を含める。分類の固定DEFAULTは作らない。空文字・空白だけは共通正規化でNULLとして扱い、コードの既存値保持・有効性・一式必須も保存入口で検査する。

[SQL Server CHECKのNULL判定](https://learn.microsoft.com/en-us/sql/relational-databases/tables/unique-constraints-and-check-constraints?view=sql-server-ver17)は固定制約の記述根拠であり、当該構成の実機合格証拠ではない。

これは仕様の修正であってDBへ適用済みのDDLではない。導入時は旧データを事前検査し、既知の旧表現（緊急３項目全NULLかつ分類だけRELATIONSHIP）のみ承認済み移行で全NULLへ変換する。他の不整合を自動修正しない。制約・列変更の製品別DDL、移行前後件数・監査・バックアップ・戻し手順は移行工程で検証する。

## 検索射影の改訂

OP-PAGEはSRC-020/021/022/023/024/025/026と行操作用student_idを返し、7列へ整形する。住所・電話・更新日時の表示列と都道府県名称JOINは除く。updated_atは許可ソート式としてだけ利用できる。非削除、型付き条件、SNAPSHOT件数＋一覧、TOP(10001)、許可ソートとstudent_id同順位、20/50/100の契約は維持。物理表・列・制約・索引・保存手順は本改訂で変更しない。
