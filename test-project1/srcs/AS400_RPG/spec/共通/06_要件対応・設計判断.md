# 要件対応・設計判断・適合試験

版：8.2／2026-10-23。文書ID：COM-STU-006。

## 改訂の要点

ユーザーの追加指定により、基本設計と共通の業務契約を言語非依存にし、詳細を7方式へ分割する。前段で作成していた単一のC#／ASP.NET Core向け詳細案を本方式共通の仕様として扱わない。現在のリポジトリに実装ソースが存在するという意味ではない。

| 方式 | 今回採用する実装前提（選定案） | 独自に定義する内容 |
| --- | --- | --- |
| VB.NET / WinForms | .NET 10、Windows Forms、SQL Server 2022 | Form、イベント、BindingSource、ErrorProvider、VB型・例外 |
| C# / WPF | .NET 10、WPF、SQL Server 2022 | XAML、MVVM、Command、通知・検証、Dispatcher |
| C# / ASP.NET | ASP.NET Core MVC／Razor、.NET 10、SQL Server 2022 | サーバー描画、ModelState、POST/Redirect/GET、認証・CSRF |
| Vue / C# API | Vue 3／TypeScript、ASP.NET Core Web API、SQL Server 2022 | SFC、Composition API、JSON契約、画面とAPIの分離 |
| AS400 / RPG | IBM i 7.5、ILE RPG全自由形式、DDS 5250、Db2 for i | DSPF・サブファイル・プロシージャー・CCSID・コミットメント制御 |

COBOLの処理系・画面方式、ASP.NETの種類、DB製品は元の依頼では未指定のため、上記を具体化のための仮定とする。COBOLはIBM CICS版ではなくGnuCOBOL CGI版。RPGは現行IBM i上のILE RPGを指し、古いRPG IIIの固定形式ではない。バージョンは設計基準であり「最新版」という主張ではない。各方式は別配備・別DBを原則とする。

## 範囲と制約

業務5表・89論理項目、5分類70コード、検索・登録の2画面、成績対象外を継承する。保持期間・学校種別・実クラス・認証基盤製品は未指定。画面パネル分割や補助技術表を追加しても業務機能の追加とは区別する。

本版の方式別評価設計は、小規模校向けに保存を短時間直列化する方法を許容する。DBの同時保存制御を利用し、プロセス内だけのフラグでは代用しない。細粒度化は性能測定後の変更とし、定員・同一人物候補・マスタ変更の競合試験を維持する。確認待ちにロックを保持しない。

AccessのACCDB単体では利用者別の強いDB権限境界を提供できない。共有ファイルを直接改変できる利用者に対し、VBA画面の権限制御を完全な保護と説明しない。信頼された職員だけの評価構成とし、本番で厳格な閲覧者／担当者分離が必要ならサーバーDBまたはAPIを介する別構成の承認を条件とする。[S-09]

5250の日本語端末表示は保存可能なUnicode文字集合と一致するとは限らない。RPG版では変換不能文字を上書きせず保持し、補助的なUnicode入力方式と実機試験を定義する。COBOLはUTF-8のWeb画面を用い、固定長バイト領域と業務文字数を区別する。

## 本方式に共通する適合試験

| 試験ID | 条件・操作 | 期待結果 |
| --- | --- | --- |
| T-01 | 初回表示・クリア | 在学・休学、20件、未検索 |
| T-02 | ＡＢ-01、氏名空白差、半角カナ | 共通正規化規則と一致 |
| T-03 | 氏名に%、_、! | リテラル検索、意図しない全件化なし |

| T-06 | 検索4条件・廃止キー・全年度クラス、登録の別学年クラス | 検索は未知条件拒否・全年度可。登録だけ組合せ検査 |
| T-07 | 停止コード・期間外クラスの既存値保持 | 参照可能、無関係な住所訂正を妨げない |

| T-09 | 同一人物候補・同姓同名の別人 | 警告、理由付き別人確認なら可 |
| T-10 | 確認後の入力・全候補版変更、期限切れ | 再確認。表示20件以外の候補変更も検出 |
| T-11 | 生年月日・入学・終了日境界 | 共通日付・区分整合を満たす |
| T-12 | 本人電話・メール・緊急電話すべてなし | 保存不可 |
| T-13 | 緊急連絡先3項目の一部だけ | 保存不可。全部空は可 |
| T-14 | 家族で電話・メール共有 | 重複だけでは拒否しない |
| T-15 | 最終1席へ2接続から同時登録 | 片方だけ成功、定員超過なし |
| T-16 | 別クラスへ同一人物候補を同時登録 | 後続保存で先行を検出、無警告で2件確定させない |
| T-17 | 同じ旧版で同時編集・削除 | 一方だけ成功、他方は競合 |
| T-18 | 履歴追記を故意に失敗 | 学生／マスタ変更も取消 |
| T-19 | 住所入力途中に論理削除 | 住所の未保存値は適用されない |
| T-20 | 卒業から在学へ担当者が訂正 | 不可。管理者＋理由＋有効クラス＋定員で可 |
| T-21 | 更新なし | 版・更新日時・履歴を増やさない |
| T-22 | 保存確定後の通信断・応答喪失 | 結果不明を案内、盲目的再送なし |
| T-23 | 別利用者・別画面の復帰識別 | 他人の条件・入力・候補を返さない |
| T-24 | コード保護値停止、参照クラス学年変更 | 拒否し、既存学生を連鎖変更しない |
| T-25 | Unicode補助文字・最大桁・変換不能 | 文字数とバイト数を区別、切捨て・代替保存なし |
| T-26 | 日本時間0時・4月1日 | 業務日・年度が共通規則通り |
| T-27 | 検索条件変更後にページ操作 | 最後に実行した条件で取得、未反映を明示 |
| T-28 | マスタ利用停止と所属登録の同時操作 | 同時保存制御後の状態で整合、両方不整合確定なし |

テスト仕様を記述したことと試験合格を区別する。実DB、端末、Office、GUI、ブラウザーの試験は実装工程で実施する。

本方式の採用DBはDb2 for i。技術根拠・保存単位・照合・関係定義は本方式の[Db2 for i DB定義](../DB定義/Db2_for_i/01_DB定義書.md)を参照し、同書と本方式の方式別共通仕様に定義済みの境界試験を適用する。

### 2026-10-23 検索・編集配置の改訂判断

小規模という利用者前提に基づき4条件を採用する。件数の実測はない。住所・電話・期間などは編集参照で確認でき、検索条件の削減は登録保存項目の削減ではない。今回の構造・静的描画を正式採点・アプリ実装・ネイティブ試験合格として扱わない。方式固有の配置と未実施は[画面最適化記録](../画面最適化記録.md)を参照する。
