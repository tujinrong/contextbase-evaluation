# 共通UI部品設計（言語非依存）

版：8.1／2026-10-23。文書ID：COM-STU-004。

## 基本方針

本書の「部品」は利用者から見た共通の機能を表す。特定のHTMLタグ、Windowsコントロール、XAML、Vueコンポーネント、端末画面ファイルを指定するものではない。物理部品とイベントは方式別仕様で決定する。

| 部品番号 | 論理部品 | 共通動作 |
| --- | --- | --- |
| UI-01 | 画面枠・見出し | システム名、画面名、モード、利用者を表示 |
| UI-02 | メッセージ領域 | 情報・警告・エラーを文字で区別。受付番号を表示 |
| UI-03 | 文字入力 | 必須・最大文字数・入力保持・項目エラー。無断切捨てなし |
| UI-04 | 西暦日付入力 | 生年月日以外。西暦4桁、実在日・範囲、任意空欄、初期値を勝手に当日にしない |
| UI-05 | コード選択 | 値と名称を分離。検索は停止値も、登録は選択可否を表示 |
| UI-06 | クラス選択 | 検索は全年度候補の一体識別・上位条件なし。登録だけ年度学年連動、人数・定員参考 |
| UI-07 | 複数選択 | 在籍区分の複数選択。全解除はすべて |
| UI-08 | 検索一覧 | 論理一覧項目を参照表示。行単位編集／参照 |
| UI-09 | ページ・並び順 | 20・50・100、許可4項目の並び順、0件と未検索を区別 |
| UI-10 | 一般確認 | 未保存破棄・削除・再読込。既定は取消 |
| UI-11 | 重複候補確認 | 全件数・最大20件、確認理由、別人確認／取消 |
| UI-12 | 未保存管理 | 最後の読込値と編集中値を比較。保存失敗で解除しない |
| UI-13 | 処理中管理 | 二重操作を抑止。完了・取消・障害時に状態を戻す |
| UI-14 | 長文編集・参照 | 表示幅を超える全文を確認・変更する手段 |

## 画面の標準構成

見出し→メッセージ→項目グループ→主要操作の順とする。検索は条件と結果、登録は基本情報・住所連絡先・在籍所属・緊急連絡先・備考・理由に分ける。文字の必須印と説明を併記。参照専用値を編集可能に見せない。削除操作は保存と明確に区別する。

このHTMLは文書内の画面表現であり、すべての方式をWebで実装する指示ではない。端末型では同じ論理項目を複数のパネル・補助入力へ分割してよい。ただし項目を省略したり表示幅に合わせて保存上限を縮めない。

## 共通状態

| 状態 | 動作 |
| --- | --- |
| 初回・クリア | 初期条件。学生一覧は未検索 |
| 処理中 | 次の保存・削除・検索を抑止。単なる連打防止でDB排他を代替しない |
| 入力不備 | 入力値保持、エラー一覧と該当項目を関連付ける |
| 0件 | 該当なし、一覧空、ページ移動不可 |
| 10,000件超 | 条件追加の案内、一部だけの結果は出さない |
| 条件変更未実行 | 新条件未反映を明示。ページ操作は最後の実行条件 |
| 版競合 | 自動上書き・自動再読込をせず、入力保持と再読込案内 |
| 通信結果不明 | 再保存の前に検索確認。成功とも取消成功とも決めつけない |

## コード・クラス連動

検索は学籍番号・氏名・クラス・在籍の4条件だけ。クラス候補は全年度・停止・期間外を含み、一体識別する。変更時は未反映表示だけ。登録の年度・学年変更は不適合クラスを解除・通知し、古い候補応答を採用しない。

在学・休学は終了日を空、クラス必須。卒業・退学は終了日必須、クラス任意。コードやクラスの既存値が停止・期間外でも表示を消さない。保存時の有効性は保存済み値と比較して判定し、画面の「未変更」申告を信用しない。

## 操作・アクセシビリティ

キーボードで入力・検索・保存・取消を行えるようにする。確認は取消を既定とし、改行やEnter入力が削除・別人続行を不用意に確定しない。エラー項目への移動方法を用意する。色だけに意味を依存させず、使用不可・警告・必須を文字で表す。

一覧の長文は折返し・横スクロール・詳細参照等で全文を確認可能にする。端末の1パネル表示行数と検索の20・50・100件の単位を分離する。文字変換不能のとき元値を代替文字で上書きしない。方式ごとの入力制約・補助編集方法・実機確認事項を詳細仕様へ記載する。

個人情報を画面アドレス、ブラウザーや端末の無制限永続領域、通常の障害ログに記録しない。画面を閉じる際は未保存変更確認を行い、正常保存を確認した後だけ未保存状態を解除する。

### 画面面積の設計確認


#### 5250の行・桁と取得ページ

既存DSPSIZ(27 132)を維持する。COND／SFLCTLは1～7行に見出し、学籍番号・氏名、クラス、在籍、取得件数・4ソート・方向・件数、状態、一覧見出しを置く。SFLROWは1学生2物理行とし、8～23行に8学生を表示する。第1行に選択・学籍番号・氏名／カナ・和暦生年月日、第2行に年度／学年・クラスコード／名称・在籍を置く。7列相当の論理8項目を、132桁へ無理に単行化しない。

SFLPAG(8)、SFLSIZ(101)。RRNは取得ページ内の1～pageSize、resultRowsがstudentIdを保持する。READCの選択2=編集、5=参照は対象RRNからIDを解決し再認可する。表示行番号をIDにしない。PageUp／PageDownは現在取得ページ内の8学生送り。20件は8／8／4、50件は8×6／2、100件は8×12／4とし、端末の空行を学生として数えない。端末内の先頭／末尾でそれ以上ロールせず状態を案内する。F7／F10は前／次のDB取得ページ、F15／F16は先頭／最後のDB取得ページで、取得後は端末先頭へ。未検索・0件・上限超過・該当端点では無効としDBを再取得しない。検索条件はAppliedCriteriaのままで、条件編集中値を混ぜない。F9で4ソート・方向を選択し、F11で20／50／100を選択した場合はDB1ページ目・端末先頭へ戻す。

24～27行に件数・端末内位置、検索日時、操作案内とメッセージを配置する。Enter=検索、F4=カーソル項目候補、F5=クリア、F6=新規（作成権限のみ）、F12=メニュー。全角は2表示セル、半角は1で行・列を測る。実DDSではDBCS属性とSI／SO制御の領域を確保し、132表示桁を超えないことをコンパイル・5250実機で確認する。ブラウザーの等幅描画は実端末のCCSID・属性バイト・SI／SO検証を代替しない。変換不能・長い値はF8/LONGTXTで全文参照し、元Unicode値をDSに保持する。

#### 2編集パネルへの集約と全項目到達

DSPSIZ(27 132)を維持し、EDBASE=基本・住所連絡先（1/2）、EDENROLL=在籍所属・緊急・備考理由（2/2）の2編集パネルへ集約する。旧EDNOTEの独立入力ページを廃し、その備考・理由をEDENROLLへ移す。CNFRMとLONGTXTは必要時だけ開く補助レコードで、通常入力の3ページ目としない。REG-001～034と全19入力、新規19／更新18＋照合値2、和暦4入力・raw上限・保存上限・必須条件は維持する。

EDBASEにはREG-001～012と025、EDENROLLにはREG-013～024と025を置く。両パネルの24～27行に現在1/2・2/2、F9=他パネル、F10=全体検査・保存、F5=編集取消、F14=再読込、F12=検索復帰、F23=管理者論理削除を置き、REG-027～031を対応付ける。F9は原入力をeditWorkRawへ退避するだけでDB保存・検査成功扱いをしない。移動先で同じDSを復元し、期待版・確認情報・未保存状態を保持する。F10は両パネルの値を検査し、最初のエラーを持つパネルへ移動して該当項目へカーソルを置く。

全角2セル・半角1セルで各パネル27行×132桁以内を設計上の上限とする。住所各45文字は2行の論理継続欄、備考120文字は3行、理由60文字は2行を確保する。通常表示欄に収まらないraw値やUnicode変換不能値はF8→LONGTXTで全文編集できる。補助入力は項目ID・現在文字位置・ページ数・raw／保存上限を表示し、PageUp/Downで文字境界を保持して移動、F10で原項目へ返す（DB保存しない）、F12で補助編集だけを取消。原表記と改行を保持し、不可逆な切捨て・代替文字の上書きをしない。

CNFRMは重複確認／削除理由／未保存破棄を別状態として1レコードだけ表示する。REG-032は全候補件数と最大20件、端末1枚に入る分をロールし、REG-033=明示続行、REG-034=取消を各画面の操作行へ固定する。取消が既定でEnterだけでは続行しない。REG-026削除理由はCNFRMの削除状態だけへ置き、通常編集中値を保存しない。新規／参照／認可・再認可・保存境界は変えない。ブラウザー描画確認とDDSコンパイル／5250実機の確認を分け、SI/SO・CCSID往復は未実施とする。

## 和暦生年月日部品

UI-15は元号・年・月・日と項目エラーを持つ。候補は[共通暦定義](07_日付・和暦仕様.md)。元号名と識別値を分け、元年は表示に使用する。元号変更時は年範囲と境界日を再検査し、日付を自動補正しない。原入力と正規化日付を分離する。入力4値が空の新規状態と、未知元号・不正日を区別する。

一覧・参照・重複確認も共通16で和暦を表示。UI-04を全体的に和暦へ切り替える実装は不可。各方式はUI-15の物理コントロール名と保存側変換入口を方式別共通仕様に定義する。
