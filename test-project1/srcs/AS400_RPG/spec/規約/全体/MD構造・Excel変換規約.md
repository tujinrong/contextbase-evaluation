# MD構造・Excel変換規約

版8.0／2026-10-12。仕様書の書式改訂。業務アプリ・実DBの実行試験は未実施。

## 章とシートの対応

ここでのListは箇条書きではなく、1行1レコードの矩形表を意味する。章種別をLIST／GRIDとして文書冒頭のspec-metaコメントへ宣言する。本文の章名は「概要」「項目一覧」「イベント仕様」「補足説明」を基本とし、選択候補一覧・項目移送仕様・項目更新仕様などの一覧章を追加してよい。

原則1文書＝1ワークブック、実際の見出し2の1章＝1シート。タイトル・属性表は別の「表紙」シートへ配置するが、MD本文に第5の標準章「表紙」は新設しない。LIST章内には小見出し、文章、箇条書き、注記、図、HTML、コードブロック、複数の表を入れない。説明は表の説明列、または概要・補足説明へ移す。

GRID章内に小さな説明表を置くことはできる。その表だけを暗黙にListシートへ昇格しない。変換器は章名の部分一致で分類せず、宣言を使う。章名重複や未宣言章は検査エラーとする。

## LIST構文

必ず見出し行1行、区切り行1行、データ行0行以上のMarkdownパイプ表1つとする。すべての行の列数を一致させ、ヘッダー名称を一意にする。先頭列または指定した複合キーでレコードを識別する。合計、節タイトル、繰返しヘッダーをデータ行へ混ぜない。

セルは原則1行。表示内改行が不可避なら、列内の改行を区切りとしない形式として`<br>`を使い、Excelではセル内改行へ変換する。`<br>`以外のHTML、入れ子表、セル結合、rowspan／colspan、画像、複数行コードはLIST内で禁止。リテラルの縦棒は`&#124;`へ符号化し、変換後は縦棒として復元する。コードの論理和なども同じ。

同上・ditto記号・空白による前行の継承を禁止する。真偽、任意、必須、条件付き、非適用、未確定を区別する。存在しない上限は「非適用」、未決定は「未確定（QA-ID）」と書く。空セルで両者を兼ねない。長さの数値には単位を別列で与える。

## LISTのExcel配置

表のヘッダーを1行目、データを2行目以降へ配置し、列幅は列の意味に応じて決める。細かい方眼列へ分解しない。オートフィルター、先頭行固定、折返し、必要な表示幅を設定し、データ部のセルを結合しない。印刷見出しはExcelの印刷設定で再掲し、表データに挿入しない。

仕様値は既定で文字列セルとする。コード01、郵便番号、64bit ID、ISO日付、正規表現、長さ範囲を勝手に数値・日付・式へ変換しない。数値として出力する列は明示した安全な数値列のみとし、元表記も復元できるよう保持する。`=`, `+`, `-`, `@`などで始まるセルも式として実行せず文字列として書く。数式安全化のために原データそのものを恒久的に改変しない。

32,767文字のセル上限や行・列上限を超える場合は切り詰めず変換エラーにする。別の論理レコードへの分割は、IDと継続順を付けた設計変更としてMD側で行う。日付をExcel内部日付へ変換して和暦範囲検査の代替にしない。[EX-01]

## GRIDのExcel配置

本プロジェクトの標準方眼は120列、列幅2.0相当、基準行高15ptとする。これは本プロジェクトの配置設定でありExcelの製品既定値ではない。タイトルと大見出しは1～120列、見出しラベルは1～20列、値・本文は21～120列を基本とし、図と画面は必要な範囲へ割り当てる。

文字数と折返しに応じ行数を増やし、方眼の列幅を本文ごとに変えない。セル結合はGRID内だけで許容する。段落・番号付き処理手順・分岐の順序・見出し階層を維持し、コードは等幅文字、空白と改行を保持する。ER図やフローは別の描画工程で配置し、元のMermaidテキスト・図IDを失わない。

概要内のHTML画面は画面設計用の構造として解釈し、固定の表・段落・静的入力表現の配置へ変換する。スクリプトを実行しない。LISTに禁止されるcolspan／rowspanは、概要内の静的HTML画面では許容する。図を画像化する場合も、元の構造・項目ID・代替テキストをメタ情報に残す。

## メタ情報と復元

文書先頭に1つのHTMLコメントを置き、JSONオブジェクトを格納する。コメントは書式制御用であり業務情報を隠す場所ではない。説明例のコードフェンス内を実際の章と数えない。

```text
<!-- spec-meta: {"schema":"spec-md/1.0","documentId":"DET-VB-SRC","version":"7.0","sheets":[{"heading":"概要","kind":"GRID","sheet":"01_概要"},{"heading":"項目一覧","kind":"LIST","sheet":"02_項目一覧","key":["項目ID"]}]} -->
```

各章のheadingは実見出しと完全一致。sheetは空でない31文字以内とし、`/ \ ? * : [ ]`を禁止する。大文字小文字を無視して同一ワークブック内で重複させず、予約名・先頭末尾アポストロフィ等も避ける。自動短縮時は元見出しとsheetの対応を保持し、衝突は安定した番号で解決する。[EX-02]

Excel内のメタ情報には文書ID、版、元ファイル相対パス、元ハッシュ、章IDと順序、シート名、元ヘッダー、文字列／数値の型指定、図ソースを保存する。実装方法は非表示のメタシート等でよいが、隠し情報だけに業務要件を置かない。復元は意味・ID・原値を優先し、フォント・列幅の差を業務差としない。

## 検査と参照資料

静的検査では宣言と章の一対一、LISTに表1つだけ、列数、キー重複、空見出し、旧参照、文字列の非損失、セル長、シート名長を検査する。Excel変換後の合格には、別途実ファイルの読戻し、和暦・先頭ゼロ・長いIDの保持、方眼の描画・改ページ・図の可読性を試験する。MDの構造合格だけでExcel変換済みとしない。

EX-01：Microsoft「Excel specifications and limits」https://support.microsoft.com/en-us/excel/excel-specifications-and-limits （2026-10-11参照）。EX-02：Microsoft「Rename a worksheet」https://support.microsoft.com/en-us/excel/rename-a-worksheet （同日参照）。GFMの表・HTML・エスケープの基礎：https://github.github.com/gfm/ （同日参照）。LIST／GRID、120列、JSONコメント、文字列優先は本プロジェクトの独自規約であり製品仕様ではない。

## 描画可能な画面HTML・評価チェックリスト

詳細仕様の画面レイアウトは概要の下に完全な静的HTMLとCSSを埋め込み、ブラウザーでレンダリングして確認する。入力欄、選択欄、操作、一覧、必須表示、メッセージ、モード・確認ダイアログを実画面に近い配置にする。画面項目IDと物理コントロール／バインド先をHTMLのdata属性でも対応付ける。実装UIの種類は変更しない。RPGは5250レコード・ページ構成、Accessはフォーム部品の制約を反映する。

仕様書の正本はMD。補助成果物として同じ断片から生成した単独HTMLとレンダリングPNGをassetsへ置く。MD内のHTML、単独HTML、PNGを同時更新し、作成元ハッシュ・画面サイズ・ブラウザー版を画面確認記録へ残す。MDビューアーの安全化でCSS・フォーム要素が除去される場合はPNGと単独HTMLで確認する。GitHubに載せたHTMLが自動で実アプリとして動くとは説明しない。

LIST章には引き続き表１つ以外を置かない。描画用HTML・CSS・PNG・説明はGRIDである概要章だけへ置く。Excel変換時は画面を方眼領域へ画像として配置してよいが、元HTML・CSS・項目IDをメタ情報へ保持し、画像だけからDBや制約を逆推定しない。描画例を表の単なるセル結合へ劣化させない。

各プロジェクトのspec-evalに具体的な期待値と配点を持つ評価表を置く。一般規則は[評価規約](評価規約.md)。一覧1行1レコードとし、評価期待値をAgentの一般書式へ混在させない。

描画技術の参照：Playwright Python Screenshots https://playwright.dev/python/docs/screenshots 。Markdownの表・HTML構文と安全化の注意：https://github.github.com/gfm/ （2026-10-11参照）。本プロジェクト独自のLIST／GRIDと配点は上記外部仕様が定めたものではない。

## テーブル文書の同一シート特例

テーブル仕様書・DB定義書の分冊は[テーブル規約](テーブル仕様書記述規約.md)を適用する。schema=spec-md/1.1、layout=TABLEに限り、ヘッダー表と９列の項目詳細表を同一シートへ配置する。通常の１章１シート・別表紙・LIST見出し１行目の規則より優先する。項目詳細のLIST内に文章を混ぜる許可ではない。TABLEを未対応の変換器はGRIDに黙って変換せずエラーにする。

TABLE形式のPK・NOT NULL・初期値・長さの空欄規則はテーブル規約を優先する。一般LISTで未確定値の明記を求める規則を、TABLEの非該当セルへ埋草を入れる理由にしない。
