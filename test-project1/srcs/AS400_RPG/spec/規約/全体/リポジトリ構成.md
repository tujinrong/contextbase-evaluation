# 本方式の独立プロジェクト構成

版8.2／2026-10-25。設計・評価基準。アプリ実装・実機試験・逆生成採点は未実施。

## 概要

本書はAS400_RPGの独立プロジェクト内の配置を定義する。仕様作成・順生成は本方式のspec配下を入力とし、本方式内のソース・DB資材・ビルド手順・証跡を扱う。他プロジェクトの仕様やコード、外部の共通正本を入力に含めない。逆生成では本仕様と評価資料をコード入力から隔離する。

## 配置一覧

| 領域 | 目的 | 書込み範囲 |
| --- | --- | --- |
| spec/規約/全体/ | 本方式専用の仕様作成・MD/Excel・記述・配置規約 | 本方式内の規約だけを更新する |
| spec/ | 本方式専用の要求・基本・業務規則・詳細・DB定義・開発規約 | 本方式の仕様だけを更新する |
| database/ | 本方式専用の物理DB資材 | 本方式のDB定義に対応する資材だけを更新する |
| ./（本方式プロジェクト直下） | 本方式のソース・設定・ビルド手順・証跡 | 本方式内に閉じる。仕様解析のコード入力に本仕様・評価資料を含めない |

## 識別と変更

projectId/仕様セット版/方式ID/文書ID/機能ID/項目IDを識別子として保持する。プロジェクトを跨いだ同じ項目IDは別物。移動では相対リンク・メタ情報path・評価根拠・画像参照も更新する。同一IDの意味を変更した場合は仕様版を更新する。評価旧版はGit履歴で保持する。共通ルールを変えても、既存プロジェクトの承認済み範囲へ無断適用しない。

### 独立方式の仕様配置

srcs/方式ID/specで方式が既に確定している場合、詳細仕様書と方式別共通の下へ同じ方式IDのフォルダを重ねない。詳細文書はspec/詳細仕様書/直下、方式固有の共通実装仕様はspec/共通/方式別/直下へ置く。複数方式が1つのspecRootを共有する構成だけは、方式を区別する下位階層を使用できる。

DB定義の採用DB名は方式名とは異なる分類である。DB定義/Access、DB定義/SQLServer、DB定義/Db2_for_i等のプロファイル階層は保持する。フォルダ整理ではファイル名・文書ID・機能/項目/イベントIDと業務定義を維持し、相対リンク・spec-meta.path・索引・現在の検査manifestを新しい配置へ合わせる。過去生成時の入力パスとハッシュを現在の生成結果へ偽装しない。

## テーブル文書の配置

本方式のspec/基本設計書/テーブル/およびspec/DB定義/＜本方式のDB＞/テーブル/へ１テーブル１文書を置く。本方式同梱の[記述規約](テーブル仕様書記述規約.md)を使用する。具体的な業務項目・長さ・DB採用も本方式内の仕様に保持する。
