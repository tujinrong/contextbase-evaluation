# 独立プロジェクトの工程境界

版8.2／2026-10-25。現行の独立配置。各実行結果は試験報告の範囲で判定する。

## 対象

選択方式の仕様正本specRoot=test-project1/spec/方式ID/で仕様を確認し、生成ソース正本sourceRoot=test-project1/srcs/方式ID/で生成・ビルド・試験を行う。各方式専用の規則も選択specRoot内に収容する。業務仕様と仕様間参照は選択specRoot内で閉じ、旧sourceRoot/specや他方式の仕様を代替入力にしない。

## 引用境界

ProjectReference、Compile Link、SQL include、生成器の入力、ローカル文書リンクを他方式へ出さない。ビルド・試験ツールの既定出力はsourceRoot内に置く。最終配布物と検査結果・入出力manifestはsourceRoot/build/の固定先へ更新し、中間生成・cache・試行はsourceRoot/.tmp/へ置く。全方式集約だけproject/build/とproject/.tmp/を使う。過去生成結果を実行ID別に残さずGit履歴を使う。

## 検証境界

逆生成には当該方式のソースZIPを渡す。移動後のtest-project1/spec/全体、spec-eval、入力manifest、他方式、過去報告を含めず、取得・調査・独立検証から除外する。実行済み・未実施・静的検査・fake使用・実機を区別し、入力と出力の版とハッシュを記録する。

## 変更範囲

工程ごとの許可範囲を守る。全体ルールの改訂が明示依頼された場合はdocs/agentsを同期する。業務仕様や未決のDB共有契約を配置修正だけで変更しない。構造問題はsourceRoot/build/generation/の固定先へ記録して中断する。
