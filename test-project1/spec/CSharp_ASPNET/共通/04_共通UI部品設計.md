# 共通UI部品設計（言語非依存）

版：8.4／2026-10-25。文書ID：COM-STU-004。検索条件・一覧と学生編集画面を省スペース化。登録・保存の制御は維持。

## 基本方針

本方式はWEB系の画面設計とする。ブラウザーの入力・選択・表とキーボード操作を用い、条件・一覧・操作を近接させる。今後の追加画面も入力桁数に応じた幅、グループ内の整列、狭幅時の折返し、フォーカス・項目エラー・確認の到達方法を定める。取得件数とページ移動は本方式の既存契約に従う。

本書の「部品」は利用者から見た共通の機能を表す。特定のHTMLタグ、Windowsコントロール、XAML、Vueコンポーネント、端末画面ファイルを指定するものではない。物理部品とイベントは方式別仕様で決定する。

| 部品番号 | 論理部品 | 共通動作 |
| --- | --- | --- |
| UI-01 | 画面枠・見出し | システム名、画面名、モード、利用者を表示 |
| UI-02 | メッセージ領域 | 情報・警告・エラーを文字で区別。受付番号を表示 |
| UI-03 | 文字入力 | 必須・最大文字数・入力保持・項目エラー。無断切捨てなし |
| UI-04 | 西暦日付入力 | 生年月日以外。西暦4桁、実在日・範囲、任意空欄、初期値を勝手に当日にしない |
| UI-05 | コード選択 | 値と名称を分離。検索は停止値も、登録は選択可否を表示 |
| UI-06 | クラス選択 | 検索は全年度のクラスを1選択欄で表示。年度・学年・コード・名称で識別。登録は年度・学年連動、人数・定員は参考 |
| UI-07 | 複数選択 | 在籍区分の複数選択。全解除はすべて |
| UI-08 | 検索一覧 | 学籍番号、氏名＋氏名カナ、生年月日、年度・学年、クラス、在籍区分、操作の7列。氏名とカナは同セル2段、行単位編集／参照 |
| UI-09 | ページ・並び順 | 20・50・100、許可4項目の並び順、0件と未検索を区別 |
| UI-10 | 一般確認 | 未保存破棄・削除・再読込。既定は取消 |
| UI-11 | 重複候補確認 | 全件数・最大20件、確認理由、別人確認／取消 |
| UI-12 | 未保存管理 | 最後の読込値と編集中値を比較。保存失敗で解除しない |
| UI-13 | 処理中管理 | 二重操作を抑止。完了・取消・障害時に状態を戻す |
| UI-14 | 長文編集・参照 | 表示幅を超える全文を確認・変更する手段 |

## 画面の標準構成

見出し、項目グループ、主要操作、メッセージを近接配置する。検索は条件と結果をまとめ、結果の案内は一覧・ページ操作の近くへ置く。登録は基本情報・住所連絡先・在籍所属・緊急連絡先・備考・理由に分ける。文字の必須印と説明を併記。参照専用値を編集可能に見せない。削除操作は保存と明確に区別する。

検索条件は学籍番号・氏名・クラス・在籍区分の4項目だけを常時表示し、詳細条件や折畳み条件は設けない。条件、主要操作、結果、ページ操作を同じ画面内へまとめる。一覧から住所・本人電話・更新日時を外し、必要時は学生登録画面の編集／参照で確認する。業務上限やページ件数を縮めず、表示行が領域を超える場合は一覧領域内でスクロールする。物理的な画面サイズと配置の検査条件は検索詳細の画面確認記録を参照する。

学生登録・編集・参照は、基本情報を上段へ横並びで置き、下段を住所・連絡先、在籍・所属、緊急連絡先・備考・確認理由の3列にまとめる。通常サイズでは全入力グループと更新・取消・再読込・検索へ戻る操作を同じ画面内へ配置する。狭幅・拡大時は2列／1列へ折り返す。保存項目や必須・文字数上限を減らして面積を調整しない。物理名は利用者向け表示から省き、仕様表と画面data属性に残す。

重複・論理削除・変更破棄の確認は通常画面とは別のダイアログ状態とし、必要なものだけを表示する。取消を既定とし、背景操作を抑止して、閉じた後は起動操作へ戻す。通常画面の下に確認画面を並べてページ長を増やさない。ダイアログも候補の全件数・表示上限、理由、取消・続行を欠落させず、長い内容はスクロールで確認できるようにする。

## 共通状態

| 状態 | 動作 |
| --- | --- |
| 初回・クリア | 初期条件。学生一覧は未検索 |
| 処理中 | 次の保存・削除・検索を抑止。単なる連打防止でDB排他を代替しない |
| 入力不備 | 入力値保持、エラー一覧と該当項目を関連付ける |
| 0件 | 該当なし、一覧空、ページ移動不可 |
| 10,000件超 | 条件追加の案内、一部だけの結果は出さない |
| 条件変更未実行 | 新条件未反映を明示。ページ操作は最後の実行条件 |
| 版競合 | 自動上書き・自動再読込をせず、入力保持と再読込案内 |
| 通信結果不明 | 再保存の前に検索確認。成功とも取消成功とも決めつけない |

## コード・クラス連動

検索では年度・学年・未所属のみの条件を設けない。クラスの「すべて」はクラス未設定の学生も対象に含む。クラス候補は全年度・停止・期間外を含め、年度・学年・コード・名称を表示する。条件変更は未反映表示だけを更新し、再検索や候補取得通信を起動しない。

登録では年度・学年変更で不適合となるクラスを解除し通知する。候補取得の新旧が逆転したとき古い結果を採用しない。

在学・休学は終了日を空、クラス必須。卒業・退学は終了日必須、クラス任意。コードやクラスの既存値が停止・期間外でも表示を消さない。保存時の有効性は保存済み値と比較して判定し、画面の「未変更」申告を信用しない。

## 操作・アクセシビリティ

キーボードで入力・検索・保存・取消を行えるようにする。確認は取消を既定とし、改行やEnter入力が削除・別人続行を不用意に確定しない。エラー項目への移動方法を用意する。色だけに意味を依存させず、使用不可・警告・必須を文字で表す。

一覧の長文は折返し・横スクロール・詳細参照等で全文を確認可能にする。端末の1パネル表示行数と検索の20・50・100件の単位を分離する。文字変換不能のとき元値を代替文字で上書きしない。方式ごとの入力制約・補助編集方法・実機確認事項を詳細仕様へ記載する。

個人情報を画面アドレス、ブラウザーや端末の無制限永続領域、通常の障害ログに記録しない。画面を閉じる際は未保存変更確認を行い、正常保存を確認した後だけ未保存状態を解除する。

## 和暦生年月日部品

UI-15は元号・年・月・日と項目エラーを持つ。候補は[共通暦定義](07_日付・和暦仕様.md)。元号名と識別値を分け、元年は表示に使用する。元号変更時は年範囲と境界日を再検査し、日付を自動補正しない。原入力と正規化日付を分離する。入力4値が空の新規状態と、未知元号・不正日を区別する。

一覧・参照・重複確認も共通16で和暦を表示。UI-04を全体的に和暦へ切り替える実装は不可。各方式はUI-15の物理コントロール名と保存側変換入口を方式別共通仕様に定義する。
