# 共通UI部品設計（言語非依存）

版：8.4／2026-10-25。文書ID：COM-STU-004。

## 基本方針

本方式の画面分類はText系。本書の「部品」は利用者から見た共通の機能を表し、物理表現は等幅文字・固定行桁・保護/入力属性とする。具体的な位置とキーは本方式内の基本/詳細・方式別共通仕様で閉じる。WEB系（WPFを含む）・WinForms系（Accessを含む）の部品を本方式の画面へ混在させない。

| 部品番号 | 論理部品 | 共通動作 |
| --- | --- | --- |
| UI-01 | 画面枠・見出し | システム名、画面名、モード、利用者を表示 |
| UI-02 | メッセージ領域 | 情報・警告・エラーを文字で区別。受付番号を表示 |
| UI-03 | 文字入力 | 必須・最大文字数・入力保持・項目エラー。無断切捨てなし |
| UI-04 | 西暦日付入力 | 生年月日以外。西暦4桁、実在日・範囲、任意空欄、初期値を勝手に当日にしない |
| UI-05 | コード選択 | 値と名称を分離。検索は停止値も、登録は選択可否を表示 |
| UI-06 | クラス選択 | 検索は全年度の独立選択。編集だけ年度・学年連動、人数・定員は参考 |
| UI-07 | 複数選択 | 在籍区分の複数選択。全解除はすべて |
| UI-08 | 検索一覧 | 論理一覧項目を参照表示。行単位編集／参照 |
| UI-09 | ページ・並び順 | 20・50・100、許可4項目の並び順、0件と未検索を区別 |
| UI-10 | 一般確認 | 未保存破棄・削除・再読込。既定は取消 |
| UI-11 | 重複候補確認 | 全件数・最大20件、確認理由、別人確認／取消 |
| UI-12 | 未保存管理 | 最後の読込値と編集中値を比較。保存失敗で解除しない |
| UI-13 | 処理中管理 | 二重操作を抑止。完了・取消・障害時に状態を戻す |
| UI-14 | 長文編集・参照 | 表示幅を超える全文を確認・変更する手段 |

## 画面の標準構成

見出し→メッセージ→項目グループ→主要操作の順とする。検索は条件と結果、登録は基本情報・住所連絡先・在籍所属・緊急連絡先・備考・理由に分ける。文字の必須印と説明を併記。参照専用値を編集可能に見せない。削除操作は保存と明確に区別する。

検索・学生編集の具体的な配置図は各基本/詳細の同一埋込みHTMLを正本とする。共通文書へ別配置の画面見本を重ねない。通常は27行×132桁、見出し1行/情報2行/操作22～24行/共通キー26行/状態27行を使用。検索は4条件、一覧4件×2行の表示窓。編集は全通常入力を同じパネルへ置き、長文はF8全文へ到達する。補助パネルも27×132とし、通常画面と同時に積み重ねない。

## 共通状態

| 状態 | 動作 |
| --- | --- |
| 初回・クリア | 初期条件。学生一覧は未検索 |
| 処理中 | 次の保存・削除・検索を抑止。単なる連打防止でDB排他を代替しない |
| 入力不備 | 入力値保持、エラー一覧と該当項目を関連付ける |
| 0件 | 該当なし、一覧空、ページ移動不可 |
| 10,000件超 | 条件追加の案内、一部だけの結果は出さない |
| 条件変更未実行 | 新条件未反映を明示。ページ操作は最後の実行条件 |
| 版競合 | 自動上書き・自動再読込をせず、入力保持と再読込案内 |
| 通信結果不明 | 再保存の前に検索確認。成功とも取消成功とも決めつけない |

## コード・クラス連動

検索の4条件は独立し、全年度クラス候補を使用する。条件変更は未反映表示だけ。編集に残す年度・学年の所属補助では、不適合なクラスを解除して通知し、逆転した古い候補応答を破棄する。

在学・休学は終了日を空、クラス必須。卒業・退学は終了日必須、クラス任意。コードやクラスの既存値が停止・期間外でも表示を消さない。保存時の有効性は保存済み値と比較して判定し、画面の「未変更」申告を信用しない。

## 操作・アクセシビリティ

キーボードで入力・検索・保存・取消を行えるようにする。確認は取消を既定とし、改行やEnter入力が削除・別人続行を不用意に確定しない。エラー項目への移動方法を用意する。色だけに意味を依存させず、使用不可・警告・必須を文字で表す。

一覧の長文は表示窓とF8保護全文で確認可能にする。端末の1パネル表示行数と検索の20・50・100件の単位を分離する。文字変換不能のとき元値を代替文字で上書きしない。方式ごとの入力制約・補助編集方法・実機確認事項を詳細仕様へ記載する。

個人情報を画面アドレス、ブラウザーや端末の無制限永続領域、通常の障害ログに記録しない。画面を閉じる際は未保存変更確認を行い、正常保存を確認した後だけ未保存状態を解除する。

## 和暦生年月日部品

UI-15は元号・年・月・日と項目エラーを持つ。候補は[共通暦定義](07_日付・和暦仕様.md)。元号名と識別値を分け、元年は表示に使用する。元号変更時は年範囲と境界日を再検査し、日付を自動補正しない。原入力と正規化日付を分離する。入力4値が空の新規状態と、未知元号・不正日を区別する。

一覧・参照・重複確認も共通16で和暦を表示。UI-04を全体的に和暦へ切り替える実装は不可。各方式はUI-15の物理コントロール名と保存側変換入口を方式別共通仕様に定義する。

### 省スペース配置の適用

検索4条件と8論理一覧項目、編集REG全34項目を維持。通常の条件/全項目/操作位置を27×132の格子に収め、サイズ不足は適合エラーにする。検索取得1頁20/50/100と4件表示窓を別管理し、候補の6件×2行窓やF8の欄内移動も取得ページと混同しない。F4候補、F8全文、F1説明、F12取消、Tab/Shift+Tab移動。複数エラー/候補/重複/削除/未保存破棄は別パネルへ切替。確認はN既定、明示Y+F5で続行、Enterは検査のみ。取消でrawと起点を復元し、確認中の背景操作を通さない。実機のキー割当・Unicode glyph/IMEはQA-TEXT-COBOLで検証する。アプリ認証は本サンプルでは対象外。

## Windows認証なしサンプル

| 項目 | 本方式での適用 |
| --- | --- |
| 利用者指定 | 「Windowsで実行できる環境を想定する」「サンプルのため、認証はしない」 |
| 実行前提 | Windows x64／GnuCOBOL 3.2／同bit C／Windows標準ConsoleとWin32 W API／Windows ODBC Driver18。Linux・unixODBC・pkg-configの必須前提を置換する |
| 認証の例外 | このサンプルではログイン・Windows token・利用者/role mappingを行わず、実行側が固定actor `sample-user`、固定操作role `Administrator` を設定する。全サンプル機能確認用であり、本番認証・認可への適合を主張しない。一般の認証/権限表と用語は、本サンプルではこの例外を適用して読む |
| 信頼境界 | actor/role/sessionを端末rawまたはREMOTE_USER/ST_TRUSTED_ROLEから受付けない。DB接続の権限・TLS・保存時の業務検査・期待版・理由・同時保存・監査は維持する |
| 状態 | 接続ごとのCSPRNG32byte・64桁hex session、画面instance・要求ID・期待Revision・期限を照合。検索30分・確認10分。実キー活動だけがidle期限を更新し、timerでは延長しない。idle30分で失効し、終了/切断/再起動/別プロセスへ引き継がない |
| 正本と未実施 | [Windows実行環境](方式別/02_Windows実行環境.md)を適用。QA-AUTHは本サンプルで対象外、QA-TEXT-COBOLはOS/技術選定済み・実glyph/IME/キー適合未検証。実DB・本番受入・正式採点は未実施 |
