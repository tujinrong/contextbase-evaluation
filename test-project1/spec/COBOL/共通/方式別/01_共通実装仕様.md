## PROGRAM-ID・COPY・呼出関係

```text
cobol/STMAIN.cob    認証済み端末要求の受付・振分け
cobol/STSRCH.cob    検索・ページ
cobol/STEDIT.cob    新規／既存表示
cobol/STSAVE.cob    登録更新の確定単位
cobol/STDELT.cob    論理削除
cobol/STNORM.cob    正規化呼出
cobol/STVALID.cob   入力チェック
cobol/STRULES.cob   存在・状態・期間・定員
cobol/STDUP.cob     同一人物候補・確認
cobol/STAUDIT.cob   操作履歴
cobol/STSTATE.cob   要求間の検索・確認状態
cobol/STAUTH.cob    共通認証アダプター
cobol/STRENDER.cob  固定行桁のTextパネル表示
cobol/STMAINT.cob   管理者CLI
copy/ST-REQUEST.cpy, ST-STUDENT.cpy, ST-SEARCH.cpy, ST-RESULT.cpy
copy/ST-DB-REQUEST.cpy, ST-DB-RESULT.cpy
bridge/student_bridge.c  ODBC・Unicode・暗号の境界処理（端末入力は別アダプター）
```

共通01～03＝STAUTH/STCLOCK、04～05＝STNORM/STVALID、06～10＝STMLOOK/STRULES/STDUP、11～12＝STSTATE、13＝STSAVE＋STDBOP、14＝STAUDIT、15＝STMSG/STRENDER。STCLOCK・STMLOOK・STMSGも呼出可能プログラムとして同じcobol配下に実装する。

```mermaid
flowchart TD
    MAIN[STMAIN] --> SRCH[STSRCH]
    MAIN --> EDIT[STEDIT]
    MAIN --> SAVE[STSAVE/STDELT]
    SAVE --> CHECK[STAUTH/STNORM/STVALID/STRULES/STDUP]
    SAVE --> AUDIT[STAUDIT]
    SRCH --> DB[STDBOP C bridge]
    SAVE --> DB
    AUDIT --> DB
    MAIN --> STATE[STSTATE]
    MAIN --> RENDER[STRENDER]
```

GnuCOBOLにEXEC SQLのプリコンパイル機能が標準であるとは仮定しない。DB操作は明示したCブリッジのODBCパラメーターAPIを使う。C側に学生業務を全移植せず、接続・型境界・固定SQL実行・Unicode処理だけを置く。

## SQL・エラー処理

共通の保存・検索手順は[SQL Server DB定義](../../DB定義/SQLServer/01_DB定義書.md)の補足説明を適用する。ここで定義するRepository/UnitOfWorkはその入出力・確定境界を実装する。名前だけを別DBへ置換したSQLは使用しない。

COBOLのcommand_idはST-COUNT/ST-LIST/ST-LOAD/ST-UQ/ST-DUP/ST-CAP/ST-INSERT/ST-UPDATE/ST-DELETE/LOG-INSERTを維持。ST-DB-REQUEST/RESULT COPYの引数は下記ODBC境界に対応する。

## Text端末・Unicode・状態

本方式の画面分類はText系。利用者の追加指定により、旧CGI Web画面を固定27行×132桁の端末画面設計へ変更する。GnuCOBOL 3.2/Linux、SQL Server/ODBC/Cブリッジの設計基準は維持する。端末製品・描画ライブラリー・入力/認証アダプターは未選定（QA-TEXT-COBOL）で、特定ランタイムのSCREEN SECTION/ファンクションキー対応を実装済みと仮定しない。既存CGIプログラムは今回未変更であり、新仕様との接続実装は未実施。

端末アダプターはSTMAINへ認証済みセッション、画面ID、action、要求ID、期待revision、名前付き原文字列/実バイト長/NULL標識を渡す。入力メッセージの最大65536byteは既存安全境界として維持し、不足/超過/不正UTF-8/NUL/同名単一項目重複/許可外項目を拒否する。端末制御シーケンスを学生文字列として実行せず、データを検査した上で端末描画APIへ渡す。仕様書埋込みHTMLのエスケープは文書表示のためで、製品HTTP応答ではない。

STNORMはCブリッジのUnicode正規化関数を呼ぶ。NFKC、Unicode scalarの単純大文字対応、空白除去、カナ対応、コードポイント数検査を行い、COBOLのFUNCTION UPPER-CASEやバイト置換だけで日本語を正規化しない。ライブラリー版を固定して共通ベクトルと照合する。

補助`t_runtime_state`を設ける：state_id varchar(64) PK（256bit乱数64桁hex）、owner_id nvarchar(128)、login_session_id varchar(64)、state_kind varchar(16)、encrypted_payload varbinary(max)、expires_at datetimeoffset(7)、revision bigint、consumed bit。検索30分・確認10分・成功Flash一回。業務5表ではない。payloadは認証済み暗号化、鍵は信頼する配備基盤の秘密管理、所有者と目的を照合、状態の更新・消費は条件付きで原子的に行う。期限切れを定期削除する。

認証済み端末接続の主体をSTAUTHへ渡し、端末入力欄の利用者名/Roleを信用しない。セッションの所有者/期限/画面目的/要求ID/期待revisionを毎回検査し、別接続の検索・確認状態を返さない。旧WS-CSRF-TOKENは内部項目ID維持のための互換名とし、新Text入口では端末セッション検証情報を保持する。HTTP Cookie/REMOTE_USER/ブラウザーCSRFを本画面の必須UI契約にしない。QA-AUTHの基盤製品未指定は継続し、端末認証との結合をQA-TEXT-COBOLで決める。login_session_idは認証済み端末接続ごとに分離する。同一接続内の画面再作成は所有者/画面/期限/Revisionを照合して復帰可。切断/再認証/アイドル期限で当該接続の検索/編集/確認状態を失効し、再接続は未検索・未確認へ初期化する。接続暗号化・切断失効・アイドル期限・認可は信頼する接続基盤側で実装し、DB資格情報/鍵はソースや画面へ保存しない。

## 共通規約・日付実装

対象読者は実務経験５年程度のプログラマー。[検索詳細](../../詳細仕様書/01_学生検索画面.md)／[登録詳細](../../詳細仕様書/02_学生登録画面.md)／[開発規約](../../規約/開発規約.md)／[日付正本](../07_日付・和暦仕様.md)。

共通16の入力は元号識別値・年・月・日という原文字列4値と業務日。出力は正規化日付と和暦表示文字列、または項目エラー。共通17は項目種別と日付／年度にDATE-R01～06を適用する。変換で不正日を補正しない。OS全体の暦設定を変更しない。元号表の版を画面・保存側で一致させる。

| 役割 | 実装仕様 |
| --- | --- |
| 共通16物理名 | STDATE / ST-DATE-INPUT COPY |
| 内部日付型 | PIC X(10)、SQL NULLは別標識 |
| 入力と保存 | 和暦原入力4値から日付を生成。StudentDraft等のbirth_date相当は正規化日付。元号をDBへ重複保存しない |
| 通信境界 | 端末の保存要求は元号/年/月/日の4原文字列を受け、保存側で厳密変換。既存取得応答のbirthDateはISO日付。入力と応答の型を混同しない |
| 表示 | 一覧・参照・重複確認のBirthDateWareki相当文字列は共通16で生成。その他の日付・日時は西暦 |
| 例外 | CHK-032～034、E-DATE-001～003。構文検査後、実在日、元号境界、逆変換、業務範囲、前後関係を順に検査 |
| 参考試験 | DATE-T01～20。ライブラリーの解析成功だけで元号境界を合格にしない |

### 保守入口・方式固有の適合条件

#### 処理単位

クラスを前提にしない。`STMAIN`が端末要求を受けて`STSRCH`（検索）、`STEDIT`（登録表示）、`STSAVE`（保存）、`STDELT`（削除）、`STMAINT`（管理者CLI）へ振り分ける。データ構造はCOPY句で共通化する。文字パネルは`STRENDER`が行/桁/属性/実長を端末アダプターへ渡して表示する。

### 保守・試験

`student-maint`は学生端末画面と分離した管理者CLI。STMAINT→同じ検証・保存・監査プログラム。初期5分類70値、差分時上書き禁止、クラス年度内一意、参照時学年不変、定員・期間・保護コード規則を維持する。

共通T-01～28、UTF-8の1～4バイト文字、PIC領域境界、端末制御文字の混入・重複項目・入力65536byte超過、同一接続内の画面再作成時の復帰、端末切断/再認証/再接続時の旧状態失効、C ABIの長さ・NULL・ポインター、DB失敗時のSQLSTATE、全候補を20件だけで判定していないことを試験する。

### SQL Server接続・型・共通呼出契約

検索Repositoryは型付き条件、page/pageSize、Cancellation/要求IDを受け、上限超過/件数/一覧/検索日時を返す。STSAVE/STDBOPのトランザクション管理は検索をSNAPSHOT、保存をREAD COMMITTED＋Transaction所有のsp_getapplockで制御する。全DBコマンドは同じConnection/Transactionを受け、個別Commitを禁止する。保存戻り値はSuccess/ValidationError/ConfirmationRequired/Conflict/NotFound/Unknownに分ける。OUTPUT値はCOMMIT確認前にSuccessへしない。

COBOLの型は下記ODBC境界に従う。.NETのSqlParameter/DateOnlyクラスはこの方式の依存関係に追加しない。

WHERE/LIKE/ページ/例外・ゲート戻り値はSQL Server DB定義を正本とし、LIKEは!/%/_/[のリテラル化を含む。接続暗号化、証明書検証、認証主体を最小権限で分離。UIの権限表示だけを更新認可として使わない。

### COBOLのODBC境界

GnuCOBOLはSQL Server用の組込みEXEC SQLプリコンパイラを前提としない。student_bridge.cがMicrosoft ODBC Driver 18 for SQL Server＋unixODBCを使用する設計案とする。環境・ABI・依存版はビルド工程で固定する。SQLAllocHandle→SQLSetEnvAttr→SQLDriverConnectW→SQLPrepareW→SQLBindParameter→SQLExecute→SQLFetch/SQLGetData、SQLGetDiagRecWでSQLSTATEとネイティブ番号を別々に返す。ハンドルの所有権・解放、SQL_SUCCESS_WITH_INFOの切捨て診断を明記し、01004を成功と扱わない。

COBOL UTF-8 PIC X(4×raw上限)＋実バイト長＋NULL標識をCブリッジへ渡す。CはUnicodeを検証してUTF-16へ変換し、SQLWCHARの実サイズ/ABIを確認する。SQL_C_WCHAR/SQL_WVARCHARのColumnSize（宣言長）とBufferLength（バイト長）とStrLen_or_IndPtr（実バイト長またはSQL_NULL_DATA）を区別する。SQL_C_SBIGINT/SQL_BIGINT、SQL_C_BIT/SQL_BIT、SQL_C_TYPE_DATE/SQL_TYPE_DATEも明示する。STCLOCKの日付はDB側の信頼時刻を基準とする。

SQL_ATTR_AUTOCOMMIT=OFFの同一HDBCで分離レベルとゲートを設定し、SQLEndTran(SQL_COMMIT/SQL_ROLLBACK)で終了する。文字列配列は個別パラメーターへ展開、採番はOUTPUT INSERTEDを読みCOMMIT成功後だけ返す。C側に学生業務の分岐を移さずSTVALID/STRULES/STDUP/STAUDITを維持する。t_runtime_stateは本DB定義の型へ合わせ、トークンは64桁hexとする。

参考：Microsoft ODBC https://learn.microsoft.com/en-us/sql/connect/odbc/microsoft-odbc-driver-for-sql-server ／SQLBindParameter https://learn.microsoft.com/en-us/sql/odbc/reference/syntax/sqlbindparameter-function 。2026-10-11参照。C ABIとODBC実機接続は未試験。

### 派生分類と監査の共通実装

新規／通常更新は[共通データアクセス](../08_データアクセス仕様.md)の緊急４保存項目一式を適用する。続柄分類を常にRELATIONSHIPへ設定する処理は禁止し、続柄値未設定時は分類もNULLへバインドする。コード値を更新する際は分類も同時更新し、変更列監査へ含める。必須３分類は固定のまま。

マスタ監査は[共通モジュール](../03_共通モジュール設計.md)の状態遷移表に従い、停止中の名称変更はUPDATE、状態が実際に停止へ変わる時だけDISABLEとする。認証不成立はE-COM-001、認証済み利用者の認可拒否はE-COM-002を使用し、実装の誤った番号を仕様値として採用しない。


### Text端末の検索・編集と省スペース配置

STRENDERは通常検索の4条件と8論理一覧項目を固定行桁のTextパネルへ出力する。SEARCHの業務条件名はstudentNo/name/classId/statusCodeだけ。未知名・廃止名は空値でもE-SRC-002、反復可能はstatusCodeだけ。STSRCHはST-SEARCH COPYへ検証済み4条件を渡し、ST-COUNT/ST-LISTを同一SNAPSHOTで実行する。Q-STUDENT-NOはPIC X(60)、Q-NAMEはPIC X(32)＋実バイト長、正規化氏名は640byte以上、Q-CLASS-IDは正64bit＋NULL標識、Q-STATUSはPIC X(2) OCCURS 4＋件数。検索で年度・学年・未所属連動を行わず、編集OPTIONSの所属補助は維持する。

STSTATEの暗号化payloadへ形式版search-compact-1を記録する。所有者・期限・期待Revisionを条件付き更新で照合し、旧形式はW-SRC-002で初期条件・未検索へ再初期化する。プロセス終了を跨ぐ状態をWORKING-STORAGEへ置かない。端末の再表示でも未実行入力と実行済み条件を分け、ページでは保持済み4条件だけを使う。

STEDIT/STRENDERは通常編集の全入力と管理値/主要操作を27行×132桁にまとめる。行桁・表示幅・P/U/R/E属性・キーは機能別詳細の配置表に従う。端末サイズは今回の設計値。検索取得1頁20/50/100と表示窓4件を区別し、窓移動でDB検索を増やさない。基本/詳細の埋込みHTMLは同一の等幅pre/span断片とし、Webコントロールへ置換しない。

F4候補は6件×2行、F8は全文編集/保護参照、複数エラーは選択番号付き別パネル。重複/削除/破棄は専用確認パネルでN/取消既定、明示Y+F5だけ続行。Enterのみで保存せず、F12で元入力/起点へ戻す。長文・raw不正値・補助文字・結合文字を表示幅で切捨てず、UTF-8容量/実長/NULL/65536byte/業務スカラー長と保存境界を維持する。変換不能は代替保存せずコードポイント編集経路または明示エラーとし、採用端末での実機適合を残す。

### 原入力保持・確認操作の整合補正

入力版の郵便番号raw領域と共有action許可列挙に不整合があったため、今回の入力保持・確認配置の関連範囲で補正する。E-POSTALのraw10スカラーはPIC X(40)＋実バイト長、正規化ST-POSTAL-CODEはASCII7桁、DB varchar(7)を維持する。ST-REQUEST COPYとSTRENDERの再表示へ同じraw40byteを渡し、28byteへ暗黙縮小しない。

STMAINの共有端末action許可集合はINIT/OPEN/NEW/MENU/SEARCH/PAGE/CLEAR/OPTIONS/CREATE/UPDATE/DELETE/CONFIRM/RESET/RELOAD/BACK/CANCEL。許可名と状態可否を別に検査する。RESET/RELOAD/BACKの変更破棄待ちはSTSTATEへraw入力・pendingActionを保存し、CONFIRMでサーバー保持の対象操作だけを続行、CANCELで確認を失効して原入力へ戻す。重複・削除のCONFIRMはサーバー保持種別から各イベントへ振り分け、削除理由や同一人物の確認を破棄承認で代替しない。所有者・期限・期待revisionと認証済み端末セッションを毎回照合する。WORKING-STORAGEだけで要求を跨ぐ確認待ちを保持しない。
