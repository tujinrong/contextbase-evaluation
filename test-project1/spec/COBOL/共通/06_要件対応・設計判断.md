# 要件対応・設計判断・適合試験

版：8.3／2026-10-25。文書ID：COM-STU-006。

## 改訂の要点

ユーザーの追加指定により、基本設計と共通の業務契約を言語非依存にし、詳細を7方式へ分割する。前段で作成していた単一のC#／ASP.NET Core向け詳細案を本方式共通の仕様として扱わない。現在のリポジトリに実装ソースが存在するという意味ではない。

| 方式 | 今回採用する実装前提（選定案） | 独自に定義する内容 |
| --- | --- | --- |
| VB.NET / WinForms | .NET 10、Windows Forms、SQL Server 2022 | Form、イベント、BindingSource、ErrorProvider、VB型・例外 |
| C# / WPF | .NET 10、WPF、SQL Server 2022 | XAML、MVVM、Command、通知・検証、Dispatcher |
| C# / ASP.NET | ASP.NET Core MVC／Razor、.NET 10、SQL Server 2022 | サーバー描画、ModelState、POST/Redirect/GET、認証・CSRF |
| Vue / C# API | Vue 3／TypeScript、ASP.NET Core Web API、SQL Server 2022 | SFC、Composition API、JSON契約、画面とAPIの分離 |
| COBOL | GnuCOBOL 3.2/Linux、Text系端末アダプター（製品未選定）、SQL Server 2022 | PROGRAM-ID、COPY、固定行桁・端末要求、UTF-8、CのODBC Driver18／Unicode補助 |
| AS400 / RPG | IBM i 7.5、ILE RPG全自由形式、DDS 5250、Db2 for i | DSPF・サブファイル・プロシージャー・CCSID・コミットメント制御 |

COBOLの処理系・画面方式、ASP.NETの種類、DB製品は元の依頼では未指定のため、上記を具体化のための仮定とする。COBOLの旧CGI画面案は今回の利用者指定によりText系へ改訂する。GnuCOBOL/Linux/SQL Serverは維持し、端末製品・描画/認証アダプターは未選定。IBM CICS等の別ランタイムを採用済みとみなさない。RPGは現行IBM i上のILE RPGを指し、古いRPG IIIの固定形式ではない。バージョンは設計基準であり「最新版」という主張ではない。各方式は別配備・別DBを原則とする。

## 範囲と制約

業務5表・89論理項目、5分類70コード、検索・登録の2画面、成績対象外を継承する。保持期間・学校種別・実クラス・認証基盤製品は未指定。画面パネル分割や補助技術表を追加しても業務機能の追加とは区別する。

本版の方式別評価設計は、小規模校向けに保存を短時間直列化する方法を許容する。DBの同時保存制御を利用し、プロセス内だけのフラグでは代用しない。細粒度化は性能測定後の変更とし、定員・同一人物候補・マスタ変更の競合試験を維持する。確認待ちにロックを保持しない。

AccessのACCDB単体では利用者別の強いDB権限境界を提供できない。共有ファイルを直接改変できる利用者に対し、VBA画面の権限制御を完全な保護と説明しない。信頼された職員だけの評価構成とし、本番で厳格な閲覧者／担当者分離が必要ならサーバーDBまたはAPIを介する別構成の承認を条件とする。[S-09]

5250の日本語端末表示は保存可能なUnicode文字集合と一致するとは限らない。RPG版では変換不能文字を上書きせず保持し、補助的なUnicode入力方式と実機試験を定義する。COBOLはText系の固定行桁パネルとF8全文/コードポイント編集経路を設計し、表示桁/固定長バイト領域/業務スカラー数を区別する。文字化け・代替保存・無断切捨てを許容しない。

## 本方式に共通する適合試験

| 試験ID | 条件・操作 | 期待結果 |
| --- | --- | --- |
| T-01 | 初回表示・クリア | 在学・休学、20件、未検索 |
| T-02 | 検索の全角番号・氏名空白差、登録の半角カナ | 検索N-06/N-03、登録N-04/N-05と一致 |
| T-03 | 氏名に%、_、! | リテラル検索、意図しない全件化なし |
| T-04 | 検索0・10000・10001件 | 該当なし／正常／上限警告 |
| T-05 | 廃止した入学日範囲キー・未知キー | 空値でも検索要求を拒否。ID維持 |
| T-06 | 全年度クラス選択、旧状態形式／旧Revision | 検索の上位絞込なし。旧形式再初期化、旧Revision拒否。編集の所属整合は維持 |
| T-07 | 停止コード・期間外クラスの既存値保持 | 参照可能、無関係な住所訂正を妨げない |
| T-08 | 使用済み学籍番号、削除済み番号 | どちらも保存不可 |
| T-09 | 同一人物候補・同姓同名の別人 | 警告、理由付き別人確認なら可 |
| T-10 | 確認後の入力・全候補版変更、期限切れ | 再確認。表示20件以外の候補変更も検出 |
| T-11 | 生年月日・入学・終了日境界 | 共通日付・区分整合を満たす |
| T-12 | 本人電話・メール・緊急電話すべてなし | 保存不可 |
| T-13 | 緊急連絡先3項目の一部だけ | 保存不可。全部空は可 |

| T-16 | 別クラスへ同一人物候補を同時登録 | 後続保存で先行を検出、無警告で2件確定させない |
| T-17 | 同じ旧版で同時編集・削除 | 一方だけ成功、他方は競合 |
| T-18 | 履歴追記を故意に失敗 | 学生／マスタ変更も取消 |
| T-19 | 住所入力途中に論理削除 | 住所の未保存値は適用されない |
| T-20 | 卒業から在学へ担当者が訂正 | 不可。管理者＋理由＋有効クラス＋定員で可 |
| T-21 | 更新なし | 版・更新日時・履歴を増やさない |
| T-22 | 保存確定後の通信断・応答喪失 | 結果不明を案内、盲目的再送なし |
| T-23 | 別利用者・別画面の復帰識別 | 他人の条件・入力・候補を返さない |
| T-24 | コード保護値停止、参照クラス学年変更 | 拒否し、既存学生を連鎖変更しない |
| T-25 | Unicode補助文字・最大桁・変換不能 | 文字数とバイト数を区別、切捨て・代替保存なし |
| T-26 | 日本時間0時・4月1日 | 業務日・年度が共通規則通り |
| T-27 | 検索条件変更後にページ操作 | 最後に実行した条件で取得、未反映を明示 |
| T-28 | マスタ利用停止と所属登録の同時操作 | 同時保存制御後の状態で整合、両方不整合確定なし |

## 5.0版の受入責務・差分

顧客の所在団体IT部門は論理DB連携・権限境界・運用条件・異常時結果を確認する。開発者は経験５年程度を想定し、共通規約を参照しつつ機能固有の物理割当・分岐を実装する。

1機能1ファイル化、概要内HTML、項目ID・候補取得元・イベントER・IO・項目更新仕様を整備。生年月日の和暦表示とDATE-R01～06を追加。1900年下限は設計案として顧客確認が必要。

[DATE-T01～20](07_日付・和暦仕様.md)を適合試験へ追加。今回の静的レビュー結果と未実施の実機試験をレビュー記録で区別する。

### v7のDB選択

DB変更は利用者指定。SQL Serverは従来のPostgreSQL5方式の置換である。Access/Db2は維持する。現在の技術根拠は[SQL Server定義](../DB定義/SQLServer/01_DB定義書.md)のSS-01～06を参照。新しいLIKEの角括弧エスケープ、負ゲート戻り値、COMMIT後だけ成功表示を境界試験へ追加する。

### 2026-10-23 検索・学生編集の配置判断

小規模学生管理という利用者前提により、番号・名前・所属・在籍の4条件で探索する。実データ件数や利用頻度の実測はしていない。検索で除外した個人情報は編集・参照に残し、DB保存項目・索引・制約は変えない。通常編集はREG全34項目を維持し、27行×132桁の固定配置と別の候補/全文/エラー/確認パネルへ整理する。静的モックの描画確認をアプリ試験・受入・正式採点へ読み替えない。

### 2026-10-25 Text系画面の設計判断と未決

ユーザー指定の分類はWEB系（WPF含む）/WinForms系（Access含む）/Text系（COBOL・AS400_RPG）。本方式はText系とし、27×132は通常編集の全項目/検索の4条件と4件表示窓/操作を収容する今回の設計値。端末の一般標準値や採用ランタイムの製品保証ではない。旧CGI入口を現行画面仕様の唯一方式として残さず、端末要求への割当を詳細/共通/規約へ同期する。プログラムは未改修。

QA-TEXT-COBOL（未解決）: 端末製品・描画/入力API・認証アダプター・利用環境・フォント/IME・27×132対応・キー割当・補助/結合文字の完全往復を実装前に選定/試験する。実装を確定できない点をGnuCOBOLが標準提供するとの推測で埋めない。表示窓は上限の縮小ではなくF8全文/コードポイント編集から同じrawへ戻す設計。既存QA-AUTH・日付/学校等の未決は継続し、DB物理型・業務規則・認可・保存・監査の契約は変更しない。
