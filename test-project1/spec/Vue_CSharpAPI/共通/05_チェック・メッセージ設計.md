# 共通チェック・メッセージ設計（言語非依存）

版：8.3／2026-10-28。文書ID：COM-STU-005。34チェック・58メッセージの正本。

## 正規化の意味

実装API・変数型は方式別仕様に定義する。業務上の長さはUnicodeコードポイント数。物理領域のバイト数や文字列処理系の長さと同一視しない。

| ID | 対象 | 共通規則 |
| --- | --- | --- |
| N-01 | 一般文字列 | 前後Unicode空白除去。任意空文字は未設定。NUL・制御文字は禁止。単一行では改行・タブ不可。備考・理由だけ改行可、改行はLFに統一 |
| N-02 | 氏名・住所・緊急氏名 | 前後空白だけを除き、内部空白・中点・異体字等の原表記を保持 |
| N-03 | 氏名照合用情報 | 氏名をNFKC→カルチャー非依存英大文字→Unicode空白除去。中点・長音・異体字を推測統合しない。160文字以内 |
| N-04 | 氏名カナ | NFKC→ひらがなを対応するカタカナへ→前後空白除去→内部空白を半角1字に集約。ァ～ヺ、ー、・、ヽ、ヾ、空白を許可。保存18文字 |
| N-05 | カナ照合用情報 | N-04の結果から空白を除く。中点・長音を残す |
| N-06 | 学籍番号・クラスコード | NFKC→前後空白除去→英大文字。先頭英数字、以降英数字またはASCIIハイフン。15文字／9文字。数値化しない |
| N-07 | 業務コード値 | NFKC後、分類の数字固定桁を確認。1を01に自動補完しない |
| N-08 | 郵便番号 | NFKC→空白・許可ハイフン除去→数字7桁。表示は3桁－4桁 |
| N-09 | 電話 | NFKC→空白・許可ハイフン・丸括弧除去。国内は0始まり10または11桁。国際は+の後に0以外で始まる7～15桁 |
| N-10 | メール | 前後空白除去。ASCIIの限定形式、ドメインだけ小文字化。ローカル部の大小は保持、全体60文字以内 |
| N-11 | 日付 | 生年月日は和暦原入力から変換、その他は西暦。共通日付仕様（文書07）で実在日・元号境界・範囲を検査。不正日を補正しない |
| N-12 | 検索メタ文字 | 利用者入力中の%、_、!等をその文字として照合し、問い合わせ式として解釈しない。方式ごとに安全なバインド・リテラル照合を実装 |

許可ハイフンはASCII、U+2010、U+2011、U+2212、およびNFKCでASCIIになる全角ハイフン。他の記号や英字を黙って削除しない。国内表記と国番号表記を相互変換しない。ひらがなの繰返し記号は対応カタカナへ変換し、未結合濁点等が許可範囲外ならエラー。

メールの限定形式は、@が1つ、ローカル部1～64文字、ASCII英数字と `. ! # $ % & ' * + - / = ? ^ _ `（バッククォート）` { | } ~` を許可。先頭末尾・連続ドット不可。ドメインは2ラベル以上、各1～63文字、英数字・ハイフン、両端英数字。国際化メール・引用ローカル部・IPリテラルは対象外。到達確認はしない。全有効メール構文を受け付ける規格適合を意味しない。

正規化前上限：学籍番号15、氏名8、カナ36、郵便番号10、住所各45、電話各20、メール60、緊急氏名8、備考120、理由60文字。正規化で短くなる場合でも入力上限を超えた値を黙って受け付けない。制限は正規化後の保存上限とも別に検査する。

## 補足説明

### チェック一覧の補足

CHK-015：旧席と新席は、非削除の在学・休学なら所属クラス、それ以外なら席なし。新席が未設定でなく旧席と違う場合だけ増加先を検査する。卒業・退学・削除による席解放には人数加算の定員検査を行わない。定員未設定は制限なし。CHK-031：クラス開始日≦終了日、かつクラス終了日≧入学日。最終所属なし、または所属・日付・区分を保持した住所等の変更には重なりを再強制しない。

### メッセージ一覧（58件）の補足

項目名パラメーターは日本語論理名。文言へ内部列名・SQL・例外スタックを露出しない。複数項目の基本エラーはまとめて表示する。



成功文言は確定を確認した後だけ表示する。結果不明の場合はE-COM-004に加えて「再保存前に検索で結果を確認してください」と案内する。保存されていないと断定しない。方式固有のHTTP状態、例外番号、SQL状態は各方式別共通仕様・DB定義・開発規約で上記番号へ対応付ける。

### 日付追加メッセージ



生年月日の上下限メッセージも和暦、それ以外は西暦。実在日エラーE-STU-005、前後関係E-STU-006～008は維持する。追加チェックの契機・順序・試験は[共通07](07_日付・和暦仕様.md)。

### 4条件要求の境界検査

検索条件はSRC-001/002/006/008だけ。未知名と廃止名は空値でもE-SRC-002で拒否する。登録のカナ・住所・電話・年度学年・日付検査は維持する。CHK-014の年度学年とクラスの照合は編集の選択補助に適用し、検索のクラスIDへ要求しない。旧形式の検索状態はW-SRC-002で未検索へ戻し、旧条件から自動再検索しない。

### 2026-10-28 イベント別の検査・メッセージ対応

基本設計の各イベントに、既存CHK/共通処理→成立条件/分岐→本書の日本語メッセージ→復帰/確定境界を対応付けた。既存34チェックID・58メッセージIDと廃止IDは維持し、新しい業務チェックや文言IDを追加しない。項目のraw上限、正規化後上限、必須条件、コード分類・既存停止保持、在籍/クラス/連絡先一式の検査は既存定義が正本。

4手順以上は意味のまとまりで番号を階層化し、元の処理順と条件を保持する。形式が成立した項目だけ日付関係等を判定する。保存直前は存在・版・学籍番号一意・席増加・参照を既存保存単位で再確認し、確認待ちはロックを保持しない。成功は業務変更と履歴の確定後だけ。変更なし・取消・版競合・結果不明を区別し、結果不明時の自動再保存は禁止する。
