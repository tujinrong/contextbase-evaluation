# 共通UI部品設計（言語非依存）

版：8.4／2026-10-25。文書ID：COM-STU-004。

## 基本方針

本方式はWinForms系の画面設計とする。標準Form/Label/TextBox/ComboBox/CheckBox/GroupBox/DataGridView/Buttonを使い、項目の表示桁数から幅を決める。今後の追加画面もラベル位置・入力左端・同種部品の高さを揃え、基準DPIのpxと拡大時の動作を明記する。学生検索は既存の全件取得・DataGridView内スクロールを使用する。

本書の「部品」は利用者から見た共通の機能を表す。特定のHTMLタグ、Windowsコントロール、XAML、Vueコンポーネント、端末画面ファイルを指定するものではない。物理部品とイベントは方式別仕様で決定する。

| 部品番号 | 論理部品 | 共通動作 |
| --- | --- | --- |
| UI-01 | 画面枠・見出し | システム名、画面名、モード、利用者を表示 |
| UI-02 | メッセージ領域 | 情報・警告・エラーを文字で区別。受付番号を表示 |
| UI-03 | 文字入力 | 必須・最大文字数・入力保持・項目エラー。無断切捨てなし |
| UI-04 | 西暦日付入力 | 生年月日以外。西暦4桁、実在日・範囲、任意空欄、初期値を勝手に当日にしない |
| UI-05 | コード選択 | 値と名称を分離。検索は停止値も、登録は選択可否を表示 |
| UI-06 | クラス選択 | 検索は全年度の識別付き候補、編集は年度・学年連動。人数・定員は編集の参考値 |
| UI-07 | 複数選択 | 在籍区分の複数選択。全解除はすべて |
| UI-08 | 検索一覧 | 論理一覧項目を参照表示。行単位編集／参照 |
| UI-09 | 並び順・一覧移動 | 許可4項目・昇降順、上限内の全一致を一括表示し内部スクロール。0件と未検索を区別 |
| UI-10 | 一般確認 | 未保存破棄・削除・再読込。既定は取消 |
| UI-11 | 重複候補確認 | 全件数・最大20件、確認理由、別人確認／取消 |
| UI-12 | 未保存管理 | 最後の読込値と編集中値を比較。保存失敗で解除しない |
| UI-13 | 処理中管理 | 二重操作を抑止。完了・取消・障害時に状態を戻す |
| UI-14 | 長文編集・参照 | 表示幅を超える全文を確認・変更する手段 |

## 画面の標準構成

見出し→メッセージ→項目グループ→主要操作の順とする。検索は条件と結果、登録は基本情報・住所連絡先・在籍所属・緊急連絡先・備考・理由に分ける。文字の必須印と説明を併記。参照専用値を編集可能に見せない。削除操作は保存と明確に区別する。

## 共通状態

| 状態 | 動作 |
| --- | --- |
| 初回・クリア | 初期条件。学生一覧は未検索 |
| 処理中 | 次の保存・削除・検索を抑止。単なる連打防止でDB排他を代替しない |
| 入力不備 | 入力値保持、エラー一覧と該当項目を関連付ける |
| 0件 | 該当なし、一覧空、行操作不可 |
| 10,000件超 | 条件追加の案内、一部だけの結果は出さない |
| 条件変更未実行 | 新条件未反映を明示。並び替えは最後の実行条件、スクロールは取得済み一覧内だけ |
| 版競合 | 自動上書き・自動再読込をせず、入力保持と再読込案内 |
| 通信結果不明 | 再保存の前に検索確認。成功とも取消成功とも決めつけない |

## コード・クラス連動

検索は学籍番号・氏名・クラス・在籍区分の4条件。クラスは全年度・停止・期間外を含め、年度・学年・コード・名称を表示し上位条件連動は行わない。編集だけ年度・学年変更で不適合クラスを解除し通知し、古い候補応答を採用しない。

在学・休学は終了日を空、クラス必須。卒業・退学は終了日必須、クラス任意。コードやクラスの既存値が停止・期間外でも表示を消さない。保存時の有効性は保存済み値と比較して判定し、画面の「未変更」申告を信用しない。

## 操作・アクセシビリティ

キーボードで入力・検索・保存・取消を行えるようにする。確認は取消を既定とし、改行やEnter入力が削除・別人続行を不用意に確定しない。エラー項目への移動方法を用意する。色だけに意味を依存させず、使用不可・警告・必須を文字で表す。

一覧の長文は折返し・横スクロール・詳細参照等で全文を確認可能にする。DataGridViewの可視行数と全一致の取得件数を分け、表示件数の指定やページ取得を設けない。文字変換不能のとき元値を代替文字で上書きしない。方式ごとの入力制約・補助編集方法・実機確認事項を詳細仕様へ記載する。

個人情報を画面アドレス、ブラウザーや端末の無制限永続領域、通常の障害ログに記録しない。画面を閉じる際は未保存変更確認を行い、正常保存を確認した後だけ未保存状態を解除する。

## 和暦生年月日部品

UI-15は元号・年・月・日と項目エラーを持つ。候補は[共通暦定義](07_日付・和暦仕様.md)。元号名と識別値を分け、元年は表示に使用する。元号変更時は年範囲と境界日を再検査し、日付を自動補正しない。原入力と正規化日付を分離する。入力4値が空の新規状態と、未知元号・不正日を区別する。

一覧・参照・重複確認も共通16で和暦を表示。UI-04を全体的に和暦へ切り替える実装は不可。各方式はUI-15の物理コントロール名と保存側変換入口を方式別共通仕様に定義する。

## 省スペース配置

通常編集は従来のWinFormsフォームとして、上段を「基本情報」、中央左を「住所・本人連絡先」、中央右を「在籍・所属」、下段を「緊急連絡先・備考・理由」のGroupBoxへ配置する。幅の長い住所・メール・備考を左側へまとめ、短い日付・年度・区分を右側へまとめる。各グループ内はラベル左端、入力左端、同じ種類の入力高さ、32pxの行送りを揃える。短い番号・日付・氏名・電話をグループ全幅まで引き延ばさない。REG-001～034と和暦4入力、raw／保存上限、条件付き必須、保存19入力／更新18入力＋生成照合値2は維持する。

設計基準はClientSize=1180×610、96DPI、Segoe UI 9pt（日本語フォールバックはYu Gothic UI）、SystemColors.Control背景・WindowText文字の標準部品である。静的HTMLでは標準外枠・タイトル26pxを加えた1182×638pxの設計見本とし、1366×650および1280×650 CSS px・100%で確認する。TextBoxは単行23～24px、ComboBoxは24px、Buttonは27pxを基準とする。9ptの可読文字に必要な内側高さを確保した従来デスクトップ設計であり、34px固定のWeb風入力欄やカードの等分割、色帯・角丸・影は採用しない。

通常のフォーム本体は1画面に収め、確認は所有者付きShowDialogの別Formへ排他表示する。既定・Escapeの取消で元操作へ戻し、通常フォームに確認例を縦積みしない。HTMLのdata-state=duplicate/delete/discardは別確認Formの静的状態を表す。エラー一覧は高さに応じて内容を押し下げ、AutoScrollで全項目と操作へ到達可能にする。待機中のDBロック保持、権限、保存制約は変更しない。

表示幅は保存制限ではない。単行TextBoxはAutoScroll相当のカーソル移動・Home/End・選択で全文へ到達し、備考と理由はMultiline=True、ScrollBars=Vertical、AcceptsReturn=Trueとする。MaxLengthはrawのUTF-16領域を確保し、業務長はUnicodeスカラー値で別検査する。長文の省略表示だけで元値を切り捨てない。画面サイズ低下・DPI拡大時は最小部品幅を維持してフォームのAutoScrollを使い、HTMLのブレークポイントでカードを組み替える設計にはしない。実装・ネイティブ実機・DPI試験は未実施。
